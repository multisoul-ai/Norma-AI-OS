# 下一步建议：与紧凑原型对照

原型：`docs/prototypes/brain-readable-cards/screenshots/compact-proposal-dark.png`。只对照本次“需要你处理”中的卡片，不把演示画布、统计栏或历史面板当成本次差异。

- `01-proposals.png`：两条建议默认收起，位于连续分隔列表中；行动、对象和右侧拒绝/采纳清楚可辨，按钮不依赖展开，栏标题和顶部待你处理计数均为 2。
- `02-expanded.png`：三条编号行动完整可见，动作标签有强调；顺序为行动、原因、交付，再到靠左且仅文字宽度的“完整任务”入口。不得出现一整条居中的宽按钮，不得丢失“不得推送”等范围限制。
- `02b-original.png`：第二层原文展开后目标、全部步骤和验收完整，外层拒绝/采纳仍可操作；原文不替换派发载荷。
- `03-ignored.png`：只移除被拒绝项，另一条保持收起与可操作，待处理计数为 1。
- `04a-waiting-confirmation.png` / `04-dispatch-ready.png`：阻塞原因和禁用明确，解除后采纳恢复可用。
- `05-dispatched.png`：无需展开即可采纳，目标接收一次完整原文，被拒绝项未派发。
- `05b-dispatched-panel.png` / `05c-dispatched-detail.png`：既有幕僚活动面板保留“你批准”及“触发 · 你批准提议”；展开包含“理由：你批准了幕僚的提议”和“停止该 Agent”，没有“以后这类先问我”。本次若仅验布局差异，可复用原有有效视觉证据，不能把未查看的图标记通过。

硬断言继续要求：重启恢复两条提议；确认前未发送任务；忽略项未发送；Bella 仅收到一次完整原文；最终提议文件存在且是含空 items 的有效 JSON。

本次覆盖 Ink Black 与 Sapphire Night，均为现行深色主题。问答及审批外层操作使用各自最小场景复验；脚本化模型只证明 UI 与生产派发链，不证明真实模型的文案质量。
