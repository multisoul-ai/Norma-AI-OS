# Norma Super-Agent：大对话、决策待办与原画布

本目录是第二轮设计原型。它依据 `docs/research/2026-11-04-super-agent-workflow.html` 和同目录研究记录，保留原画布的执行现场，增加完整对话页面与需要用户处理的事项。没有修改正式 App。

## 打开

在仓库 / worktree 根目录运行：

```bash
python3 -m http.server 8745 --bind 127.0.0.1
```

- 原型：`http://127.0.0.1:8745/docs/prototypes/norma-super-agent/?v=1`
- ELI5 说明：`http://127.0.0.1:8745/docs/research/2026-11-04-super-agent-workflow.html`

也可以直接打开 `index.html`。它引用仓库内默认视频和静态兜底资源；移动文件时需保留相对目录。背景实际播放 `crates/app/assets/wallpapers/norma-awake.mp4`，没有用静态截图替代。系统减少动态效果时默认暂停视频，用户可主动播放。

底部比较器 / 数字键 1–3 / 左右方向键切换风格。URL 保存选择；刷新恢复示例数据。三套共用一份当前页面内的工作、决定、对话与接管状态。

## 三种风格

| 名称 | 视觉与信息组织 | 适用场景 | 代价 |
| --- | --- | --- | --- |
| 玻璃会客厅 | 通透深色大对话；右侧卡片完整呈现所有待决定主题，选中后展开材料 | 沉浸感、快速看见全部关键事项 | 多事项时需要滚动清单 |
| 纸感简报 | 浅色纸感对话、编辑式排版；右侧先选事项，再读一张完整决定单 | 长文阅读、一次专注做一个决定 | 全部决定的细节无法同时对比 |
| 连续行动流 | 紧凑深色对话；可切换明确工作上下文，行动记录与待决定队列并行 | 连续多任务沟通、反复跟进同一工作 | 对话关联状态需要用户可见、可核对 |

三套共用大对话 + 右侧决策清单的产品结构，均可切回原画布。视频、卡片现场和返回路径保持连续。正式 GPUI 的无限画布仍需生产集成；本页是对应工作、卡片平移与接管反馈的浏览器演示，不声称已经实现生产接管协议。

## 信息与行为

- **Work、Worker、卡片分开建模。** 示例工作保存明确 id 与 owner；待办用 work id 关联原问题，画布通过关联找到 Agent 卡片。
- **人类待办只有回答、授权、验收。** 回归、文档与正常进度不会逐条进入主清单。
- **推荐带理由与材料。** 展开依据显示原问题、证据、影响范围；技术方案标明来自原 Agent，由 Norma 汇总。
- **采用不等于完成。** 采用登录方案后工作继续；允许预览后进入执行；本轮验收通过只变为待合并，不自动发布或合并。
- **修改答复有记录。** 保留用户输入，答复写入已处理记录，重复或过期决定不会重复提交。
- **定位与返回。** 进入同一示例画布后，目标卡片居中、高亮；返回保留对话草稿、选中事项和阅读位置。
- **直接接管。** 接管 Agent 后禁止自动采用该 Agent 的建议，显式交还后恢复。此处只改变示例状态，不控制真实 PTY。
- **可选建议独立收纳。** 后续派给原 Agent，忙碌时不可派发，不把可选建议当成人必须完成的紧急事项。
- **完整交互反馈。** 支持依据、方案调整、稍后处理、已处理记录、按需工作进展、搜索、工作关联、语言切换、视频播放 / 暂停和系统语音摘要。
- **本地演示。** 自由输入会进入对话并得到演示回复；不调用 LLM、真实部署或真实 Agent。示例材料与运行数据均有标注。

## 技能与设计依据

参考 `prototype`、`apple-design`、`emil-design-eng`、`frontend-design`、`ponytail`；研究与说明分别使用 `research`、`answer-me-with-html`。

- Apple 信息层级：用户目标与对话为主，必须决定的事项在旁；原画布随时可达。
- 平台熟悉性：顶部保留 macOS 标题栏语境，两个明确的视图入口；Escape 关闭、Tab 约束焦点、Enter 发送、Shift+Enter 换行、IME 组合期间不误提交。
- 直接反馈：采用、修改、授权、验收、接管均产生具体状态；按钮覆盖 hover / pressed / focus / disabled。
- 材质：文字落在稳定的玻璃 / 纸感表面，背景视频保留在同一层，不随画布平移移动。
- 动效：高频页面切换和定位即时；不加入循环 UI 装饰动画。按钮按下反馈 120ms；原型比较器按技能规范使用 250ms 滑动，减少动态效果时禁用。
- GPUI 后续映射：视图与输入意图进入 runtime 纯路由，定位复用既有卡片能力；控件优先 `ui::component`；视频维持既有低拷贝渲染，不以 HTML 原型实现替换生产解码路径。

## 验收

2026-11-04：6 组 Playwright 交互测试通过。测试使用本机独立 Chrome，不接管已有浏览会话；背景解码真实读到 1920px 视频宽度。

| 用户需求 / 边界 | 验证 |
| --- | --- |
| 保留画布并能快速进入现场 | 三风格都验证目标卡片横纵居中，误差 < 4px |
| 大对话与右侧需人工事项 | 三风格主流程与 3 条待办计数 |
| 减少管理负担、推荐可处理 | 采用 / 编辑原问题，已处理记录、工作状态同步 |
| 答复不冒充完成 | 登录答复后继续执行，本轮验收后仍待合并 |
| 直接接管不能被自动派发覆盖 | 接管时禁用采用，交还后恢复 |
| 返回保留上下文 | 选中事项与未发出的输入草稿 |
| 双语与键盘 | 英文三风格切换，输入数字不误切原型，视频可真实暂停 |

另检查三套全部事项处理后的空态、说明页 8 个部分与两张图，以及 1280 / 1024 / 768 / 390px 布局。结果以实际检查记录为准，不能只凭截图文件存在认定通过。
