# Norma 助手模式交互原型

入口：[index.html](index.html)。单文件 HTML，CSS、JavaScript、图标和示例图片均内嵌，无构建步骤；声音分析使用附带的本地 macOS 语音服务。

**当前版本包含文末「光学材质重设计」与「卡片连续过渡 · 2026-10-04」。** 保留原来第一款「极光」，并放在首位；新增「玻璃」和「水银」两种原创光学材质，三种外观共享真实声音响应与全屏左下角停靠。旧流光、虹彩、棱镜和绸光已被本轮新材质替换；星云和波纹保持移除。此前版本记录为历史。

直接双击 HTML 可查看视觉与文字交互；声音驱动体验需在 macOS 上通过以下本地服务打开，服务使用系统自带的 `say`（Tingting 声音）和 `afconvert`，浏览器通过 Web Audio 播放及分析实际 PCM。浏览器支持 `SpeechRecognition` 时可使用其识别能力；文字指令不需要麦克风权限。

```bash
python3 docs/prototypes/norma-assistant/server.py --port 8765
```

打开 `http://127.0.0.1:8765`，点击“演示一下”，或输入：

- “看看项目进度和网页”：同时展开进度、网页卡片。
- “找一下设计文件”：展示三个可展开的内置示例文件。
- “看看图片和视频”：图片可放大，动态预览可播放、暂停、拖动进度。
- “关闭网页”：定向关闭网页，保留其他卡片。
- “收起所有卡片”：回到纯净舞台。

体验声音响应：点击右上角扬声器开启播报，再点击“查看进度”或发送文字指令。点击同一扬声器关闭时立即停止播放。普通静态 HTTP 服务不提供 `/api/tts`，无法体验此声音分析。

“打开网页”直接进入全屏内容模式；“网页摘要”保留卡片展示。文件正文、图片以及每张卡片右上角的全屏按钮也可进入内容模式，或输入“全屏展示文件”“全屏展示图片”“全屏展示视频”。

全屏时圆球缩到左下角，底部保留输入框，完整内容独立滚动。按 Esc、点击“返回对话”或输入“退出全屏”恢复对话舞台，原有卡片保留。普通对话中 Esc 打断尚未完成的回应。卡片的固定按钮改变固定状态与边框反馈，关闭和收起指令仍可主动移除固定卡片。本轮不保存卡片状态。

## 范围

这是对话驱动界面的视觉与交互验证，没有接入 Norma 的 Agent Runtime、生产 ASR/TTS 或项目数据。语音播报由本地 macOS 系统声音合成，音频不发送到远程 TTS。进度、网页和文件正文为预置示例；全屏网页呈现完整可滚动的本地网页布局，并非 Apple 官网实时内容，顶部提供原网页入口。图片是原创 SVG；视频卡片为 Canvas 动态预览，并非真实视频播放器。浏览器语音识别可能使用其在线识别服务。

## 设计依据

参考 `.agents/skills/apple-design`、`.agents/skills/animate`、`.agents/skills/emil-design-eng`、`.agents/skills/review-animations` 及已安装的 `frontend-design`。

- 内容优先：初始不展示仪表盘，圆球为唯一中心；卡片按需要出现。
- 材质与层级：纯黑背景、柔和光场、半透明玻璃卡片与胶囊输入框；正文使用 macOS 系统字体。当前助手外观以文末“光学材质重设计”为准。
- 即时反馈：按下立即反馈；倾听、思考、回应均有可读状态；语音权限或服务问题在页面说明。
- 空间连续性：卡片从左右各自方向进入；预览就地展开，关闭后回到触发控件。
- 可访问性：所有按钮有标签与可见焦点，输入可用键盘，dialog 支持 Esc 和焦点恢复；减少动效时圆球静止、卡片仅淡入，减少透明度及增强对比度也有替代样式。
- 科幻感用于助手的存在感，拒绝全屏移动背景、密集 HUD 仪表和装饰性遥测数字。

未来 GPUI 实现需验证钉死版本，材质映射到共享主题，卡片对应真实 Live Node，圆球采用 Metal 绘制，对话决策放到域层；本轮没有改动生产 Rust 代码。

## 全屏内容模式 · 2026-10-03

继续采用 apple-design 的内容优先、直接反馈、可返回原则：完整内容替代小型预览弹层，助手在左下角持续可用。网页、文件、图片、视频和进度共用内容容器；网页与文件可滚动，媒体保持原比例，工具栏提供返回和来源入口。

新补 5 项失败测试后实现，全套 11 项通过。纯函数 `applyPresentation` 决定当前全屏目标，返回只清除展示目标，不删除卡片；关闭无关卡片或收到帮助回复时保持正在阅读的内容。

| Before | After | Why |
| --- | --- | --- |
| 内容集中在小型居中预览弹层 | 完整视口内容区，圆球停靠左下角 | 让网页和文档获得足够阅读空间 |
| 返回可能丢失内容上下文 | 保留卡片及触发控件焦点，恢复对话舞台 | 不打断用户继续查看信息 |
| 视频全屏重新创建播放控件 | 移动同一 Canvas 与控件，返回后恢复原位置 | 避免重复 id 和失效事件处理器 |

动效结论：Approve。圆球位置切换使用 260 ms 的 transform/opacity 动画，从当前可见位置开始，快速反向可接管；内容淡入 180 ms。键盘触发及减少动效时即时切换，不插值布局尺寸。对话回复仅改变圆球状态，不遮住正在阅读的内容。

真实浏览器 Computer Use 已验证：

- 单独打开网页进入全屏；1280 × 720 下内容宽度为 1280，圆球位于 x=14、y=627，实际光体在左下角可见。
- 网页导航能滚动到正文；正文 scrollHeight=1331，不被小型弹层截断。
- 全屏图片保持原比例；Esc 返回后网页与图片卡片各保留一张。

- 阅读中输入暂不支持的问题，帮助回复出现且当前文件仍保留。
- 视频全屏可播放、暂停，返回后卡片与播放按钮各一份，控件仍可用。
- 从全屏收起所有卡片后，卡片为 0，圆球恢复居中。
- 浏览器控制台无 error/warn。

## 连续动效优化 · 2026-10-03

当前版本以这里的参数为准。目的为保持空间连续性、反馈助手状态、衔接内容切换。按 apple-design 的移动弹簧采用 response=0.4 s、damping=1：X、Y 和缩放分别保存位置与速度，通过临界阻尼解析解推进。圆球在约 0.4 s 内走完 98% 的路程，之后收敛；这段跨越主视图的助手迁移保留物理减速尾段，没有终点弹跳。普通控件与内容淡入仍控制在 280 ms 内。

| Before | After | Why |
| --- | --- | --- |
| 圆球 260 ms ease-out，取消后重启速度 | 临界阻尼移动，反向继承当下位置和速度 | 避免快速切换时硬切方向，保持助手的位置连续 |
| 提前将圆球缓冲区缩到 100 px 再放大移动 | 飞行保留较大端分辨率，停靠后再降采样 | 大小变化保持清晰，不每帧重建绘制缓冲区 |
| 输入框和文案瞬间换位，内容退出立即消失 | 输入框同步移动，文案交接淡入，正文进入与退出均过渡 | 避免多个层分别跳变；新操作可以随时接管 |
| 全屏内容之间直接替换 DOM | 旧内容快照 160 ms 淡出，新内容 240 ms 淡入 | 网页、文件、图片和视频切换保持视觉连续；快照不可交互并自动清理 |
| 圆球约 30 Hz 节流、能量按帧变化 | 光流与位移共用 requestAnimationFrame，能量按时间平滑 | 刷新率不改变响应节奏；低频呼吸、单条轨道光、状态波形提供克制的科技感 |
| 卡片关闭立刻删除，多卡片同时出现 | 收起 160/200 ms 淡出，出现间隔 60 ms，淡出中召回复用卡片 | 让信息出现与离开的节奏一致，避免重复节点 |

审查结论：**Approve**。位移仅写 transform；场景衔接使用 transform/opacity；布局仅在目标切换时测量。后台跳过圆球绘制。键盘触发视图切换即时完成；减少动效时不播放位移，圆球固定着色器时间，状态反馈与文字继续保留。没有增加第三方依赖。

新增 4 项聚焦测试，先确认运动模块缺失时失败，再实现：验证起步连续、无弹跳收敛、中途反向速度继承、60/120 Hz 下位置与能量一致。与原有 11 项对话意图测试合计 15 项通过，3 个内嵌脚本语法检查通过。

```bash
node --test docs/prototypes/norma-assistant/tests/*.test.mjs
```

真实 Codex 浏览器经 Computer Use 检查：

- 进入全屏和返回均观察到中间位移；快速返回后再次展开，圆球保持飞行中的位置与较大端绘制分辨率，最终停靠左下角。
- 默认 1060 × 959 视口下内容宽度 1060 px；停靠圆球为 100 px，正文与输入框均可见。
- 网页切换至文件、文件间切换、图片完整展开，光球继续停靠，切换后快照为 0，DOM 无重复 id。
- 全屏视频播放、暂停、切到文档、返回卡片正常；视频 Canvas 与播放控件各保留一份。
- Esc 即时返回，圆球 transform 已清空，展示层 hidden=true，快照为 0。
- 最新版本调出图片与视频两张卡片，再定向关闭图片：图片移除、视频继续保留，输入焦点恢复。
- 浏览器控制台无 error/warn。减少动效的系统设置没有在本轮切换，验收仅覆盖相关代码与计算逻辑。

## 黑色玻璃与简洁布局 · 2026-10-03

应用 apple-design 的材质分层、内容优先、文字层级与克制原则。首页背景为纯黑，保留品牌、圆球、主标题和对话输入；移除问候区、装饰性英文、口号与多余的输入提示。状态改为中文，仅在倾听、思考与回应时出现。四个建议入口精简为“查看进度”“打开网页”“浏览文件”“图片与视频”。

玻璃材质由半透明底色、柔和反射渐变、细边缘高光与内侧亮边共同构成：输入框与卡片采用 26 px backdrop blur，文档侧栏采用 20 px，帮助窗口采用 28 px。通过不同材质重量区分内容和操作；较高对比度的文字与选中背景保证深色界面可读。系统减少透明度或浏览器不支持 blur 时切换到实色背景。

圆球减少网纹、细线与颗粒，强化顶部反射和边缘高光；保留蓝色内部光流与既有连续停靠动效。内置网页示例和文件阅读器统一为近黑底色，完整内容区和左下角助手布局继续保留。这里的网页配色只作用于原型内置示例。

| Before | After | Why |
| --- | --- | --- |
| 深蓝背景叠加颗粒与多处装饰文字 | 纯黑背景、简短主标题和中文状态 | 保留留白与主次关系 |
| 方形输入框和较硬的面板边缘 | 玻璃胶囊、浮动圆角卡片、反射亮边 | 在黑色背景中建立轻盈的材质层次 |
| 圆球表面密集能量纹理 | 稀疏光流、柔和镜面反射、清晰轮廓 | 使科技感与简洁风格一致 |
| 文档与内置网页为白底 | 深色阅读面、玻璃侧栏与工具栏 | 保持整体黑色视觉，减少展示切换时的明暗跳变 |

验证：15 项现有对话与运动测试通过，3 个内嵌脚本语法检查通过。真实 Codex 浏览器通过 Computer Use 检查首页、玻璃卡片、全屏网页、文档与文件切换、Esc 返回、帮助窗口开关。默认视口 1060 × 959 下无页面横向溢出；圆球停靠左下角，完整内容宽度 1060 px；无重复 id，控制台无 error/warn。检查中收口了卡片栏的横向溢出，避免进入动效产生多余滚动条。减少透明度和增强对比度的系统设置本轮未切换，已提供相应样式。

## 语音播报波动 · 2026-10-04（历史版本）

本节记录此前使用浏览器 speechSynthesis 的版本；其程序节奏与扩散涟漪已被下一节的真实声音分析替换。

## 真实声音驱动 · 2026-10-04

此前浏览器 `speechSynthesis` 不提供 PCM，轮廓使用固定节奏，无法对应每句话的音量和音高变化。当前播放链路为：本地 `say` 合成 → 24 kHz 单声道 PCM WAV → Web Audio `BufferSource` → `AnalyserNode` → 扬声器。用于分析和听到的声音来自同一路音频。

`server.py` 仅监听 `127.0.0.1`，负责静态页面与 `/api/tts`。文本作为文件输入系统语音工具，临时文件自动清理；合成结果缓存 32 条，并行合成上限为 2。声音启动最多等待 20 秒；播放长度由音源结束事件决定，打断会取消请求及正在播放的音源，迟到结果不会重新开始播报。

### 声学映射与连续性

| 声音特征 | 控制方式 |
| --- | --- |
| PCM RMS 音量 | 决定主要波动幅度；约 -48 dBFS 以下按静音处理 |
| 70–650 Hz 基频 | YIN 估计实际音高；在有限范围内调整幅度、缓慢的轮廓流动速度 |
| 70–350 Hz 低频能量 | 增加宽阔、柔和的整体形变 |
| 1800–6000 Hz 高频能量 | 增加小幅边缘细节；无周期噪声仍有能量，但不伪造音高 |
| 频谱重心 | 平滑调整光场内部运动速度 |

声学窗口约 85 ms，分析以 30 Hz 更新，每个显示帧再做包络平滑。起伏上升响应为 75 ms，回落为 105 ms；音高和频段以 120 ms 平滑。运动相位积分使用已平滑的音高和重心，避免参数改变时突然跳到另一方向；单帧推进上限为 50 ms，后台恢复不补播。

移除固定播报节拍、两层扩散光圈与高阶快速抖动，轮廓只保留小幅 2/3 阶起伏。播放中的静音停顿让声音幅度自然回落。极光、星云、波纹共用同一声音分析；全屏时仅左下角光场变化，正文宽度和助手位置保持稳定。遵循 apple-design 的连续反馈、内容优先与克制原则：减少动效关闭轮廓运动、保留静态强度和状态文字；WebGL 不可用时采用小幅局部缩放。

星云和波纹选项、shader 与 CSS fallback 已移除，首页仅保留「极光 / 流光」。流光直接移植 [React Bits Plasma](https://github.com/DavidHDev/react-bits/blob/main/src/content/Backgrounds/Plasma/Plasma.jsx) 的体积步进动画，保留原旋转场、距离估计和光强累积，采用冰蓝与淡紫的局部光流；没有增加全屏背景动效。原型仍为单文件，不需要 CDN 或 React/OGL 依赖。完整来源与许可见 `THIRD_PARTY_NOTICES.md` 和 HTML 内嵌通知。

### 设计与动效验收

| 原行为 | 当前行为 | 依据与目的 |
| --- | --- | --- |
| 三种外观，星云与波纹均不符合预期 | 极光 + 直接改编的 Plasma 流光 | 使用成熟开源效果的体积形体，减少方案噪声 |
| 移除的方案仍可能被本地偏好恢复 | 旧 orbit / badge 偏好安全回退极光 | 始终有可用形态；用户再次选择流光后可刷新恢复 |
| 外观切换可能出现硬切 | 约 300 ms 连续混合，可反向中断 | apple-design 的空间连续性；animate 的当前状态交接 |
| 声音与内容需要同时可见 | 局部光流随真实 PCM 起伏，正文固定 | 内容优先；不让声音推动阅读区域 |

源码适配 WebGL1，显式初始化累积量，并用有界指数式计算 tanh；48 次步进以 60/48=1.25 补偿步长，缓冲区上限保持 540 px。基频、低高频和真实音量沿用已有分析，声音只推动平滑弯曲与受控扩张，不重启原动画相位。减少动态效果时固定相位、关闭声音形变，保留状态文字。WebGL 不可用时使用静态软光替代。

### 测试和真实浏览器证据

外观偏好测试先失败（新增流光尚不能恢复、旧星云仍能恢复），再实现；全套 **39 项 Node 测试通过**。覆盖新选择的持久化、旧方案回退、存储受限、反向切换、声学映射、播放生命周期、内容调度与减少动效。6 个内嵌脚本语法检查通过。

真实 Codex In-app Browser 经 Computer Use 操作验证：

- 首页实际渲染极光和流光，流光随时间连续改变形体；选择流光后刷新仍选中流光，旧选项不可见，Canvas 正常渲染。
- 播报为真实 PCM：流光读取 RMS=0.1625、基频=250.9 Hz；全屏网页另读取基频=296.0 Hz。声音特征随播放改变。
- 全屏播报中先切极光再切流光，状态仍为 playing / pcm，观测 RMS=0.1376；自然结束为 idle。
- 全屏位移收敛后 Canvas 与按钮均为 100 px、位置 x=14，内容宽度为 1060 px；切换外观保留网页，返回对话保留卡片。
- 页面无重复 id、横向溢出，浏览器无 error/warn。最终预览停留在流光首页。

本轮未测真实麦克风、系统减少动效设置、移动设备或实际 GPU 帧率；减少动效由纯函数测试与实现检查覆盖。未改动生产 Rust 或接入生产语音运行时。

## 五种外观对比 · 2026-10-04

在极光和流光之外新增三种可以直接切换比较的材质，均移植成熟项目的核心 shader，无新增运行时依赖：

| 外观 | 形体与材质 | 来源 |
| --- | --- | --- |
| 虹彩 | 珍珠玻璃球，连续变化的干涉色与局部反光 | React Bits Iridescence |
| 棱镜 | 缓慢旋转的立体金字塔，冷色体积光 | React Bits Prism |
| 绸光 | 银青球面，柔软移动的织光褶皱 | React Bits Silk |

按照 apple-design 的内容优先与连续反馈原则，动画仅占助手局部区域，阅读内容不移动；切换沿用约 300 ms 连续混合，允许快速反向与中途跳到任意方案。animate 的目的为状态提示与避免突变，沿用现有 WebGL 和连续状态时钟；减少动效固定相位、关闭声音形变。形态列表统一由偏好模块提供，五项混合权重通过复用的 Float32Array 传入 shader，不增加每帧 uniform 数组分配。每个新外观都有静态 CSS fallback、选中反馈和键盘切换。

新偏好测试先失败，再实现；全套 **40 项 Node 测试通过**，包括五种外观刷新恢复、存储受限仍能切换、跳到列表末尾的连续过渡、反向切换时未选中的三项保持零权重，以及减少动效直接选择棱镜。6 个内嵌脚本语法检查通过。

## 卡片连续过渡 · 2026-10-04

参考当前 `crates/app/src/workspace/desktop/camera.rs` 的多工作空间相机：k=225=15²、c=30=2×15，使用同样的临界阻尼，位移和缩放保留中途反向的速度。没有修改生产 Rust。

- 卡片从 92% 尺寸、向助手方向 6 px 的轻微偏移和 12 px 的纵向偏移连续展开；透明度采用独立的快速包络，同一批卡片错开 50 ms。
- 收起沿原路径反向退场；退场时离开布局流，剩余卡片从实际可见位置平滑补位。外壳负责布局、内层负责进入，避免两个 transform 相互覆盖。
- 退场中召回复用同一个元素并保留运动状态。退出时控件立即 inert / aria-hidden，焦点返回输入；实际元素在退场收口后删除。
- 普通文字对话提交与鼠标调出都展示该过渡；减少动效时只做 120 ms 淡入淡出。全屏阅读、内容滚动和助手外观保持可用。
- 复用现有 RAF 和解析弹簧；每帧只更新 transform / opacity，不在循环内测量布局；结束清理 will-change 和退出元素。

验收先增加 4 项聚焦测试，确认缺少卡片运动接口时失败，再实现。全部 43 项 Node 测试和 6 个内嵌脚本语法检查通过。

真实 Codex 浏览器通过 Computer Use 验证：入场过程中实际缩放约 0.954、透明度约 0.826；文字对话同批卡片透明度依次约 0.741 / 0.352 / 0 / 0，确认不是同时突然出现。收起进度后，文件卡片最终平滑归位到 y=215 px，进度节点被删除。800 px 窗口下为两列 333 px 网格，无横向溢出；已恢复默认 1060 px 窗口。展开网页并返回后保留四张原卡片，无重复 id、无残留退出元素，控制台无 error/warn。截图为 `assets/assistant-card-transition.jpg`。

Apple 设计原则落地：运动用于连接状态与空间位置，镜头式缩放无终点弹跳；内容稳定后静止，减少动效保留可见反馈。
