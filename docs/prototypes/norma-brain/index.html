总体架构

Norma App 同时担任三个角色：hook 事件的汇聚点、ACP client（拉起大脑并审查它的每一次工具调用）、norma CLI 的服务端。大脑本身没有文件和终端权限，只能通过 norma 命令行动。

一次审批的生命周期

  • 先查规则：安全闸门先判断是否高风险。命中就不经过大脑，直接用语音问你
  • 大脑判断：未命中时交给审批会话，左侧显示“Norma 判断中 · 已等 N 秒”，不设固定时限
  • 随时接管：判断过程中你可以点“我来处理”，之后大脑再给出的结论作废
  • 有结论：大脑执行 norma approval decide 才算结论，放行的操作记入“Norma 自主处理”
  • 转给你：大脑拿不准、出错崩溃、快到 hook 的 120 秒上限，这三种情况会转到“需要你处理”
  • 首版范围：审批代理只覆盖 Claude Code 卡片，其他 Agent 只汇报进度

大脑看到什么

  • 推送：结构化的 hook 事件（完成、出错、工具调用、空闲），以及每轮最终回复的摘录
  • 按需拉取：norma agent tail <agent> 读取卡片上下文（需新增）
  • 派活依据：卡片上下文，加上只读的项目文件和文档（plan、README、相关代码）
  • 去抖：同一 Agent 1s 内的多条进度事件合并后再推送，定时摘要只发变化量
  • 上下文：主会话定期压缩，并把目标摘要写入 ~/.norma/brain/，崩溃后可据此重建

你说话时

  • 检测到你开口，立即停止播报，ReportQueue 暂停
  • 前台对话先回答：豆包 / GPT-Live 由实时模型自己答，Legacy 和 Dock 文字由 NormaSession 答
  • 需要派活或读代码时，前台先说“我去看看”，把任务转给后台主会话，结果再经 norma report 播报
  • 对话结束后，主会话把这期间积压的播报合并成一句

crate 落点（草案）

  • 新 crate brain：事件分流、两个会话、ACP client、ACP 权限白名单、高风险规则（纯函数），不依赖 GPUI，可以独立测试
  • norma：CLI 新增子命令，protocol 增加 approval、stop、report；权限桥后续扩展到 Claude 以外
  • app 新增：brain_host（在后台执行器上运行 brain）、approval_broker（挂起的审批、接管、120 秒上限）、安全闸门
  • app：扩展 ReportQueue，在 agent_announcements 中接入播报，新增设置页与概览 Attention 类型
  • agent：NormaSession 保留，负责前台快速对话和兜底；新增“转给后台”工具；记忆与 brain 共用
  • app/gpt_live：派活改为交给 ACP 大脑，不再由 NormaSession 做规划

风险

  • 审批延迟：快模型通常 2–5s 完成，但所有 Agent 的每次审批都要经过大脑，高峰期需要并发处理或批量合并
  • ACP 适配器差异：Claude Code 和 Codex 依赖第三方 ACP 适配器，权限请求的字段和工具名需要逐个对齐
  • 大脑误放行：自主权较大，每个决定都需要可追溯，并能一键停止对应 Agent
  • 成本：两个常驻会话加定时摘要，需要在设置页显示用量

还需要你确认

  • 判断较慢时是否提醒你：只在概览显示（推荐），还是超过 60 秒后语音提醒一次
  • 多个审批同时到达时，并行处理（推荐）还是排队逐个处理
  • 需要验证：hook 120 秒超时后，Claude Code 会不会退回终端里的权限提示
  • 需要实测：Claude Code 通过 ACP 回答一句话的首字延迟
  • “Norma 自主处理”记录要保留多久，是否需要每天汇总一次
