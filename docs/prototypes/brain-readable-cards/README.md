# 幕僚卡片：紧凑展开原型

入口：`docs/prototypes/brain-readable-cards/index.html`。

本轮按用户反馈收敛为一个方向：保留窄侧栏，默认收起，点击原位展开。上一轮的大卡片、独立详情和逐项面板已从当前入口移除。所有操作仅改变内存中的演示数据，不会派发真实任务、回答真实问题或批准真实命令。

## 信息与空间

- 三种事项默认都收起，合计 **187px**；每条约 62px。
- 收起时显示行动标题、类型、Agent 和必要状态；标题完整换行。**审批按钮始终位于外层行右侧**，无需展开即可允许或拒绝。
- 同时只展开一条。展开任务时显示三条行动要点、原因与交付；下一步建议的暂不采纳/派发同样常驻外层。
- 问答展开后才显示问题、推荐理由与分行选项；推荐不自动选择，选择不等于发送。
- 决策展开后只显示用途、精确命令和本次授权范围。审批控件与展开按钮是同级元素；点击审批不会展开或收起详情。收起时审批结果也在外层即时显示并接收焦点。
- 长指令与请求原文采用第二层展开，默认不占空间。
- 收起和切换事项保留回答草稿；处理后保留具体回执。“恢复演示”只用于原型，不承诺真实动作可以撤销。

截图中的长任务被整理为：

1. **核对证据**：官方协议 + 各 Agent 真实事件。
2. **修复串扰**：隔离 Grok / OpenCode 父子会话。
3. **补齐测试**：覆盖延迟 Stop、后台退出与漏报。

原始任务仍保留精确字段、其他 provider 的待证要求与完整派发内容。本轮标题和要点是人工整理的演示摘要；正式实现需要明确摘要来源，不能直接用摘要替换派发指令。

## 设计依据

继续采用 `apple-design`、`emil-design-eng`、`frontend-design` 的信息层级、内容优先、即时反馈与可访问性原则。用户已明确选择折叠方向，本轮不再发散三个方案，也不保留方案选择器。

| 原则 | 原型落实 | 原生落地时的验证 |
| --- | --- | --- |
| 控制空间 | 紧凑两行标题，详情按需原位展开 | 保持现有抽屉宽度，desktop-e2e 核对收起与展开的自然高度 |
| 易于扫描 | 动作动词加粗，三条短句；原因、交付分行 | 用真实长任务验证摘要保留目标、范围、约束与不确定性 |
| 直接反馈 | 即时 hover/pressed、清晰展开状态、忙碌禁用 | 复用 `ui::component`，真实 App 覆盖深浅主题与状态 |
| 用户控制 | 审批外置、内容按需展开；显式发送、明确授权、草稿保留 | 沿用问题校验、ProposalBlock 与真实授权服务，补聚焦状态测试 |
| 可访问性 | 语义按钮/radio、aria-expanded、键盘焦点、回执状态 | 原生焦点与键盘全流程验收 |
| 克制动效 | 展开与收起即时，无产品动效 | 无须添加入场、缩放或面板过渡 |
