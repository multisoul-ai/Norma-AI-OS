Spatial productivity system

Many agents. One living canvas.

Multisoul 的界面语言以深色玻璃为底，以轨道和节点表达多个智能体的实时协作。工具层保持冷静，品牌信号保持鲜明，让用户感觉自己正在调度一个有生命的工作空间。

Color Tokens

颜色只做语义信号。深色中性表面承载内容，高饱和色用于当前选择、Agent 状态、实时连接、生成、成功、警告和失败。

Graphite #05090B

App 根背景与深色空间底色，不使用纯黑作为唯一层级。

Panel #0E1B16

玻璃表面的基础色，与现有 `cardBase` 气质一致。

Pulse Orange selected

当前、选中、主操作。来自 logo 的橙色节点。

Orbit Cyan running

实时、同步、连接。适合运行轨道和 live 状态。

Agent Green done

成功、健康、完成。只用于小面积状态反馈。

Soul Violet generate

创造、AI 能量、实验能力。避免大面积铺满。

Sync Blue web

外部资源、Web、远程同步和链接状态。

Destructive failed

失败、错误、危险操作。不能用橙色替代。

SwiftUI Contract

视觉规范要能直接翻译为代码。新增玻璃表面复用 `liquidGlassSurface`，复杂状态使用 resolver，动效走 `WorkspaceMotion`。

Text("Status")
    .font(.system(size: 12, weight: .semibold))
    .lineLimit(1)
    .minimumScaleFactor(0.82)
    .padding(.horizontal, 12)
    .frame(height: 28)
    .liquidGlassSurface(
        cornerRadius: 14,
        tint: WorkspaceGlassPalette.selectedAccent.color,
        isInteractive: true
    )

CanvasNodeChrome.resolve(
    isSelected: isSelected,
    isFocused: isFocused,
    isHovered: isHovered,
    isPressed: isPressed
)

Review Checklist

用于提交 UI 变更前的快速自检。通过这组检查后，视觉才算符合 Multisoul 的工作台语言。

  • ✓颜色是否来自共享 palette，并且有清晰语义。
  • ✓常规工作区文字是否保持 10-16pt 的信息密度。
  • ✓玻璃表面是否复用 `liquidGlassSurface`，没有复制视觉链。
  • ✓hover 是否弱于 selected / focused，并且不会覆盖它们。
  • ✓icon-only button 是否有 help 和 accessibility label。
  • ✓Terminal、code、diff 是否保持可读，未被装饰视觉干扰。
  • ✓Reduce Motion 下是否没有大幅空间位移。
  • ✓Reduce Transparency 下文本对比是否仍然足够。
