首轮交付接通现有桌面工作空间，不创建第二套对话或画布。左侧复用 `VoiceInteraction`，中央只显示 Agent 与 Terminal；原命令 Dock 和其中的页面导航保持常驻，右侧统一承载网页和文件。

## A 第一条纵向链路 {span=2}

```flow LR
[⌘E 现有对话] -> [真实状态查询]: 问进度
[真实状态查询] -> [悬浮运行概览]: 按项目呈现
[悬浮运行概览] -> [中央 Agent 卡片]: 定位或处理审批
[悬浮运行概览] -> [右侧内容标签]: 打开有来源的产物
[⌘E 现有对话] -> [跨项目路由]: 指名派活
[跨项目路由] -> [逐目标回执]: 成功或失败
```

```callout ok 首轮完成的判据
在真实 App 中按 `⌘E` 询问当前项目进度，收到真实结果；从概览定位 Agent 或打开产物；再对另一项目明确派活并看到逐目标回执。两种现有语音模式均走同一只读查询能力。
```

## B G0–G3 任务拆分

| 阶段 | 实施任务 | 阶段完成标志 | 依赖 |
| --- | --- | --- | --- |
| G0 身份与契约 | 固定工作空间／项目／节点／任务／产物／审批引用；定义每轮可见视图、当前工作空间和聚焦项目快照；定义状态新鲜度、标签身份和旧节点清理；修订冲突规格 | 同一资源、目标和请求能稳定识别；总览无焦点不沿用旧项目；旧数据处理可重复执行 | 现有画布、语音和跨项目路由 |
| G1 工作台外壳 | 左右透明抽屉贴边占位，中央画布随开合调整宽度；窄窗口切换为覆盖式；左栏映射现有会话；右栏多标签承载网页、文件、图片与视频；隐藏 Ego 画面 | 两侧可独立收起；中央只有 Agent／Terminal；内容可打开、关闭与恢复 | G0 |
| G2 真实概览与直达 | 聚合各项目状态、任务、待审及有来源的产物；左侧抽屉加入「对话 / 运行概览」切换，画布右上角常显逐个智能体状态与步骤及待处理角标并一键切到概览，概览可弹出悬浮固定，见原型 README「运行概览」 | 概览不挤压画布；点击 Agent／审批可定位；点击文件只打开右栏 | G0、G1 |
| G3 对话与派活接线 | 每轮把当前工作空间 ID／名称和可见项目 ID／名称加入现有 Norma 环境；两种语音模式共用只读状态查询；接通现有跨项目派活路由；返回澄清与逐目标回执 | `⌘E` 可问进度并派活；工作空间和项目切换后上下文正确；查询结果能通过概览定位卡片或打开文件 | G2 |

G0–G3 是一个验收批次。每阶段先补聚焦测试，再实现；最终以真实 App 完成整条链路。

## C G0 契约与数据边界

```kv
卡片定位: workspace_id + area_id + node_id
任务状态: task_ref + agent_id + 状态时间 + 来源事件
产物索引: 来源任务 + 可打开路径 + 文件版本
审批定位: 来源 Agent + 请求 ID + 当前有效性
内容标签: workspace_id + 资源身份 + 来源项目 + 选中状态
对话上下文: 可见视图 + desktop_workspace_id／名称 + 可见 area_id／名称（可为空）
```

- 桌面 host 在每个用户回合开始读取可见位置。仅当桌面工作空间页面打开时，`active_id` 才是当前工作空间。当前项目以实际显示的画布为准；`active_area_id` 记录过往打开位置，`selected_area_id` 仅表示总览选择。
- 在项目画布中，环境明确写当前工作空间与项目的稳定 ID 和名称；在工作空间总览中，环境写当前工作空间及“当前项目：无”。切换或加载期间未形成可用项目画布时标明状态，不猜目标。名称是数据，执行副作用时仍校验 ID 和实时归属。
- 概览按当前桌面工作空间的项目分组。活跃项目显示实时状态；未加载项目显示上次状态及更新时间，不自动启动。
- 产物只收录有明确任务来源和可打开路径的文件或结果。没有可靠步骤时不显示完成百分比。
- 新建 Browser、Preview 只进入右侧。旧画布内容卡片记录直接清除，不迁移为标签；本地文件和浏览器资料保留。清理已加载项目时同步移除运行时节点并保存。
- `EgoLite` 画面暂时隐藏，已有任务继续运行；概览保留状态与停止入口。旧节点清理必须区分普通 Browser 与 `EgoLite`。
- 本方案与现行桌面统一场景规格中“Browser／Preview 仍在画布”的条款冲突。G0 要同步修订该规格及相关验收项。

## D 抽屉、标签与直达规则

| 操作 | 结果 |
| --- | --- |
| 收起左栏或右栏 | 只隐藏视图；语音会话、Agent、PTY 和右侧标签继续存在 |
| `⌘E` 启动 | 沿用当前可配置快捷键和当前语音模式；左栏呈现同一会话状态、转写与回复 |
| 打开同一网页或同一文件版本 | 复用工作空间内已有标签并选中；不同文件版本另开 |
| 后台产生新成果 | 概览增加待看项与角标；点击时才展开右栏并打开内容 |
| 点击其他项目的 Agent | 切换到所属项目，显露并聚焦原卡片 |
| 点击其他项目的文件 | 保持当前画布；右侧打开带来源项目标记的文件标签 |
| 点击待审核项 | 校验请求仍有效，再切到所属项目并聚焦 Agent 终端中的审批提示 |
| 收起右栏或重启 App | 收起时保留标签；重启恢复标签列表与选中项，内容按需加载 |
| 关闭 Browser 标签 | 结束该网页会话；关闭文件标签不删除文件 |
| 从工作空间移除来源项目 | 保留其已打开标签，并标记“来源项目已移除”；不删除本地文件 |

右栏标签属于桌面工作空间，不属于单个项目。透明抽屉显示默认背景图；文件正文保持足够对比度。抽屉动效从当前可见位置连续收放，并支持减少动态效果。

## E 查询、派活与异常语义

- “看看进度”默认查询当前聚焦项目；明确说“整个工作空间”时汇总所有项目。总览没有聚焦项目时，只读查询汇总当前工作空间。
- 启动页没有打开的工作空间时，环境明确写工作空间和项目均为“无”；不能把保留的 `active_id` 误当作当前打开位置。
- 当前项目的原派活语义继续可用。指名其他项目或多个项目时，先用 `workspace_snapshot` 确认工作空间、项目和 Agent 稳定 ID，再逐目标调用 `assign_workspace_task` 并返回独立回执；目标不明确时先澄清，不向任何目标发送。
- 总览没有聚焦项目时，派活前必须明确项目。单个目标失败不得重发已成功目标。
- 查询与派活复用现有语音模式和豆包模式的入口及会话生命周期。左栏是该会话的视图，不建立独立聊天服务；已有历史沿用原能力。
- 状态引用失效、文件不存在、审批已结束或项目已移除时，显示具体原因与可返回位置，不执行过期操作。

## F 验收证据与后续边界

| 验收场景 | 必须看到的结果 | 证据 |
| --- | --- | --- |
| 抽屉与画布 | 两侧独立开合，中央仅有 Agent／Terminal，原 Dock 与页面导航常驻；悬浮概览可折叠且不挤画布；壁纸、透明材质、原有动效和运行会话保持 | app 构建检查＋desktop-e2e 真实 App |
| 旧卡与 Ego | 旧普通 Browser／Preview 记录清除；原文件及浏览器资料仍在；运行中的 Ego 任务未停止 | storage／runtime 聚焦测试＋真实 App |
| 标签生命周期 | 同资源复用、不同版本另开；重启恢复列表和选中项；移除项目后标签保留并标记 | storage／app 聚焦测试＋真实 App |
| 概览与直达 | 多项目分组、状态时间、待看角标；Agent／审批定位正确，文件仅在右侧打开 | runtime 路由测试＋desktop-e2e 真实 App |
| 对话上下文 | 项目画布、总览、启动页与切换过程的工作空间和项目 ID／名称正确；切换后下一轮更新 | 受影响 crate 聚焦测试＋真实 App 状态检查 |
| 模型对话 | 两种模式可查询真实进度、跨项目派活；回复和工具选择符合上下文 | 用户人工智能验收；工程侧提供可复现操作和真实工具回执 |
| 跨项目派活 | 明确目标逐个收到任务及回执；歧义只澄清，失败不重发成功目标 | runtime 派发测试＋真实 App 操作 |

遵循 `apple-design` 的空间连续、即时反馈与减少动态效果原则；按钮覆盖 hover、pressed、keyboard focus 和 disabled 状态。页面与交互验收优先使用 desktop-e2e 操作真实 App，不采用已禁用的 `crates/e2e`。

G4 以后再细化高级审批操作、完整会话历史与媒体打磨。G0–G3 已包含真实只读查询、跨项目派活、右侧内容和快速定位，不将这些能力推迟到后续阶段。
