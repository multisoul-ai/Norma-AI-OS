# 右侧抽屉标签操作实施方案

2026-11-20 · 待实施

以 `docs/prototypes/right-drawer/index.html` 为交互参考，覆盖画布和幕僚共用的右侧抽屉。用户能在同一位置刷新文件或网页，在二十多个标签中找到目标，并从标签操作菜单一次关闭指定范围的标签。

## 1. 交互规格

| 功能 | 用户操作与结果 |
| --- | --- |
| 刷新 | 标签条右端固定显示刷新按钮，作用于当前标签。普通文件重新读盘，网页重新加载当前地址。刷新中立即显示转圈、细进度条和文字，同一标签暂停重复触发。期间可切换或关闭标签。成功时显示更新后的正文，失败时保留可用内容并提供简短错误提示和重试入口。 |
| 定位 | 标签条支持横向滚动，右端固定显示搜索入口。浮层按标签名、文件路径或网页域名过滤，展示文件或网页图标、完整来源和当前项勾标。同名标签可通过来源区分。↑ / ↓ 浏览，Enter 跳转，Esc、Tab 或点击外部退出。确认后切换到目标标签并将其完整滚入可见区域。 |
| 快速关闭 | 内容上下文栏右侧常驻「⋯ 标签操作」，作用于当前标签。右键或 Shift+F10 打开任意标签的同一菜单，菜单标题显示目标，展开时保留当前选中项。按原型顺序显示「关闭」「关闭其他标签页」「关闭右侧标签页」「关闭所有标签页」，再用分隔线隔开「重新加载」。单标签场景禁用「关闭其他标签页」，末位禁用「关闭右侧标签页」。悬停或键盘聚焦显示 ×，支持中键关闭。 |

关闭操作按工作区标签的显示顺序计算。若当前选中项仍在则继续显示它。选中项被关闭时，优先选择其右侧最近的剩余标签，再选择左侧最近的剩余标签。关闭全部后留在抽屉首页，由现有新建网页和项目入口恢复。标签关闭涉及带未保存编辑的工作台时复用现有离开确认，确认完成后一次提交，取消则保留整批标签和编辑内容。

视觉沿用现有 52 px 标签条、40 px 上下文栏和 32 px 顶部控件。用当前主题 token 表达悬停、按下、键盘焦点、选中与禁用状态。按下立即反馈，搜索和菜单靠近触发器，弹层关闭后恢复触发器焦点。新文案和状态走中英文 i18n。

## 2. 实施顺序

### A. 先打通批量关闭

1. 在 `crates/runtime/src/desktop_drawers.rs` 用纯函数根据操作范围、目标 ID 和有序标签列表计算要关闭的 ID。以点击菜单项时的列表为准，点击后到达的 Agent 标签保持打开。若菜单目标已经消失，退出菜单。
2. 在 `crates/storage/src/desktop_content_tab_store.rs` 增加工作区范围内的批量关闭事务。事务内按 `position, id` 计算存活项和下一选中项，提交删除与选中变化，返回实际关闭的 ID 及最新列表。沿用当前表结构。
3. 在 `crates/app/src/workspace/desktop/drawers/content/tabs.rs` 让单关、右侧、其他、全部走同一关闭入口，复用 `content_tab_task` 的串行队列和导航代次。若目标涉及有编辑的 `ProjectFiles`，在工作台离开流程中暂存本批次并展示现有确认界面，保存成功或明确放弃后再提交，取消后恢复原选中项。SQLite 后台提交成功后按实际关闭 ID 回收 WebView、预览资源、临时快照和加载状态。回收针对已提交关闭的 ID，列表及选中项只由当前工作区的最新导航代次更新。失败时保留标签与资源并显示本地化错误。
4. 在 `crates/app/src/workspace/desktop/drawers/content/chrome.rs` 接菜单和工作台入口。工作台当前跳过阅读器上下文栏，在现有工作台头部放同款「标签操作」按钮。鼠标、键盘与中键共用关闭入口。

### B. 统一文件与网页刷新

- 把刷新按钮和菜单「重新加载」接到按标签 ID 分发的同一入口。浏览器地址栏的刷新迁入共用入口，返回、前进和地址输入继续由 `crates/app/src/workspace/desktop/drawers/content/browser_toolbar.rs` 负责。工作台使用现有的项目刷新逻辑，保留编辑缓冲和外部变更检测。
- 在 `crates/app/src/workspace/desktop/drawers/content/preview_load.rs` 复用原有后台读取、路径校验及富预览生成流程，区分首次载入与显式刷新。收到新结果后替换同一标签的预览资源，释放旧资源。版本化交付物按已选版本重读归档快照。以工作区、标签 ID、资源和加载序号核验完成结果，处理重复点击、关闭标签、切换工作区和迟到回调。
- 网页复用 `crates/app/src/app/browser/store.rs` 现有 WebView 和加载时间线。抽屉在发起前检查该视图是否已在加载，避免触发 `reload()` 的停止分支。已有视图按其当前地址刷新，尚未创建视图的恢复标签在首次显示时载入该地址。状态来自真实加载信号及现有超时判断。

### C. 做标签搜索和浮层整合

- 复用 `crates/app/src/workspace/desktop/project_picker.rs` 的可搜索列表做法和现有 `ui::component`。搜索和键盘浏览只更新浮层，确认时按稳定标签 ID 调用 `select_desktop_content_tab`。沿用标签栏现有的横向滚动，在工作区内持有 `ScrollHandle`，用已提交的选中 ID 定位滚动目标。用户主动横滚时保留其停留位置。
- 在真实 WebView 和富文件预览上先检查弹层层级与命中。若原生视图盖住弹层，复用 `crates/app/src/app/browser/presentation.rs` 的可见性控制，仅在重叠时暂时隐藏抽屉内容对应的原生视图。关闭弹层后恢复同一实例，并检查网页历史、页面状态及键盘焦点。
- 搜索和菜单互斥。切换工作区、收起抽屉或目标标签消失时关闭浮层。窄抽屉里保留刷新、搜索和标签操作入口，长路径和标题按空间截断，完整文本可通过提示或搜索结果查看。

## 3. 验收矩阵

每项先写能失败的聚焦测试，再接实现。真实 App 验收使用隔离数据与回环 HTTP 页面。

| 验收项 | 自动化断言 | 真实 App 观察点 |
| --- | --- | --- |
| 四种关闭和选中回退 | 验证每种范围的具体保留和删除 ID、相邻回退、空列表、跨工作区隔离、重复命令与事务失败。覆盖工作台取消和保存失败时数量不变。 | 3 标签场景从常驻按钮和右键进入。验证右键未选标签时仍操作该标签，末位和单标签正确禁用。关闭全部后显示首页，重开工作区时结果一致。 |
| 文件和网页刷新 | 验证旧请求晚返回、切换或关闭标签、刷新失败可重试、快照维持版本。 | 直接改写夹具文件，从原内容切到新内容。用可控制响应的回环 HTTP 夹具展示刷新中，再断言同一地址的页面内容已变化。在刷新中切换标签并切回，检查状态归属。 |
| 24 标签快速定位 | 验证同名文件、路径、域名、空结果，以及确认前选中 ID 不变。 | 窄抽屉中的横向溢出、搜索远端标签、键盘确认后自动滚入视野。让网页作为当前内容，验证菜单和搜索能覆盖原生视图，关闭后网页仍可操作。 |
| 视觉和可访问性 | 运行 i18n 检查，核对状态文案、键盘焦点、缩减动态效果。 | 墨黑中文和另一套可选暗色主题的英文各验证一次触发器、菜单、搜索和刷新态。对仍可由夹具直接构造的浅色主题检查对比度和控件反馈。 |

- 存储复用 `crates/storage/tests/desktop_content_tabs.rs`，运行 `rtk cargo test -p storage --test desktop_content_tabs`，并定向运行同域并发用例。对新范围规则运行 `rtk cargo test -p runtime desktop_drawers`。
- App 运行相关单元测试、`rtk cargo check -p app`、`python3 scripts/check-i18n.py`、`python3 scripts/check-resource-lifecycle.py` 与 `rtk cargo lint-resources`。
- 在 `test/desktop-e2e/Scenarios/content/ContentModule.swift` 登记看图场景 `content-tab-controls`，复用 `test/desktop-e2e/Fixtures/content/ContentBrowserFixture.swift` 的回环服务器并添加可更新页面。运行 `bash scripts/desktop-e2e.sh content-tab-controls --visual`，保留关闭菜单、24 标签搜索和文件或网页刷新中的关键帧；复用现有 `canvas-content-tabs` 和 `content-workbench` 做恢复与工作台回归。
