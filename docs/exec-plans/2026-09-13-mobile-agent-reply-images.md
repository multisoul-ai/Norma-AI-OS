# 手机端 Agent 回复内图片：实施方案

状态：待审阅；本轮仅编写方案，尚未修改功能代码。

## 1. 交付目标

任意已接入 Norma 的 Agent 生成设计稿、截图或其他图片后，手机在对应回复的位置直接显示图片。用户可点开放大、继续要求修改，并回看每一轮的结果。

最终覆盖当前五类 Agent：Codex、Claude、Cursor、OpenCode、Grok。后续新增 Agent 沿用同一图片协议与手机组件；接入时必须通过相同的契约测试。

推荐路径：**统一图片交付入口 → 保存图片版本 → 把回复转换成有顺序的文字／图片块 → 复用手机传输与大图查看。**

## 2. 当前实现与实际缺口

| --- | --- |

| [图片传输](../../crates/app/src/mobile/server/connection/image.rs) 已有鉴权、分片和按项目读取 | 复用连接与授权方式，补生成图片的注册、读取及原图大小策略 |

桌面 Agent 卡片仍使用终端渲染；本方案的图片展示落在手机原生聊天页面，不以实现终端图片协议为前置。

## 3. 用户可见行为

```text
Agent：这是第一版首页，重点突出主要操作。

┌────────────────────────┐
│                        │
│        首页设计稿       │
│                        │
└────────────────────────┘
首页 · 点击查看大图

你：标题再小一点。

Agent：已调整，这是第二版。
┌────────────────────────┐
│        修改后的设计稿   │
└────────────────────────┘
```

- 图片出现在回复引用的位置；“文字—图片—文字—图片”的顺序保留，不统一堆到消息末尾。
- 单图按聊天宽度等比例显示，完整呈现、不裁切；长图限制首屏占高，点开继续查看。多图按正文顺序纵向排列。
- 触摸图片立即有按下反馈，打开现有原生大图页；捏合缩放，关闭后保留对话滚动位置和输入草稿。
- 图片加载前按宽高预留位置；图片就绪不抢走用户正在阅读的位置。跟随最新回复沿用现有聊天滚动规则。
- 图片加载失败仅影响该图片，显示说明和重试入口，回复文字继续可读。
- 每轮引用已保存的图片版本；第二轮覆盖电脑上的同名文件，不改变第一轮图片。

设计依据：已加载的 `apple-design`。落实为内容优先、系统查看手势、即时反馈、保持上下文；图片有替代文字，控件触摸区至少 44 pt，适配动态字号与 VoiceOver，尊重“减少动态效果”。不新增装饰性入场动画；实施时若改造现有手势或转场，再加载 `emil-design-eng`。

## 4. 统一图片交付规则

### 4.1 正式路径：生成完成后先保存，再写入回复

为所有 Agent 提供同一个本地交付入口，沿用现有 `norma` CLI 和已认证的卡片调用上下文。拟新增命令形态如下，最终参数名在协议步骤确定：

```sh
norma agent image publish --path ./output/home.png --alt "首页设计稿"
```

入口成功后返回图片标识和可直接放入回复的引用，例如：

```markdown
这是第一版首页。

![首页设计稿](norma-image://<asset-id>)
```

该命令是给 Agent 使用的内部能力。用户照常提出设计要求，不需要输入路径、手动上传或选择图片来源。

处理顺序：

1. Agent 工具将图片完整写入文件并关闭文件。
2. 发布入口核验来源项目、卡片、运行和会话，在接收请求时固定生成批次；文件读取、解码、缩略图生成和保存均在后台执行。
3. Mac 保存不可变的图片副本及元数据，提交成功后才返回可展示的图片引用。
4. Agent 在回复中插入该引用；手机取得该条真实消息时，按引用位置展示图片。

发布时手机不必在线。生成器若只返回远程 URL，由 Agent 下载成文件后走同一入口，首版不增加自动抓取任意外部 URL 的服务。

### 4.2 为什么需要保存入口

只在手机打开聊天时读取 `home.png`，可能读到后来覆盖的新内容。保存必须发生在 Agent 交付这一版时，才能兑现“历史版本不变”。

统一接入说明应要求 Agent：生成图片后完成发布，再把返回引用放进回复。通过 Norma 管理的 Provider 配置／能力说明分发，不逐个修改用户项目的 `AGENTS.md` 或 `CLAUDE.md`。

仅有提示词不算实现完成：每个 Provider 都要实际调用入口、返回引用并在手机显示，失败时给出可观察错误，不能报告图片已交付。

### 4.3 现有回复与原生图片结果

- 现有回复中的本地 Markdown 图片引用，可在已授权项目范围内做按需导入；标注为首次导入的版本，不承诺恢复未曾保存的历史像素。
- Provider 若原生返回图片附件，可转换到同一资产与内容块模型；有明确消息归属后再展示。
- 裸文件路径、代码块里的图片语法、工具读取过的任意图片不自动当成最终设计稿。只有明确的回复图片引用／交付结果进入这条展示链路。

## 5. 消息、版本与兼容性

### 5.1 统一内容模型

在现有 `ConversationItem` 上增加可选 `parts`，按顺序包含两种内容：

| 内容块 | 最小字段 |
| --- | --- |
| 文字 | `type=text`、`text` |
| 图片 | `type=image`、`asset_id`、`alt`、`width`、`height` |

保留 `id/role/text/details`。图片块只携带引用和尺寸，图片字节通过独立图片连接读取，不塞进每次聊天订阅更新。

复用 app 已安装的 `pulldown-cmark` 解析回复，按源码范围保留图片前后文字，覆盖转义、中文路径、引用式图片和代码块。纯协议结构放 `norma`；解析、文件访问与资产投影放 app 后台路径。

新 iOS 优先渲染 `parts`，缺失时走原有文字／用户附件流程。旧 iOS 继续读取原字段；明确测试其忽略新字段的行为。新图片读取动作通过能力标记协商，连接旧 Mac 时保留文字并提示更新，不导致整页聊天失败。

### 5.2 资产与消息身份

- 资产以内容摘要标识；原图与预览图分别校验摘要。同图重复发布复用文件，不重复增加存储量。
- 保存资产来源项目、会话、生成批次及最终消息关联；消息引用位置使用稳定消息 ID 加块序号，同一图片可以在正文不同位置重复出现。
- `route_id` 用于实时路由校验，不作为永久存储身份。历史读取不依赖原窗口仍然存在。
- 后台结果必须核验原请求身份；切项目、重开卡片、取消任务后的迟到结果不能挂到新的当前回复。
- 发布重试使用稳定操作 ID，崩溃后可回查结果。先持久化文件，再提交元数据，再回成功；中断不得留下可见但不可读的“成功图片”。

### 5.3 原图、缓存与边界

首版支持 PNG、JPEG、静态 WebP；动图、SVG、HTML、Figma 文件需要 Agent 导出静态图后交付。

建议初始预算如下，全部作为实现与测试的显式参数：

| 项目 | 建议值与依据 |
| --- | --- |
| 原图输入 | 编码文件 ≤32 MiB、像素 ≤6400 万；沿用 iOS 现有预览解码的输入数量级，后台最多同时解码 1 张，最坏 RGBA 约 64M×4=256 MB |
| 聊天预览 | 长边 ≤2048、编码 ≤2 MiB；可复用当前小图片传输预算，RGBA 上限 2048²×4=16 MiB |
| 大图查看 | 按需取原图，后台解码至最多 4096 长边，RGBA 上限 4096²×4=64 MiB；必须用含小字号的设计稿验收可读性 |
| 网络分片 | 复用 64 KiB 二进制片大小与当前帧上限；原图逐片读取和验证，不能仅放宽当前整包 Base64/JSON 的 3 MiB 上限 |
| Mac 存储 | 首版沿用全机 256 MiB／2048 项上限；上传图、生成图及预览共同计入，满时明确拒绝新交付，不自动删除历史版本 |
| 手机缓存 | 按电脑、项目、资产、图片版本隔离；建议 128 MiB 有界磁盘缓存，可淘汰并重新读取，不影响 Mac 的历史副本 |

保留原图，缩略图压缩不得覆盖源文件。图片超限或预览无法生成时返回具体原因，不能用模糊缩略图冒充原图可读。

手机已有缓存可在暂时断网时继续显示；这不等于新增完整离线聊天能力。忘记电脑／明确撤销授权时清理相关缓存；图片读取继续沿用项目授权、传输中重验和取消行为。手机按资产 ID 读取，不提供任意 Mac 路径下载入口。

## 6. 所有 Agent 的接入与完成标准

| Provider | 当前证据 | 本次必须补齐 |
| --- | --- | --- |
| Codex | 已有完整会话分页、消息 ID 和手机订阅 | 发布能力、回复图片转换、实时／历史一致 |
| Claude | 已有 transcript 消息和手机读取 | 同上，覆盖只含图片、混合内容和流式半条记录 |
| Cursor | 已有卡片与 Hook；完整手机聊天读取未接入 | 核验权威回复来源，补稳定消息身份、正文读取与图片关联 |
| OpenCode | 已有卡片与 Hook；完整手机聊天读取未接入 | 同上 |
| Grok | 已有卡片与 Hook；完整手机聊天读取未接入 | 同上 |

适配器差异留在 Mac，手机使用统一模型。不能从终端字符网格猜消息边界，也不能把现有 1200 字符的会话摘要当成完整回复。

第一步必须对后三类 Provider 各采集一条真实完整回复，确认读取 API／Hook／会话文件及稳定身份。若某个 Provider 缺少这些能力，记录具体缺口并补接入；在解决前，不能把总目标标为完成，也不能用发布成功代替手机回复位置正确。

未来新增 Provider 的准入测试固定为：生成文件 → 发布 → 回复内引用 → 手机展示 → 同路径修改 → 两轮各自保留正确图片。

## 7. 实施顺序与代码归属

| 步骤 | 主要工作与拟改动位置 | 完成证据 |
| --- | --- | --- |
| 1. 锁定契约和五类回复来源 | `crates/norma/src/mobile/conversation.rs`、`cli.rs`、`protocol.rs`；核验各 Provider 回复来源 | 真实样本与身份映射；先补会失败的协议／顺序测试 |
| 2. 保存交付图片 | app 下共享图片模块；`crates/storage/src/` 新增资产元数据与迁移；复用现有原子写入和摘要规则 | 手机未连接时发布成功；覆盖源文件后首次图片摘要不变；失败无成功回执 |
| 3. 接通所有回复读取 | `crates/app/src/norma/endpoint/mobile_conversation.rs`、runtime 各 Provider 历史读取、统一后台图片投影 | 五类 Provider 的实时、分页、重连、归档均绑定正确消息；图片就绪唤醒现有变更通知 |
| 4. 扩展图片传输与手机渲染 | `image.rs`、`ChatImageTransport.swift`、`Conversation.swift`、`ConversationMessageRow.swift`；新增必要的回复图片布局，复用 `ReviewImageCanvas` | 正文顺序、整幅展示、点开缩放、加载失败与缓存恢复 |
| 5. 验收与配套构建 | `crates/e2e`、Swift Core、iOS UI／DeviceTests、真实 App Computer Use | 下节矩阵全部有对应证据，列明模拟器与物理设备结果 |

执行按步骤推进，不为本任务另建通用附件框架、云端图床、图片编辑器或终端图片协议。图片读写模块从连接处理器中提取到 app 的共享位置，避免 Agent 发布入口反向依赖 WebSocket 私有模块。runtime 前台只处理身份与事件；SQLite、图像编解码、网络和文件操作均后台化。

步骤 2–4 可以先用 Codex／Claude 完成可展示的贯通里程碑，供检查交互；五类 Provider 全部通过步骤 5 才是本需求完成。不把前一个里程碑当作缩减范围的最终交付。

## 8. 验收矩阵

以下是待新增／更新的测试计划，尚未执行。

| 验收场景 | 必须成立的正／负结果 | 自动化证据 |
| --- | --- | --- |
| 五类 Agent 各回复一张图 | 图在该条回复中；不出现在其他卡片或工具读取记录中 | `crates/e2e` 五类 Provider 公共契约 + 真实 CLI 专项 |
| 一条回复两张图，前后有文字 | 文字 A→图 A→文字 B→图 B；不丢字、不调序、不重复 | Norma/app 聚焦测试 + Swift Core + iOS UI |

| 同路径两次生成，手机第二轮后才上线 | 第一条显示版本 A、第二条版本 B；A 不变成 B | 存储测试 + 新增 `crates/e2e/tests/mobile_reply_images.rs` |
| 纯图片回复、分页重读、重连、归档 | 图片不因空文字被当成工具卡；消息 ID 稳定、无重复 | 现有 conversation/archive 网络用例扩展 |
| 生成完成前取消、写入失败、发布重试 | 原卡其他回复保留；不串轮、不留可见半成品、不重复入库 | app/runtime/storage 聚焦回归 |
| 大图、长图、透明 PNG、小字号设计稿 | 首屏可判断布局，放大可读目标文字；图片不裁切、界面不阻塞 | iOS UI + 真实 App Computer Use；记录尺寸／内存预算 |
| 加载失败、断网与再次连接 | 文字仍可读，缓存图片可见，未缓存图可重试；不自动重发用户指令 | 网络中断测试 + iOS Device/UI Tests |
| 跨项目读取、路径逃逸、符号链接、传输中撤销 | 合法本项目图片可读；无权文件不可读，撤销后停止传输 | `mobile_image_network` 扩展 |
| Mac/iOS 新旧版本组合 | 旧消息和用户发图保持可用；不因新增图片字段导致整页失败 | Rust/Swift 解码契约测试 |

新增测试遵守仓库场景、数据构造、执行过程、预期结果注释规范；数值说明推导，每个断言附失败说明，关键保留／删除状态逐一验证。

实现期先运行聚焦失败测试再实现。涉及的 Rust crate 跑对应测试，跨 crate 完成时执行 `cargo test --workspace`、`cargo check -p app`；运行 `swift test --package-path ios` 和受影响 iOS UI／DeviceTests。App 配套构建运行 `cargo build -p app --release`，并执行行数、禁 allow、存储边界及性能护栏。

页面验收必须使用 Computer Use 操作实际运行的 App；模拟器中点击图片、缩放、关闭返回和读旧版本，并保存证据。`TestAppContext` 和网络测试不能替代此项。物理 iPhone 的 LAN／Tailscale 验收单独列结果，不以模拟器或编译通过冒充。
