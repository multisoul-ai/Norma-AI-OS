### 3.2 通话与执行流程

2026-09-13 用户追加顺序：先迁入豆包实时对话，再继续指挥台剩余工作。当前默认豆包，设置中保留 GPT。豆包使用同源一次性 WebSocket 票据，上传 16 kHz PCM16、播放 24 kHz PCM16；插话上报真实已播放位置，音频播放完毕才确认完成，挂断等待 ACK 后允许新连接。后台只停止角色更新。本地 Plan 网关现在声明独立的 `doubao_` 媒体身份与任务/汇报能力，经 30 秒一次性票据把已授权 Mac 加入 `/v1/tools`；iOS 每次重绑定领取新票据。旧线上网关未声明能力时继续聊天，不伪造工具就绪。下图展示 GPT 路径；豆包使用同样的 Mac 执行与持久回执边界，独立汇报直接 TTS，不进入讨论历史。

```text
用户主动开聊
    |
    +--> iPhone 向现有语音网关领取短期凭证
    |        |
    |        +--> 与 GPT 建立 WebRTC，保存 Location 中的实时 call_id
    |                  |
    |            耳机 <== 实时音频 ==> GPT
    |
    +--> 已配对通道：绑定实时会话 + Mac + 获授权项目
                       |
                 Mac 加入同会话 sideband
                       |
                  GPT 请求工具
                       |
           共用工具定义 / 校验 / 权限 / 预算
                       |
              现有 Agent 卡片与队列
                       |
              持久接收回执 + 任务事件
                       |
              +--------+---------------+
              |                        |
       通话中简短汇报             现有成果与记录入口
              |                        |
         继续讨论/派工          有界面变化：待你验收
                                       |
                               通过 / 退回原任务修改
```

普通聊天不串行调用桌面 `NormaSession` 做第二次 LLM 推理。任务工具返回真实接收回执后继续聊天，执行结果随后通过事件汇报；不得把 accepted 当作任务完成。

App 生命周期持有唯一通话协调对象，不能放在会被 `.id(model.selectedID)` 重建的页面状态内。通话固定绑定 Mac 与项目；浏览其他页面、项目或电脑不会改变派工目标。明确要求切换后校验新目标权限，已有任务仍留在原项目。

前后台音频与角色渲染分离：锁屏关闭角色持续渲染，保持已主动开始的通话；修正 companion 在后台 suspend 以及 establish/reconnect 的 foreground 守卫。其他页面沿用现有 `model.disconnect()` 行为。指挥台所需连接由独立通话对象管理，挂断及时释放麦克风和音频资源。系统音频中断、耳机拔出和切网显示真实状态，不意外切扬声器播报；恢复后核对回执。

### 3.3 最小接口与复用规则

| 接口/能力 | 实施约定 |
|---|---|
| 会话绑定 | 已认证通道提交实时 `call_id`、目标项目与连接代次；设备身份取自已验证连接，Mac 校验项目权限并返回绑定/工具可用状态；挂断解除绑定，不取消任务 |
| 鉴权 | 沿用现有网关签短期凭证；Mac 长期凭据保存在现有安全存储，必须有权访问网关创建的同一 OpenAI 项目会话。手机不持有 OpenAI 长期密钥，日志不输出密钥 |
| 工具注册 | 复用 `norma_tool_definitions()`、`NormaToolRuntime.execute` 与 `AgentCardAdapter`；把当前 Rig 内的共同校验/预算策略提供给实时入口，保持既有每回合 20 次、连续失败 3 次等约束行为 |
| 唯一执行方 | Mac 唯一执行任务工具，iOS 仅处理 `set_behavior` 等本地角色工具；两端观察到同一事件不能重复派工。工具结果与继续回复按同一 response 协调，避免两端重复触发播报 |
| 身份与回执 | 区分实时会话 `call_id` 与 function 调用 `call_id`；工具操作映射到既有 `operation_id`，复用 `mobile/command.rs` 的 reservation、持久回执与 `outcome_unknown` 处理，不以 agent 内存缓存替代可靠去重 |
| 无窗口执行 | 复用现有后台项目与可选 Window 的编排入口，补齐实时 adapter 接线；手机服务开启时关窗继续，主动退出遵守现有统一停止规则 |
| 事件与恢复 | 沿用现有任务身份、事件和成果元数据；重连先核对回执并补齐事件，不盲目重放写操作。未提交想法保留草稿，结果未知时先查证，不自动当作新任务提交 |

sideband 鉴权或项目绑定失败时，仅标记 Mac 工具不可用；语音媒体和凭证获取不依赖 Mac 在线。Mac 离线可继续聊天，但不能派工、声称任务已接收或把旧快照当最新进度。2026-09-14 用户在已列明剩余网关任务后要求完成全部剩余任务，按[网关范围补充](../design-docs/2026-09-13-doubao-task-gateway-extension.md)继续 Norma 仓库内的本地适配与验证。参考 companion 保持只读；不自动部署公网服务或上传模型。

### 3.4 意图、汇报与验收

讨论阶段允许查询、分析、整理草稿；“这个思路不错”不派工，明确执行意图才自主选 Agent、拆任务并执行。任务保留目标、约束和交付标准，不新增逐项确认流程；已有工具审批与权限边界继续适用。

插话和挂断不取消任务，取消需明确意图及执行层回执。普通完成事件默认约 5 秒合并、单次播报约 10 秒以内，用户讲话时排队；“先别汇报”只暂停播报。执行完成、用户验收通过和语音已播放分别记录，不能共用一个完成标志。

| 成果 | 提供给用户 | 完成条件 |
|---|---|---|
| Web 页面与交互 | 手机可访问的交互预览、截图与验证证据 | 用户实际查看并明确通过 |
| 手机页面与交互 | 对应设备测试构建、录屏与验证证据 | 用户在对应设备操作后通过 |
| 桌面页面与交互 | 测试构建、录屏/截图与验证证据 | 用户在桌面设备操作后通过 |
| 非界面任务 | 约定产物与自检证据 | 按任务验收条件判定，区分失败与未验证 |

有界面变化的任务在实现/自检后进入“待你验收”，不阻塞无依赖任务；退回意见续接原任务，新版本重新验收。挂断后沿用成果与记录入口。APNs 按既有决定不部署，不能将锁屏推送承诺为本次已可用能力；不新增通用远程桌面。
