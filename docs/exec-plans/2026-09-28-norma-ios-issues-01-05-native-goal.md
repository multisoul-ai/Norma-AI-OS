## 由开发 Agent 自行完成的验收

每票都要完成以下闭环，不以「代码已写」代替验收：

1. **失败测试先行**：为该票的正例、反例、旧数据/权限回归写聚焦测试，再实现。新增测试遵守仓库的场景、数据构造、执行过程、预期结果注释和具名断言规范。
2. **自动化证据**：iOS 域逻辑运行 `swift test --package-path ios`；原生导航、页面、持久化和可观察交互运行 iPhone Simulator `xcodebuild -project ios/Norma.xcodeproj -scheme Norma -destination 'platform=iOS Simulator,name=iPhone 17 Pro' test`，按验收条件增加/更新 UI 测试。#55 若修改 Mac 协议、授权或存储，运行受影响的 `cargo test -p app -p storage`、`cargo check -p app` 及相关 `cargo test -p e2e`；#58 运行 `npm --prefix services/norma-cloud test` 并核对真实云端文字请求与鉴权。若采用更窄的定向检查，记录命令、范围和原因；每票收口时补齐对应必跑检查。
3. **真实 App 操作**：使用 Computer Use 操作已构建的 iOS App，从入口到完成逐步点击、滚动、输入、返回，分别检查成功、离线、权限拒绝、失败与重启恢复。SwiftUI 预览、XCTest 截图或网页原型不能代替这项证据。
4. **逐屏对照**：在一致机型、显示尺寸、浅色外观及标准字号下保存真实 App 截图；裁出参考图的屏幕内容，逐张比对信息顺序、位置、间距、字号、色彩、圆角、头像、玻璃层和状态。另检查大字号、减少动态效果和 VoiceOver，不拿视觉 fixture 证明网络或 Agent 已工作。
5. **独立子 Agent 审核与返工**：每个页面切片完成后，启动一名只读 UI/交互验收子 Agent（可选 `Evidence Collector` 角色），给它参考图、真实 App 截图和可操作的 App。它只负责截图对比、实际点击和带证据的问题报告，不改实现文件；须告知它并非独自在代码库中工作，不得撤销他人的编辑。报告按每屏列出布局层级、字体/间距、色彩/材质、素材、状态、点击/滑动/键盘/返回/Sheet、动效与无障碍的 **PASS 或 NEEDS WORK**，每个偏差附参考图与实图位置、复现步骤和影响。开发 Agent 逐项修复，重新跑受影响测试与 Computer Use，再交子 Agent 复核。**所有对应屏幕得到 PASS、所有主要交互可达后才能关闭票据**；发现视觉/交互偏差必须打回，不由开发 Agent 自评代替。

把逐屏原图、真实截图、对比图、操作录屏/步骤及原始日志保存在 `target/norma-ios-evidence/goal-01-05/`；在 `docs/exec-plans/` 写可复查的验收记录，逐票列出测试命令与结果、十张适用原型的截图对照、子 Agent 的初审问题与最终复核结论、真机和真实云服务的证据范围。此处「一比一」要求信息结构、主要比例、视觉语言和交互状态逐项匹配；系统字形抗锯齿、真实状态栏和动态内容的合理差异需记录，不得以此掩盖布局或功能缺失。若 Computer Use 或真实服务证据缺失，写明未验收状态和具体阻断；真机扫码/麦克风按最新用户指令移交用户后置验收，不阻塞其他开发。不得把尚未验证的项目写成已通过。

## 五票联合端到端场景

1. 飞行模式记录文字想法与语音想法 → 保存显示「已记录」 → 重启恢复正文、录音和待转写状态 → Workspace 数与任务数不变。
2. 扫码连接 Mac → 在 Mac 明确授予本机当前及未来项目 → 手机能看到真实项目；撤销后目录、已排队但未执行的操作不能沿用旧权限。旧逐项目配对保持原范围。
3. 创建 Workspace A、B → 只给 A 关联已有项目和 Agent → 从想法建 A 的线程并发送消息 → 原想法留在库内，B 不出现 A 的项目或消息；归档/重开 A 后历史仍在。
4. 关闭或退出所有 Mac 后，从 Norma 页进行真实云端文字对话 → 回复和错误状态正确 → 重启后继续查看历史；私聊内容不自动进入 A 的线程，云回复不显示为 Mac 执行结果。
