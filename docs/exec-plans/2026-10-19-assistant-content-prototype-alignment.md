## 3. 目标布局与尺寸

```text
┌────────────────────────────────────────────────────┐
│ 收起图标  [文件 ×]  [网页 ×] …                       │
├───────────────────────────────┬────────────────────┤
│ 当前文件路径                   │ 项目选择器          │
├───────────────────────────────┤ 筛选文件…           │
│  1  文件真实内容               │ ▾ 已更改的文件  ·   │
│  2                            │   ▾ docs           │
│  3  等宽字体，保留空白          │     文件.md    [+]  │
│                               │ ─────────────────  │
│                               │ ▾ 所有文件          │
│                               │   ▸ src            │
│                               │   文件              │
└───────────────────────────────┴────────────────────┘
```

- 沿用现有 52px 标签栏、抽屉边界和动效；文件/变更标签隐藏通用 40px 上下文条和常驻“文件 / +”行，不能通过增加额外卡片包装达成。
- 普通文件视图：目录在右侧；宽度按原型 `max(170px, 32% × 内容区宽度)`，余下宽度交给正文，分隔线 1px。约 565px 的右栏对应约 181px 目录；约 474px 的常规右栏也应保持约 170px 目录。
- 原型的 `@media(max-width:520px)` 是全窗口条件，不能照搬为“抽屉宽 < 520px 就隐藏目录”。仅当正文可用宽度不足约 200px（总宽约 371px 以下）才采用紧凑模式，保留一个可发现的目录按钮，使用临时浮层或可关闭目录；关闭后恢复原文件与滚动位置。185px 极窄栏不得强行并排，也不得丢失文件或切换入口。
- 内部文件面板背景参考 `#101114`，路径条 `#15171b`，正文 `#e8f1ec`，次级文字 `#cdd5e0`，行号 `#6f7b8b`，边线为低透明白。原型内板面保持深色，外壳跟随现有主题；保留可辨的焦点和状态反馈。
- 正文使用 SF Mono / Menlo，12px、约 22.8px 行高；行号区域约 38px，数字右对齐。路径条约 36px 高，使用系统字体 12px；独立于正文滚动并保持可见。
- 目录字体 12px、树行约 28px 高；侧栏 padding 12px/10px，树层级缩进 10–12px。项目选择与搜索各约 32px 高、9px 圆角；图标 11–14px。具体以原型 CSS 为准，不直接使用 Button 的默认大内边距和居中布局。

## 4. 文件树与选择交互

1. 右侧顶端选择器展示真实来源项目，复用已有可搜索 Select；“示例工作区”只用于验收夹具，不写死到产品。
2. 搜索同时过滤变更树和全部文件树，保留匹配项的祖先路径；清空后恢复正常树形与原展开状态，不把文件夹变成平铺搜索按钮。
3. “已更改的文件”和“所有文件”是两个可折叠 section。变更树按目录层级组织；同一文件在两棵树中引用同一身份，点击后选中状态和正文一致。
4. 全部文件行包含展开箭头/文件类型图标、名称及必要状态。左对齐；长名称省略并提供完整路径 tooltip。文件夹与文件使用可辨图标；不以居中圆点加文字代替树。
5. 变更项用真实 Git 状态与原型的绿色名称、紧凑状态标记及尾部约 15px `+` 操作呈现；`+` 只暂存该项且不触发行选择。已暂存项提供明确取消暂存入口，不能继续显示意义错误的“+”。
6. hover、pressed、selected、keyboard focus、disabled 均可辨。支持键盘上下选择、左右展开/收起、Enter 打开；复用组件已有能力，避免重写整套输入系统。
7. 复用现有目录后台扫描、选中路径与展开集合；大目录维持虚拟列表。源项目移除、文件删除、无项目、非 Git 目录、空变更和权限错误都要有对应空态或错误反馈。

## 5. 正文、编辑与真实内容

- 文件标签内默认显示所选真实文件的源码/文本，行号与内容同步滚动；长行可水平滚动，保留空行、缩进、Tab 和复制结果。文件名、选中路径、正文必须一致。
- 原型把同一段示例正文用于不同文件，这是演示数据限制；不能照搬成“点哪个文件都显示同一内容”。截图中 `.git` 的示例展示也不能成为放开真实 Git 内部读取的理由，沿用现有安全边界。
- 复用 `ui::component` 输入能力实现编辑；先核实钉死版本的可用 API。行号依据编辑后当前文本更新，滚动保持同步；不为此引入完整 IDE、语言服务或新的编辑器框架。原型没有要求的语法高亮不作为本轮前置任务。
- 编辑、保存、预览、系统打开使用路径条右侧的紧凑图标/溢出菜单和已有快捷键；路径条不再叠一整行大文字按钮。未保存标记与保存/放弃/取消流程保留。
- Markdown/HTML 保留源码与富文本预览切换；图片与视频在正文容器内使用已有预览，按需提供其自身控件。源码行号不套到图片或富文本预览上。
- 文件切换与项目切换保留现有防迟到结果、草稿保护和文件版本保存机制；不得为了样式重写已验证的保存、文件隔离或 WebView 资源授权逻辑。

## 6. Git 变更呈现

- 点普通文件显示正文；点变更项进入对应文件的差异视图。复用现有 `Comparison::Local`/分支比较、已暂存/未暂存语义，清楚标明当前查看的是哪一类。
- 分支比较主区参考原型 `changesPage()`：紧凑的分支/目标及增删摘要，文件路径头，带行号和增删语义的 diff。显示实际 Git 结果，不写死原型的 `+89` 或分支名。
- 改名、删除、二进制变更均有明确呈现；不能把所有 diff 行统一染成新增，不能把工作树修改混入 merge-base 到 HEAD 的分支差异。
- 刷新、隐藏/忽略选项、分支选择、批量暂存/取消、提交等操作移至 section 菜单或按需浮层，保留原有能力；提交输入与按钮只在用户打开提交操作时出现。
- Git 写操作保留明确结果与错误；撤销继续确认，提交正常运行 hooks，不推送、不切换分支。反馈优先就地呈现，不让长驻成功消息增加整个预览区域的高度。

## 7. 浏览器、媒体与外壳边界

本轮只修正右侧内容区及必需的关联测试。不改左侧 Norma、中央画布/PTY、壁纸、语音、GPT Live 或快捷键体系；不做新视觉方案、动画探索、打包发版或远程推送。
