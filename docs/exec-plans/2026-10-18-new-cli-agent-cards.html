已确认的 5 项决定(2026-10-18)

  1. Kimi:接 Kimi Code CLI。命令仍是 kimi,安装 curl -fsSL https://code.kimi.com/kimi-code/install.sh | bash。旧版 kimi-cli 已归档,不支持;卡片名叫 “Kimi”。
  2. ZCode:是智谱/Z.ai 的 zai-org/ZCode。README 没有写 resume 和 hooks,Phase 0 先跑 zcode --help 并读 apps/zcode-cli/ 源码确认。
  3. 图标:找各家官方 icon,转成终端可显示的像素风格。见下方“图标流水线”。授权以官方品牌页的使用条款为准。
  4. 快捷键:Kimi=Cmd+7、Pi=Cmd+8、Hermes=Cmd+9,ZCode 默认不绑定;全部进 Settings 可录制、可恢复。
  5. 范围:hooks、会话恢复、编排都要做。仍按 P1 → P2 分批合并,避免被四个 CLI 里最不确定的部分拖住 P1。

现有接入流程(以 Grok 为模板)

我对照了 docs/research/2026-07-19-grok-build-integration.md 和代码里所有 AgentProfile::OpenCode 的匹配点。接入是穷尽匹配驱动的:先在 canvas 加枚举值,编译器会逐处报缺口。

canvas  AgentProfile  →  runtime  PtyCommand / 恢复命令 / 会话发现
   →  norma  协议·CLI·hook source  →  storage  稳定编码
   →  agent  create_agent schema·提示词  →  app  菜单·设置·图标·动画·快捷键
   →  测试  各 crate 单测 + desktop-e2e

图标流水线

目标:每个 CLI 一套像素风图标,在终端里的卡片初始化动画和 Dock 里都能用,风格与现有 toolbar-grok.svg、toolbar-opencode.svg 保持一致。

  1. 取官方素材。只从各自官网、品牌页或官方仓库取 SVG/PNG,记录来源 URL 与使用条款;条款不允许时改用字母占位并标注。
  2. 像素化。先用现有图标的网格(查 assets/icons/toolbar-grok.svg 与 cards/intro 的 AGENT_FRAMES 尺寸)确定分辨率,再把官方图形降采样为单色/双色网格。脚本放 scripts/,输入输出路径由参数传入,产物可复现。
  3. 两种产物。Dock 与菜单用 toolbar-<名>.svg(整数像素的 rect 拼成);卡片初始化动画用帧数据,配色从 ui/theme.rs 取 accent。
  4. 验收。浅色与深色下各截一张真实 App 图;图标在 16、24 px 下仍可辨认;在 Dock 图标测试里加一条“四个新 profile 都有图标”的断言。

分阶段实施

先横向打通共用层,再纵向逐个 CLI 交付,这样一个 CLI 的不确定性不会阻塞另外三个。

PHASE 0

真实 CLI 探测(半天)

  • 本机安装四个 CLI,记录 --help、版本号、首次登录流程。
  • 确认 Kimi Code 新版的 resume 参数、hooks 机制和会话目录。
  • 确认 ZCode 的 resume 和 hooks;确认 command -v zcode 指向官方二进制,避免装到第三方同名包。
  • 确认 Hermes 是否有生命周期 hooks 或插件事件。
  • 把结论写进 docs/research/2026-10-18-new-cli-agents.md,并更新上面“待验证”项。
出口:每个 CLI 的 P2 方案(hook 方式、恢复命令)有书面结论,没有的标注“P2 不做”。
PHASE 1

四个卡片能创建、运行、保存(核心)

  • TDD:先写 canvas、storage、runtime、norma 的失败测试,参照 Grok 的测试文件。
  • 按“改动清单”标 P1 的行逐层实现,以编译器的穷尽匹配错误为检查表。
  • 菜单、Dock、Settings、快捷键、图标、初始化动画全部接通。
  • PTY 清理沿用现有 kill_all 路径,不新增子进程管理。
出口:cargo test -p canvas -p runtime -p storage -p norma -p agent 与 cargo check -p app 通过;mechanized 脚本全绿。
PHASE 2

状态灯、会话恢复、编排(逐个 CLI)

  • Pi 先做:文档完整、扩展事件齐全。写 ~/.pi/agent/extensions/ 下带 Norma 标记的扩展,事件归一化为 Ready、Thinking、RunningTool、Done、Failed;卸载只删带标记的文件。
  • Kimi、Hermes:按 Phase 0 结论选 hook 或进程内事件;没有 hook 时只做恢复,状态灯标为不可用。
  • ZCode:最后做,依赖 Phase 0 对其源码的结论。
  • 会话 ID 由 hook 写入缓存,不在 PTY drain、渲染、关闭路径上扫目录或查 SQLite(Hermes 的 state.db 尤其如此)。
出口:每个 CLI 的 hook 单测、恢复命令单测通过;真实 App 里提交任务后卡片状态正确变化。
PHASE 3

真实 App 验收与文档

  • desktop-e2e 新增场景,放在对应模块目录并在 Catalog.swift 追加 manifest。
  • 浅色与深色下检查菜单、Settings 选择器、Dock 图标的 hover/选中/禁用状态。
  • 手机端能看到新卡片并正确显示名称。
  • 同步 CLAUDE.md、AGENTS.md、快捷键文档。

风险

风险级别应对
