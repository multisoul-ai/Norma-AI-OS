# 桌面多项目工作空间：实施拆分

依据：[桌面工作空间 SPEC](../product-specs/2026-09-29-SPEC-desktop-multi-project-workspaces.md)。本文件是本地实施任务草案，不代表已经创建 GitHub Issues。每一项都要形成可演示的桌面行为和自动化证据，按阻塞关系推进。

## 任务 01：可创建和打开空桌面工作空间

**阻塞：** 无。

**交付：** 桌面首页从最近项目入口转为工作空间缩略图网格；用户可新建、改名、搜索并打开空工作空间。工作空间在本机保存，重启后仍在。旧项目画布不自动导入，旧文件不删除。

**实施边界：** 在 `workspace` 定义桌面身份和关联规则，在 `storage` 持久化目录，在 `app` 改造启动页和空画布。保留现有项目身份和手机路由含义。

**验收：** 自动化创建两个不同工作空间，验证名称／ID／最近顺序独立，重启后恢复；真实 App 核对空状态、搜索与 1600 × 1000 的 12 缩略图密度，较小窗口可滚动。

## 任务 02：一个工作空间内添加并展开一个项目

**阻塞：** 01。

**交付：** 从最近项目、本地目录或克隆结果创建项目区域；区域可展开为独立项目画布，创建 Agent 时选择 worktree，保存并恢复卡片。再次添加同一项目只定位已有区域。

**实施边界：** 以「桌面工作空间 ID + 项目身份」建立新画布存储和运行身份。项目打开流程不能结束另一个桌面工作空间的运行实例；旧项目级 `workspace_id` 与手机协议保持原意。现有按项目根目录唯一化的窗口逻辑不能决定桌面区域身份。

**验收：** 打开项目目录与其 worktree 目录只形成一个区域；创建 Agent 后区域和卡片归属正确；重启恢复新画布，不读取旧桌面卡片存档；既有手机项目路由仍通过现有测试。

## 任务 03：一个工作空间同时操作多个项目

**阻塞：** 02。

**交付：** 添加项目 A、B 后自动排列成两个固定区域；总览可直接看到并回复两边 Agent，展开 A 只放大 A 的项目画布，返回后仍是同一会话。所有项目区域在窗口尺寸变化后可达，不相互覆盖。

**实施边界：** 工作空间总览合成多个项目画布的可见状态，卡片输入始终路由到其所属项目实例；完整终端、长对话与项目内布局操作保留在展开视图。隐藏区域持续接收输出，但不做无意义的逐帧绘制。

**验收：** 可控 Agent 分别在 A、B 回执；在总览回复 A 不写入 B；展开与收起不复制卡片、不中断任务；尝试跨项目拖动卡片不能改变归属。

## 任务 04：当前窗口快速切换与同项目多工作空间

**阻塞：** 03。

**交付：** 在底部工具栏加入切换按钮；`⌘⇧K` 和按钮打开同一工作空间缩略图切换器。当前窗口内切换，原空间 Agent 继续运行；同一项目加入另一个工作空间后拥有独立卡片和画布，两个空间的 Agent 可同时选择同一个 worktree。

**实施边界：** 快捷键接入现有注册表与 Settings 的录制／恢复；卡片聚焦时也由 App 消费。窗口只更换当前工作空间与视角，运行实例以「工作空间 + 项目」寻址。旧顶部“打开启动页”动作不得因切换创建新窗口。

**验收：** A 空间项目 P 的 Agent 持续输出时切到 B 空间；B 中同项目 P 的新卡片与 A 不同，但可使用同一 worktree；切回 A 后可见期间输出且视角恢复；按钮、快捷键和键盘焦点路径一致；不增加窗口数量。

## 任务 05：当前工作空间内的 Norma 跨项目派工

**阻塞：** 03、04。

**交付：** Norma 从当前工作空间的一条指令识别多个明确项目／Agent 目标，分别派工并展示逐目标回执。卡片内回复仍只送目标卡片；目标含糊时提出一次最小澄清，不猜项目或触达其他工作空间。

**实施边界：** 利用现有项目级派发与回执能力，在桌面工作空间层解析和验证目标；保留既有手机及 CLI 的项目身份，不把桌面工作空间 ID 塞入手机协议。单个目标失败不重试已成功目标。

**验收：** A、B 各有 Agent 时，一条明确指令产生两个可追踪回执；A 失败、B 成功时如实分别呈现；只有“修一下”且多目标可选时先澄清；指定其他工作空间的 Agent 不会被当前工作空间隐式执行。

## 任务 06：移除项目区域与删除工作空间

**阻塞：** 04。

**交付：** 可移除当前工作空间的项目区域，也可删除整个工作空间。运行中操作先提示；取消完全保留，确认后只停止受影响的 Agent/PTY。重新加入同一项目从空画布开始，项目目录及其他空间保持原样。

**实施边界：** 先停止并回收目标运行实例，再清除对应的桌面关联、画布和卡片存档；不得按项目根目录全局删除共享项目数据。关闭窗口和主动退出沿用现有手机服务生命周期边界。

**验收：** A、B 空间均含项目 P 且使用同一 worktree；移除 A/P 后 B/P 持续运行；取消移除时 A/P 继续运行；确认后 A/P 结束并消失，重新添加为空。删除 A 后 B 及仓库仍在。真实 PTY 验证子进程停止与回收。

## 集成验收

- 每项实现时补聚焦的域层／`crates/e2e` 证据；按触及 crate 运行仓库规定的测试和边界护栏。用户可见页面和交互状态用 Computer Use 操作真实 App 验收，不能只靠 headless GPUI。
- 最终跑完整桌面流程：创建 → 添加 A/B → 跨项目操控 → 展开 → 快速切换 → 同项目双空间同 worktree → 移除／删除 → 重启恢复。
- 对共享项目加载、关闭和会话路由跑现有手机后台服务回归，确保 iOS 页面、协议与项目级访问没有变化。
