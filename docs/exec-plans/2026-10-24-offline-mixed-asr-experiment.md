# 中英混合离线 ASR 选型实验 Goal

日期：2026-10-24。状态：Goal active；完成现状核查与实验规划，尚未运行候选对比。

## 1. 目标与范围

在 Norma 的语音指令/听写链路中，找出同时满足低延迟、中英句内混合准确率和 Mac 资源约束的本地 ASR 架构。最终交付可复现实验、逐条结果、选型表、一个默认推荐和一个本地降级模式；若无人达标，明确报告差距，不能把“相对最好”写成“已达标”。

用户已明确：**必须完全离线，音频只在 Mac 本地处理**。这条约束覆盖创建 Goal 时包含云端比较的初始表述。Azure、豆包、远程转写、远程 LLM 纠错均退出本实验；音频、转写、术语上下文和评测明细均不外发。模型和公开资料可以预先下载，推理与验收在断网/禁止实验进程联网条件下进行。缺模型时报告未就绪，不静默调用云端。

本轮交付规划，不修改正式默认模型。实验先走独立入口，完成选型后提供接入原型和迁移步骤。豆包/GPT-Live 实时对话、TTS 和通用 LLM 规划质量不计入 ASR 得分；真实 App 验收止于本地最终文本和本地测试动作，避免现有云端规划器收到转写。

## 3. 候选矩阵

不同架构尽量共享采集、样本、时间戳、VAD 和评分器。先验证后端可运行与模型许可，再进入真实质量测试。多语言支持不自动代表同一句话中切换语言的表现。

| ID | 架构与模型候选 | 实验要回答的问题 | 首轮优先级 |
| --- | --- | --- | --- |
| B0 | 当前 App 实际配置，另留现有双语 Zipformer / Paraformer 基线 | 用户当前到底慢在初始化、出字、收尾还是错误重试？ | 必跑 |
| S1 | 优化的单遍流式：Sherpa 双语 Zipformer / 双语 Paraformer | 只改常驻、音频链路、搜索参数与术语，能改善多少？ | 必跑 |
| N1 | 本地分句：Silero VAD + SenseVoiceSmall，优先 Sherpa/ONNX 可用后端 | 中文主导的混合语音是否更准确，句末推理是否足够快？ | 必跑；非原生逐帧流式 |
| W1 | Whisper large-v3-turbo，whisper.cpp Metal；MLX 作为后端复测项 | 英文与混合语音质量、滑窗延迟和 16 GiB 下的代价如何？ | 必跑；滑窗不冒称原生流式 |
| Q1 | Qwen3-ASR 0.6B int8，先验证 Sherpa ONNX CPU，再比较 MLX；必要时再测 1.7B | 较新多语言模型能否在本机同时满足质量与延迟？ | 后端可运行性门槛后进入 |
| H1 | S1 流式预览 + N1 对相同音频作二遍校正 | 快速反馈与准确终稿能否同时达标？ | 主要架构假设 |
| H2 | S1 流式预览 + W1 或 Q1 胜者二遍校正 | 更强终稿是否足以抵偿额外延迟和资源？ | 只测单模型筛选胜者 |

后备项：更新的 FunASR streaming 工件、Whisper large-v3、Apple 本地 SpeechAnalyzer。仅当首轮存在明确缺口且官方证据/平台支持足够时引入，避免所有模型、后端与参数做全排列。Apple 支持中英文 locale 不等于支持单句混合；Qwen 官方服务端流式也不等于 Mac 后端流式。具体版本、量化、license、工件 SHA-256 在运行前冻结。

Sherpa 上游支持某模型不等于仓库当前 Rust 绑定已经支持：本仓库使用 `sherpa-onnx = "1.13"`，并有 `vendor/sherpa-onnx-sys-1.13.3/` 补丁。新模型先在隔离 runner 验证，核对 API/ABI 后再评估接入，不为实验直接升级生产依赖。

## 4. 主实验架构

```text
原生麦克风 / 带时间戳的真实录音回放
            │
     单次重采样 → 16 kHz mono PCM
            │
     有界音频缓冲 + 样本序号 + VAD
            ├── 常驻流式识别器 ──→ Partial（仅预览）
            │
            └── 本地句段重识别 ──→ CandidateFinal
                                    │
                  本地提交控制器：截止时间、取消、版本去重
                                    │
                           CommittedFinal（只提交一次）
```

- 常驻所选模型，后台初始化；使用每会话独立解码状态。先测冷启动，再测常驻收益，不能把预热成本藏掉。
- 原始音频只缓存在本地。VAD 负责边界而非丢弃一切静音；验证 200–300 ms 起始预留，保护弱起音和英文首辅音。实际预留时长在开发集上选定。
- 按键结束立即发出输入结束信号；自动结束才等待 VAD 静音门槛。保留真实末尾音频，尾部 padding 如后端必需须单独记录，禁止靠截尾换延迟。
- H1/H2 二遍必须重新听相同音频，不仅依据第一遍文字猜测。先测“每句二遍”，再测“按稳定性/术语风险选择二遍”；不同模型原始置信度不可直接横向比较。
- 二遍超时或失效时使用已经完成的一遍终稿，记录降级；如果一遍也未完成，明确失败。对外只产生一次最终提交，迟到二遍不得改写已执行命令。
- 串行与重叠执行分别测，模型并行不能抢占实时音频线程；只让入围模型常驻。长句使用有重叠的有界分段，测试拼接的漏词与重复。
- 默认不加生成式文本纠错。需要规范大小写、数字、代码术语时单独测确定性规范化，同时保留原始文本；不能通过改写掩盖 ASR 错误。
- 推理、加载、队列 drain、join 全部后台化；app 仅接收事件。接口复用 `asr::RecognizerFactory` / `RecognitionEvent`；模型无关协调放 ASR 域，采集/VAD 留在 voice_input，用户交互生命周期由 app 适配。

## 5. 数据集与公平比较

### 主数据集

目标是 300 条真人样本：60 条中文、60 条英文、120 条句内混合、60 条静音/噪声/易误识别负例。正例覆盖短指令、连续听写、自然停顿、快速说话、口音、数字、路径和代码标识符；常规短句 2–15 s，另留 30–60 s 长句专项。至少 6 位说话者；样本可来自许可适用的公开真人语料和本地自愿录音，来源/许可随 manifest 记录。

建议例句只用于设计覆盖面，不能代替真人测量：

- “把这个 React component 拆出来，再跑 cargo test。”
- “在 feature slash voice 分支修改 src slash main dot rs，保留 GPUI。”
- “Use the 中文配置，then restart the terminal。”
- “不要关闭第二个 terminal，切换到第三个。”

固定 80 条开发集 + 220 条冻结测试集，开发/测试的说话者及提示文本独立；同一句的噪声增强、不同音量和重复录音必须归同一侧。混合样本和三种语言切片在两侧均有覆盖。固定一组测试正例制作 20 dB / 10 dB SNR 派生集并分开报告，不把派生录音当独立新说话者。

用户自己的典型口述可另建不少于 30 条个性化测试集；没有该集合时仅报告通用选型，不宣称已经验证用户口音。个人录音与标注保存在本机忽略目录，只向仓库提交可分发夹具和汇总方法。TTS 合成样本只作协议/极端边界冒烟，不作为最终准确率排名依据。

### 回放与运行协议

1. 为 WAV/原始录音记录 SHA-256、参考文本、说话者、语言切片、设备、噪声、真实 speech onset/offset、术语与危险混淆词。
2. 质量/吞吐评测可以加速喂音频；**交互延迟必须按真实采样时钟喂入**，并保留末尾静音。另做真实麦克风验收补足采集、设备缓冲和 UI 延迟。
3. 每个入围配置执行 3 轮完整热态集，随机轮转候选顺序；冷进程启动至少 10 次，另记文件缓存是否温热。进程重启不冒称磁盘冷缓存。
4. 固定电源模式、并发负载、模型参数和术语表；记录热状态。另在预定义编码工作负载下测赢家，防止空闲机器上的成绩掩盖抢资源问题。
5. 不同时跑两个候选性能实验。参数仅在开发集上调，测试集解封后不继续调同一轮参数；需要再调时开新版本并保留原结果。
6. 逐样本记录失败、空输出、超时、降级和早截断；延迟报告列出失败分母，不只计算幸存成功请求。质量重复运行不冒充更多独立样本。

负例没有有效参考词数时不计算 MER/CER/WER，改报误出字率和误提交率。终稿早于真实语音结束的样本记截断失败，不能以负数延迟进入“更快”统计。单模型无 partial 时记“不支持”，不能填 0 ms；二遍回退的最终文本与质量必须计入该架构总成绩。

## 6. 指标和初始验收目标

以下是**实验目标，不是已测成绩或性能承诺**。P1 先冻结口径；门槛若需调整须保留旧结果与理由。

| 维度 | 定义 | M4 / 16 GiB 初始目标 |
| --- | --- | --- |
| 完全离线 | 模型已安装后禁止网络；验证没有远程回退/转写外发 | 必须通过 |
| 首字延迟 | 第一段非空 partial 可见时间 − 真人语音开始时间 | 热态 P50 ≤300 ms，P95 ≤600 ms |
| 稳定出字 | 首个之后不再撤回的前缀出现时间；另报每词稳定延迟/改写率 | 首稳定前缀 P95 ≤800 ms，不能以反复改字“刷首字” |
| 手动收尾 | CommittedFinal 可用时间 − 用户结束信号 | 2–15 s 短句 P95 ≤500 ms |
| 自动收尾 | CommittedFinal 可用时间 − 人工标注最后语音样本时间 | 2–15 s 短句 P95 ≤800 ms，包含 VAD 等待 |
| 混合错误率 MER | 中文按字、英文按词，固定混合 token 规则做整体编辑距离 | 干净混合测试集 ≤5%；10 dB 噪声集 ≤12% |
| 基线改进 | 对冻结混合集做配对比较，按说话者/句子报告 bootstrap 区间 | 争取 MER 相对下降 ≥25%；基线已很低则看绝对值与区间，不强造提升 |
| 分语言退化 | 同时报告中文 CER、英文 WER 和混合中的英文术语错误 | 中文/英文各自错误率不得较基线恶化 >1 个百分点 |
| 术语与命令 | 术语精确匹配、插入率、数字/路径和关键否定词准确率 | 术语准确率 ≥95%；冻结关键产品指令逐条全部正确 |
| 错误行为 | 句首/句尾截断、静音幻觉、重复 final、取消后迟到提交 | 固定边界集零错误；同时报告样本数量 |
| 资源 | 全部 ASR/VAD 进程树 CPU、峰值 RSS、Metal/统一内存可用统计、RTF | 常驻预算目标 ≤4 GiB、峰值 ≤6 GiB；无持续内存压力；稳态 RTF <1 |
| 启动与持久运行 | 模型加载/开麦就绪分段时间、30 分钟连续运行 | 单列冷/热结果；队列无持续积压，无累积内存增长 |

MER/CER/WER 的规范化只处理预先约定的 Unicode、空白、英文大小写和标点；原文同时保存。路径、代码标识符、数字与否定词另做严格匹配，不能把删除/翻译英文术语视为正确。简繁、数字口语的等价规则在跑模型前锁定。

统一时间戳：请求开始、模型可用、麦克风可用、首 PCM、speech onset、首 partial、首稳定前缀、speech offset、用户结束、VAD end、模型 final、committed final、UI 显示。模型 final 与 UI 显示延迟分开；手动和自动结束不混成一个分布。长句单独报告，不借短句指标掩盖长句回放成本。

## 8. 验收与测试映射

| 验收项 | 证据入口 |
| --- | --- |
| 评分正确 | 人工可计算的 MER/CER/WER、空输出、插入/删除、混合分词和数字/代码标识符聚焦测试 |
| 时间可信 | 已知发声边界与事件延迟的夹具，校验实时喂入；模拟处理时间不可标注为模型性能 |
| 句首/尾完整 | voice_input 音频序号与样本总数断言；dialogue 的 VAD 延迟、预留、短停顿与连续切句测试 |
| final 一致性 | ASR 协调器的二遍先/后完成、超时、取消、重入、过期 generation 和恰好一次提交测试 |
| 可完全离线 | 模型本地加载、拒绝网络时全链路完成；缺模型/失败无云端回退；明确实验进程边界 |
| 真实质量/延迟 | 相同真人 WAV 下逐候选的实际引擎结果；UI 首字和 final 用真实 App 定向验收补充 |
| 资源与稳定性 | 真实进程树采样、音频队列水位/丢块计数、30 分钟试验；区分缓存与泄漏 |
| 产品体验 | 真实 App 中英口述、取消、重新开始、修改术语、长句；新增视觉交互时加载 apple-design 和 norma-desktop-e2e skill |

## 9. 最终选型规则与结果表

1. 先过离线、边界正确性、许可/可交付性及内存约束；再过延迟与质量门槛。
2. 对合格者比较准确率、延迟和资源的 Pareto 集；在延迟预算内优先更低的混合 MER 与术语错误。
3. 对相近结果查看配对区间与失败样本；收益不确定时优先更简单、内存更低的架构，不靠任意加权总分宣布胜者。
4. H1/H2 只有在显著改善终稿且实际收尾仍达标时胜出；否则选 S1 或单模型赢家。降级始终本地，若仍未达标则保留基线并列出下一轮具体缺口。
5. 本机达标不自动授予全平台推荐；要发布通用推荐，补 `docs/quality/asr-model-release-gate.md` 要求的受支持机型证据。
