# Norma 正常记忆读写与设置页实施方案

日期：2026-10-03。实施记录更新：2026-10-04。状态：正常记忆读写、Norma 设置与 Voice 导航迁移已实现；验证范围及限制见第 10 节。

基线：`13713111` 已交付 Markdown MemoryStore；本方案复用该存储基础，不另建记忆数据库。

## 1. 已确认范围

用户确认本次先完成“正常读写与设置页”，普通交流后的自动学习放到下一步。

本次交付：

- Norma 对话能够按需发现、读取个人、当前项目和当前工作树记忆。
- 用户明确要求“记住”或“更新这条记忆”时，经真实写入回执保存；后续对话和重启后仍可读取。
- Settings 新增 Norma 一级页，提供记忆查看、新增、编辑、纠正与 Markdown 导入。
- 现有 Voice 配置整体迁入 Norma 的语音分区，原配置、凭据引用、模型和后台任务继续复用。
- 无项目时个人记忆和个人会话可用；项目与工作树内容默认隔离。

本次不实施普通交流后自动学习、Dream、Skill/插件成长、手机历史迁移、新的人格编辑体系、完整遗忘与历史清理。首版不提供尚未实现的相关操作或占位分区。纠正是发布新内容；历史仍保留，不能把纠正、删除当前文件或存储回滚描述为完整遗忘。

不新增普通聊天的自动归档或聊天历史页面。本次只持久化记忆写入的真实授权来源、设置编辑事件、必要的关联回执与写入结果；持久经历与自动学习沿后续票建设。

## 2. 架构与已有接入点

```text
对话：memory_list / search / read / write ─┐
                                         ├─ App 记忆协调模块 ─ Markdown MemoryStore
页面：查看 / 新增 / 编辑 / 导入 ──────────┘          │
                                                    └─ app.sqlite：归属、来源、操作结果
```

| 层 | 本次职责 | 现有接入点 / 目标目录 |
| --- | --- | --- |
| `agent` | 可信会话绑定的数据类型、记忆命令和结果、目录与工具结果预算、统一上下文拼装 | `src/memory.rs`、`src/adapter.rs`、`src/rig_tools.rs`、`src/master.rs`、`src/master_prompt.rs`；新增逻辑按职责拆分 |
| `storage` | 复用文件读写；新增归属、来源、操作结果的 SQLite 存取及必要的发布结果核验 | `src/memory/`、`src/migrations.rs`、`src/workspace_identity_store.rs`；新增 `memory_source_store` 等明确职责模块 |
| `app` | 授予范围、绑定真实来源、处理版本和取消、后台文件/SQLite IO、向会话和页面返回真实结果 | `src/app/agent_runtime.rs` 及其 adapter、submit；建议新增 `src/app/memory/` |
| `app` 设置 | Norma 导航、记忆列表/详情/编辑、Voice 导航迁移 | `src/settings/{navigation,content,panel,panel_lifecycle}.rs`；建议新增 `src/settings/norma/` |

MD 正文是长期记忆的唯一权威，`MEMORY.md` 继续由主题描述生成。SQLite 不再维护另一份可编辑的记忆正文。

`agent` 不依赖 storage、GPUI 或文件系统。复用现有 typed command/adapter 协议；记忆命令在后台分流执行，不能直接把阻塞 Store 调用放入现有 adapter pump 的 GPUI `update_in` 闭包。

当前 `NormaSession` 与 `submit_project_agent` 以项目为前提；本次引入明确的个人/项目会话绑定，个人模式不得靠伪造项目路径获得能力。无项目时只授予个人记忆和非项目能力。

Rig 和桌面豆包使用相同的范围、目录、读写协议与政策；豆包当前只在有项目时建立工具 adapter，本次须补个人记忆接入。iOS 云端独立对话及手机历史迁移不包含在本次。

## 3. 范围与加载

### 3.1 宿主确定范围

模型只使用 `personal / project / worktree` 别名，不能传任意项目 ID 或路径。

- Git 项目由现有 `workspace::project::identify_project` 提供 canonical common directory，多个 worktree 据此共享项目记忆；以当前工作树根和已有 workspace 身份确定工作树范围。
- 在 `app.sqlite` 建立记忆归属映射，绑定上述身份与受管记忆 ID；不把 canvas 路由 ID、显示名或 remote URL 当作项目身份。
- 不同 clone 默认独立；非 Git 项目按自己的已验证目录身份隔离。
- 同路径仓库替换或身份无法核实时，不继承旧范围；路径搬迁不静默导入另一份记忆。实施时以目录身份校验和失败关闭测试约束映射。
- 每次操作及后台结果应用时核对会话绑定/代次，A 项目的迟到结果不能刷新 B 项目的界面或上下文。

### 3.2 会话加载与刷新

| 时机 | 行为 |
| --- | --- |
| 创建、恢复、重新激活会话 | 后台取得允许范围的快照，准备有预算的目录并注入会话 |
| 持续会话每轮 | 继续携带已加载目录，不每轮扫描磁盘或自动刷新所有目录 |
| `memory_list/search/read` | 重新取得当前有效快照；操作内固定版本，返回有界结果及来源 |
| 当前会话写入成功 | 工具回执返回主题、范围和新版本；同回合据回执知道保存结果 |
| 设置页修改记忆 | 页面刷新已提交范围；持续会话通过记忆工具获取新内容，或下次激活重载 |
| 关闭 Norma 的记忆读取 | 清理该会话中记忆目录与已读取内容，后续模型请求不得重新注入；必要时重建协议上下文 |

目录总量建议最多 8 KiB（参考已调研 AgentConnect catalog 的 8,192-byte 上限），且不得超过模型实际剩余上下文预算；不是每个范围各占 8 KiB。截断明确提示目录不完整并提供 list/search。

历史预算须扣除系统、环境、工具定义、目录和回复预留；不能沿用当前固定历史比例再无条件追加记忆。正文读取按剩余预算限制，长文支持明确的续读标识，UTF-8 边界正确且不能假装已返回全文。

首版使用后台有界词法搜索，匹配标题、描述和正文，验证中文无空格查询；不以英文分词规则代替中文召回。检索范围在宿主实际过滤，不只依赖 prompt。来源文字作为数据，不升级为系统指令。

## 4. 写入与来源

### 4.1 对话入口

1. 建立全局唯一的 session/turn 身份，持久记录此次明确记忆请求及真实用户原文。来源落盘失败，则不得发布无来源的记忆。
2. 宿主绑定允许范围和授权；明确的个人偏好写 personal，项目约定写 project，分支/版本/任务事实写 worktree。归属不清时才要求用户澄清。
3. 模型读取目标旧主题后提出完整更新；新主题以当前范围快照作为基线。没有明确写入授权的普通交流或模型推断不得自动发布。
4. `expected_revision` 绑定宿主记录的读/列表快照，不能在写入时悄悄刷新版本掩盖覆盖冲突，也不能信任模型伪造的来源或基线。
5. 后台调用 `commit`，获得真实保存回执后才能回答“已记住”；冲突、忙、验证失败与无法确认的状态分别返回。

命令仍叫 `memory_write`，新增/更新共用入口；对用户“纠正”意味着更新正文，目录随同一 revision 一起发布。不能只把修正事实追加到仍包含矛盾旧值的主题。

写入前已取消则拒绝；写入完成后被打断不意味着自动撤销该次保存。来源及结果仍归属于原会话，不能迁移到新项目。回执不确定时核验实际发布结果，不盲目重试或宣称失败后又重复保存。

### 4.2 设置页入口

1. 新增、编辑或导入时记录 `SettingsEdit` 来源，导入仅读取用户明确选中的文件，不监听或让用户直接改受管版本目录。
2. 编辑草稿绑定打开时的范围、主题 ID 和 revision；保存复用同一个协调模块。
3. 提交前验证 ID、UTF-8、frontmatter、空正文与现有容量上限；中文名称与正文保留。
4. 多文件导入先预览全部候选，明确同 ID 覆盖，再作为一个范围的一次提交；一项无效不部分覆盖旧库。
5. 保存成功刷新列表和详情；冲突/失败保留草稿，允许重载对比后重新保存，不静默覆盖。关闭页面有未保存正文时提供保存、放弃或继续编辑。

### 4.3 文件与数据库衔接

来源/操作记录先持久化，随后发布 MD，最后记下结果；不宣称 SQLite 与文件系统共享一笔事务。

来源记录保留唯一操作身份、范围、主题、预期版本、候选摘要和状态。重启或 `PublishedButUnsynced`/回执丢失后，核验有效发布链中的版本、内容摘要及来源；必要的核验接口复用 MemoryStore 的校验链，只查已发布版本，不采纳编号最大的未发布目录。不能证明结果时返回“无法确认，需重新核验”，禁止自动重放。

本次来源面板至少显示对应的用户原文或设置编辑事件；格式正确的 reference 不等于来源已经验证。校验条件和分支/版本证据由宿主提供，不由模型编写证明。

## 5. Norma 设置页

```text
Settings → Norma
           ├─ 记忆：读取/保存设置、范围、搜索、主题列表、详情与编辑
           └─ 语音：现有 Voice 配置、Setup、模型管理、修复入口
```

首版不新增尚无实现支撑的“与你相处 / 做梦 / 成长”导航。Norma 身份保持统一；模型/Provider 继续从同一 Norma 的语音/AI Connection 配置区域访问。

### 5.1 记忆区

- 两个明确开关：允许 Norma 使用长期记忆；允许 Norma 保存新记忆。默认开启，分别阻止对话召回与对话写入；设置页的用户查看与人工编辑仍可用。关闭保存不能被模型绕过，关闭读取须清理已注入上下文。
- 范围选择：个人、当前项目共享、当前工作树；无项目时后两者不可选并说明原因，个人区正常使用。
- 列表展示名称、描述、范围及修改信息；详情展示正文、来源和版本。内部目录、工具 JSON 默认不显示。
- 新增、编辑、导入和重载是直接操作；正文使用明确保存/取消，开关即时反馈并异步保存，保存开关失败要恢复真实状态。
- 覆盖 Loading、Empty、Ready、Editing、Saving、Saved、Conflict、Failed；旧范围的迟到结果丢弃，草稿按范围保留。

无项目时访问个人设置和个人对话不得要求创建临时项目。现有桌面/Settings 宿主路径如限制 Canvas，须调整到实际可用的宿主入口，而不是仅在独立组件测试中构造页面。

### 5.2 Voice 迁移

复用现有 `VoiceSettingsState`、输入控件、原配置键、凭据引用、模型安装和就绪检查；迁移导航与容器，不重建语音能力。

侧栏移除独立 Voice 配置入口；`open_voice_settings`、Set up Voice、不可用修复、模型管理与原定位路径统一打开 `Norma → 语音`，保留待处理项展开、滚动定位和模型状态刷新。

覆盖麦克风、ASR Provider/模型、TTS/声音、语音模式和触发方式、豆包、本地/云端、AI Provider、Setup、下载管理及试音。下载关闭 Settings 后继续，重进恢复状态；不能因为换页面清空凭据、重新下载或替换当前可用供应商。

### 5.3 设计与验收依据

参考已加载的 `apple-design`：沿用现有 Settings 的字体、主题、导航和分组；内容和状态优先，键盘可完成切换、搜索、编辑和保存；交互覆盖 hover/pressed/focus/selected/disabled。不添加无功能作用的持续动画，减少动态效果后反馈仍明确。

GPUI 实现前加载适用 `gpui-*` skills，使用钉死版本与 `ui::component`。现有原型决策若已有用户确认则复用，不重新创建重复原型票；本次简化为已确定的记忆/语音范围，不宣称已批准其余分区。真实 App 验收中核对最终布局和操作。

验证命令：`cargo test -p agent`、`cargo test -p storage`、`cargo check -p app`；改 ui 时 `cargo test -p ui`；页面改动 `cargo build -p app --release`；跨 crate 最终 `cargo test --workspace`。运行存储/性能边界、行数、禁止 allow 等适用护栏，正常提交执行 hook。

不运行已禁用的 `crates/e2e`。真实 App 使用隔离数据根、专用测试项目及可验证 Provider；单测和内部状态只能补充实际页面/对话验收。

## 10. 实施与验证记录

### 实际实现

- `agent::memory_access` 提供受控范围和四个 typed tools；`agent::master` 管理个人/项目会话、目录和回合预算，关闭读取以 recall epoch 清理历史上下文。
- `storage::memory_access` 复用 Markdown MemoryStore，提供可信目录归属、中文搜索、来源、CAS 发布及回执核验；个人偏好设置的单项修改使用事务，避免陈旧页面覆盖另一开关。
- `app::memory` 在后台执行存储操作；Rig 和桌面豆包复用范围、来源、写入授权与预算。旧主题更新必须先完整读取同一版本，普通聊天不自动发布。
- `settings::norma` 提供记忆开关、范围、中文搜索、查看、新增、编辑/纠正和原生 Markdown 文件选择。整组导入先预览，再作为一次 CAS 保存；冲突保留草稿，结果不确定时核验原操作，不重放写入。
- 无项目主页的文字输入支持 Cmd+K 聚焦、Enter 提交、等待防重复和真实回复/错误；主页推进抽屉动画，展开项目的输入仍归属项目。无需伪造项目或完成语音 Setup 才能进行文字对话。

### 设计落地

按 `apple-design` 的内容优先、直接操作与即时反馈原则，重做为 macOS 列表/详情双栏。左栏固定 235 逻辑像素，搜索、记忆列表和新增/导入各有稳定位置；右栏展示正文、用途、来源时间与版本。名称、用途、正文使用独立表单，用户无需编辑 frontmatter；保存/取消位于固定底部。

选中项、悬停、按钮按压、输入焦点和禁用范围具有反馈；使用现有主题与 `ui::component` 输入、按钮和开关。无项目时项目/工作树禁用并解释原因；未选中、无结果、加载、保存、失败与冲突均有明确内容。关闭有草稿时保留继续编辑、保存和放弃路径。

Norma 的语音分区复用原 Voice 配置与 Setup。记忆双栏使用内部滚动；语音长页面保持自然内容高度，由设置视口统一滚动。真实验收发现并修复迁移容器固定高度导致末尾配置不可访问的问题，补充真实布局与滚轮的回归测试。
