# Goal：Norma OS iOS 频道协作高保真原型

状态：**计划待审阅** · 2026-09-25  
工作分支：`codex/norma-ios-companion`  
Goal：完成「频道协作 + Norma 实时虚拟人」的可交互 iPhone 原型；保留旧版，比较三种信息架构，并验证关键流程与动效。

## 1. 本轮交付

1. 一个浏览器可运行的高保真 iPhone 原型，入口为 [`docs/prototypes/norma-realtime.html`](../prototypes/norma-realtime.html)。三种方案用 `?variant=A|B|C` 切换，底部浮动切换器和方向键可操作；切换时保留当前演示状态。
2. 一份旧版原型的原样归档，包括 HTML、检查脚本和浏览器用例；README 明确新旧入口。
3. 可点击的完整演示：建频道 → 共享上下文 → Norma 派工 / `@Agent` 回应 → Agent Card → 成果验收 → 用户归档 / 重开；频道内可启动虚拟人实时对话，转写和回执回到原频道。
4. 至少一组实际浏览器操作截图及验证记录，明确区分 HTML 模拟与原生能力。

本轮只制作**产品原型**；不修改原生 iOS、Mac Runtime、真实录音或生产数据。演示中的 Agent 回复、执行、成果和语音均为本地模拟。

## 2. 已确定的产品规则

| 场景 | 原型应表现的规则 |
| --- | --- |
| 想法 | 保存即建频道；只记录或讨论时不启动 Agent。 |
| 执行 | 用户明确表达执行意图后，Norma 在硬约束内自主关联项目、加入 Agent 并派工；普通工作范围可自行调整。 |
| 协作 | 频道可以跨多个项目；成员共享目标、硬约束、已确认决定、消息、任务状态和成果。原始文件按需取用。 |
| `@Agent` | 每次提及必须收到明确回应；空闲 Agent 可接任务，活跃 Agent 优先沿原任务续聊。Agent 间派工由 Norma 统一处理。 |
| 注意力 | 收件箱只放需要人处理的决定、失败与成果验收；普通进展留在频道和任务卡片，不主动打断。 |
| 语音 | Norma 虚拟人通话绑定当前频道；可打断、静音、看转写和延后汇报；挂断不取消任务，转写与回执回到频道。 |
| 收口 | 用户验收成果后归档频道，之后可重开。标记为硬约束的禁令不可由 Norma 自行越过。 |

## 3. 三种可比较的信息架构

| 方案 | 首屏重心 | 主要入口 | 需检验的问题 |
| --- | --- | --- | --- |
| A · 频道优先 | 频道列表与每件事的当前状态 | 点频道进入共享对话，语音作为频道动作 | 用户能否迅速回到某件事，并保持跨项目上下文？ |
| B · Norma 优先 | 大幅虚拟人与当前频道的实时状态 | 先和 Norma 说话，再下钻到频道与任务 | 陪伴感能否成立，同时不掩盖频道和待办？ |
| C · 待办优先 | 需要人决定的少量事项 | 先处理验收/阻塞，再回看频道 | 能否进一步减少注意力切换，又不让人失去全局感？ |

三种方案采用**不同的首屏层级和主操作**，而非仅换颜色。它们共享一套演示数据和业务规则，便于只比较交互设计。最终由用户选方向；本轮不把任何一个方案直接视为正式 iOS 实现。

## 4. 实施顺序

| 阶段 | 具体动作 | 完成证据 |
| --- | --- | --- |
| 0 · 保全 | 原样复制旧入口及其当前检查脚本、浏览器用例；记录散列，写归档说明。 | 归档文件可打开，源与副本散列一致。 |
| 1 · 状态模型 | 建立 `Channel`、`ChannelContext`、`Message`、`AgentTask`、`InboxItem`、`VoiceSession` 的最小演示状态；先写会失败的聚焦检查。 | 检查覆盖“保存不执行、开始后派工、`@` 回应、语音归属、验收与归档”。 |
| 2 · 三种高保真首屏 | 完成 iPhone 状态栏、导航、频道列表、虚拟人、待办首屏与 URL 切换；复用既有真实 Norma 形象参考资源。 | A/B/C 各有清晰不同的首屏和触控主路径；刷新 URL 后仍可打开指定方案。 |
| 3 · 关键页面 | 完成频道对话、共享上下文、派工回执、Agent Card、收件箱、成果验收、归档/重开及频道语音层。 | 从新想法到归档可连续点击走通；每次 `@Agent` 都有可见回应。 |

| 5 · 验收与交付 | 运行状态检查，在真实浏览器用 Computer Use 点击 A/B/C 的主要流程，留截图和问题记录；更新 README。 | 检查通过，截图可见，文档附运行命令与模拟边界。 |

## 5. Apple 交互与动效规范

依据项目的 `apple-design` 与 `emil-design-eng` 技能设计，并按 `review-animations` 审查动效：以内容层级、即时反馈、空间连续性和可中断性服务操作，不做持续吸引注意的装饰动画。与静态屏幕稿相比，原型应体现以下状态变化。

| 操作 | 动效与目的 | 无动画时的明确反馈 |
| --- | --- | --- |
| 点频道进入 / 返回 | 内容沿同一导航层级轻微位移与淡入，约 180–220ms；帮助辨认进出方向。 | 标题和返回路径立即更新。 |
| 打开共享上下文或操作抽屉 | 从底部进入，约 220–260ms，强减速曲线；遮罩可点按关闭，手势或反向操作不被锁住。 | 抽屉立即出现或关闭，焦点移入可用控件。 |
| 派工与 `@Agent` 接收 | 按钮即时压下；收到回执后任务卡片轻微强调一次，明确“送到哪位 Agent”。不使用长距离粒子特效。 | 文本回执含 Agent 名、项目和任务状态。 |
| 实时聆听 / Norma 回应 | 仅通话活跃时让波形呼吸，字幕随着演示指令更新；静音、打断与挂断即时改变状态。 | “聆听中/已静音/已结束”文字与控件状态同时更新。 |
| 待验收 → 已验收、归档 / 重开 | 状态标签与列表位置平稳更新，避免整页跳动；高频列表切换不加动画。 | 状态文案、频道位置和收件箱数量更新。 |

所有移动只使用 `transform` 与 `opacity`，单次 UI 动效不超过 300ms；按钮按下约 100–140ms。`prefers-reduced-motion` 下移除位移与循环波形，保留必要的颜色、文字和状态反馈。键盘左右键切换方案不播放页面动画，输入框聚焦时不劫持方向键。

## 6. 验收清单

- [ ] 新想法生成一个频道，显示“尚未执行”，没有任务卡片；明确开始后才出现具名 Agent 接收回执。
- [ ] 同一频道关联 iOS App 与 Norma API，并可查看共享目标、来源、决定、硬约束、任务与成果；别的频道不混入消息。
- [ ] 在频道输入 `@Codex`、`@Design` 或 `@Norma` 均有回应；活跃任务续聊不复制任务。
- [ ] Norma 语音从当前频道进入；模拟转写、Agent 回执、挂断后记录均回到该频道，任务继续存在。
- [ ] 收件箱只展示决定、失败与待验收；成果有证据、退回修改与验收入口，未验收不得误显示完成。
- [ ] 用户可归档已收口频道并重开；三种方案的 URL、底部切换器和键盘切换可用。
- [ ] 浏览器实际检查手机窄屏、桌面预览、至少 44pt 的主触控目标、可见焦点、减少动态效果；记录任何未通过项。
