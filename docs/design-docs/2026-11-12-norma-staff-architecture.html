Norma 幕僚架构

Norma 是幕僚：你开一个会话就是一个任务，任务派出多张智能体卡片（Worker）去做。下面六节依次回答：放在哪一层、数据怎么组织、怎么分派、状态怎么变、事件往哪走，以及对现有汇报的影响。

现有部分本方案新增或扩展

1　整体分层：幕僚就是 brain，新增的是任务和会话池

幕僚不是新组件，是现有的 brain。它继续不依赖 GPUI 和存储，只通过 norma CLI 行动；App 通过现有的 brain_host 订阅任务快照。

2　数据结构：任务下挂 Worker，Worker 绑定卡片和引擎会话

任务是唯一的归属单位。Worker 记着两样东西：现在对应哪张卡片，以及引擎那边的会话号。卡片被回收后 card_id 清空，会话号保留，之后就能接着原来的会话继续。

3　分派流程：先提议，你确认后才派

幕僚拆解后给出提议，沿用现有的 Proposal 机制。你点「采用」才会创建或唤起卡片，画布上不会凭空出现卡片。

4　状态：任务阶段由 Norma 推进，你可以改

列表里的「需要你 / 处理中 / 等待中」由存活 Worker 推出来，「待合并 / 已完成」是任务阶段。已回收的 Worker 不参与判断。

5　事件路由：每个任务只收到自己的事件

宿主先反查归属，再核对 dispatch_id：不一致的迟到事件只留历史。事件先落盘再唤醒，会话忙就排队，会话已回收则先重建，所以事件不会丢。

6　与现有汇报的关系：分流规则不动，任务会话不播报

现有汇报按工作空间统一做：Router 去抖、静默池、定时摘要，由主会话播报。任务会话只负责各自任务里的对话，汇报、摘要和语音仍由主会话完成。事件先落盘，只有需要立即汇报，或你正打开这个任务时，才唤醒任务会话。

环节现有行为本方案的调整
事件分流Router 去抖，triage 判断立即汇报或静默不改；分流在分发给任务之前完成
静默池普通成功攒满窗口再让大脑扫一遍静默事件只写入 Task.messages，不唤醒任务会话
播报主会话按语音模式播报仍只有主会话播报；任务会话不出声，避免重复
摘要与回来时概览覆盖本工作空间所有 Agent改为读取各任务摘要：标题、阶段、需要你的 Worker
目标摘要最近 5 条 Goal 随主会话提示发送由任务摘要取代，迁移时旧 Goal 转成单 Worker 任务
失败立即汇报不变；任务页同时显示「需要你」
中断 Interruptedtriage 判为静默任务页显示「需要你」；语音保持静默（已决定）

7　MVP 拆分：先跑通一条主线

主线：建任务 → 提议 → 采用 → Worker 执行 → 结果回到任务对话 → 你验收。

降级方案（已决定）

  • 「一任务一会话」验证不过时，复用主会话，并按任务重放 Task.messages。

已确定

  • 幕僚就是 brain，新增 Task / Worker，取代 Goal
  • 每个任务一条独立 ACP 会话，消息以 Task 为准
  • 卡片只带 dispatch_id；宿主用 node_id 反查任务与工作空间
  • 事件先落盘再唤醒，串行处理；失败生成终态消息转人工；重启先对账
  • 先提议、确认后再派；Worker 不建依赖字段
  • 存量卡片进「未归属卡片」，手动归入任务

实现前要核对

  • 三种适配器对一任务一会话的支持
  • 各引擎 CLI 能否按会话号恢复
  • 热会话数量上限与回收策略
  • 冷会话重放的成本，是否需要摘要
  • Norma 自动推进阶段的误判处理（M1 即自动推进，需保护「用户改过不覆盖」）
