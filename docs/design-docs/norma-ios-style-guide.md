# Norma OS iOS 样式规范

状态：iOS 原生界面的目标样式规范；不表示现有 App 已完成还原。  
适用：`ios/App/` 的页面、组件、图标、动效与视觉验收；不覆盖 macOS 画布样式。  
基线：[W01–W09 原型](../product-specs/norma-ios-prototypes-2026-09-26/生成提示词.md)及 [逐屏还原与验收](../product-specs/2026-09-28-norma-ios-prototype-fidelity-acceptance.md)。
视觉速览：[HTML 版](norma-ios-style-guide.html)。若两者内容冲突，以本文为准。

外部方法参考：`/Users/alan/Documents/codes/yakami0129/multisoul/mobile/docs/design.md` 与同目录的 `design.html`。本文借鉴其从设计原则、语义色、排版、间距、材质、组件、动效到验收的组织方法。**MultiSoul 的品牌色、字体、暗色控制台和产品组件不属于 Norma iOS。** Norma 的品牌身份以[品牌视觉规范](../brand/norma-os-brand-guidelines.md)为准。

## 1. 范围与优先级

1. **样式**：以 W 系列的浅色 iOS、近白卡片、深蓝文字、蓝色主操作、薄荷与少量粉黄为基线；P 系列延续相同视觉语言。[P03 工作空间](../product-specs/norma-ios-ideas-workspaces-2026-09-28/P03-workspaces-drawer.png)与 [P05 工作线程](../product-specs/norma-ios-ideas-workspaces-2026-09-28/P05-work-thread.png)是对应首页和线程的主构图，W01/W04 补充搜索、筛选、对话及卡片状态。
2. **产品结构与文案**：以[逐屏验收文件](../product-specs/2026-09-28-norma-ios-prototype-fidelity-acceptance.md)和现行产品规格为准。W 图中“想法即工作空间”、Workspace“硬约束”、Norma 私聊默认进入 Workspace 等旧设定只保留视觉参考；不得写回新页面。
3. **角色身份**：W07 的人物大小、字幕与控件布局可参考；Norma 本人的发色、X 发夹、蝴蝶结与服装以品牌规范及获批素材为准，不把 W07 的黑发形象定为角色标准。
4. **平台**：用 iOS 原生导航、输入、Sheet、安全区和辅助功能。项目最低 iOS 17；可用新版系统玻璃效果时采用系统 API，旧系统采用系统材质，具体 API 以所用 SDK 核实。

## 2. 设计原则

- **先看懂内容，再看到品牌**：按 2026-09-29 用户确认，冷启动先显示 P01 想法库；工作空间从底部导航进入，角色在 Norma 单聊主屏成为主视觉。
- **颜色解释状态**：蓝色提示可操作或当前选中；薄荷/绿色表示在线、运行或完成，必须同时配文字或图标区分；粉色提示需要决定；黄色提示限制或风险。
- **内容用实底，功能层用玻璃**：长消息、任务、证据、终端和成果卡保持稳定对比；导航、悬浮输入、底栏和 Sheet 可用克制的系统材质。
- **一次突出一个行动**：同屏至多一个最强主操作；次操作有清晰位置和文本，危险操作有明确后果。
- **直接、可逆、可追溯**：Sheet 跟手、页面返回保持位置与草稿；任务状态、接管权和验收结果始终可见。

## 3. 颜色与状态

下表为**设计实现起点**，依据原型观感设定，并非从生成图中精确取样。原型的抗锯齿、光照与设备外壳不可当作色值。实现时集中管理语义 token，并用真机截图、对比度检查校准。

| Token | 基准值 | 用途 |
| --- | --- | --- |
| `ios.canvas` | `#F8FAFC` | 页面背景，略暖的浅灰白 |
| `ios.card` | `#FFFFFF` | 消息、列表、简报、证据等阅读面 |
| `ios.control` | `#EEF2F7` | 搜索、筛选、次级控件底 |
| `ios.ink` | `#13213D` | 标题、正文和主要图标 |
| `ios.muted` | `#566783` | 次级说明、时间与项目归属 |
| `ios.line` | `#E5EBF3` | 轻描边和组内分隔 |
| `ios.action` | `#2468F2` | 主按钮、选中项、链接与焦点 |
| `ios.actionSoft` | `#E8F0FF` | 蓝色状态底、项目标签 |
| `ios.positive` | `#008F61` | 在线、成功、已完成的前景色 |
| `ios.positiveSoft` | `#DFF8EC` | 薄荷状态底 |
| `ios.attention` | `#C52C60` | 需人决定、待处理的前景色 |
| `ios.attentionSoft` | `#FCE8EF` | 粉色提醒底 |
| `ios.caution` | `#9A5B00` | 限制、警告和待核对的前景色 |
| `ios.cautionSoft` | `#FFF2D5` | 淡黄提示底 |
| `ios.terminal` | `#07152D` | 仅终端内容区的深底 |

- 蓝色是**操作语义**，不要把所有非蓝状态都画成蓝色。运行、完成等细分状态必须有文字；颜色不得是唯一线索。
- 粉色用于“需要处理”，真正的失败、删除与终止另用系统破坏性语义和明确文案，不把粉色等同于删除。
- 少量黄、粉、薄荷色可以出现在插画或预览装饰中；不要占据正文卡、连续消息或整页背景。
- 当前原型只定义浅色目标。若支持深色外观，须单独定义深色语义色并验收；不能机械反相。

## 4. 字体与信息层级

使用 iOS 系统字体及中文系统回退；终端与命令使用系统等宽字体。以下 pt 为默认文字大小下的**视觉目标**，实现优先采用 Dynamic Type 文本样式，随用户字号扩展行高与容器。

| 层级 | 默认目标 | 典型位置 |
| --- | --- | --- |
| 一级大标题 | 34 pt / bold | 工作空间、收件箱、Norma |
| 详情主标题 | 26–28 pt / bold | 任务、目标、验收结果 |
| 卡片标题 | 18–20 pt / semibold | 工作空间、电脑、收件箱事项 |
| 正文与消息 | 16–17 pt / regular | 对话、简报、说明 |
| 次级信息 | 14–15 pt / regular | 项目、来源、摘要 |
| 时间与短标签 | 12–13 pt / medium | 时间戳、状态 chip |
| 终端 | 12–14 pt / monospaced | 命令及输出，可按用户设置缩放 |

- 标题靠字重、大小和留白建立层级，不靠大写英文或持续渐变。中文正文以可读行高为先；长内容左对齐。
- 辅助文字仍须可读；不要用淡灰承载限制、错误、证据或唯一操作提示。
- 大字号下允许卡片增高、标签换行；关键信息不强制单行截断，不限制用户的 Dynamic Type 上限。

## 5. 间距、形状与材质

| 元素 | 起始规格 | 依据 |
| --- | --- | --- |
| 页面水平安全边距 | 20 pt；窄屏可降至 16 pt | W01/W08 的宽松列表边界 |
| 间距阶梯 | 4、8、12、16、24、32 pt | 统一文本组、卡片组与页面分区 |
| 标准卡片 | 18–24 pt 圆角，16–20 pt 内边距 | W01/W02/W08 的近白卡片 |
| 搜索与输入 | 胶囊或约 20–26 pt 圆角 | W01/W04 的低对比输入槽 |
| 状态 chip | 胶囊，色底加文字/图标 | W01/W06/W08 |
| Sheet | 顶部约 28–32 pt 圆角，系统拖动指示器 | W03 的项目选择层 |
| 主按钮 | 高度至少 44 pt；优先约 48–52 pt | W02/W05/W09 的底部操作 |
| 图标触控区 | 至少 44×44 pt | 返回、更多、搜索、静音 |

- 同一页面的卡片尽量共用半径和左右对齐；子项目优先用分隔线与行距，不无意义地嵌套卡片。
- 卡片用细线或低不透明阴影与背景分层；不要靠强光晕表达可点性。选中、按下、禁用和加载要各有明确反馈。
- 系统玻璃只承载**功能层**。减少透明度开启时改为更实的系统材质或不透明面，保证文字对比；正文阅读面始终稳定。
- 状态栏、Home Indicator、键盘和设备边框由系统负责；原型中的 iPhone 外壳与 9:41 是展示框架，不绘入 App。

## 6. 页面与组件

| 组件或页面 | 样式规则 | 参考 |
| --- | --- | --- |
| 底部导航 | 三个等权入口「工作空间／Norma／收件箱」；浅色悬浮功能层，选中用蓝色文字/图标，未读数只计需人处理项；详情页可按导航层级隐藏 | W01、W07、W08 |
| 工作空间卡 | 状态先于标题；项目标签、最近进展、参与者分层排布；整卡可点，筛选有明显选中态 | W01、P03 |
| 电脑与项目行 | 电脑在线/离线、最后同步、其下项目清楚成组；离线项目保持可读但操作禁用，并说明原因 | W02、W03 |
| 项目选择 Sheet | 背景遮罩、顶部标题/完成、按电脑分组、独立勾选态；高度随内容与键盘调整，关闭保留未提交上下文 | W03 |
| 工作线程 | 标题和状态固定清晰，简报/目标入口在消息前；用户蓝色消息、Norma 近白消息；具名回执与任务卡属于时间线，输入栏避让键盘 | W04、P05 |
| 简报与任务 | 目标用较大字；项目、决定、来源、进展时间线和证据分区；过时的“硬约束”卡用真实工作要求或状态替换 | W05、W06 |
| 终端接管 | 页面外壳保持浅色，终端内容单独深底、等宽字；输入权归属、当前电脑/项目和交还入口持续可见；功能键在系统键盘上方 | W06a |
| Norma 通话 | 角色作为主视觉，实时字幕优先于波形装饰；当前上下文、听/说/静音状态、结束与文字入口一眼可辨 | W07 |
| 收件箱 | 仅需决定、失败或待验收的事项；大标题、状态 chip、来源、原因/建议、下一步操作形成固定扫描顺序 | W08 |
| 成果验收 | 真实预览、结论、可打开的证据、退回/通过双操作；操作后同步更新线程和收件箱 | W09 |

图标优先使用 SF Symbols 的统一线宽与填充规则；Agent 和项目身份使用获批资产。Norma 头像保持固定识别特征，不用 emoji 或随机头像替代。

## 7. 交互与动效

- 列表进入详情、返回与 Sheet 关闭保持同一空间关系；拖动跟手，松手后从当前可见位置继续，转场可被中途打断。
- 触按立即给视觉反馈；选择、接收、交还终端、验收等动作完成后更新文字状态。加载期间显示进度，并防止重复提交。
- 普通状态变化用约 0.2–0.35 秒的短过渡；角色呼吸和说话反馈只在通话中使用，不给静态卡片持续脉冲。
- 开启“减少动态效果”时改为短淡入与静态状态；开启“减少透明度”时提高功能层实度。声音与触觉反馈只服务有意义的接收、完成或错误事件。
