## A 用户要得到什么

```callout info 实时说话，就能创建智能体卡片并操作项目
使用 GPT-Live 实时对话，语音提出请求后，画布实际发生对应操作，GPT 根据真实结果回复。对话保持连接，后续可以继续下发任务、查询状态和插话。
```

| 用户动作 | 必须出现的结果 |
| --- | --- |
| 说“帮我创建一个 Codex 智能体卡片” | 当前项目出现一张正确类型的卡片，返回真实 node ID |
| 继续向该智能体下发任务 | 任务进入项目原有任务系统，回传真实接收状态 |
| 询问卡片或任务状态 | 读取项目实际状态，再通过语音回答 |
| 一边执行一边继续对话 | 音频收发继续；工具执行放在后台 |
| 更正、取消或重新连接 | 未提交请求能撤销；已执行操作可核对，避免重复创建 |

整个过程保持 GPT-Live 对话，工具操作直接在语音流程内完成。支持实时对话，也支持用户选择按住 Cmd+E 说话。

本次只整改 GPT-Live。豆包的代码、配置、交互、模型策略和运行流程均保持原样；它用于参考可用实现和验收效果。

## D GPT-Live 自己完成对话和工具调用

语音主流程：

```flow LR
GPT输入控制 -> GPTLive双工会话
GPTLive双工会话 -> GPT音频播放
```

项目工具分支：

```flow LR
Live委派通知 -> LiveBridge本地调度
LiveBridge本地调度 -> NormaSession工具规划
NormaSession工具规划 -> 现有项目工具
现有项目工具 -> 本次请求的真实回执
```

真实回执回传给发起委派的 GPT-Live 会话，再由 Live 语音告知用户。语音会话与工具分支异步推进，工具后台不会接管音频收发。

| 名称 | 实际含义 | 创建卡片时做什么 |
| --- | --- | --- |
| Live 委派 | Live 发给应用的处理通知 | 表示需要应用处理一项请求；通知本身不是完整的工具参数 |
| LiveBridge | GPT 路径中的本地 Rust 调度代码 | 关联原话、上下文和请求版本，排队并取消过期规划 |
| NormaSession | 可复用的工具会话引擎 | 调用所配置的文字模型，选择工具并组织参数 |
| 项目工具 / App Adapter | 现有项目操作入口 | 校验权限并实际创建卡片，返回 node ID 和真实状态 |

LiveBridge 本身不调用模型。NormaSession 是代码类型，其内部会调用后台模型；用户无需另外创建一个名叫 Norma 的智能体卡片。

当前 GPT 分支已经创建独立的 NormaSession 实例。整改沿用该隔离方式，由 GPT 路径负责配置、输入控制、提示词和调度。

系统提示词接入已实施，内容来源与生效时机如下：

| 提示词内容 | 当前 Live 语音侧 | 当前工具后台 |
| --- | --- | --- |
| 设置中已保存的人格与交流补充说明 | 建立通话时读取，并发送到 `session.start.instructions` | 处理委派时通过 MemoryAdapter 重新读取 |
| 普通 Norma 的完整系统提示词 | 已复用公共系统提示词生成函数，包含固定身份、完整工具规则与启动时项目环境 | 使用公共身份、工具规则和当前项目环境 |
| 固定记忆操作规则 | 已复用与 NormaSession 相同的规则常量，包含写入授权、合并和真实保存回执要求 | 继续使用原规则，文字保持一致 |
| 通话期间保存的新偏好 | 未接自动同步；结束后重连才重新读取 | 后续委派可以读取新值 |

整改前的本地回放确认：用户补充说明进入了启动消息，公共 Master 身份及项目环境缺失。新增回归测试先在固定身份断言处失败，接入完整系统提示词后通过。测试使用隔离设置库和真实 Live 启动消息序列化，不代表云端人格效果已验收。

本次实现：GPT 语音使用完整公共系统提示词、已保存的人格与固定记忆规则，并追加 Live 委派规则。环境及会话尾部明确标为启动快照，当前状态必须委派后台只读核验。通话内保存偏好尚未自动同步，需要重新连接读取新值。

源码依据：`app/gpt_live/prompt.rs`、`app/gpt_live/startup.rs`、`agent/master_prompt.rs`、`agent/master/memory_session.rs`。固定记忆规则仅提取为共享常量，原有后台提示词内容保持逐字节一致。

提示词接入验证：App 原生三项测试及生产 Release 编译检查通过；Agent 回归 114 项通过，1 项按既有标记跳过。详见[接入验收记录](../quality/2026-10-18-gpt-live-persona-acceptance.md)。

## F 配置只保留四项

选中 GPT-Live 后，只显示以下选择。其他服务的设置保持现状。

```tree
GPT-Live 设置
  OpenAI API Key | 唯一必填的服务凭据
  交互方式 | 实时对话 / 按住 Cmd+E 说话
  麦克风 | 默认跟随系统，可选其他设备
  音色 | Marin / Cedar，提供默认值
```

| 截图中的项目 | 原来为什么提出 | 修订后的处理 |
| --- | --- | --- |
| 语音状态 | 告知是否连接成功 | 放在当前操作附近显示，由程序更新 |
| 项目工具状态 | 防止“能聊天”被误认为“已能创建卡片” | 成功时简洁反馈；失败时显示具体原因与重试 |
| 工具后台 | 当前 Client 委派接入需要规划器处理工具请求 | 使用内置默认值，取消本轮的模型、地址和凭据覆写入口 |
| 空闲结束 | 原本用于控制 Live 保持连接时的用量 | 取消本轮配置项及 30 秒自动结束建议，使用明确的开始/结束控制 |
| 诊断 | 用来定位失败环节 | 失败时提供脱敏详情，不作为独立配置组 |

状态无需用户填写，也不要求用户手工准备工具。保存 Key 后即可连接。连接时，程序在后台自动准备 GPT 独立的语音检测文件。首次工具调用才验证账户的工具模型权限。未打开项目时，委派会明确提示先打开项目。

内部默认：语音使用 `gpt-live-1`，工具规划使用 `gpt-5.4-mini`，两者复用 GPT 的 OpenAI 凭据引用。两个模型各自计量。保存 Key 不发模型请求；工具调用时才使用工具模型。

VAD 自动后台准备，使用 GPT 独立目录。准备失败时显示原因，结束后重连会重试。工具调用失败时提示检查 OpenAI Key 的模型权限或网络。

已有 Live Key 保留。原有全局 Norma 模型设置保留；GPT 不读取这些设置，也不会把 Live Key 发给自定义地址。GPT 交互方式独立保存，新用户默认实时对话；不改豆包偏好、全局 Norma 模型或卡片模型。

按 Apple Design 使用清晰分组、系统字体和就地反馈。已移除的悬浮转写框保持移除。

## G GPT 实时交互怎样验收

| 动作 | GPT 实时对话 | GPT 按住说话 |
| --- | --- | --- |
| Cmd+E | 开始或结束 Live 对话 | 会话就绪后按住输入真实声音 |
| 松开 E 或 Cmd | 保持实时对话 | 收口本次输入，保持连接等待回复 |
| 工具执行中 | 双工音频继续，可继续对话 | 继续接收回复，可开始下一次输入 |
| 用户主动静音 | 保持静音 | 按键不覆盖静音选择 |
| 失去焦点 | 保持明确的通话状态及结束入口 | 收口本次按住输入，避免持续误收音 |
| 冷启动未完成就松键 | 不适用 | 撤销本次输入；迟到回调不得开启麦克风 |

工具执行前重验项目、会话代次、原话授权和最新版本。按住模式需确认本次输入已释放；实时模式结合说话状态及转写版本判断。松键和 ACK 都不代表转写已经完整。

GPT 松键后继续发送协议要求的静音帧，不上传按键区间外的真实麦克风声音。松键只结束本次输入，已建立的会话保持到显式结束。已采尾音排空，并确认 transport 完成发送后，才恢复工具调度。此确认不是云端转写完成证明。

首版不新增空闲倒计时或自动挂断设置。对话入口持续显示连接状态和结束操作；静音及等待期间仍可能产生 Live 用量。

VAD 失败时聊天仍可继续，Live 委派的项目工具暂停，并显示重连重试提示。设置中的操作核对仍可只读查看本地回执。

切换服务沿用现有入口。GPT 的迟到回调按原会话身份处理，不得改变新会话状态。

| 顺序 | 验收项 | 必须得到的证据 |

| 5 | 并行对话与更正 | 工具执行时音频继续；更正、取消、挂断及未知结果处理正确 |

源码范围以 GPT 接入为准。豆包用于核对体验和兼容性，验收不以改造豆包为前提。
