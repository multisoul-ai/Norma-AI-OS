已实施“设置 → 对话模式 → 语音指令”的分组列表。 单次入口采用统一候选，保留现有 ASR 与 TTS 接口。 原准确率实验 Goal 保持暂停，Jev 生产禁用。

对象 已核实的事实 本次设计

Jev 不能凭错误文字还原丢失的声音证据。 它也不能证明某个合法名字就是用户所指。 现有浏览器 skill 不应直接嵌入 App 运行时。

识别来源统一为“本地”

用户认可总体方向，并提出合并两个本地选项。 截图中的“本机”对应 LocalSherpa。 “本地精准”对应 LocalA1；两者都在本机处理。 建议来源只区分“本地”和“云端”。

用户看到什么 内部怎样处理
本地识别 保留兼容引擎与 A1，由本地策略管理
本地识别已就绪、准备中或不可用 显示可用状态，不要求用户理解引擎名称
单次语音指令 A1 通过真实验收后，可作为优先链路
持续聆听 使用已支持该模式的本地引擎；当前不能选 A1
高级诊断 可查看当前实际引擎、模型与失败原因

A1 已包含预览和终稿两个内部角色。 用户不需要为这两个角色各选一次来源。 合并入口不等于立即删除兼容引擎。 首轮迁移保留当前已选本地引擎，不擅自切换。

引擎在录音开始前完成选择，并绑定本次录音。 若 A1 失败，不能将预览文字当终稿派发。 重试须得到同一录音的有效终稿，或要求重录。

资源不足只影响本地可用性，不自动切换云端。 实现时迁移旧配置，并验收中英文状态与模式兼容。 生产设置已采用分组列表；完整验收见实施计划 H 节。

Jev 启用有两个待验证条件

当前核实的是外部 API 接法，本机部署能力尚未确认。 保留此前本机处理约束，不发送录音或真人转写。 Jev 终稿后推理也不能承诺 T_route 小于 5 ms。 默认保留接口与旁路设计，不启用线上决策。

B

目标架构：两种理解来源，一个提交者

这是目标架构，虚线表示默认未启用的 Jev 分支。 预览只负责反馈，不产生任务副作用。 模型只提供提议，不持有派发权。 应用提供名单、当前项目和会话快照。 ASR 不读取 Storage，也不负责选择执行对象。

宿主在同一请求下只接受一个有效提交。 规则、Jev 和主模型均不能各自执行一遍。

C

Jev 选择什么：动作、画布目标与完整方案

当前尚未接入 Jev

以下是人工编写的设计示例，不是准确率结果。 纯文本契约探针已完成，生产选择分支未接入。

官方 Choice 可从给定选项中选择一个答案。 建议让它选择完整候选方案。 动作、目标、正文引用和约束必须属于同一方案。 不把各字段的独立选择随意拼成一条命令。

新增显式职责：这句话交给画布上的谁

目标解析必须单独呈现，不能藏在动作分类里。 同一轮判断动作与目标，不新增串行模型调用。 Bruno 和 Henry 只是示例，选项来自当前画布。

目标候选 含义 处理方式
画布上的 Bruno 指向当前项目中的具体 Agent 卡片 关联稳定节点与现有会话
画布上的 Henry 指向另一张 Agent 卡片 不因提到 Bruno 就改选 Bruno
Norma 自己 用户希望当前助手回答或处理 普通回答不派发给画布成员
其他已知成员 名册中存在，但当前画布没有对应卡片 检查明确的创建授权，或澄清
其他类型的卡片 终端、浏览器或预览对象 交支持该动作的主路径，不当作 Agent
尚不确定 未点名、重名、音近或指代不足 保留正文，只补问目标

“其他已知成员”与“不知道是谁”必须分开。 多人指令首版交主模型，不强行选其中一个。

用户说什么 目标判断 动作或限制
Bruno，继续刚才的登录任务 Bruno 的唯一现有任务 回复；不能新建替代
Henry，帮我检查 Bruno 写的方案 执行者是 Henry；Bruno 是被提及者 复杂角色关系交主模型
你帮我解释一下这段代码 Norma 自己 回答，不派工
让 Alice 来做，但 Alice 不在画布 其他已知成员或未知名称 不拿在场成员替代
继续刚才那个，且没有可靠上下文 尚不确定 问 Bruno 还是 Henry

应用提供节点、成员、别名、会话和画布版本快照。 执行对象使用项目与节点身份，不能只保存显示名。 同名多卡片时保留多个候选，不取第一个命中。 被选中卡片只提供上下文，不能替代用户点名。

目标目录不能把裁剪后的画布摘要当完整名册。 候选超限或覆盖不足时退出快速路径。 提交前重新核验卡片存在、作用域及当前会话。

例 1：明确的新建任务

给 Daisy 新建一个任务，检查登录报错。

程序提供当前项目、成员名单和合法候选。 本例假设 Daisy 精确匹配且在作用域中唯一。

候选 程序定义的含义 能否直接执行
PLAN_0 给 Daisy 新建任务；正文引用“检查登录报错” 通过宿主校验后可以
CLARIFY 目标或任务指代不唯一 不执行，只补问
MAIN_MODEL 候选无法表达完整语义 沿用主模型结果
NO_TASK 普通讨论、提及或解释词义 不产生任务

Jev 的期望输出是选择 PLAN_0。 宿主查验 ID 和版本后，再调用新建任务工具。 正文来自原文，Jev 不生成改写后的任务内容。

例 2：点名查询，不给对方追加工作

Daisy 那边修登录的任务做完了吗？

若唯一现有任务可定位，程序可提供查询候选。 Jev 的期望选择是“查询该任务状态”。 宿主读取真实状态，再反馈给用户。 不把这句话作为新任务或会话回复发给 Daisy。 若查询候选无法表达问题，就交主模型回答。

例 3：复杂话术退出快速路径

原话 首版处理 Jev 的权限
Daisy，解释一下“新任务”是什么意思 检测到引用，交主模型解释 不创建任务
Daisy，不要新建，继续刚才的方案 检测到否定，交主模型提议 可旁路比较，不直接提交
不是 Alan，是 Daisy，继续刚才的任务 检测到更正，交主模型提议 不能让旧候选继续执行
名字听成“戴西”，无法唯一确定成员 保留正文，只问目标 高 confidence 不能替用户认定

上表的复杂请求首版可以直接绕过 Jev。 退出快速路径由宿主策略控制。 不能把这些例子描述成 Jev 已经解决的识别问题。

程序与 Jev 各自负责什么

程序只生成有原文依据的候选。 若明确禁止新建，不生成新建任务候选。 若无法可靠提取正文或约束，直接走主模型。 候选数量受配置上限约束；超限时退出快速路径。

首版快速路径只覆盖简单、单目标、明确动作。 检测到否定、更正、引用、转述或多目标时走主模型。 允许候选集以后扩展，不代表首版立即扩大执行范围。

Choice 返回概率分布和 confidence。 宿主验证候选 ID、完整分布与模型版本。 confidence 是分布统计量，不是本产品实测正确率。 阈值必须用业务样本校准，不能套用文档示例值。 名字仅有音近依据时，高 confidence 也不能绕过澄清。

Jev 提供语义选择，程序决定是否合法及是否执行。 是否优于现有规则或主模型，仍需后续比较。 Jev 不转写音频，不执行编码任务，也不负责 TTS。

D

统一候选保留什么：原话、语义与更正关系

信息 作用
原始终稿、来源、交互模式、录音标识 保留识别证据，不覆盖原文
名称与别名命中、歧义标记 区分精确匹配和音近猜测
动作 新建、回复、查询、取消、讨论或未确定
实体角色与稳定 ID 区分执行者、被提及者和任务对象
正文引用与约束 保留用户内容、否定、禁止新建和作用域
request_id 与 revision 澄清沿用请求，更正递增版本
项目、会话和 generation 阻止切换后的迟到结果生效
operation_id 与真实回执 复用既有执行身份，防止重复派发

识别层可以规范化确定别名，音近匹配只提供候选。 正文采用原文引用，不让 Jev 自由生成任务内容。 若用文本区间引用，宿主验证范围和 UTF-8 边界。 模型生成的摘要不能替代用户原话中的限制。

澄清状态保存在宿主的待处理请求中。 用户下一次只说“Alan”，可补齐同一请求的目标。 新录音有新录音标识，逻辑请求保留原 request_id。 作用域切换、过期或明确的新请求使旧草稿失效。 不根据消息到达先后，猜测它属于哪次录音。

提交前重查目标、会话、约束、权限和最新版本。 新建与回复必须保持不同动作。 禁止把“无法续聊”静默降级为“新建任务”。 已提交后收到更正，要按真实状态请求取消或补偿。 停止播报不代表业务任务已经取消。

时延安排：先旁路，再按证据启用加速

阶段 路径 模型调用与执行权
默认落地 严格规则或现有主模型 → 统一候选 → 提交 不增加串行模型调用
影子核验 在部署条件允许后，并行比较 Jev 与主路径 Jev 无提交权；本轮未运行
可选加速 主模型和 Jev 并行生成候选 仅宿主能选择并提交一次

可选加速不先等待 Jev，再启动主模型。 两路均只提议，不允许推测性工具写操作。 Jev 超时、错误或证据不足时，主路径继续推进。 主路径结果就绪，不等待 Jev 附加确认。

Jev 先命中时，仍需通过快速路径准入和宿主校验。 提交成功后取消另一路，并丢弃其迟到结果。 若本机资源不够并行，关闭 Jev，不拖慢主路径。

指标 沿用或新增的口径 约束与状态
T_final Finish → Qwen 终稿 保留不超过基线 1.1 倍的门槛；未实测
T_route 终稿 → 工具参数确定 包含 Jev、主模型和等待时间
直接路由 单独报告 direct 分组的 T_route 原文直接路径门槛为 p95 < 5 ms
模型路由 单独报告 model 分组的 T_route 不伪装为 direct，也不省略模型耗时
提交时延 Finish → 宿主接受派发 新增端到端指标，不代替原口径
路由错派 目标、动作和约束导致的错误执行 验收样本要求为 0；不是全局零错误证明
模型决策与 5 ms 门槛存在冲突

终稿后调用 Jev，不能承诺 T_route p95 小于 5 ms。 若该门槛适用于全部请求，Jev 只能保留为旁路。 现有主模型兜底同样需要报告真实耗时。 可选加速必须另有适用路径的预算与实测证据。

顺序 交付 先写的失败测试与验收

2 Voice 单一提交与待澄清状态 迟到版本、重复提交、跨项目、续聊禁止新建

修改 agent 后运行 cargo test -p agent。 修改 app 后运行 cargo check -p app。 真实单次流程核验最终目标、动作与任务回执。 新增用户提示须走 i18n 并做双语验收。 只有实际改变产品页面时，补定向 desktop-e2e。
