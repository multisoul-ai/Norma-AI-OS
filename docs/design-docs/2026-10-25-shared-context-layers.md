五类信息是来源，四层规则决定何时加载。语音和幕僚共享事实，各自取用当前需要的部分。

## A 哪些固定，哪些按需

```callout info 建议采用：稳定底座 + 小型当前状态 + 按需片段 + 原文查询
固定的是信息槽位。动态槽位只保留最新值，不把每次更新追加成一段历史。
```

| 层级 | 放什么 | 何时带入 | 控制体积的方法 |
| --- | --- | --- | --- |
| L0 稳定底座 | 职责、边界、精简个性、工具协议、补读规则 | 始终有效；配置变化时更新 | 稳定前缀；语音会话初始化时注入 |
| L1 当前状态 | 当前项目与焦点、当前话题、相关目标约束、最近汇报引用、待回应事项 | 每轮使用最新小快照 | 固定字段；只留与当前话题有关的摘要 |
| L2 相关片段 | 相关记忆、任务结果、决策摘要、较早对话 | 当前问题或关联事件命中时 | 按任务和话题选择；去重后限额 |
| L3 原文与证据 | 完整对话、决策依据、执行回执、文档内容 | 摘要不足，或用户追问详情时 | 工具定向读取；分页和返回长度限制 |

当前用户输入必须保留。当前通话的近期消息使用模型原生对话机制，不再复制进系统提示。

对无状态接口，每轮请求仍需携带底座。对有状态实时接口，优先初始化一次，再更新变化部分。

## B 你的五块信息分别放在哪层

| 信息来源 | 固定保留的最小内容 | 按需补充的内容 |
| --- | --- | --- |
| 系统提示与个性 | L0：Norma 是谁、如何协作、表达偏好、工具规则 | 只在设置变化时替换 |
| 环境与智能体卡片 | L1：工作空间、项目、焦点卡片引用、相关 Agent 状态 | L2：相关卡片详情；L3：完整卡片清单与会话 |
| 统一对话历史 | 原生近期消息；L1：当前话题与最近汇报引用 | L2：相关旧轮次；L3：更早原文 |
| 长期记忆 | L0：如何读取记忆、召回是否启用 | L2：与本轮相关的条目；L3：条目正文 |
| 幕僚决策记录 | L1：当前相关决策的引用与状态 | L2：结论、简要理由、关联任务；L3：证据 |
| 当前工作状态 | L1：当前目标、有效约束、相关阻塞和待回应项 | L2：任务进展与结果；L3：执行回执和产物 |

系统、环境与卡片仍属于你提出的第一大块。表中分开列出，因为它们的更新频率不同。

```callout warn 两类内容需要明确边界
临时约束如“这次先别发布”归当前状态。长期偏好如“回复简短”归个性或长期记忆。

决策记录保存结论、简要理由和证据引用。调试轨迹不作为固定语音上下文。
```

## C 四种场景，实际带什么

以下均为说明方案的虚构场景，不代表当前任务状态。

| 用户说的话 | 已有内容 | 自动补入 L2 | 何时读取 L3 |
| --- | --- | --- | --- |
| “今天有点累” | L0 + 近期对话；L1 不展开项目细节 | 无需项目内容 | 通常无需读取 |
| “刚才为什么拒绝了？” | 最近汇报指向决策 D17 | D17 的结论、理由、关联任务 | 理由不完整时读取该审批与回执 |
| “按第二个方案继续” | 最近一组选项的引用、当前约束 | 那组选项及用户选择 | 缺少明确目标时补读原话，仍不明确则澄清 |
| “上次定的接口规范是什么？” | 当前项目身份 | 项目记忆中的相关规范 | 读取规范正文与来源 |

“现在所有 Agent 做到哪了”才需要整体任务快照。普通闲聊无需带上全部 Agent 对话。

跨来源出现同一条汇报时，只保留一份正文。历史、决策和任务通过引用关联。

```text title="本轮上下文示意 · 非实现代码"
稳定底座：Norma 职责 / 个性 / 工具规则
当前输入：刚才为什么拒绝了？
近期消息：沿用当前通话原生历史
当前状态：项目 P1；话题 T3；最近汇报 R9 → 决策 D17
本轮补充：D17 的结论和简要理由
需要再读：read_decision(D17) → 关联审批与执行证据
```

## D 两边怎样共享，才不会再次割裂

```text title="建议的数据流 · 统一事实，分别组装"
用户已提交的话 ─┐
Agent 执行回执 ─┼─→ 带来源的共享记录 ─→ 当前状态投影
幕僚决策与汇报 ─┘          │                  │
                          ├─→ 语音上下文组装 ─┤
                          └─→ 幕僚上下文组装 ─┘
```

| 发生什么 | 更新哪里 | 另一边怎样感知 |
| --- | --- | --- |
| 用户修改目标或约束 | 对话记录 + 当前状态的新版本 | 幕僚下一轮读取最新有效值 |
| 幕僚形成决定或提议 | 决策记录 + 待回应事项 | 语音通过当前引用获知，追问时补读 |
| 任务真正结束 | 任务事实 + 执行回执 | 两边从同一结果来源回答进度 |
| 幕僚向用户汇报 | 对话事件 + 汇报与决策的关联 | 下一轮语音能理解“刚才那个” |
| 用户打断播报 | 汇报的播放状态 | 标记播报被打断，不假设用户听完 |

共享记录至少带上：来源 ID、工作空间与项目、关联任务、时间、版本和有效状态。

语音转写以已提交的轮次入库。临时识别片段留在当前通话，修订时替换同一轮。

“已生成、已入队、播放完成、被打断”分别记录。服务端确认收到不能代表播放完成。

用户在语音里的普通讨论只更新上下文。单纯同步上下文不触发幕僚行动或重新授权。

## E 怎样避免越拼越长、越聊越慢

| 规则 | 建议做法 |
| --- | --- |
| 不重复传递 | 实时接口已持有的原生历史不再次拼接；新会话按预算恢复 |
| 不持续追加快照 | L1 替换为最新版本；旧值失效，不叠加 |
| 不每轮总结 | 任务、决策、播报事件增量更新状态；长历史压缩放后台 |
| 不先调用一次大模型选资料 | 先按当前项目、任务 ID、话题和最近汇报定位；模糊问题再检索 |
| 不固定塞记忆目录 | 默认按问题召回；精简个性仍放 L0 |
| 不全量同步所有项目 | 默认只取当前范围；跨项目问题显式扩展范围 |
| 不把过期摘要当事实 | 当前状态附时间与版本；状态类问题核对最新回执 |
| 不无限等待检索 | 查询超时不阻塞整段通话；先说明正在核对，再异步补充 |

预算先预留输出与工具返回空间。再保留当前输入、协议必需消息和有效约束。

可裁剪部分优先丢弃无关旧历史与重复片段。相关摘要保留证据引用，完整工具轮次一起保留或移除。

首版按模型分别配置预算。用真实 token 数、首句延迟和追问正确率调整；这里不预设未经测量的数值。

```callout info 实时接口需要单独适配
若接口支持替换上下文，直接替换当前状态。

若接口只支持追加，更新需带版本与失效说明。限制累计体积，必要时在通话间隙重建会话。

静默上下文更新不应自动触发播报。是否支持静默更新，需要按语音后端验证。
```

## F 当前代码已经有什么，缺口在哪里

以下结论来自本次工作区阅读，运行时行为尚未做真实通话验收。

| 位置 | 当前实现 | 对方案的影响 |
| --- | --- | --- |
| `crates/app/src/app/gpt_live/prompt.rs` | GPT-Live 启动时带入环境与卡片会话尾部 | 需要区分启动快照与持续更新的当前状态 |
| `crates/app/src/app/doubao/plan/chat.rs` | 每轮读取画布上下文；聊天历史由通道维护 | 可复用更新入口，加入共享引用与按需补读 |
| `crates/app/src/app/doubao/plan.rs:113` | 幕僚播报直接调用 TTS，未在此写入聊天历史 | 汇报需要成为可追问的对话事件 |
| `crates/app/src/app/brain_host/ops.rs:26` | 幕僚交接入口接收请求文字 | 交接需要附带话题与上下文引用 |
| `crates/brain/src/goal.rs` | 保留最近五条 Agent 任务作为目标 | 还需表达有效约束、修订与撤销 |
| `crates/agent/src/master/memory_session.rs` | 按预算把记忆目录加入前台提示 | 可逐步改为相关条目召回，保留查询入口 |

只共用一个可见聊天窗口，还不足以让两个模型拿到同一份上下文。

## G 建议怎么落地

| 顺序 | 做什么 | 验收什么 |
| --- | --- | --- |
| 1 汇报可追问 | 给汇报、决策、任务建立稳定关联；补入近期对话或当前引用 | 播报后问“为什么”，能定位原决定；被打断不当成已听完 |
| 2 意图可回流 | 共享当前话题、目标与约束；交接携带引用 | 用户说“这轮先别发布”，幕僚下轮遵守；修改后旧要求失效 |
| 3 上下文可控 | 统一按需查询；适配豆包、GPT-Live 和普通对话 | 切换入口可接续；跨项目不串话；体积有上限 |

第一步就为相关状态设置版本与范围。后续接入复用这些关联，避免再维护两份摘要。

实现边界建议放在宿主层：汇集已有对话、任务和决策来源，再构造各自的上下文视图。

保持域层依赖边界。幕僚不直接依赖语音模块；通过类型化事件接收必要摘要。
