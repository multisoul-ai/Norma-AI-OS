## 结论

建议以 AgentConnect managed 的源码机制为主要参考：长期记忆采用 `MEMORY.md` 索引与主题 Markdown，启用回合后增量蒸馏，并通过 Dream 的快照、完整暂存库、差异校验、采纳与备份形成成长闭环。复用现有 Rig、后台执行和工具回执；SQLite 继续承载会话经历、运行状态与来源管理。

2026-10-03 修订：用户要求直接分析 AgentConnect 源码。上一版“SQLite 作为长期记忆正文权威”的建议尚未获确认，现已撤回；本版改为 Markdown 长期记忆方案，并按用户要求拆成实施票。自动记忆、Dream 采纳等产品策略继续在相应决策票确认，不视为整份实施 SPEC 已锁定。

用户已明确：个人偏好跨项目保持、项目记忆默认隔离；允许自主学习，新增能力需确认；温度同时包含习惯记忆、持续关心、人格与陪伴、主动提醒和日常交流。具体自动写入规则、提醒强度、Skill 更新门槛仍需讨论，不能把下文推荐值当成已授权行为。

会话组织已确认：统一人格和个人记忆，个人对话与各项目会话分开。同一仓库多个 worktree 共享项目约定与通用经验，分支和任务事实分别隔离。会话重启恢复与跨端同步尚待确认。

总体运行架构已确认：以 Mac 为主体，Mac 承载 Norma 的核心运行、记忆、做梦与能力管理，手机连接同一个 Norma；模型仍可调用云端服务。

## 已确认的整体蓝图

2026-10-03，用户确认以下五部分及其协作方向。它们是产品职责划分；实现复用现有 Master、存储、后台任务和执行链，具体技术方案仍待讨论。

| 模块 | 职责 |
| --- | --- |
| 主智能体 | 保持统一人格，理解用户、交流、规划任务，并决定何时主动关心或提醒 |
| 记忆 | 保留个人偏好、项目知识与过往经历，使交流和工作具有连续性 |
| 能力与执行 | Skill 提供方法，插件提供工具，Coding Agents 执行任务并返回真实结果 |
| 做梦与成长 | 回顾经历、整理记忆、总结成功与失败，提出新的方法和能力建议 |
| Norma 专属设置页 | 管理相处方式、记忆、做梦、能力与权限，展示学习与成长 |

协作闭环：交流与工作 → 主智能体调用记忆、规划并执行 → 经历与真实结果 → 做梦整理、反思与提炼方法 → 改善后续交流与执行。设置页贯穿闭环，提供查看、纠正和控制；新增能力启用或扩权仍需用户确认。

讨论按“整体蓝图 → 模块分工与总体运行架构 → 核心模块技术方案”推进。先对齐会影响多个模块的架构选择，再进入字段、阈值和分支规则。

## 已确认的总体运行架构

2026-10-03，用户选择以 Mac 为主体。

```text
Mac 对话 / 语音入口                 手机入口
         │                            │
         │                   已授权连接 / 必要的中继
         └──────────────┬─────────────┘
                        ↓
                 Mac 上的 Norma
          ┌─────────────┼─────────────┐
          ↓             ↓             ↓
     人格与分域会话   本机记忆档案   能力与执行
                        ↑             │
                        └── 做梦与成长 ← 经历 / 结果
                        │
                 Norma 专属设置页

云端模型 ← 本轮所需上下文 → Mac 主控
```

Mac 主控和本机档案是目标架构；云端提供模型推理及必要的连接、通知能力。Mac 退出、睡眠或不可连接时，手机无法继续使用该 Mac 上的核心能力。启用手机服务后的关窗后台运行复用现有生命周期规则；首期建议在 App 进程内实现，独立常驻服务不作为前置条件。

现有手机云端会话与实时语音链并未因本次确认完成迁移。新增入口应接入 Mac 管理的相同人格、记忆范围与能力策略；现有历史的迁移、保留与多设备冲突另定具体方案，不自动批量导入旧私聊。

## 调研证据

外部机制与固定版本见 [AgentConnect 记忆研究](../research/2026-10-02-agentconnect-memory.md) 和 [Hermes Agent 成长研究](../research/2026-10-02-hermes-agent-evolution.md)。参考项目身份、源码默认值与实现限制以这些一手证据为准。

| 参考实现 | 一手证据中的实际机制 | Norma 值得采用的部分 |
| --- | --- | --- |
| [AgentConnect](https://github.com/agentconnect-md/agentconnect/tree/478aab4e0aceb2127acc53429236d25e74515ed6) | 默认 managed 是 Markdown 索引与主题文件，搜索为加权子串匹配；Dream 真实存在，采用快照、staging、版本校验与备份；默认记忆 auto-adopt，Skill 启用另需审核 | 增量整理、有来源的候选、查看差异、冲突检查与独立 Skill 启用；项目身份尚需用户确认，此处是最吻合候选 |
| [Hermes Agent](https://github.com/NousResearch/hermes-agent/tree/b78931e3b0959c42dca7400c78a4dffd1bb48575) | 小型 MEMORY.md/USER.md 常驻区，SQLite FTS5 原文搜索，Skill 管理、回合后 review 与空闲 Curator；没有在所查模块中发现独立 dream 状态机 | 少量常驻记忆、按需回查经历、稳定人格与个人偏好分开、由经验改进 Skill |
| [Mem0 OSS](https://github.com/mem0ai/mem0/blob/abb81c88e1f738a8117d8293530fbc31a5ef8fd9/mem0/memory/main.py) | 条目化记忆、身份与 filter、抽取与向量搜索、更新与删除记录 | 稳定记忆 ID、归属过滤和真实保存回执；不必先搬入完整 SDK |

Hermes 属于 Nous Research，DeepSeek 是其模型 Provider。三者的“学习”不等于基础模型权重训练；插件安装也不等于已经验证能力提升。AgentConnect 的 Agent/channel 范围和 Hermes 的 profile 范围都不天然满足 Norma 的个人＋项目隔离。

两处尤其不能直接照搬：AgentConnect 当前 Dream 不在读取输入时硬排除本 Agent 的私密会话，普通删除也不足以证明历史和备份中的事实不会复活；Hermes 插件的进程内 consent/audit 并非文件与网络沙箱。Norma 需要宿主层范围校验和真实遗忘规则。

## AgentConnect 源码调用链与 Norma 适配

直接复核固定版本 `478aab4e0aceb2127acc53429236d25e74515ed6`，以下路径相对于 AgentConnect 仓库；完整一手链接与限制见研究文档。

| 源码调用链 | 实际行为 | Norma 的对应设计 |
| --- | --- | --- |
| `memory/store.ts::ensureMemory/readIndex/renderMemoryIndex` 与 `memory/frontmatter.ts` | 主题 Markdown 保存正文，description 生成 `MEMORY.md` 链接目录；会话读有预算的目录，按需读主题 | 各记忆范围独立 Markdown home；索引由宿主生成，主题是正文权威 |
| `memory/providers/managed.ts::standingContextAtSessionStart`、`memory/entries/activation.ts::memoryActivationContext`、`memory/entries/managed.ts::lexicalMatch` | 激活注入索引/catalog；managed 的 `recallForTurn()` 返回空数组；主题读取与当前加权子串搜索由工具完成 | 主会话得到小目录，按本轮需要调用受控 list/read/search；先验证中文检索质量，不假定已有向量召回 |
| `daemon.ts::queueMemoryPostTurn` → `recordTurnForBinding` → `ManagedMemoryProvider.recordTurn` → extraction → `writeMemoryFile` | 可见回复送达后排队；检查 capture gate；启用蒸馏时提取耐久事实，经工具写 Markdown 并重建目录 | 在用户回复之后运行增量蒸馏；受控记忆工具传入可信范围和来源，结果回执表示真实写入 |
| `DreamRunner.start/reserve/run` → `dreamer.ts::MEMORY_DREAM_SYSTEM_PROMPT` | 同一 Agent 单活跃 Dream，读取记忆快照和近期会话，受限 extraction 向空 staging 写完整保留主题集合，并生成目录 | 每次 Dream 绑定一个可信范围；输入为该范围的记忆快照与经历，输出是完整新版本，未写出的文件构成删除提案 |
| `DreamRunner.adopt/rebaseDistillWrites`、`skillAccept` | 校验已审内容与 live digest；仅蒸馏追加的漂移可 rebase；锁内 live→backup、replacement→live，失败恢复；Skill 单独审核启用 | 核验差异、来源及版本后发布 Markdown；冲突保留提案，来源不清的漂移不自动覆盖；Skill 启用保持独立确认 |

AgentConnect 的普通 writer 还有 transactional-home 分支：`store.ts::writeMemoryFileHoldingLock` 在端口支持 `atomicTransaction/stageTransactionFile` 时进入 `atomic-write.ts`；统一条目接口也按真实端口能力声明条件写入与删除。Markdown 是正文载体，不等于实现可以省略事务、范围验证、来源和后台运行记录。其 Dream 的两次目录 rename 也不能表述为一个跨文件系统与数据库的全局事务。

## 建议的能力模型

| 概念 | 内容 | 不应承担的职责 |
| --- | --- | --- |
| 身份与相处方式 | 稳定人格、称呼、表达方式、主动程度 | 不由一次梦境自动重写核心身份或权限 |
| 个人偏好 | 用户明确表达的习惯与稳定偏好 | 不携带项目代码、业务秘密或临时情绪推断 |
| 项目记忆 | 经来源支持的目标、决定、事实与经验 | 不自动跨项目读取，不把摘要当实时状态 |
| 经历 | 可见对话、操作回执、任务结果的来源记录 | 不收集私有推理，不把整个终端输出默认存入个人记忆 |
| 梦境记录 | 整理了什么、提出什么、依据什么、采用了什么 | 新联想先是建议，不能自动变成事实 |
| Skill | 可复用的步骤、触发条件与限制 | 说明本身不能新增工具、密钥或系统权限 |
| 插件 | 增加可执行工具或连接外部系统的能力包 | 不能绕过宿主授权、取消和真实回执 |

“自进化”先指记忆与操作经验的改进，不指基础模型权重训练。温度来自连续记住、恰当响应与可靠行动；模型、人格、记忆和工具权限要能分别管理。

## 记忆：先做到可信、可纠正、可忘记

建议沿用 AgentConnect 的“索引 + 主题 Markdown + 受控记忆工具”，长期记忆正文以 Markdown 为权威；`MEMORY.md` 由主题描述生成，不独立维护另一套事实。个人、项目共享、工作树事实分别归属于独立目录；`type: project` 只是内容分类，权限与范围由宿主解析，不能依赖 frontmatter 或模型自行选路径。

以下为当前有效记忆的逻辑布局，根目录沿用现有 App 数据目录；物理版本发布与来源元数据由存储实现管理：

```text
norma/memory/
├── personal/
│   ├── MEMORY.md
│   ├── preferences.md
│   └── feedback.md
└── projects/<project-id>/
    ├── shared/
    │   ├── MEMORY.md
    │   ├── conventions.md
    │   └── decisions.md
    └── worktrees/<workspace-id>/
        ├── MEMORY.md
        └── branch-facts.md
```

建议一期写入规则：用户明确说“记住”或在设置中编辑的内容立即生效；任务结果可形成有回执支持的项目事实；模型从对话推断的个人偏好先成为待确认候选。临时情绪、健康等敏感推断不自动固化为个人事实。

主题采用 frontmatter 描述名称、描述、分类与修改时间，正文保存自足的事实；Norma 补充稳定条目身份、来源和版本管理。SQLite 保留经历、真实回执、运行与抑制记录，必要的检索缓存可从 Markdown 重建；不将同一记忆正文在 Markdown 与 SQLite 中同时设为可编辑权威。来源须回到真实用户原话或准确任务回执。

一次召回按此顺序进行：

1. 先确定当前项目的稳定归属与用户个人范围，过滤无权限或已忘记内容。
2. 注入有预算的个人、项目和当前工作树目录；必要的少量明确偏好可常驻，其余经 list/read/search 工具按需读取主题正文。
3. 来源文字作为数据与引文，不能覆盖系统规则或解释成执行指令。
4. 用户说“为什么这样回答”时，能够展示使用的记忆和来源；记忆不确定时直接说明。

一期参考 AgentConnect 对标题、描述和正文的有界关键词匹配，并在后台读取或使用已验证的缓存，不能每轮在 GPUI 前台扫描目录。先用中文问题验证命中；只有检索质量或规模表明不足，再增加可重建全文/语义索引。索引负责发现条目，最终依当前 Markdown 与版本核实内容。

### 读写协议与调用链（具体实现建议，尚待确认）

第一张票提供存储接口；第二张票把接口接入对话和蒸馏工具；设置页票使用同一接口查看和修改。复用现有 `AdapterCommand`、`ToolContext` 与异步 `AgentCardAdapter::execute` 执行链，添加类型化记忆命令和结果；`agent` 只处理协议与纯数据，`storage` 负责磁盘操作，`app` 负责后台调用及可信范围/来源绑定。所有对用户可见的保存状态都依据宿主结果。

**何时加载目录。** 用户已确认仅在创建、恢复或重新激活会话时，由 app 后台加载个人、当前项目共享和当前工作树的有预算 `MEMORY.md` 目录；持续对话不每轮自动刷新。模型先看主题名称与 description，再按需调用 list/search/read 发现更新、读取正文。每次工具操作重新取得当前有效快照并校验授权、遗忘状态，一次操作内固定同一版本；成功写入返回真实主题和版本回执，其他更新由工具刷新或下次激活发现。没有项目时只提供个人范围。Rig 与豆包应使用相同规则；这些接入属于后续票，第一票不修改当前对话行为。

| 建议的模型工具 | 参数 | 返回内容与约束 |
| --- | --- | --- |
| `memory_list` | 可选范围别名、分页游标 | 允许范围内的主题 ID、摘要、版本；不返回任意目录 |
| `memory_search` | 查询、可选范围别名、结果上限 | 在允许快照中匹配标题/描述/正文，返回主题 ID、命中片段与版本；下一步 read 取得正文 |
| `memory_read` | 主题 ID、范围别名 | 快照内的 Markdown 正文、来源引用和版本；范围外、不存在或已遗忘均返回明确结果 |
| `memory_write` | 范围别名、可选主题 ID、Markdown | 创建或更新提案；宿主按该调用来源及已确认政策决定提交或待确认，结果区分已保存/待确认/冲突/失败 |
| `memory_forget` | 范围别名、主题 ID | 经宿主校验的遗忘操作；撤销召回资格及再提取资格，不能仅删文件后报告完成 |

范围别名最多选择宿主本轮授予的 personal/project/worktree，宿主解析为固定 ID 与目录；模型不传绝对路径、任意项目 ID 或自己生成的来源凭据。写入所依据的版本来自宿主保存的快照，来源来自真实用户输入、设置编辑事件或已记录的执行回执。

**三类普通写入入口。** 用户明确要求记住时，模型在回复前调用写入工具；宿主完成持久化后才可回复“已记住”。设置页打开主题时保存其版本，用户保存或导入时携此版本提交，冲突显示重新查看而不覆盖。普通交流结束后，先持久化可见经历，再让受限后台 extractor 读取旧主题并调用同一写入工具；自动发布或待确认由既有记忆决策票确定，任务排队不等于事实已保存。

**第一票存储接口。** `snapshot(scope)` 取得校验完成的不可变版本、主题摘要和目录，`read(snapshot, entry_id)` 在该快照读取正文与来源；`commit(scope, expected_revision, changes)` 提交创建/更新/删除集合并返回版本和变更主题回执；`restore(scope, expected_revision, target_revision)` 只恢复已发布历史，并将旧内容发布为新版本。接口接受宿主范围身份而非任意路径，搜索工具留到记忆接入票实现。旧快照可以保持一致读取，旧版本写入必须失败；对话工具不得用旧快照绕过后来发生的遗忘。存储层删除和回滚不代表完整产品遗忘，来源抑制与派生内容处理属于后续票。

**人工编辑已确认。** 第一版通过 Settings → Norma 编辑主题或导入外部 Markdown，统一校验预期版本后发布；不启用外部直接编辑受管目录的监听模式。`MEMORY.md` 始终从主题描述生成。无 frontmatter 的主题逐字保存；第一票的格式、物理布局、发布接口及验收矩阵见 [MemoryStore 接入说明](../references/norma-memory-store.md)。

**一次真实提交。** 第一票先获取该范围系统写锁、校验 expected_revision，再从旧快照准备完整候选版本、应用主题变更、生成确定性的 `MEMORY.md` 和文件清单/校验值；所有内容写在同一数据根目录下。路径、UTF-8、格式、来源引用与完整性校验及文件/目录同步完成后，通过同文件系统 rename 更新活动指针。读者固定版本，切换前失败保持旧库；切换后目录同步失败明确返回已可见版本，调用方须重读快照核实。SQLite 的经历、运行记录及恢复衔接属于后续票，不宣称文件和数据库共享一笔原子事务。

**Dream 的写入。** Dream 只得到某范围的只读快照/经历与仅写 staging 的工具，普通 live 写工具不可用。它生成完整候选集合，宿主展示新增/修改/删除差异；采纳时再进入同一个 commit，检查生成以来 live 是否变化及被遗忘内容是否失效。未经采纳的文件不会被普通对话召回，自动采纳门槛仍待确认。

普通增量学习与 Dream 分开：回复送达后蒸馏稳定事实，读取相关旧主题并提出追加；经宿主检查来源、范围与版本后写入，再生成目录。“只追加”要有写入规则约束，不能只复用 AgentConnect prompt 后宣称 writer 已强制保证。

“忘记”要撤销当前记忆、缓存与派生摘要的召回资格，并阻止旧来源再次自动提取。可以保留不含被忘记正文的删除标记与来源标识；不能一边承诺忘记，一边保留可再次注入的副本。删除原始经历和删除其衍生记忆分别展示，批量清理说明影响范围。

## 做梦：参考 AgentConnect 的离线记忆重建

建议做梦直接采用 AgentConnect 的 snapshot → extraction → staging → diff/校验 → adopt/backup 骨架。先支持“现在做梦”，随后支持 App 运行且用户空闲时自动执行。Mac 睡眠或 App 已退出时不会工作，页面如实显示延期。

```text
同一范围的 Markdown 快照 + 近期可用经历 / 工具轨迹
                         ↓
          独立后台 extraction，只读输入
                         ↓
        合并重复、处理矛盾、保留精确事实、清理临时信息
                         ↓
        空 staging：写出完整保留主题，宿主生成 MEMORY.md
                         ↓
        差异预览 + 来源 / 格式 / 预算 / 内容版本检查
                         ↓
        按策略采纳 → 发布新版本 → 保留备份与真实回执

重复操作经验 ──→ SKILL.md 候选 ──→ 验证与独立启用确认
```

Dream 与回合后蒸馏职责不同：蒸馏倾向追加，Dream 可提出重写、合并或删除，只写暂存库；无需修改的文件保留原字节，未写出的文件必须显示为删除，空提案不能清空已有记忆。关联想法仍是建议，不混入事实。纯整理的自动采用边界与含删除/矛盾的采用门槛尚待确认；新能力启用或扩权维持独立确认。

一次运行记录来源游标与输入快照 digest，每个范围最多一个活跃 Dream。首版已确认先人工审核差异并采纳，发布前检查 live 变化与已审 staged 内容；并发人工编辑或遗忘造成冲突时保留提案并重新整理，暂不实现 distill-only rebase。新内容发布成功后才推进该批来源游标，不照搬最多 100 个会话后直接跳过旧积压的策略。自动 Dream 与自动采纳策略留到后续对应票。

多文件发布由宿主协调：第一票实现完整 Markdown 版本目录准备、校验后切换活动指针，内部读者固定同一版本，已发布旧版本作为恢复来源。来源与运行记录跨文件/SQLite 的恢复衔接留到接入票；不能把逐文件 rename 或 SQLite transaction 宣称为整库原子采用。普通写入和 Dream 使用同一范围写协调；第一版人工修改经设置页或导入进入该链，直接修改受管目录会触发完整性失败。

执行用现有 Provider 与后台任务；注入只读输入及仅写 staging 的记忆工具，模型以工具写出的文件作为产物，完成说明不代替产物。提供预算、暂停、取消与真实消耗；取消后的迟到写入不得被采用。运行状态、来源、错误与采纳结果仍保存在 SQLite，并通过设置页展示。

## 自进化：把成功经验变成可验证能力

```text
真实成功 / 失败 / 用户纠正
             ↓
      提炼 Skill 草稿与适用条件
             ↓
     在隔离测试或受限 dry-run 中验证
             ↓
      展示版本差异、结果与所需权限
             ↓
      用户确认新增能力 → 下次会话启用
             ↓
          留版本 → 可禁用与回滚
```

一期 Skill 只组合已经允许的工具与流程。禁止用“测试 Skill”为理由直接运行草稿中的任意脚本；新增工具、外部连接、可执行脚本或权限扩张都经过明确启用步骤。已有 Skill 的自动修订权限仍需用户讨论，不能从“自主学习”推导为任意覆盖。

每次成长需要回答：以前哪里失败、现在怎么变、在哪个可重复场景验证、是否新增权限、如何回退。只有实际执行验证通过才显示“已验证”；格式正确或模型评审通过只能显示相应检查结果。

插件按真实需求接入现有 typed tool 注册与执行链。一期先支持一个经过验证的能力包：声明稳定 ID、版本、来源校验值、提供的工具与请求权限；安装、验证、启用是不同状态。先确定首个工具，再固定必要字段，无需预先搭建 Python 嵌入、任意动态库加载、通用插件市场或多后端抽象。

Norma 可根据重复失败提出缺失能力、查询候选并生成安装建议；首次启用显示来源、用途、验证结果和权限差异，由用户确认。更新增加权限时重新确认；禁用或撤销后宿主停止受理新调用，运行中的调用遵循取消与真实回执规则。外部可执行插件优先独立进程与结构化协议，明确文件/网络允许范围和资源上限；独立进程本身不等于沙箱。

插件给 Norma 增加可调用能力，Skill 让她学会何时、怎样使用已获授权能力；两者各自保留版本与回滚。不要让做梦生成的脚本直接成为新插件，也不要把静态扫描结果显示为功能验证通过。

## 温度与主动性

建议保留 Norma 的稳定身份，让用户调整相处方式；提供语气与称呼的可预览选项，不用一个“温度”滑块把人格、陪伴与主动程度混在一起。已有“诺诺”和柔软尾音只是表达层，继续使用与否应可以预览。

温度需要可观察行为：记得你偏好短回复、接上昨日明确目标、在任务真正完成时提醒、在受挫时回应当下表达，且不把猜测说成了解你的心理。陪伴允许自然交流，不诱导依赖，也不虚构自身情绪或永远在线。

主动提醒先由真实任务完成、显式提醒请求和待处理成长建议触发；日常问候独立可关闭。设置支持频率与安静时段，关闭即停止新增提醒；没有有用变化时保持安静。用户当前输入优先于做梦与主动交流，任务完成回执不能变成重复问候。

## 独立 Norma 设置页：已确认范围与建议结构

用户已确认在现有 Settings 中增加 `Norma` 专属一级页面，记忆的设置与查看放在此页，之前的语音设置整体迁入。页面沿用居中面板、侧边导航与画布背景，区别于管理 Coding Agent 的 `Agents` 和安装外部编排能力的 `Orchestration`。具体分区布局和交互仍通过原型确认。

语音迁移覆盖现有麦克风、ASR、TTS/声音、语音交互与触发方式、本地/云端及豆包模式、模型/Provider 配置、Setup 和模型管理入口。原配置键、凭据引用、模型安装与就绪检查继续复用；侧栏的独立 Voice 入口收口，旧打开语音设置的路径定位到 Norma 内对应分区。

页面进入后先回答“她现在能做什么、记住了什么、最近学到了什么”；不要只堆开关。

```text
Settings → Norma
┌──────────────────────────────────────────────┐

```

| 分区 | 常用内容 | 必须可见的反馈 |
| --- | --- | --- |
| 与你相处 | 称呼、表达预览、人格说明、陪伴与主动程度、安静时段；模型放折叠的高级区域 | 改动如何影响相处，是否保存成功，当前模型是否可用 |

| 能力与成长 | 已启用 Skill/插件、成长候选、验证证据、权限差异、禁用与回滚 | 待验证/待确认/已启用；安装失败与部分成功不能冒充可用 |

页面不默认展示完整 prompt、工具 JSON 或内部路径；查看来源与技术详情时按需展开。没有项目时仍能管理个人偏好与人格，项目区域说明需选择项目；不要因当前 Master Runtime 需要项目而使整个设置页不可用。

普通偏好即时生效并异步保存；失败在字段就地反馈。高影响变更采用可读预览与明确“启用”，批量删除说明范围。不要用一个全局 Save/Cancel 混合这两种行为。

Apple-design 的落地标准：沿用系统字体、共享分组与组件；状态、来源和控制优先；操作即时反馈，长任务可取消；轻重主题均有清晰 hover/pressed/focus/selected/disabled；键盘可完成筛选和批准；减少动态效果后仍保留状态反馈。无需用持续动画表现“人格在线”。

### 共同接入边界

| 层 | 最小职责增量 |
| --- | --- |
| `crates/agent` | 记忆/成长的纯数据与政策、召回预算、共享人格与上下文拼装、受限反思逻辑；保持零 GPUI/Storage |
| `crates/storage` | Markdown MemoryStore 的文件、版本及发布适配；经历、来源、整理运行与抑制记录的 SQLite 存取，复用现有数据目录和后台存储方式 |
| `crates/app` | Provider 与 Store 注入、后台调度、授权确认、真实副作用与设置页；前台只处理状态与输入 |
| `crates/norma` | 只有需要给外部 Coding Agent 安装受管能力时才扩展；不要把 Master 的学习运行时误放到现有编排模板中 |

长期记忆正文由 App 数据目录中的受管 Markdown 持有。人格配置、Norma 分域会话、经历索引、Dream 运行与来源管理沿用 app.sqlite；既有项目任务记录与 Agent 历史保留原归属，通过精确来源引用接入。范围由宿主授予，所有读取与写入据此解析到允许目录；不能让模型任意指定 scope 或通过路径访问其他项目。

现有 [`workspace::project::identify_project`](../../crates/workspace/src/project.rs) 已将 canonical Git common directory 识别为 `ProjectIdentity.key`，工作树根目录独立保存在 `root`；桌面项目区域持久化 `project_key/root`，共享 Agent 定义库也已按 `project_key` 定位。现有 `WorkspaceIdentityStore` 则按 canonical root 分配身份，桌面画布还使用自己的路由 ID，均不能直接当作仓库级记忆 ID。宿主应复用已验证的项目识别结果并提供可信记忆范围；第一张存储票只接受宿主传入的范围标识，不自行猜测项目归属。仓库搬家后的持续身份、同路径替换仓库以及分支/版本/任务来源绑定，在接入票明确；不同克隆不因 remote URL 相同而自动合并。

app 在后台准备受限记忆目录和快照并传给 agent，agent 不直接打开数据库或扫描文件系统。按需读取与写入沿现有 command/adapter 边界扩展；provider 调用只拿到该轮允许的记忆工具。Rig 与豆包共用人格、范围与拼装规则，记录最终可见经历；直接点名路径也要进入经历与蒸馏接入点。

项目范围必须先匹配当前稳定项目身份，再检索；查询层实际过滤范围，而非只在 prompt 中要求模型遵守。同一仓库多个 worktree 共享项目约定与通用经验，分支和任务事实须绑定各自来源、分支、版本与任务；不能将局部测试结果自动推广为共同事实。显示名与路径变化不能静默串记忆。

新能力按已确认的 Mac 主体运行并在本机存储；使用云模型时明确说明本轮相关内容会发送给该 Provider，“本机保存”不等于“从不离开设备”。手机新增入口建议通过现有授权与连接链读取 Mac 上相同范围的会话、记忆和状态；支持个人对话需要扩展当前绑定项目/卡片的接口。现有手机云端历史的迁移与多设备同步另定方案。

## 推荐的建设顺序与验收

以下是分期建议，不是已获批准的实施任务或完成证明。

| 阶段 | 建设内容 | 验收证据 |
| --- | --- | --- |
| 先形成可讨论的页面与规则 | 用户确认写入/忘记/主动/Skill 更新边界；Norma 页面入口、相处预览、记忆来源与空状态原型 | 用户反馈；只呈现已确定的信息，不显示虚假的能力已就绪 |
| 可信记忆闭环 | Markdown 主题与目录、持久经历、范围工具、回合后蒸馏、纠正/忘记；Norma 页面承载记忆设置与查看，现有语音设置整体迁入 | 重启保留偏好和原语音配置；A 项目事实在 B 不召回；主题变更同步更新目录；修正旧值不再出现；来源能查回；中文检索及现有语音配置流程验收 |
| 有产物的做梦 | 手动 Dream 的快照→完整暂存库→差异/版本校验→采纳/备份先走通，再接空闲调度与预算 | 未采纳不改变 live；未写出的主题可见为删除；索引与主题属于同一有效版本；冲突不覆盖；取消与失败保持原库；旧来源不复活被忘记内容；UI/PTY 不阻塞 |
| 经验证的成长与主动性 | Skill 草稿、验证、权限预览、启用、版本回滚；真实事件提醒与日常交流策略 | 未批准新能力不能调用；验证失败不启用；旧版本可恢复；同一完成事件只提醒一次；安静时段正确 |
| 受控插件一期 | 选定一个真实缺失工具，打通来源校验、安装/验证/启用、权限变更确认、禁用与回滚 | 未启用不能调用；更新不静默扩权；撤销后新调用被拒绝；取消/超时与来源不可信有明确结果 |
| 需求证明后再扩展 | 语义检索或跨端同步 | 用已固定数据集证明收益，补范围隔离、删除传播与冲突测试 |

实施时先 TDD，测试遵守仓库的完整场景注释与正负断言。改 agent/storage 分别跑 `cargo test -p agent`、`cargo test -p storage`；改 app 跑 `cargo check -p app`，GPUI/打包改动按规则跑 Release 构建。跨 crate 的实际改动再执行规定的工作区验证与边界护栏。

页面与视觉状态必须用 Computer Use 操作隔离的真实 App 验收，覆盖来源查看、项目切换、纠正/忘记、做梦暂停和成长确认；不使用已禁用的 `crates/e2e`。本次只检查研究、代码证据与地图关系，未运行生产代码测试，也不宣称完成页面验收。
