# 豆包任务通道：本地网关范围补充

现有默认网关已验证可以转写、对话、返回PCM和处理插话。参考实现的服务端只接受音频、静音、关闭、角色工具与主动问候；不接受任务工具注册、任务结果或任意播报文本。仅修改手机不能补齐豆包派工和结果语音回流。

现行[Goal §3.3](../exec-plans/2026-09-13-norma-ios-realtime-command-goal.md)规定“现有网关代码不在本次修改范围”，且参考companion只读。2026-09-14 用户在看到剩余网关事项后要求“继续完成所有剩余的任务”，据此继续下列本地适配；参考 companion 仍只读，部署不在本轮授权内。

## 最小改动

- 在Norma仓库的 services/voice/ 内维护必要的网关适配和协议检查，参考companion不修改。先在回环地址验证，不部署新服务。
- 创建语音会话时增加一份短期、一次性、只允许绑定该媒体会话的Mac工具票据。手机通过已认证的配对通道转交票据；不传OpenAI或豆包长期密钥。
- 网关向已绑定Mac转发带有原始转写、媒体会话ID、用户回合ID和function ID的工具事件；只有Mac注册的工具可用。Mac继续复用现有意图门、权限、20次/连续失败3次预算与持久操作回执。
- Mac向网关回传真实工具结果；每个response只有一个续答方。插话停止播报，已提交任务不取消；未知操作只能回读。
- 汇报使用已认证任务通道的独立播报请求，沿用现有16k采集/24k播放和实际播放确认。网关没有工具连接时关闭任务能力，聊天继续。

## 验收

本地真实PCM和TLS双Mac测试必须覆盖：讨论不派工、明确任务仅执行一次、错会话/过期/重复票据拒绝、手机不能自称Mac工具执行方、跨连接/进程回读、插话与静音、汇报排队和播放确认。通过本地测试不代表默认线上网关已支持。

外部部署、线上凭据配置、模型授权及真机声学验收另行处理，不由本范围补充自动授权。
