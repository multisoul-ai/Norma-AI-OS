# Norma iOS 原生替换：架构与数据结构讨论稿

状态：**A0 产品与架构边界已获用户确认，具体接口契约进入 to-spec；原生代码尚未开工** · 2026-09-28。产品边界以 [`CONTEXT.md`](../../CONTEXT.md) 和 [数据存储矩阵](../product-specs/2026-09-06-norma-ios-companion.md#appendix-storage-matrix) 中已确认的条目为准。本文聚焦实现方式，不修改原生代码。

## 1. 核心分工

![Norma OS 云服务、iPhone 与 Mac 模块架构](2026-09-28-norma-cloud-architecture.svg)

**数据归属**：iPhone 保留完整的用户可浏览产品历史；Mac 是它拥有的项目、Agent 会话、执行状态、终端、桌面产生的线程事件和原始成果的权威来源。Mac 先持久保存自己在明确 Workspace/线程内产生的对话与执行事件，手机可经云端在线中继补齐同一线程；Mac 不复制整个想法库或 Norma 私聊。手机失联时 Mac 已接收的手机任务与桌面本机交互仍可继续，新的跨 Mac 协作等待手机恢复。云端转发在线加密封套，不作为长期同步库；首版不设 Mac 间直连或换机自动恢复。具体中继边界见 [A1 云服务架构](2026-09-28-norma-cloud-service-architecture.md)。

**已确认的 Norma 云端入口**：iPhone 直接连接默认 Norma 云服务；GPT Live、豆包等模型能力及供应商长期 Key 由云端部署，用户不填模型、Key、地址，也不需要 Mac 在线或签发语音通行证。iPhone 持有长期对话与 Workspace 状态，云端做对话和规划，手机把具体任务交给项目所属 Mac。桌面现有 `NormaSession` 保留桌面直接交互和本机项目工作，不作为手机每轮对话的默认第二次推理。现有 iOS 实时语音虽已有云模型对话和 Mac 工具执行，但其云端授权仍依赖 Mac 签发，属于需要替换的旧实现；新设计还需扩到文字、长期历史、Workspace 和跨项目派工。云模型回复、派工意图与 Mac 的真实执行回执必须分开记录。此前的 [Mac 推理示意图](2026-09-28-norma-ios-inference-architecture.svg) 已不再作为实施依据。

**已确认的桌面独立发起与同步**：Mac 已取得某个 Workspace 的设置副本后，即使暂时连不上 iPhone，用户也可在桌面 Norma 中选这个 Workspace、创建新工作线程并立即处理本机项目。Mac 先持久保存线程创建事件、消息、派工与结果，均带协作 `workspace_id`、独立 `thread_id`、来源与稳定事件 ID；iPhone 重连后按 Mac 事件游标补齐线程目录及同一条时间线。桌面只能使用已同步到本机的 Workspace 配置和本机可操作的项目；新跨 Mac 协作仍等手机恢复。iPhone 发出的线程内容按需送到参与的 Mac，断线时两边保留本地状态并标示最近同步时间；手机云端 Norma 只能使用手机已同步到的内容，不能假称看见桌面未同步消息。旧的项目范围聊天没有新线程身份，不自动导入；是否提供手动导入入口可在旧数据迁移切片决定。

现有手机协议可生成单项目计划、控制 Agent 卡片，但没有 Workspace/线程身份的云端 Norma 对话和跨项目派工接口。新协作协议应让 iPhone 将私聊或线程的有界上下文送往默认云服务，取得回复与带目标项目的任务意图；iPhone 再向对应 Mac 提交执行操作并逐项核对回执。实时语音可复用现有媒体与 Mac 工具通道，但要移除 Mac 为云端对话签发通行证的前提，并扩展目前单 Mac、单项目的绑定范围。`@Agent` 可直接走目标项目端点，仍须归档到原线程。云服务需自行完成对 App 请求的鉴别与滥用控制，不把供应商 Key 下发给手机；具体接口由实施切片定稿，不要求用户配置。

## 2. 建议数据模型

| 对象 | 关键字段 / 关系 | 写入与归属 | 说明 |
|---|---|---|---|
| `Idea` | `idea_id`、正文、来源类型、转写状态、录音路径、时间 | iPhone | 不含 `workspace_id`；离线可写。一个想法可被多个线程引用，引用不会移动原记录。 |
| `Workspace` | `workspace_id`、名称、状态、版本、时间 | iPhone | 独立协作容器；一个 Workspace 有多个线程。Norma 为系统成员，不另建 Agent 定义。 |
| `WorkspaceProject` | `workspace_id`、`machine_id`、`project_id` | iPhone；Mac 项目目录供校验 | 多对多。`project_id` 是现有 Mac 项目身份；同名项目以 Mac ID 区分。关联不复制或删除仓库。 |
| `WorkspaceAgent` | `workspace_agent_id`、`workspace_id`、呼叫名、角色 | iPhone | 用户看到的逻辑成员，例如 Codex 或 Design；同一个呼叫名在一个 Workspace 内唯一。 |
| `AgentEndpoint` | `workspace_agent_id`、`machine_id`、`project_id`、`definition_id` | iPhone 引用；Mac 校验 | 把逻辑成员映射到各项目现有 Agent 定义/卡片。现有 `definition_id` 是项目范围身份，不能当全局 Agent ID。 |
| `WorkspaceFact` | `fact_id`、`workspace_id`、类别、正文、版本、来源消息 | iPhone；任务接收 Mac 留当时快照 | 记录目标、决定与共同事实；变更携带来源和版本，不设置硬约束类型。 |
| `WorkThread` | `thread_id`、`workspace_id`、标题、目标、状态、`source_idea_id?`、创建来源与事件 ID | 创建端先写入，iPhone 长期汇合目录 | 手机可从想法或直接创建；桌面可在已有 Workspace 内离线创建并先存在 Mac。一个线程属于一个 Workspace；重连按稳定 ID 合并。 |
| `Message` | `message_id`、`scope`（Norma 私聊或线程）、作者、来源设备、正文、时间、同步状态、`operation_id?` | 手机消息先在 iPhone；桌面线程消息先在 Mac；云端回复由 iPhone 接收 | 仅有明确 Workspace/线程身份的桌面消息进入同一线程；云回复、消息同步和任务执行各有独立状态。 |
| `TaskLink` | `task_id`、`thread_id`、`machine_id`、`project_id`、Agent 端点、`operation_id`、Mac 任务/会话引用 | iPhone 保存索引；Mac 保存真实任务 | 不在手机新建第二套执行队列；同一线程可有多台 Mac 的任务。 |
| `ArtifactRef` | `artifact_id`、`task_id`、所属 Mac、Mac 成果键、摘要、预览缓存 | iPhone 索引；Mac 保存原件 | 手机离线只显示已同步摘要/缓存，原件在线按需读取。 |
| `SyncState` | Mac ID、线程/上下文版本、最后事件游标、待发操作 ID | iPhone；Mac 保存已接受操作 | 用于重连核对和去重。它不是用户可见任务状态的来源。 |
| `DeviceGrant` | `device_id`、Mac ID、范围（逐项目 / 本机当前及未来项目）、权限、修订号、撤销状态 | Mac 权威保存；iPhone 只缓存展示 | 本机全项目范围须由用户在该 Mac 明确授予，包含后来注册的项目；旧配对保持逐项目范围。 |

建议使用 iPhone 本地 SQLite 保存可查询的长期记录，录音和附件放 App 私有文件，配对秘密继续放 Keychain；不引入第三方数据服务。Mac 继续使用现有 SQLite、Agent 会话文件和项目仓库，仅扩充协作关联与任务上下文所需记录。

**身份与完整性约束**：`WorkspaceProject` 以 `(workspace_id, machine_id, project_id)` 唯一定位，同一项目可关联多个 Workspace；`AgentEndpoint` 必须指向已关联项目中的真实 Agent 定义。`WorkThread.source_idea_id` 可空，引用想法不改变想法归属；`Message` 只能属于一个线程或 Norma 私聊，不能同时属于两者。每个待发执行操作有稳定 `operation_id` 和不可变请求内容；`TaskLink` 只能绑定同一操作得到的真实 Mac 回执，不能从聊天文字推断已执行。对长期上下文只持久化用户可见消息和有来源的事实摘要，模型每轮拿有界切片，不把完整历史逐轮塞入提示词。

**已确认的设备授权**：每台 Mac 在扫码配对确认或设备管理中提供一次性、可撤销的「允许这部 iPhone 控制本机当前及今后注册的项目」。用户必须在该 Mac 明确选择；手机和 Norma 不能远程把逐项目授权升级为全项目授权。授予后，本机新注册项目自动落入该设备的读/控制范围，但不会自动加入任何 Workspace；关联仍需留下记录。其他 Mac 需要分别授权，旧配对继续沿用逐项目白名单，升级不改其权限。Mac 保存授权模式与修订号，在目录读取、派工、终端和待发命令实际执行时按最新修订重新校验；撤销或缩小范围后，旧快照与排队请求不能继续放行。原有高风险操作审批仍独立生效。

## 3. 一次消息或派工如何流转

1. 用户在手机线程输入；iPhone 先写 `Message`，联网时可直接请求云端 Norma 回复。仅当产生需桌面执行的任务意图时才创建待发操作；Mac 离线时该任务显示「待发送」，云端回复仍可正常显示。只记录想法或讨论不会自动派工。
2. 手机从项目目录找到所属 Mac，核对当前设备在该 Mac 的有效授权范围、在线状态和 Workspace 关联；派工前读取该项目当前的运行路由，不能把旧 `route_id` 当成永久地址。把协作 Workspace ID、`thread_id`、项目身份、上下文版本/必要快照与稳定 `operation_id` 一同提交。
3. Mac 重新校验真实设备与项目授权，在已有持久命令/会话路径记录接收与执行；只依据正式回执把桌面任务改为「已送达」并创建 `TaskLink`。若接收后结果未知，先核对原操作，不能换新 ID 盲目重发。
4. Mac 上的桌面 Norma 可在本机已有的 Workspace 设置副本中创建线程，并在该线程产生消息、派工、进展、失败或成果；线程创建与后续事件都先本机保存。手机按来源 Mac 和稳定事件 ID 拉取/去重，先补线程再合并消息；原始终端和仓库文件按需读取，不自动灌入共享上下文。
5. 断线重连先查询旧 `operation_id` 回执与新事件，再决定是否提交仍未送达的指令；已接收任务绝不因手机重连重做。Workspace 目标和事实显示最近同步时间，不能假称其他 Mac 已收到新内容。

Mac 协议建议新增显式 `collaboration_v1` 能力及协作指令，不重定义旧 `workspace_id`：旧字段继续表示 Mac 项目；新字段明确叫协作 Workspace ID 和线程 ID。最小新能力包括协商、同步 Workspace 必要设置、带线程归属的 Agent 派工、桌面新建线程/消息/任务事件的持久写入与按游标查询；云端 Norma 回合不再默认交给桌面 `NormaSession`。能复用的项目快照、真实命令回执、成果与终端仍走既有端点。旧 Mac 不支持该能力时，手机仍可配对、浏览现有项目，但协作派工入口提示更新 Mac，不把普通项目命令伪装成线程任务。新 Mac 继续接受旧 iOS 客户端的现有命令。

**提及与路由**：`@Agent` 每次都要在原线程给出回应、接收回执或明确失败。若成员只有一个可用项目端点，直接选该端点；有多个端点时优先使用用户指定项目或线程正在处理的项目，Norma 可依据目标自主选择并记录原因；无法确定时也要在原线程说明缺少哪项信息。普通 Agent 请求另一个 Agent 协助时，由 Norma 统一派工。手机进入后台后不能假设持续联网；Mac 已接收的任务依靠随任务传入的上下文快照独立运行，跨 Mac 后续步骤等待手机再次连接。

**工作指令与权限边界**：首版不提供 Workspace「硬约束」设置、结构化动作禁令或约束版本门禁。用户在对话中提出的工作要求保留原文与来源，Norma 可依据当前目标更新普通决定并记录原因。Mac 仍按现有设备授权、项目范围和已有高风险操作审批校验真实操作；产品不能把普通工作要求展示成系统保证执行的禁令。

**注意力路由**：参考 [Agent Chief](https://github.com/SmileLikeYe/agent-chief) 的「打断／派工／归档」分流和真实结果核验，但首版用可解释的固定规则。普通 Agent 进展与 Norma 自主派工留在线程；需要用户决定、执行失败或成果待验收进入收件箱；系统通知只提醒尚未处理且值得立即查看的收件箱事项，相近事件合并，已处理事项去重。每条自主派工和提醒保留来源、原因及真实回执。Chief 的场景感知评分、学习偏好和影子模式先不进入首版，等实际通知量与误打断数据表明需要时再评估。

## 4. 旧 iOS 功能的退出路径

| 现有入口 / 数据 | 新位置与处理 | 何时移除旧入口 |
|---|---|---|
| 底部「项目」和项目卡片 | 底部改为「工作空间」；项目详情从 Workspace 设置的关联项目、任务详情或「已连接电脑」进入。 | 新导航可到达项目、Agent 卡片、旧会话和终端后。 |
| 底部「指挥台」 | 改为「Norma」；保留虚拟人、通话设置、打断、字幕与真实派工回执。 | Norma 新页的文字/语音及旧通知回源通过后。 |
| 底部「任务」 | 待人处理进入「收件箱」；完整任务及成果历史从工作线程和关联项目进入。 | 已有任务、审批、成果、终端均有新入口后。 |
| 手机扫码、Mac 项目授权、Keychain | 原实现继续使用；设备管理从「更多模块 → 已连接电脑」进入。 | 不下线能力，只替换入口。 |
| `machines.json`、`drafts.json`、`commands.json` 与草稿图片目录 | 保留原文件和读取路径；旧草稿及图片、未决指令先回查，不自动重发。 | 原记录可核验、无悬空操作后才能移除旧展示。 |
| 旧 `realtime-discussions.json` | 保留为可查看的旧通话记录；用户可手动选取片段保存为独立想法，或引用到指定工作线程，并标注旧通话来源。原记录不移动；不自动并入新 Norma 私聊或猜测 Workspace 归属。 | 旧记录可从新导航到达，手动保存/引用有验收证据，原文件仍可恢复后。 |
| `realtime-operations.json`、`realtime-reports.json` | 保留旧虚拟人操作的待核验状态与播报状态；按原 Mac/项目来源查看，不自动改写成新线程任务。 | 未知操作已核对且旧记录仍可查看后，才移除旧专用页面。 |
| Keychain 与系统偏好 | 保留每台 Mac 的配对凭据及旧语音授权记录以供迁移核对；新云端入口无需用户配置供应商、网关地址或 Mac 签发通行证。通知电脑选择、最近电脑和扫码地址仍按新入口迁移。 | 新云端文字/语音链路和旧记录验收后，清理不再使用的语音授权、网关配置入口与偏好键；配对凭据继续保留。 |
| Mac 旧项目聊天与会话归档 | 继续从对应项目/任务进入；没有明确 Workspace/线程身份的不自动导入。新桌面 Workspace 线程对话则同步到手机同一线程。 | 不删除原始 Provider 会话或 Mac 成果记录；新线程同步验收后才替换相应入口。 |
| 通知深链 | 新任务有线程链接时进线程；旧任务落到关联项目的旧记录页。 | 全部历史通知能准确回源后。 |

开发期间优先复用现有页面与能力，并在新路径可达后逐项退出旧主入口；正式版本只显示「工作空间／Norma／收件箱」三个底部标签。浅色内容与原生 iOS 层级、导航/Sheet Liquid Glass、VoiceOver、动态字号和减少动态效果贯穿每个新页面；不把 Web 原型作为原生验收证据。

| 保留桌面兼容协议 | Mac 的旧 `snapshot`/`command`/`receipt` 与项目级 `workspace_id` 语义 | 新协作协议另加能力标识；旧 iOS 客户端仍可能使用旧接口，不能因为新 UI 不再直接调用就当成死代码。 |

每个原生切片都清理它替换掉的无引用页面、状态、样式和测试夹具；最终切换再跑一次全量引用审计。删除 Swift 文件时同步更新 `ios/project.yml` 生成的 Xcode 工程，并检查资源、权限文案与通知深链。旧本地文件与偏好在迁移可验证前不删除；移除 UI 不等于移除用户数据。迁移测试需覆盖重复启动、受损 JSON 不被空数据覆盖、旧未决操作不自动重发、草稿图片仍可读和历史通知回源。

现有配对凭据使用 `WhenUnlockedThisDeviceOnly` Keychain，语音服务凭据使用 `AfterFirstUnlockThisDeviceOnly`；旧草稿/未决命令文件采用完全保护，实时讨论/操作/播报文件采用首次解锁后可读写。新本地数据库与录音文件的保护等级须按实际写入时机选择：进行中的锁屏通话若要落长期转写，相关文件必须允许首次解锁后写入；配对秘密仍留 Keychain。不能把读不到的受保护旧文件误判为空库并覆盖。

## 5. 现有 Mac 版本的兼容性问题

| 当前事实 | 对新产品的影响 | 建议处理 |
|---|---|---|
| 手机协议的 `workspace_id` 实际是单个 Mac 项目 ID；现有授权按项目 `read/control`。 | 直接把新 Workspace ID 填进去会错路由或越权；现有授权无法自动覆盖后来注册的项目。 | 保留旧字段语义；新协作身份另建字段和能力版本。新增 Mac 上显式的本机当前及未来项目授权模式，旧逐项目授权不自动扩权；实际操作仍校验目标项目。 |
| 桌面 `NormaSession` 和工具适配器按单项目运行，近期历史只在进程内；iOS 实时语音已走云模型和 Mac 工具通道。 | 桌面现有会话没有新 Workspace/线程身份，不能原样同步手机的跨项目长期历史。 | 桌面 Norma 保留本机角色；在明确 Workspace/线程内产生的可见消息与任务事件先由 Mac 持久保存，再同步到 iPhone 同一线程。手机仍对接云模型，Mac 返回真实执行回执；旧项目私聊不自动导入。 |
| 手机协议只支持单项目计划与 Agent Card 命令，没有 Workspace/线程身份的云端 Norma 对话回合。 | 新线程若直接调用旧 `generate_plan` 或 `send_message`，无法可靠区分 Norma 回复、Agent 接收与任务完成。 | 手机侧建立带私聊/线程身份的云端回合；Mac 新能力只接收带线程归属的派工并返回事件，旧命令继续保持原语义。 |
| Agent 定义、卡片和 `definition_id` 属于项目；手机可控制的 Profile 当前主要是 Codex/Claude/Cursor。 | P04 的“同一 Agent 可参与多个项目”不能只存一个 Mac 定义 ID；Design 等名称可能只是项目内别名。 | 用逻辑 WorkspaceAgent + 每项目 AgentEndpoint；不可用端点显示原因，不伪造已加入或已接收。 |
| 成果、审批、终端、会话归档都由 Mac 的项目/运行实例提供。 | 手机线程不能靠一个消息 ID 读取所有原件；旧成果不能自动归属新线程。 | 用 `TaskLink`/`ArtifactRef` 保存精确来源，并保留按需原件读取。 |
| 实时虚拟人当前绑定一台 Mac 的一个项目，只能向这个绑定项目使用任务工具。 | Norma 新主页面与跨项目线程不能直接复用原派工绑定。 | 通话渲染和音频继续复用；为新协作指令增加明确的 Workspace/线程路由及工具授权，未就绪时只讨论不报成功。 |
| 现有 `route_id` 随项目运行实例变化；普通 `send_message` 还要求准确的 Agent Card 快照。 | 长期保存线程后，旧路由或旧卡片不能作为下一次 `@Agent` 的执行地址。 | 手机只长期保存 Mac/项目/Agent 定义身份；每次派工前取当前项目路由和卡片，必要时按现有路径创建或重开卡片，再关联真实 run/turn 回执。 |
| Mac 手机服务随 Norma 桌面进程运行；已启用时可无窗口持有后台项目，但主动退出 App 会停止服务和项目。 | 用户已确认启用手机服务后随 Mac 登录自动后台运行；关窗继续，明确退出停止。只有 Mac 已登录且进程可运行时才能保证在线派工。 | 增加登录后的后台启动和中继重连验收；iOS 明示 Mac 离线，不把桌面 App 退出解释成任务仍在运行。跨 Mac 后续步骤等待手机和目标 Mac 均恢复。 |
| 当前手机连接只在可达的局域网、Tailscale 或回环地址监听，没有通用公网协作中继。 | 蜂窝网络上的 iPhone 不能稳定直连家中在线 Mac，无法满足首版跨网络立即派工。 | 新协作任务增加 Mac 主动出站到 Norma Cloud 的在线中继；旧直连保留配对及兼容能力。Mac 持久接收回执前不显示已送达。 |
| 现有命令按设备与 `operation_id` 去重；服务重启后的已接收操作可能成为 `outcome_unknown`。 | 单靠网络重试不能保证找到执行结果，也不能把未知状态显示为失败后自动重做。 | 保留原操作 ID、真实 run/turn 引用和待核验状态；优先查原 Mac 回执与会话，再决定是否允许用户明确重试。 |
| 现有项目快照按授权项目列目录，Agent 名单只在读取具体项目时返回。 | Workspace 设置不能把单个当前项目的 Agent 列表误当成所有关联项目成员。 | 按 `(machine_id, project_id)` 分别获取名单并保存来源与最后更新时间，离线时标记快照。 |
| iOS `RootView` 强制深色、以一台当前 Mac 和当前项目驱动三个旧标签。 | 只替换标签文字无法支持浅色、多 Mac Workspace 和独立想法。 | 新导航从本机协作数据驱动，旧项目能力作为目的页复用；逐步移除全局选中 Mac 对 Workspace 的隐含约束。 |
| 老 Mac 不认识新协作协议。 | 新手机若静默发旧命令，会丢线程归属与上下文。 | 协商能力；不支持时提示升级 Mac。新 Mac 保持旧手机协议兼容。 |

版本组合的预期行为：旧 iOS + 旧 Mac 继续原有项目流程；旧 iOS + 新 Mac 继续原有协议；新 iOS + 旧 Mac 可配对及查看/控制原有项目，但协作线程派工明确要求更新 Mac；新 iOS + 新 Mac 才开启完整 Workspace/线程能力。升级 iOS 时在本机建立新数据库，旧 JSON 与 Keychain 记录先保持原位；迁移须可重复执行且不得重发旧未决操作，回退旧版本时仍可读取原有数据。

## 6. 先开发什么

A0 产品与架构边界已确认。先按 [Goal 任务计划](../exec-plans/2026-09-28-norma-ios-ideas-workspaces-native-goal.md) 拆分任务并完成 to-spec，再依次交付离线文字想法、Apple Speech 语音想法、Workspace 设置、工作线程与单 Mac 真实派工回执；之后接入跨 Mac 调度、收件箱及长期 Norma 对话。新三项底栏在替代页面可用后正式切换。原生功能暂未修改。

## 7. 已确认的产品决定与最后审阅

| 决定 | 建议默认 | 若改选其他方向的影响 |
|---|---|---|
| Mac 设备授权范围 | **已确认**：用户在每台 Mac 上可一次性明确授权这部 iPhone 读取和控制本机当前及今后注册的项目；可撤销或改回逐项目范围。旧配对原权限不变，不静默扩权。Workspace 关联与现有高风险操作门禁仍独立生效。 | 实现时新增授权范围与修订号校验；旧客户端的逐项目协议保持原样，新模式通过新能力协商暴露。 |
| Norma 推理与云端接入 | **已确认**：iPhone 无需配置、无需 Mac 签发，直接连接部署好模型与供应商 Key 的 Norma 云服务；Mac 全部离线仍可云聊，需要桌面执行的任务留在手机待发送。桌面 `NormaSession` 继续服务桌面直接交互。 | 云服务的客户端鉴别与接口在实现前细化，不要求用户操作。 |
| 桌面 Norma 的线程历史 | **已确认**：明确归属 Workspace/工作线程的桌面 Norma 对话与派工进入手机同一线程；Mac 离线先保存，连接恢复后按稳定事件 ID 同步。 | 旧项目聊天没有线程身份，不自动猜归属；可否手动导入仍可在迁移切片决定。 |
| 桌面独立发起工作 | **已确认**：Mac 已有 Workspace 设置副本时，用户可在桌面创建新线程并处理本机项目，不等待 iPhone 连接；线程创建和执行事件先存 Mac，手机重连后补齐。 | 桌面暂不能替手机把新线程或任务即时传给其他 Mac；未同步的设置变化须显示时间，不能冒充最新配置。 |
| Workspace 硬约束 | **已确认移除**：首版不设硬约束模块、标记字段或新增动作级禁令；用户要求作为普通工作指令进入共享上下文。 | 设备/项目授权及现有操作审批仍按原机制生效；界面不承诺普通指令具备强制阻断能力。 |
| 旧实时讨论 | **已确认**：旧记录单独可查看；用户手动选片段保存为想法或引用到指定线程，原记录保留并标注来源。 | 不自动并入 Norma 长期私聊，也不猜测 Workspace 或线程归属。 |

**首版默认，供各切片规格细化**：语音想法转写后保留原录音直至用户删除该想法；Workspace 先提供归档与重开，不提供永久删除；没有新线程身份的旧项目聊天仍从旧项目/任务入口查看，不自动归入新线程。上述规则避免迁移期丢数据；若后续使用验证发现问题，再修改对应规格。原生功能尚未修改。
