# Norma OS 功能导览与帮助中心产品设计

- 日期：2026-08-01
- 状态：已实现，待合并
- 目标版本：0.1.50
- 产品范围：首次项目导览、长期帮助入口、功能演示内容、导览状态管理
- 实现范围：GPUI 模态导览、四个主题、应用级状态持久化、Help 永久入口、语音与高优先级浮层协调
- 关联设计：[`Onboarding 新手引导 SPEC`](2026-06-28-SPEC-onboarding.md)、[`Dispatch Receipt 离子派发特效 SPEC`](2026-08-01-SPEC-dispatch-receipt-particle-effect.md)

## 1. 决策摘要

Norma OS 增加一套统一的“功能导览与帮助中心”能力，使用同一套内容服务两个场景：

1. **首次导览**：全新用户第一次成功打开真实项目、画布稳定显示后，自动出现一次。
2. **长期帮助**：用户以后可通过 macOS 菜单栏的“帮助 → 功能导览…”随时重新打开。

首版采用画布中央的大型模态窗口，不新增第三种应用主屏，也不自动创建示例项目。导览左侧提供功能目录，右侧提供短视频或动态演示、功能价值说明、三步以内的操作方法和上下文操作按钮。

首版只解释四个决定用户能否开始工作的核心能力：

1. 语音指派 Agent。
2. 继续与 Agent 对话。
3. 管理无限画布与工作卡片。
4. 理解任务状态与派发回执。

本功能的成功标准不是“用户看完了导览”，而是用户更快完成第一次有效任务派发，并能理解任务被送到了哪张 Agent 卡片。

### 2.1 原型表达的关键关系

- 用户仍能辨认自己处在已经打开的项目画布中，而不是进入一个脱离上下文的教学页面。
- 模态窗口是唯一主要浮层；背景画布轻微压暗和失焦，用于保持位置感并集中注意力。
- 左侧目录回答“我可以了解什么”，右侧内容回答“这个功能有什么用、怎么操作”。
- 动态演示表达“语音入口 → 指令 → 目标 Agent 卡片”的空间因果。
- 离子流星命中只表达“目标 Agent 已接收”，不表达任务开始、完成或成功。
- 用户可以关闭、跳过、切换主题或从帮助菜单再次打开，不被导览困住。

## 3. 背景与问题

Norma OS 的核心心智模型是 **Live Node on Infinite Canvas**。用户打开项目后面对的是可自由组织的 Terminal、Agent、Preview 和 Browser 卡片，而不是传统应用的固定页面。与此同时，语音可以创建任务、指派 Agent，也可以继续与现有 Agent 卡片对话。

这种能力组合具有较高的新颖度，新用户容易遇到四类问题：

- 不知道打开项目后应该从哪里开始。
- 不理解 Command Dock、无限画布和 Agent 卡片之间的关系。
- 不知道语音既能派发新任务，也能继续与现有 Agent 对话。
- 看到流星或任务状态变化时，不确定它代表“已送达”还是“已完成”。

如果只依赖设置页、快捷键列表或静态文档，用户必须先知道功能名称才能找到答案。功能导览需要在真实项目上下文中，用短而明确的演示建立产品心智模型，同时保留一个可重复进入的长期帮助入口。

## 4. 第一性原理判断

### 4.1 用户真正需要的结果

用户真正需要的不是观看一套完整课程，而是：

1. 知道第一步可以做什么。
2. 能把一个真实任务交给正确的 Agent。
3. 能确认任务被送到了哪里。
4. 需要时能再次找到说明。

因此首版不追求覆盖全部功能，也不采用必须按顺序完成的长流程。自动导览控制在四个主题内，任一主题都可直接切换，所有内容都可以之后从帮助菜单重新查看。

### 4.2 为什么在打开项目后出现

- 导览内容依赖画布、卡片和 Command Dock 的空间关系，在 Launchpad 上展示会失去上下文。
- 用户已经表达了“进入工作”的意图，此时解释操作比应用刚启动时更相关。
- 真实画布作为背景可以让演示和实际界面形成对应，而不需要自动创建一个用户未要求的示例项目。

### 4.3 为什么使用模态导览而不是新页面

- 新页面会让用户离开刚打开的项目，并制造第三种应用主屏状态。
- 非模态小气泡难以同时容纳视频、文字和主题导航，也容易与复杂画布内容争夺注意力。
- 中央模态可以短暂集中注意力，同时通过关闭、跳过和 Help 入口保留用户控制权。

## 5. 产品目标与非目标

### 5.1 产品目标

- 全新用户第一次打开真实项目时，获得一次及时、短促、可退出的核心功能说明。
- 让用户理解语音新任务、Agent 续聊和派发回执之间的关系。
- 让帮助内容以后仍然可发现，而不是完成首启后永久消失。
- 让导览与权限弹窗、设置面板、语音识别等现有浮层有确定的优先级，避免闪现或被错误销毁。
- 为未来新增功能提供可版本化、可扩展的内容载体。

### 5.2 非目标

- 不建设完整的在线文档站、全文搜索或远程内容管理系统。
- 不在首版实现逐按钮聚光、强制操作式练习或复杂任务挑战。
- 不在导览打开时自动请求权限、安装 Hook 或修改外部配置。
- 不自动创建、删除或修改用户项目中的卡片。
- 不把流星效果描述为任务完成反馈。
- 不要求用户看完导览才能使用画布。

## 6. 用户与核心场景

### 6.1 全新用户第一次打开项目

用户从 Launchpad 选择或打开一个真实项目。画布首帧稳定后，功能导览自动出现，并默认停留在“语音指派 Agent”。用户可以继续浏览、暂时关闭或跳过自动导览。

### 6.2 用户需要回忆某个功能

用户通过 macOS 菜单栏的“帮助 → 功能导览…”打开同一套界面，直接选择需要的主题。手动打开不受首次导览完成或跳过状态限制。

### 6.3 用户想立即试用语音

导览根据当前语音能力状态显示“现在试试”“允许麦克风”或“配置语音”。用户离开导览后进入真实操作流程；真实语音识别、任务派发和流星回执继续使用正式业务路径。

### 6.4 用户不希望被自动教学打扰

用户可以关闭本次导览，也可以明确选择“跳过导览”。跳过后不再自动出现，但仍可从帮助菜单重新打开。

## 7. 信息架构

### 7.1 系统层级

```text
帮助与导览系统
├── 首次导览（自动入口）
│   └── 第一次打开真实项目后出现
└── 功能导览（长期入口）
    └── macOS Help 菜单随时打开

两种入口共用
├── 相同的主题目录
├── 相同的媒体资源
├── 相同的操作说明
└── 相同的能力状态判断
```

### 7.2 首版主题

#### 主题一：语音指派 Agent

- **用户问题**：如何用语音把新任务交给指定 Agent？
- **核心文案**：用语音，把任务交给 Agent。
- **演示流程**：按住语音快捷键 → 说出 Agent 名称和任务 → 显示识别文本 → 离子回执命中目标卡片 → 卡片显示“已接收”。
- **状态语义**：“已接收”表示消息已送达目标卡片，不表示完成。
- **上下文操作**：语音可用时显示“现在试试”，不可用时显示对应配置入口。

#### 主题二：继续与 Agent 对话

- **用户问题**：已有 Agent 在工作时，如何补充要求或派发后续任务？
- **核心文案**：直接对卡片继续说，任务上下文不会丢失。
- **演示流程**：选择 Agent 卡片 → 发起语音或文本续聊 → 内容进入现有会话 → 显示派发回执。
- **状态语义**：续聊仍是一次 Handoff，应有与新任务一致的送达反馈。

#### 主题三：管理无限画布与工作卡片

- **用户问题**：如何移动、缩放、聚焦和组织不同工作卡片？
- **核心文案**：把工作留在空间里，而不是藏进标签页。
- **演示流程**：平移或缩放画布 → 拖动卡片 → 聚焦卡片 → 使用 Command Dock 创建新卡片。
- **上下文操作**：关闭导览并轻量强调 Command Dock，不自动创建卡片。

#### 主题四：理解任务状态与派发回执

- **用户问题**：Agent 是否已经收到任务，现在处于什么状态？
- **核心文案**：先确认送达，再观察执行状态。
- **演示流程**：派发 → 已接收或已排队 → Agent 工作状态 → 完成或需要关注。
- **状态语义**：动画负责定位目标，文字和状态标记负责表达真实业务状态。

## 8. 界面设计

### 8.1 总体布局

- 导览以画布根视图上的中央模态窗口出现，不改变当前项目和画布状态。
- 推荐尺寸约为窗口可用区域的 70%–78%，最小尺寸下允许内容区滚动或采用紧凑布局。
- 背景使用单层遮罩压暗并轻微失焦；不得叠加多层浅色玻璃导致文字低对比。
- 主模态使用与现有 Norma OS 一致的圆角、主题色和材质，并同时适配全部现有主题。

### 8.2 左侧功能目录

- 显示“功能导览”和当前进度，如“1 / 4”。
- 每个主题包含图标和明确名称。
- 当前主题使用主题 accent、高对比文字和稳定的选中背景。
- 支持鼠标点击以及上下方向键切换。

### 8.3 右侧内容区

从上到下依次为：

1. 功能标题。
2. 两行以内的价值说明。
3. 16:9 视频或动态演示区。
4. 三步以内的操作说明。
5. 可选的上下文操作按钮。

内容必须先说明功能目的，再说明操作。不能只展示快捷键或只播放动画。

### 8.4 底部操作区

- 左侧固定说明：“以后可从‘帮助’菜单重新打开”。
- 右侧提供“跳过导览”和“下一项”。
- 最后一项的主按钮改为“开始使用”。
- 右上角关闭按钮和 `Esc` 表示暂时关闭，不等同于永久跳过。

## 9. 触发与展示逻辑

### 9.1 自动触发资格

只有同时满足以下条件，首次导览才可以自动出现：

- 用户属于全新安装或全新用户状态。
- 这是用户第一次成功打开真实项目。
- 项目已经进入 Canvas，画布首帧已经稳定显示。
- 当前窗口处于前台且可见。
- 当前没有更高优先级的阻塞界面。
- 当前导览版本没有被完成或明确跳过。

### 9.2 已有用户迁移规则

功能发布时，可能存在没有导览状态、但已经打开过多个项目的老用户。为了避免升级后突然出现模态窗口：

- 没有导览状态且没有历史项目记录：按全新用户处理，首次打开项目时自动显示。
- 没有导览状态但已有历史项目记录：不自动弹出，只增加 Help 菜单入口。

### 9.3 展示时机

```text
用户打开项目
    ↓
应用切换到 Canvas
    ↓
画布首帧确认完成
    ↓
判断自动触发资格
    ↓
检查是否存在更高优先级界面
    ├── 存在：保持 Pending，等待界面空闲
    └── 不存在：显示功能导览
```

导览不能在项目开始加载时直接出现，也不能依赖一个容易被后续状态覆盖的瞬时布尔值。产品状态需要明确区分 `Pending`、`Visible`、`Suspended` 和 `Closed`，避免导览先出现一帧又立刻消失。

### 9.4 浮层优先级

从高到低建议为：

1. License、系统权限和不可继续的阻塞状态。
2. 删除等危险操作确认和关键错误。
3. 语音识别会话、语音配置和 Settings。
4. 首次功能导览。
5. 普通通知与非阻塞提示。

高优先级界面存在时，导览应该排队或保存进度后暂停，不能被当成已完成，也不能闪现后被销毁。导览可见时，应阻止画布的误操作，但不得阻止窗口关闭、`Esc` 或应用退出。

## 10. 导览状态与操作语义

状态属于应用级，而不是项目级。用户学习的是 Norma OS 的通用能力，不应该每打开一个新项目就重新观看。

### 10.1 用户状态

- `NotSeen`：从未显示。
- `InProgress`：已经看过部分主题，记录最近主题。
- `Completed`：完成当前导览版本。
- `Suppressed`：用户明确跳过当前导览版本，不再自动出现。

### 10.2 瞬时展示状态

- `Idle`：当前没有导览会话。
- `Pending`：具备资格，但正在等待合适的展示时机。
- `Visible`：导览正在显示。
- `Suspended`：因更高优先级界面临时暂停，可恢复。
- `ClosedForSession`：本次应用会话不再自动显示。

### 10.3 操作语义

| 用户操作 | 产品行为 | 持久化结果 |
| --- | --- | --- |
| 选择左侧主题 | 立即切换内容并重置媒体播放 | 保存最近主题 |
| 下一项 | 进入下一主题 | 保存进度 |
| 开始使用 | 关闭导览，回到当前项目 | 标记当前版本完成 |
| 关闭按钮 / `Esc` | 本次会话暂时关闭 | 保留 `InProgress`，下次启动可恢复 |
| 跳过导览 | 关闭且停止自动出现 | 标记当前版本 `Suppressed` |
| Help 菜单打开 | 无条件打开导览 | 不受完成/跳过状态限制 |

自动导览完成或跳过后，不应因为用户打开另一个项目而再次出现。

## 11. 语音能力的适配逻辑

“语音指派 Agent”是默认主题，但用户的语音能力可能尚未就绪。导览需要基于真实能力状态调整上下文按钮：

| 当前状态 | 按钮文案 | 点击行为 |
| --- | --- | --- |
| 语音已就绪 | 现在试试 | 关闭导览并进入现有语音录音路径 |
| 缺少麦克风权限 | 允许麦克风 | 进入现有语音配置流程，系统授权由用户动作触发 |
| 缺少 Provider 或模型 | 配置语音 | 打开 Settings → Voice 对应位置 |
| 模型正在下载 | 正在准备语音 | 显示状态，不进入必然失败的试用流程 |
| 能力失效或需要修复 | 修复语音 | 打开现有修复入口 |

导览本身不执行语音识别，也不伪造任务。点击“现在试试”后必须进入真实语音、派发和回执业务路径。

## 12. 媒体与内容规范

### 12.1 媒体形式

- 首版采用随应用发布的三关键帧 GPUI 动态演示；每个主题都有静态最终帧和完整文字步骤。
- 演示不依赖声音，关键状态直接显示在场景和相邻文字中。
- 三帧演示低频循环，提供“重新播放”；切换主题时从第 1 帧开始。
- 后续若替换为 8–12 秒本地短视频，必须保留静态关键帧作为加载和失败兜底，并提供暂停、继续和重新播放。
- 切换主题时从对应媒体的开头开始。
- 所有媒体随应用发布，不依赖网络。

首版不使用无限循环 GIF：它难以暂停、无障碍控制较弱，也更难稳定管理解码与性能。当前 GPUI 演示只更新离散场景状态，不进行逐帧图片解码；未来视频上屏仍必须遵守项目现有的低拷贝约束，不能每帧走 CPU RGBA 或 `RenderImage` 路径。

### 12.2 文案原则

- 使用动作和结果，不使用内部架构名词。
- 标题回答“能做什么”，正文回答“为什么有用”。
- 操作步骤不超过三步。
- 快捷键必须读取或匹配用户当前配置，不能把默认键位写死成永远正确。
- “已接收”“已排队”“工作中”“已完成”必须保持不同语义。

### 12.3 首版关键文案

```text
功能导览

语音指派 Agent
用语音，把任务交给 Agent
按住语音快捷键，说出 Agent 名称和任务。
Norma 会将指令送到对应卡片。

1  按住语音快捷键
2  说出目标与任务
3  松开并派发

以后可从“帮助”菜单重新打开
跳过导览
下一项
开始使用
```

## 13. 动效与 Apple 设计原则

- **Purpose**：动效只用于解释空间因果和状态，不用于装饰或庆祝。
- **Agency**：始终提供关闭、跳过和再次打开入口，不强制完成。
- **Familiarity**：使用 macOS Help 菜单、模态层级、系统字体和熟悉的键盘行为。
- **Simplicity**：自动导览只保留四个高价值主题，每页操作不超过三步。
- **Spatial consistency**：导览在真实画布上出现；退出后回到完全相同的位置和焦点上下文。
- **Interruptibility**：切换主题或关闭时，媒体和过渡可以立即停止，不锁定输入等待动画结束。

窗口出现与退出采用克制的材质化过渡，不使用明显弹跳。开启 Reduced Motion 时：

- 模态只使用短促淡入淡出，不使用缩放或大范围位移。
- 动态演示默认显示静态关键帧，用户仍可主动播放。
- 流星演示使用 Dock 与目标卡片的同帧短脉冲替代跨屏飞行。

开启 Reduced Transparency 或增强对比度时，提高模态背景不透明度和边界对比，确保文字不依赖动态背景保持可读。

## 14. 无障碍与键盘操作

- 打开导览后，键盘焦点进入模态，但用户可使用 `Esc` 退出。
- `Tab` 顺序覆盖目录、媒体控制、上下文操作和底部按钮。
- 上下方向键切换主题，左右方向键不劫持媒体或文本控件的原生行为。
- VoiceOver 能读出当前主题、进度、媒体说明、操作步骤和按钮状态。
- 视频必须有等价的文字步骤；无法播放视频时不损失核心信息。
- 字体放大时允许内容区滚动，按钮和标题不得被裁切。
- 不仅使用颜色表示选中、完成或语音就绪状态。

## 15. 与既有 Onboarding SPEC 的关系

仓库已有 [`2026-06-28-SPEC-onboarding.md`](2026-06-28-SPEC-onboarding.md)，其方案包含：

- Launchpad 首启流程。
- 麦克风与通知权限申请。
- Agent Hooks 安装。
- 自动创建示例画布。
- 逐按钮聚光和操作式快捷键练习。

该方案与本文解决的问题部分重叠，但产品形态、触发时机和复杂度不同。如果两套方案都按当前定义实现，用户可能连续经历两轮首启教学，并产生两套完成状态。

### 15.1 推荐决策

建议把本文方案作为首版用户指导的主线，并暂停旧 SPEC 中的重型首启教学，原因是：

- 本文直接在用户选择的真实项目中解释核心工作流，不制造示例项目。
- 权限和 Hook 更适合在用户真正触发对应能力时按需解释，而不是首启集中索取。
- 视频导览可以长期复用，而旧方案完成后没有重看入口。
- 单一模态和内容目录比跨 Launchpad/Canvas 的锚点教学更容易保持稳定。

可以从旧 SPEC 保留两个设计原则：

1. 首次完成状态使用应用级持久化。
2. 权限与外部配置必须由用户明确动作触发，不能静默修改。

在进入实现前，需要正式决定旧 SPEC 是被本文取代，还是降级为未来的“交互式练习模式”。在此决策完成前，不应并行实现两套自动首启入口。

## 16. 边界与异常场景

| 场景 | 预期行为 |
| --- | --- |
| 项目打开失败 | 不显示导览，保留原有错误处理 |
| 画布还未稳定 | 导览保持 `Pending`，不得提前闪现 |
| Settings 已打开 | 等待 Settings 关闭后再展示 |
| 正在语音识别 | 不打断识别；等待会话结束后再判断是否展示 |
| 系统权限弹窗存在 | 导览暂停或等待，不与系统弹窗叠加 |
| 用户快速切换项目 | 取消旧项目的待展示请求，在新项目稳定后重新判断 |
| 用户关闭窗口 | 不标记完成；保留已浏览进度 |
| 视频解码或资源失败 | 显示封面和完整文字步骤，导览仍可完成 |
| 目标功能当前不可用 | 展示原因和配置入口，不播放虚假的可用状态 |
| 小窗口或大字体 | 内容区滚动或紧凑布局，核心按钮始终可达 |
| 已有用户首次升级到该版本 | 不自动弹模态，只提供 Help 入口 |

## 17. 成功指标

在具备用户同意和隐私保护的前提下，首版关注以下产品指标：

- 自动导览展示率、完成率和跳过率。
- 各主题的查看率和中途退出位置。
- “现在试试”或“配置语音”的点击率。
- 新用户打开项目后首次有效 Agent 派发的时间。
- 看过语音主题的用户能否更快完成第一次语音派发。
- 用户通过 Help 菜单重新打开导览的比例。

不得记录语音内容、任务正文、项目路径或 Agent 对话文本。导览完成率只是过程指标，首次有效派发才是核心结果指标。

## 18. 首版范围

### 18.1 In Scope

- 全新用户第一次打开真实项目后的自动导览。
- macOS Help 菜单中的长期入口。
- 四个核心功能主题。
- 本地三关键帧动态演示、重播和 Reduced Motion 静态兜底。
- 目录切换、下一项、开始使用、关闭和跳过。
- 应用级完成、进度和跳过状态。
- 与 Settings、权限、错误和语音浮层的展示优先级。
- 语音能力就绪、未授权、未配置和修复状态的自适应按钮。
- 键盘、VoiceOver、Reduced Motion、Reduced Transparency 和高对比度支持。

### 18.2 Out of Scope

- 在线帮助搜索、远程 CMS 和内容热更新。
- 用户可编辑或上传自己的导览视频。
- 逐元素聚光和强制操作练习。
- 自动创建示例项目或示例卡片。
- 全量功能百科。
- 新增导览专用快捷键。
- 自动请求所有权限或安装 Agent Hooks。

## 19. 验收标准

### 19.1 触发与状态

- [ ] 全新用户第一次成功打开真实项目、画布首帧稳定后，导览自动出现一次。
- [ ] Launchpad 阶段不自动出现本文导览。
- [ ] 已有历史项目的老用户升级后不自动出现导览。
- [ ] 完成或明确跳过后，打开其他项目不得再次自动出现。
- [ ] 关闭按钮或 `Esc` 只关闭当前会话，保留进度，下次启动可继续。
- [ ] Help 菜单始终可以重新打开导览，不受完成和跳过状态限制。
- [ ] 快速切换项目或关闭窗口不会把待展示状态错误计为完成。

### 19.2 内容与交互

- [ ] 左侧显示四个主题，点击与键盘切换均能立即更新右侧内容。
- [ ] 每个主题都有标题、价值说明、媒体、三步以内的操作方法和必要的状态语义。
- [ ] 动态演示可重播；Reduced Motion 下固定为静态最终帧，并始终提供完整文字。
- [ ] 最后一项显示“开始使用”，完成后回到原项目和原画布位置。
- [ ] 流星命中文案只表示“已接收”或“已排队”，不得表示任务已完成。
- [ ] 语音快捷键文案与用户当前设置一致。

### 19.3 浮层协调

- [ ] Settings、语音会话、权限弹窗或阻塞错误存在时，导览不会闪现一帧后消失。
- [ ] 高优先级浮层结束后，`Pending` 导览可以在同一有效项目上下文中显示。
- [ ] 导览暂停或关闭不会影响真实任务、语音会话和画布状态。
- [ ] 导览可见时不会把键盘或点击误发送给背景卡片。

### 19.4 无障碍与性能

- [ ] 导览可以完全使用键盘操作并被 VoiceOver 正确读出。
- [ ] Reduced Motion 下不播放自动跨屏飞行，仍保留等价的状态说明。
- [ ] Reduced Transparency 和高对比度下文字、选中态和按钮均清晰可辨。
- [ ] 动态演示只做离散 GPUI 状态更新，不进入 CPU RGBA 每帧上屏路径。
- [ ] 关闭导览后不存在导览专用的持续解码、计时器或重绘工作。

## 20. 自动化证据要求

实现阶段应把验收标准映射到以下自动化证据：

- 纯状态测试：自动资格、进度、完成、跳过、暂停和恢复。
- App 单元测试：现有用户迁移规则、Help 菜单描述、语音能力到按钮意图的映射。
- Headless GPUI 测试：导览层渲染、键盘焦点、主题切换、背景输入隔离和浮层优先级。
- `crates/e2e`：首次打开项目、关闭后恢复、跳过后不再自动出现、Help 菜单重开、动态演示静态兜底。
- 真实 App L3：首次项目进入、主题切换、动态演示、Reduced Motion 和 VoiceOver 基础冒烟。

任何页面、布局、样式或视觉状态实现完成后，必须使用 Computer Use 操作真实 App 完成视觉和交互验收；静态截图和无头测试只能作为补充。

## 21. 已确认实现决策

本轮实现采用以下决策：

1. 本文作为当前轻量用户指导主线；旧 Onboarding SPEC 不在本轮并行实现。
2. 首版固定四个主题，并以“语音指派 Agent”为第一项。
3. 关闭只结束本次应用会话；明确“跳过导览”才停止后续自动出现。
4. 语音主题提供“现在试试”，并直接复用现有 `activate_ready_voice` 正式业务入口。
5. 首版使用 GPUI 三关键帧演示；真实录屏作为后续内容升级，不阻塞首版发布。

## 22. 与当前代码结构的实现关系

本节记录已落地的实现边界：

- 当前应用主屏只有 `Launchpad` 和 `Canvas`，导览应作为 Canvas 上的应用层覆盖层，不新增第三种主屏。
- 项目打开后存在延迟恢复卡片的流程，自动导览应在画布首帧稳定后进入 `Pending`/`Visible` 协调。
