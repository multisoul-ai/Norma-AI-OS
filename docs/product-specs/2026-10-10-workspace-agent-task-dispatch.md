# 工作空间级智能体卡片派工与进度汇报：角色名称唯一与旧称呼失效

日期：2026-10-10。产品规则已确认；实现尚未开始。本规格由本次讨论整理，供 Agent 实施和验收。

## Problem Statement

用户希望在 Norma OS 的当前工作空间内，通过 Dock 向任意项目的具体智能体卡片分派任务，包括后台、收起或尚未加载的画布。展开一个项目只是正在查看的上下文，用户不希望为了派工反复切换到目标项目。

常规桌面 Dock 目前仍注入单项目 Agent 名单与画布上下文；项目内名称和具名定义无法唯一表达整个空间里的具体卡片。同一项目目录可以有多张独立画布，局部节点编号也可能相同。跨项目角色重名、共享具名定义、改名、删除后重建及异步加载，都可能让名称解析、任务提交和结果归属出现歧义。

用户还需要知道任务是否真正交给 CLI、是否开始执行、是否已经完成，以及多目标中的哪一项失败。仅有文字回复、输入成功或 Norma 结束一轮规划，都不足以证明目标卡片完成了任务；未知结果被自动重发还可能造成重复修改。

用户也需要主动询问整个工作空间的进度，了解各项目正在做什么、有哪些成果和阻塞、哪些事项需要自己处理。只展示当前项目或某次派工的逐项回执，无法回答这个问题；后台、未加载区域及直接在卡片中开始的工作也不能因此从汇报中消失。

## Solution

Dock 中的 Norma 协调整个当前工作空间。用户点名唯一角色名称、使用其中文语音别名或通过可搜索的 `@` 选择具体卡片，即可跨项目派工。角色名称就是卡片主名称，一个名称只对应一张卡片；主名称与中文语音别名在全空间共同查重。

角色改名后，旧主名称与旧语音别名失效。原角色仍存在时，历次旧称呼保留失效占用，其他角色不能复用；原角色彻底删除成功后才释放。历史重名由系统按固定顺序自动修复，并展示名称变更记录。任务一旦确定目标，就绑定稳定卡片身份，之后的改名、视图切换和名称复用都不会把任务转给另一张卡片。

用户只指定明确项目时，系统统计该项目在当前空间全部画布中的有效候选：唯一候选自动选中，多候选让用户选择，零候选保留任务并提示补全。明确点名不存在或失效角色时，也保留任务并等待选择，不用相似名称或唯一剩余卡片替代明确称呼。

任务沿用现有 CLI 消息队列，Dock 逐项更新证据支持的进度。完成或失败后提供摘要与结果入口，用户点击才打开卡片。可安全重试的明确失败由用户点击重试，结果未知先核对，已成功目标不重复提交。

用户说“汇报整个工作空间的进度”“现在有哪些任务卡住了”等，Norma 查询发送时的当前工作空间，并在来源 Dock 返回一次进度快照：先概述空间整体状态和需要处理的事项，再按项目列出角色、已知任务、阶段、等待原因、成果摘要与结果入口。范围覆盖全部项目与区域，不局限当前视图、本轮派工或 Dock 发起的任务。默认展示全部当前未结束任务及已知失败／中断／待核对事项，成果窗口为最近 24 小时；回复注明窗口，用户可用自然语言查询其他时间范围，未结束任务不因创建较早而被过滤。

汇报注明统计范围、查询时间和数据更新时间，区分角色数量、任务数量与未关联任务的卡片活动。未加载区域使用持久快照，缺失或过时的数据明确标为待核实；没有可靠计划分母时不编造百分比，不把 CLI 空闲等同于项目完成。查询复用已有事实，不向各卡片发送“报进度”任务，也不启动其 PTY；用户再次查询取得新快照。手机使用同一查询事实，仅返回获授权范围。

## User Stories

1. 作为工作空间用户，我希望在总览的 Dock 向任意项目的卡片派工，以便集中协调相关项目。
2. 作为工作空间用户，我希望展开 Web 项目时仍能给 API 项目的卡片派工，以便当前视图不限制我的指令范围。
3. 作为工作空间用户，我希望后台、收起和屏幕外的卡片仍可被点名，以便无需先找到卡片的位置。
4. 作为工作空间用户，我希望向未加载区域的既有卡片派工时只准备必要区域，以便不启动所有项目。
5. 作为工作空间用户，我希望发送后切换工作空间不改变原任务归属，以便任务继续在原空间执行。
6. 作为工作空间用户，我希望每张智能体卡片使用空间内唯一的角色名称，以便一个称呼只命中一个目标。
7. 作为工作空间用户，我希望卡片主名称与角色名称一致，以便画布展示与点名目录表达同一身份。
8. 作为工作空间用户，我希望多个智能体可以复用职责、Provider、模型和技能配置，同时各有独立名称，以便共享能力而不混淆任务目标。
9. 作为工作空间用户，我希望在另一项目或画布创建同名角色时得到明确冲突提示并保留输入，以便及时选择可用名称。
10. 作为工作空间用户，我希望英文大小写不同的同名也被识别为冲突，以便 Alan、alan 和 ALAN 不成为不同投递地址。
11. 作为工作空间用户，我希望后台、未加载和停用但仍保留的角色也占用名称，以便切换视图或恢复后不会出现重名。
12. 作为工作空间用户，我希望不同工作空间允许使用同名角色，以便各空间独立组织人员而不互相限制。
13. 作为工作空间用户，我希望同时从桌面和手机创建同名角色时只能有一个成功，以便并发操作不破坏唯一性。
14. 作为工作空间用户，我希望系统自动分配名称时跳过有效称呼与失效占用，以便自动命名也能准确点名。
15. 作为工作空间用户，我希望能用 Alan 或“艾伦”呼叫同一卡片，以便文字与语音操作一致。
16. 作为工作空间用户，我希望主名称与语音别名之间也跨角色查重，以便别名不会误投给另一角色。
17. 作为工作空间用户，我希望改名成功后只有新名称与对应语音别名有效，以便旧称呼不继续呼叫原角色。
18. 作为工作空间用户，我希望原角色仍存在时其他角色不能复用它的旧主名称或旧语音别名，以便旧指令不会投给新角色。
19. 作为工作空间用户，我希望连续改名后历次旧称呼都保持失效占用，以便早期名称不会因再次改名而重新可用。
20. 作为工作空间用户，我希望重启、关闭会话、收起卡片或停用角色不释放旧称呼，以便占用规则不随运行状态变化。
21. 作为工作空间用户，我希望新名称冲突导致改名失败时原名称和别名仍有效，以便失败操作不破坏现有身份。
22. 作为工作空间用户，我希望角色彻底删除成功后释放当前和历史称呼，以便新角色可以合法使用这些名称。
23. 作为工作空间用户，我希望删除失败时全部称呼仍被保留，以便未删除的角色不与新角色争用名字。
24. 作为工作空间用户，我希望同名新角色获得新身份，旧任务和历史回执仍归原角色，以便删除后复用名称不会转移任务。
25. 作为工作空间用户，我希望旧数据中的重名由系统自动改名，以便无需逐一处理历史冲突。
26. 作为工作空间用户，我希望重名修复以固定顺序保留一个原名称，并展示每张卡片的名称变化，以便能够核对修复结果。
27. 作为工作空间用户，我希望修复中断后继续使用已保存的映射，以便重启不会再次给同一卡片改名。
28. 作为工作空间用户，我希望只有重名文本、缺少目标身份的历史记录被标为待核对，以便系统不会猜测其归属或重发。
29. 作为工作空间用户，我希望直接说“让 Alan 修复登录”即可定位该空间的唯一卡片，以便不必补充技术地址。
30. 作为工作空间用户，我希望在 `@` 选择器中搜索角色并看到项目和画布上下文，以便确认选中了正确卡片。
31. 作为工作空间用户，我希望点名不存在或失效称呼时保留任务正文并提示补全，以便修正目标后继续原任务。
32. 作为工作空间用户，我希望补全前没有任务接收、创建或投递，以便不完整目标不产生副作用。
33. 作为工作空间用户，我希望指定 Web 项目且只有一张有效候选时自动选中，以便省去没有歧义的选择。
34. 作为工作空间用户，我希望指定项目存在多张有效候选时由我选择，以便系统不按焦点或能力评分猜人。
35. 作为工作空间用户，我希望指定项目没有有效候选时保留任务并提示补全，以便不会自动创建卡片或改投别的项目。
36. 作为工作空间用户，我希望后台与未加载候选同样计入项目候选数量，以便当前画布只有一张不被误认为整个项目只有一张。
37. 作为工作空间用户，我希望项目名称有歧义或目录尚不完整时先明确范围，以便不基于局部名单自动选中目标。
38. 作为工作空间用户，我希望明确点名失效角色时不会改投该项目的唯一剩余卡片，以便系统尊重我的具体目标。
39. 作为工作空间用户，我希望指令限定的项目与角色实际归属不一致时得到反馈，以便系统不会静默改变范围。
40. 作为工作空间用户，我希望同目录多画布和相同节点编号仍能精确派工，以便独立会话不会被混用。
41. 作为工作空间用户，我希望改名和布局调整不改变已选中的任务目标，以便异步派工仍命中原卡片。
42. 作为工作空间用户，我希望已选目标被删除、停用或替换会话时拒绝失效身份，以便不自动换卡片继续执行。
43. 作为工作空间用户，我希望普通 Coding Agent 卡片在登记唯一角色名称后也能派工，以便能力不局限于带项目定义的卡片。
44. 作为工作空间用户，我希望与 Norma 讨论方案时不产生任务，以便讨论与执行意图有明确边界。
45. 作为工作空间用户，我希望目标和执行意图明确后直接分派，以便正常派工无需额外确认。
46. 作为工作空间用户，我希望一条指令中的多个明确目标先统一预检和接收，再分别投递，以便不会在检查完成前部分写入卡片。
47. 作为工作空间用户，我希望每个目标独立显示接收和投递结果，以便一项成功不掩盖另一项失败。
48. 作为工作空间用户，我希望忙碌卡片沿用 CLI 队列接收后续任务，以便不增加必须等待上一任务终态的调度限制。
49. 作为工作空间用户，我希望等待启动、审批或用户输入占用时显示具体原因，以便知道为何尚未提交。
50. 作为工作空间用户，我希望派工不覆盖正在输入的内容、不越过审批或自动中断旧任务，以便我的接管操作仍有效。
51. 作为工作空间用户，我希望接收、提交和真正开始运行分别显示，以便 CLI 队列中的任务不会被提前称为正在执行。
52. 作为工作空间用户，我希望明确续聊继续关联原任务和卡片，以便补充说明不创建无关的新任务。
53. 作为工作空间用户，我希望取消明确任务时只影响该目标，以便同批其他任务继续执行。
54. 作为工作空间用户，我希望重复发送同一操作返回原回执，以便网络重试不会造成重复输入。
55. 作为工作空间用户，我希望有意再次执行相同正文被视为新操作，以便系统不按文本误删我的新任务。
56. 作为工作空间用户，我希望可信任务或回合事件决定完成状态，以便模型回复“完成”或 CLI 静默不被当作完成证据。
57. 作为工作空间用户，我希望旧任务、旧会话和上一轮回复不结束新任务，以便结果归属准确。
58. 作为工作空间用户，我希望 Dock 在来源空间逐项更新进度，并在终态提供摘要和结果入口，以便集中查看派工结果。
59. 作为工作空间用户，我希望后台结果不自动切换视图或抢焦点，点击回执后才打开对应卡片，以便当前工作不被打断。
60. 作为工作空间用户，我希望无可信跟踪的卡片如实显示无法自动确认完成，以便不会得到虚假的成功反馈。
61. 作为工作空间用户，我希望明确且可安全重试的失败由我点击重试，并保留原目标和正文，以便控制新的尝试。
62. 作为工作空间用户，我希望多目标重试只处理失败项，以便成功项不重复修改文件。
63. 作为工作空间用户，我希望结果未知先核对原任务证据，以便系统不盲目重发可能已执行的任务。
64. 作为工作空间用户，我希望执行失败但已有副作用时保留原因和结果，以便检查后决定下一条处理指令。
65. 作为工作空间用户，我希望卡片已删除时仍可查看历史结果，并知道原目标已移除，以便不会打开同名新卡片。
66. 作为工作空间用户，我希望区域移除后保留必要的任务和结果快照，以便历史不只指向已删除的数据库。
67. 作为工作空间用户，我希望重启后能查询历史且不自动恢复旧派工队列，以便不会因恢复而重复执行。
68. 作为已授权的手机用户，我希望手机与桌面共用同一工作空间的目标与任务事实，以便两端结果一致且仍遵守手机权限。
69. 作为已授权的手机用户，我希望断线后已接收任务继续、重连可查询原操作，以便恢复连接不重复派工。
70. 作为工作空间用户，我希望名称登记、查询和异步加载不阻塞界面，以便画布与终端保持可操作。
71. 作为键盘用户，我希望目标选择、回执查看和重试具备明确焦点与状态反馈，以便无需鼠标也能完成操作。
72. 作为工作空间用户，我希望浅色、深色和减少动态效果设置下都能看清选择与任务状态，以便反馈持续可辨。

78. 作为工作空间用户，我希望能查询指定时间范围的成果或某个项目的进度，以便在同一事实基础上继续追问。
79. 作为工作空间用户，我希望看到每项任务的当前阶段、等待原因与需要我处理的事项，以便区分正常排队、审批等待和执行异常。
80. 作为工作空间用户，我希望汇报区分接收、提交、运行与终态，以便排队中的任务不会被描述成正在执行或完成。
81. 作为工作空间用户，我希望汇报包含直接在卡片中开始的有证据工作，以便进度不局限 Norma 从 Dock 分派的任务。
82. 作为工作空间用户，我希望没有任务记录的卡片活动被单独标明，以便已知活动不会被遗漏，也不会被虚构为一个已跟踪任务。
83. 作为工作空间用户，我希望无可靠跟踪、结果未知和旧快照明确标注，以便汇报不把证据不足当作空闲或完成。
84. 作为工作空间用户，我希望看到汇报覆盖范围、查询时间、各项事实更新时间与缺失范围，以便判断内容是否足够新且完整。

86. 作为工作空间用户，我希望只有已验证的完整任务计划才显示步骤完成数，以便没有分母时不生成完成百分比或推断整个项目完成。

88. 作为工作空间用户，我希望查进度不创建任务、不写卡片输入、不启动未加载 PTY，也不代替我审批或重试，以便查询不改变正在进行的工作。

92. 作为已授权的手机用户，我希望使用与桌面相同的进度事实，并明确仅覆盖我的授权范围，以便两端一致且不泄漏无权查看的项目。

## Implementation Decisions

- **共享分派入口**：提取入口无关的工作空间分派服务，向 Dock、手机适配器和后续语音入口提供目录、提交、查询与取消能力。提交明确区分 Assign 和 Reply。复用现有 `AgentCardAdapter` 与 typed tools 的边界，将入口授权留在各入口适配器，任务副作用只由共享分派服务驱动一次。
- **模块职责**：`norma` 承载共享协议；`agent` 承载工作空间上下文、typed tools 和实例级任务协调；`runtime` 表达纯目标解析与计划校验；`storage` 持久化身份、命名、操作、回执与结果；`app` 执行异步准备、GPUI 适配、提交副作用与事件投影。域层不反向依赖 UI 或存储。
- **协调范围**：发送时固定来源工作空间、来源主体、消息与操作身份。展开、选中、聚焦和视口只提供观察上下文，不覆盖解析结果；未选定工作空间时执行前补全空间。
- **空间角色身份**：角色名称是卡片主名称，同一空间内具名角色与卡片一对一。项目定义可关联配置，但不作为卡片唯一身份；不能共享同一具名身份，再只改卡片别名绕过唯一性。无项目定义的既有卡片也必须登记独立角色身份。
- **名称规范**：复用现有 AgentName 格式与规范化键，去除输入首尾空白，英文忽略大小写；英文名称为 2–16 个字母，中文名称为 2–8 个汉字，Norma 保留。自动名称使用现有名称池与合法后备名，不生成不符合现行格式的数字或连字符名称。
- **命名登记**：使用 app 级持久登记维护工作空间、角色、卡片和呼叫键归属。工作空间与规范化呼叫键的组合唯一；主名称和中文语音别名共同仲裁，所有跨角色主名／别名组合都不能碰撞。全部区域均参与，停用但仍保留的角色继续占名。
- **呼叫键状态**：区分有效键和失效占用键，两种状态都参与占用仲裁，但只有有效键可以寻址。改名在事务中使新名称和对应别名生效、旧称呼转为失效占用；失败保留原有效状态。点名目录和语音提示只展示有效称呼，卡片标题同步使用当前角色名称。
- **旧称呼生命周期**：原角色仍存在时，其他角色不能复用其历次旧主名称与旧语音别名，连续改名、停用、关闭会话和重启均不释放。彻底删除成功后，在同一事务中释放所属当前及历史占用；删除失败不释放。历史身份与任务归属仍保留，不因名称复用而转移。
- **历史重名修复**：后台读取完整持久目录，先保留已有合法登记和无冲突称呼，再按稳定区域与卡片身份排序，固定保留一个重名角色，给其他角色自动分配合法未占用名称及对应别名。共享旧键只登记给固定保留者，不重复变成其他角色的失效占用。保存原名、新名和卡片身份映射，恢复使用已保存映射；登记未完成时不按冲突名称派工。
- **名称修复与历史任务**：已有稳定身份的任务、回执和结构化提及继续归原卡片；只有重名文本的历史记录标为待核对，不据此重绑或重放。不得通过修改项目共享定义隐式改名其他工作空间的角色。
- **精确目标协议**：目标快照包含工作空间、区域、持久卡片身份，以及可用的节点、Runtime 路由代次和 Provider 会话指纹。已有卡片恢复保留持久身份，删除后重建使用新身份；局部节点编号复用不能恢复旧目标。模型使用系统目录返回的结构化目标引用，不以任意目录、项目名称或定义 ID 替代投递身份。
- **点名与补全**：结构化提及直接绑定卡片引用，自然语言只精确匹配当前空间有效主名称或语音别名。未知、失效、冲突、任务指代不清或明确项目不匹配时保留任务并补全；补全前零任务接收、零创建、零提交。名称变更历史、相似名称和当前焦点不能用于自动猜目标。
- **项目候选规则**：只有派工意图和执行项目都明确时才进行项目内选择。有效候选必须仍存在、启用、完成唯一登记、符合入口授权并支持本次提交；忙碌和未加载本身不排除候选，缺少结果跟踪也不等于不能提交。候选覆盖该项目在当前空间的全部区域；目录未完整或项目有歧义时先补全，不能误判唯一。零候选保留任务，唯一候选自动绑定，多候选用户选择；绑定后失效则拒绝，不重新选人。
- **目录与加载**：内存目录是持久登记和运行状态的投影，通过事件更新；未加载区域从保存快照提供候选。查询与普通讨论不启动所有 PTY；选定目标后只异步准备必要区域，随后复核空间归属、卡片、目录、授权和会话。现有卡片的 cwd 不随当前展开项目改变。
- **实例级调度**：队列、待提交正文、续聊、Hook 和结果处理都以具体卡片实例为调度键；定义 ID 仅关联角色配置，不寻找某个定义的第一张活跃卡片。现有单项目工具由兼容适配器接入同一登记和执行约束，不自动创建替代卡片。
- **原子接收与独立投递**：遵守“多 Agent 委派先原子接收再独立投递”的既有 ADR。预检整组明确 assignments 后统一接收并冻结目标，或整组不接收；每项稳定 assignment 身份。接收后独立投递，后续一项失败不否定整组接收，也不把批次笼统称为全成功。投递副作用不能事务回滚，回执逐项报告。
- **CLI 队列行为**：沿用现有正文与 Enter 分阶段提交、启动就绪、审批和输入占用机制。任务 A 未结束时 B 可接收并在 CLI 允许时提交，实际开始由 CLI 决定；不增加等 A 终态的严格串行调度。缺少可信 Hook 且可能忙碌时保留现有需要用户明确发送的约束，模型不能自行 force。等待条件恢复是同一任务的提交推进，不是新任务重试。
- **续聊与取消**：新任务关联 task_ref，定向回复关联接收后的 turn_id，均保留 Provider 指纹。明确续聊沿用原目标和任务；取消指定任务只影响对应目标，取消全部必须有明确整批意图。指代不清时先补全，不误取消同批其他任务。
- **状态与证据**：分别保存来源操作状态、任务状态和跟踪能力。收到消息／定位、已接收／等待提交、已提交、正在执行、等待审批、完成／失败／取消／中断有各自证据。提交成功不等于运行或完成；终态只由同 task 或 turn 的可信事件确定。outcome_unknown 表示状态待核对，untracked 表示无法可靠确认完成，均不能靠静默、空闲或文本关键词判成功。
- **工作空间进度查询**：在共享服务的 query 能力内增加只读进度查询与对应 typed tool，明确区别于 Assign／Reply／Cancel。发送时固定来源工作空间与入口主体，查询不要求指定角色，也不使用派工有效候选列表排除停用或未加载角色；项目和时间条件只缩小明确查询范围。目录尚不完整或部分读取失败时返回已知结果与覆盖缺口，不宣称全空间已完整统计。
- **汇报事实来源**：聚合工作空间操作／assignment、项目任务账本、当前 Runtime 和已通过会话身份校验的 Hook／turn、既有工作摘要与持久结果快照。已加载区域取当前内存事实，未加载区域后台读取持久快照并标注未验证当前运行状态；不扫描终端全文或向各 Agent 发消息获取汇报。复用现有活动汇总、任务进度与摘要机制，但不能沿用其仅包含已加载或有关联定义卡片的范围限制。直接卡片输入产生的可信活动同样可见，无法关联任务时单列为卡片活动。
- **汇报身份与统计**：按工作空间、区域、持久卡片和稳定任务引用合并事实；同一 task 的多个回执、事件、续聊和重试尝试只占一个逻辑任务，真正新操作仍算新任务。无明确关联键时不按相同正文猜测合并。角色／卡片数、任务数和内部步骤数分列；每个任务只归一个可证实的最后状态，并附观察时间，无法确认阶段时单列未知。跟踪不足、快照过时和待核对作为额外标记，不能重复加入状态总数；无法解释的状态冲突保留待核对，不用新写入的旧会话快照覆盖可信终态。名称改动只更新展示，同名新角色与历史原角色不合并。
- **汇报内容与时间口径**：默认覆盖当前未结束任务和已知失败／中断／待核对事项，不设隐式解决状态或自动清除异常；近期成果采用查询时点之前 24 小时的已知终态，指定时间范围可覆盖此窗口。未明确时区的“今天”“本周”按 Mac 本地时区解释并回显起止时间和时区；任务状态分布与近期成果分别统计，不相加。内部计划只在有完整可信分母时展示已完成步骤／总步骤，不对不同任务做百分比平均，不据此声明整个项目完成。等待审批、用户输入、启动、失败和未知分别说明依据；无证据的业务阻塞原因不由模型猜测。
- **汇报快照合同**：返回查询时点、目录版本、入口授权范围、已覆盖／缺失范围，以及各项事实的来源、观察时间和实时／持久／待核实标记。多区域采样不是跨 PTY 的原子实时状态；采样期间身份、目录或权限发生变化时重新校验或排除失效项并说明。即使某一区域不可读，也可返回明确标注的部分结果；手机不暴露未授权项目名称、数量或任务内容，只说明汇报限于授权范围。
- **汇报呈现与副作用边界**：来源 Dock 回复依次展示空间概况、待处理事项、项目／角色／任务摘要与结果入口；详情使用有界摘要和分页，统计不能只取首屏。生成文字只基于查询快照，不新增执行权限或改变任务状态；即使同时看到待审批或失败，也不能自动审批、催办、重试或创建“报进度”任务。不加载全部运行实例、不写 PTY、不抢焦点。一次查询产生一次带时间的汇报，后续刷新是新查询，旧汇报保留原时间；不默认持续订阅或周期推送。
- **确定性派发**：遵守“Dialogue 约束任务，CardTask 以证据完成”的既有 ADR。模型生成目标与任务计划，代码验证后执行已冻结 assignments；不让第二个模型重新决定是否派发，也不以 Norma 回合结束或查询工具成功代替真实回执。
- **操作记录与幂等**：共享操作记录保存来源主体、操作 ID、来源消息、工作空间、执行意图、原文与请求指纹；assignment 保存目标快照、正文、阶段、任务引用、错误与重试资格；事件保存游标、证据与结果快照。按来源操作和稳定 assignment 身份去重，同键不同参数冲突；模型 tool_call_id 变化不能绕过去重，用户有意再做相同正文是新操作。
- **崩溃窗口与恢复**：SQLite 与 PTY 之间不存在原子事务，不承诺端到端 exactly-once。记录接收、正文、Enter 与回写阶段；崩溃或超时后先核对原任务证据，未知不自动重放。重启不恢复未提交的旧队列，历史明确标中断或待核对；名称占用和卡片持久身份正常恢复。
- **反馈与导航**：来源空间 Dock 使用紧凑逐项回执，显示角色、项目／画布、摘要、当前状态和必要等待原因，终态附结果入口与失败原因。后台事件和工作空间切换不自动导航；只有点击回执才打开原卡片。已删除目标保留历史结果并说明已移除，不按同名寻找新卡片。
- **重试合同**：公开的明确失败只有在可证明安全时提供用户点击的重试入口，保留原目标身份与正文并重新复核，使用关联原记录的新尝试身份。多目标只重试失败项，成功项不重发。结果未知先查询证据；已有文件修改等副作用且无法证明安全时，保留结果并由用户检查后提出新指令，不重放整个任务。既有提交过程中确认尚未写入目标的内部安全推进遵守既有 ADR，但不能把失败或未知项自动作为新任务发送。
- **历史与生命周期**：区域移除前对账，将必要正文、目标和已知结果快照保存到工作空间级记录，避免历史只引用即将删除的区域数据库。切换、收起或手机断线不停止已接收工作；关窗、后台项目和主动退出沿用现有生命周期，主动退出统一回收实例，不因该功能延长进程寿命。
- **上下文与权限**：Norma 会话按当前工作空间隔离，复用同一 Mac 的人格与个人记忆；每轮使用有界目录，项目正文和记忆按需读取。手机继续遵守配对、项目权限和已授权范围；结构化目标引用不代替授权。桌面不能伪造手机设备或 token，现有 CLI 区域路由身份与手机兼容由适配器保持。
- **界面规范**：保留现有 Dock 和卡片内部输入，新增可搜索的紧凑目标选择浮层及逐项回执，不新增常驻派工栏或专用派工动效。选择器遵循 Material 菜单的紧凑密度、搜索和明确状态，其余交互按 Apple 原则落实层级、即时反馈与可访问性；适用的 hover、pressed、focus、selected 和 disabled 在浅深主题下可辨，减少动态效果仍有文字反馈。
- **性能边界**：目录扫描、SQLite、文件读取、模型调用、会话加载和结果核对放后台；GPUI 前台只读内存快照、复核状态和执行短 Runtime 副作用。输入路由、PTY drain、鼠标移动、render 与无脏关闭不新增阻塞查询或扫描。

## Testing Decisions

1. **主要测试接口**：以共享工作空间分派服务的目录、提交、查询和取消接口为主，走生产适配器与真实目标校验，输入任务后检查实际 PTY 写入、持久回执、任务结果和目标归属。这延续已讨论的模块边界，不为每个入口增加另一套业务测试接口。
2. **良好测试的标准**：验证用户可观察的结果与副作用，不绑定私有 helper 调用顺序、提示词片段或表结构实现。每个成功派工场景同时验证目标卡片收到唯一指令、所有非目标卡片零输入；重复操作验证零新增输入，失败和未知验证正确状态与重试资格。
3. **现有测试基础**：复用 typed tool 到 AgentCardAdapter 的 RecordingAdapter 合同测试、生产卡片命令执行测试、可控 PTY 正文／Enter／清行故障注入、同目录多区域存储测试、主名称与语音别名交叉查重测试，以及手机工作空间完成状态投影与断线恢复测试。进度汇报复用工作空间活动只读汇总与授权测试、可信任务步骤及工作摘要测试；补充必要的名称事务单测与身份路由纯测试，避免重新搭建四套桌面／手机／语音／CLI 调度模拟。
4. **名称与删除**：覆盖跨项目、大小写、主名与别名全部组合、停用和未加载占名、并发创建、手动冲突保持原状态、连续改名的历次失效占用、重启恢复，以及删除失败不释放／成功释放全部所属键。原角色删除后复用名称必须使用新身份，旧任务和迟到结果不得命中新角色。
5. **历史修复**：构造包含未加载区域、合法名称已占用、语音别名已占用和共享具名定义的历史数据；验证固定保留者、合法新名、共享旧键唯一归属、变更记录、重复恢复不再次改名，以及仅名称旧记录被标待核对。不能只测单张当前画布。
6. **目标解析与候选**：覆盖文字／语音／结构化目标、普通讨论、未知与失效称呼、项目不匹配、零／一／多候选、同目录多画布和相同 node_id。加入“当前画布一张、后台另一张”和“目录尚未完整”的反例；自动选择不受焦点影响，点名失效不使用项目唯一候选替代。
7. **首个跨项目闭环**：展开项目 A，通过 Dock 指定 B 的既有卡片；B 收到独有任务并产生关联回执与可信结果，A 和其他卡片零输入，视图和焦点不跳转。再覆盖总览、后台与未加载目标，验证只加载必要区域。
8. **异步身份复核**：在目录读取、操作预留、后台事务和加载之间注入改名、删除、停用、会话重建及路由代次变化；展示改名仍绑定原身份，真正失效则拒绝，不能重选另一卡片或同名新角色。
9. **原子接收与幂等**：整组预检失败时零接收零写入；接收后部分投递失败时分别呈现。重发同键返回原回执、不同参数冲突；新的 tool_call_id 不产生重复输入，有意的新操作允许执行，安全重试只新增对应失败项。
10. **队列和提交阶段**：验证 A 未结束时 B 能依法接收和提交；仅有提交证据时 B 不显示运行或完成。审批、启动和输入占用显示具体等待原因且不覆盖输入；正文成功但 Enter 或清理失败时不释放不安全占用或盲目重发。
11. **完成证据与恢复**：旧 task、旧 turn、旧会话、上一轮回复、模型文本和静默均不能完成新 assignment。覆盖 submitted、running、waiting_approval、可信终态、untracked、outcome_unknown，以及提交前后写回失败、退出和重启不重放旧队列。
12. **回执、导航和重试**：逐项更新来源空间状态并保存终态摘要；后台结果不抢焦点，点击才导航，已删除目标只显示历史。明确安全失败手动重试保留原身份，结果未知先核对，有副作用的不安全失败不提供盲目重放；成功项零新增输入。
13. **手机兼容与授权**：验证桌面和手机调用同一业务事实、权限范围仍有效、结构化目标不能跨越授权、断线重连按原操作查询；桌面不依赖伪造设备身份。共享路径变更运行现有手机回归，不新建完整手机聊天界面。
14. **真实 App 与真实 Provider**：对 Dock、选择器、跨项目任务、回执、导航、浅深主题、键盘与焦点使用 Computer Use 操作真实 macOS App，并检查最终结果。TestAppContext、headless 点击和静态截图只是补充；Echo PTY 只证明输入送达，可信完成另用支持的真实 Provider／Hook 验证。
15. **工程验收**：实施先写能失败的聚焦测试，再改代码；测试按受影响的 agent、runtime、storage、norma、app 维护，执行相应 crate 测试与 app 检查，跨 crate 行为按仓库约定验证。旧 e2e 套件已禁用，不新增、维护或运行；域层独立测试、存储与热路径边界、源码行数和禁止压制诊断等约束继续适用。
16. **全空间汇报闭环**：展开 A 后查询全空间，构造 A 当前任务、B 后台任务、C 未加载快照与停用角色，验证全部在范围中；直接卡片输入的可信工作同样可见，未关联活动不虚构任务。检查所有卡片零新增输入、零任务创建、零 PTY 启动，焦点和视图不变；再次查询可读取新的证据。
17. **统计与名称归属**：同一任务同时出现在操作记录、项目账本与 Runtime，且有续聊、重试和内部步骤，验证只计一个逻辑任务、状态互斥、步骤不当任务。改名按原身份合并，同名新角色不合并；分页后的总计仍覆盖完整已知范围。默认全部未结束任务与异常不按创建时间过滤，24 小时成果窗口边界、指定窗口、无任务空间均有明确说明。
18. **证据与完整性**：缺失计划、旧 Hook、静默、untracked、outcome_unknown、过时快照和部分区域读取失败不得推断完成。完整可信计划可展示步骤数，事件缺口则隐藏比例；跨任务不生成平均完成率，CLI 空闲不代表项目完成。返回覆盖缺口和各项观察时间，部分失败仍展示可用结果，生成文字不能升级结构化状态。
19. **查询隔离与授权**：发送后切换空间、采样期间删除或改名、目录版本变化及手机权限撤销时复核范围；结果归原空间，不误绑定同名新卡片。手机仅返回授权数据，不暴露未授权名称或数量；部分授权不能称为完整全空间汇报。异常事项不触发自动审批、取消、催办、重试或订阅。
20. **汇报真实 App 验收**：在真实 App 的总览和展开项目中输入全空间进度查询，核对空间概况、项目分组、角色／任务、成果、等待原因、缺失提示及结果入口；点击才导航，浅深主题、键盘焦点与减少动态效果仍可辨。真实 Hook 验证状态依据，快照不可用场景显示诚实的部分汇报。

## Out of Scope

- 按能力、最近使用、焦点或模型评分自动选人；首版只在明确项目具有唯一有效候选时自动选中。
- 因目标不存在自动创建角色、卡片或替代会话；明确新建并派工是另一类操作。
- 新增任务依赖、严格串行调度、抢占、中断旧任务或承诺 CLI 实际执行顺序。
- Agent 向其他项目卡片自主委派、任务树循环治理和相应预算授权。
- 完整桌面／手机群聊页面、全部历史呈现的一致性，以及工作空间归档或彻底删除后的历史保留期限。
- 自定义语音别名编辑产品、放宽名称格式、模糊名称匹配、保留旧称呼作为有效隐式别名。
- 卡片跨项目或跨空间迁移、同一目录文件隔离、自动创建 worktree、目录写入锁和冲突自动解决。
- 新的派工专用动画、常驻派工输入栏、快捷键或与本功能无关的工作空间页面重构。
- 端到端 exactly-once 承诺、未知副作用的自动重放，或仅凭模型文本确认工作成果已通过用户验收。
- 周期汇报、进度订阅、自动催办或推送配置；新的项目计划／里程碑管理、跨工作空间汇报，以及无可靠分母的业务完成百分比。

## Further Notes

- 本规格综合已经逐项确认的产品规则，并按用户要求补充主动汇报整个工作空间进度的场景，不重新发起需求采访；测试采用已讨论的共享分派模块与现有适配器入口。名称生命周期、CLI 队列、项目唯一候选选择、Dock 反馈与只读全空间汇报是本次实现合同。最近 24 小时成果窗口等新增默认值是本轮实施建议，不标作此前已确认决定。
- 历史 Issue #65 与 #70 提供桌面工作空间和跨项目派工背景。本规格以当前支持同目录多区域、手机复用桌面空间的实际模型为基础，补齐正式 Dock 与命名／实例调度／结果闭环；不把旧票关闭或测试特性中的 dispatcher 当作本规格已经实现。
- 既有 ADR 0016“多 Agent 委派先原子接收再独立投递”与 ADR 0020“Dialogue 约束任务，CardTask 以证据完成”继续约束原子接收、确定性派发、可信回执与幂等。本功能公开失败后的新尝试遵守用户确认的手动安全重试规则。
- 已有九项开发任务按“持久卡片身份 → 命名与失效占用 → 旧数据修复 → 完整目标解析 → 实例调度 → 通用操作与投递 → Dock 与共享入口 → 反馈及恢复 → 全空间进度汇报”推进；实例调度可在身份合同明确后先开发，正式入口等待命名登记和目标校验接通。进度查询复用已有 query 边界，不另建派工执行器。
- 首版完成必须覆盖已登记的普通 Coding Agent 卡片；若实施中发现能力限制，明确报告不支持原因，不在未说明范围缩减的情况下宣称任意卡片均可派工。
- 当前与目标运行逻辑如下；图中的“接收”与“提交”保持独立，不以输入成功代替任务完成。

当前正式桌面 Dock：

```text
用户指令
   ↓
当前项目上下文与 Agent 名单
   ↓
项目内名称 / 别名 → 定义 → 复用或激活卡片
   ↓
项目协调器接收 → 等待 CLI 条件 → 正文 / Enter 提交
   ↓
Provider CLI 执行 → 可信事件 → 本项目任务账本与界面
```

优化后的工作空间派工：

```text
全空间名称登记：有效称呼可寻址；历次旧称呼失效占用
   │  改名保留占用；角色彻底删除成功后释放
   ▼
固定来源工作空间与操作身份 → 同操作返回原回执
   ↓
执行意图 + 点名 / @ / 明确项目的完整候选
   ├─ 普通讨论：回复
   ├─ 全空间进度查询：只读聚合 → 带时间与覆盖说明的来源 Dock 汇报
   │                    └─ 当前事实 + 未加载快照；不创建任务、不启动 PTY
   ├─ 无有效称呼或零候选：保留任务、补全
   ├─ 多候选：用户选择
   └─ 唯一有效目标：绑定稳定卡片身份
                          ↓
                 按需加载与身份复核
                          ↓
                 整组预检与原子接收
                          ↓
                 每项沿用 CLI 队列提交
                          ↓
                 同 task / turn 的可信证据
                          ↓
                 来源 Dock 逐项状态与终态摘要
                   ├─ 点击回执才打开原卡片
                   ├─ 安全失败：手动重试并复核原目标
                   └─ 状态未知：先核对，不自动重发
```
