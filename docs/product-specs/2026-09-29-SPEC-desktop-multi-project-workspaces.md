## Problem Statement

桌面版当前以项目目录打开单张画布。用户同时处理多个项目及 Git worktree 时，需要在项目窗口间切换，无法在一个工作空间里查看和操作不同项目的 Agent，也无法把同一个项目放进不同工作空间并保留各自的卡片。

## Solution

桌面工作空间是一张本机总览画布，可以包含多个自动排列的项目区域。每个区域可展开为完整的项目画布；总览中仍能阅读、回复和指挥多个项目的 Agent。工作空间切换发生在当前窗口，切走后 Agent 继续运行。一个项目可以出现在多个工作空间中，各自拥有独立卡片与会话；不同 Agent 可以同时使用同一个 Git worktree。

### 术语和归属

| 概念 | 定义 | 归属 |
| --- | --- | --- |
| 桌面工作空间 | 有独立 ID 和名称的本机画布集合 | 本机桌面 App；与 iOS 协作 Workspace 不共用身份 |
| 项目 | 本地仓库或普通项目目录；同一项目可关联多个桌面工作空间 | 本地文件目录 |
| 项目区域 | 某工作空间对某项目的一处可见区域；同一工作空间内同一项目只出现一次 | 桌面工作空间 × 项目 |
| 项目画布 | 项目区域展开后的完整视图；与总览区域操作同一批卡片 | 桌面工作空间 × 项目 |
| Agent 卡片 | 属于一个项目画布的独立会话；新建默认使用所属项目区域目录作为 cwd，无需选择或确认 worktree | 项目画布 |
| Git worktree | Agent 的执行目录，不是项目区域或工作空间的身份 | 本地 Git 仓库 |

项目画布只显示 Agent 与 Terminal；网页和文件在工作空间级内容抽屉中打开。卡片不能在项目区域或工作空间之间移动。总览中的 Agent 卡片和展开后的卡片是同一会话的两种呈现，不复制会话。

### 用户流程

1. **进入首页**：桌面首页直接以工作空间画布缩略图填充主区域，移除顶部标题、说明和搜索横幅；搜索与新建集中在底部紧凑工具栏。首页按创建时间从早到晚固定排列（同时间戳按ID），新建追加末尾；打开或选择工作空间不重排，重启后保持同一顺序。每张工作空间卡片显示完整总览画布的缩小投影：项目区域按总览布局排列，每个区域内使用该项目画布的真实节点类型、边界和相对位置。已加载的会话显示实时卡片内容；未加载的会话使用保存的画布节点快照，不用项目名与通用矩形拼出假预览。1600 × 1000 的参考尺寸下一屏显示 12 个；较小窗口保持可读尺寸并滚动，不为凑数量缩到无法辨认。工作空间名称位于卡片内部的紧凑顶部标题栏，左侧名称、右侧「⋯」，与真实预览共用半透明外壳；禁止把名称悬挂在卡片外。项目数、最近活动和运行状态为次要信息，窄窗口优先保留名称与菜单，长名称单行省略并可查看全文。预览在标题栏下方等比显示，不与标题重叠，不为标题增加卡片外间距。空／加载中／非空卡片一致；点击名称或主体进入同一工作空间，菜单不触发进入。展开时标题随外壳淡出，返回时同步恢复。
2. **创建工作空间**：先在紧凑命名对话框输入名称，再创建并进入空项目总览；空状态提供「添加项目」。名称去掉首尾空白后须为 1–80 个 Unicode 字符，支持中文、允许同名但 ID 独立；不得自动以 `Workspace N`／`New Workspace` 代替命名。Enter 提交有效名称，输入法组词中不误提交；Escape／取消不创建记录或切换画布，提交中防止重复创建，保存失败保留输入供重试。所有新建入口共用此流程；项目目标选择器中新建时先命名，取消返回选择器且保留待添加项目。名称在目录缩略图和切换入口一致显示、可搜索并在重启后恢复，继续支持改名和删除。
3. **添加项目**：从工作空间的「添加项目」选择最近项目、本地目录或克隆仓库。选择 Git worktree 目录时识别所属仓库项目，同时保留所选实际目录作为该区域新 Agent 的默认 cwd；非 Git 项目直接使用项目目录。同一项目在当前工作空间重复添加时定位已有区域，不隐式替换区域目录或既有 Agent 的 cwd；在其他工作空间添加则创建独立的空项目画布。添加项目不自动启动 Agent。
4. **首页及菜单打开项目**：首页没有醒目的「打开项目／克隆」主操作。从首页触发 `⌘O` 或文件菜单选定项目后，用户选择目标工作空间或新建一个；在已打开的工作空间中触发时直接加入当前工作空间。克隆完成后遵循同一归属规则，不产生无归属的项目窗口。
5. **总览与展开**：总览按固定规则排列项目区域，不允许拖动区域或跨区域拖动卡片；项目多于可视范围时仍可到达每个区域。项目区域内按真实项目画布节点的边界和相对位置等比绘制缩小卡片，Agent 缩略卡片复用当前会话的卡片标题、状态和终端内容。单击 Agent 缩略卡片，在当前工作空间画布内展开为可读、可输入的同一 Agent 卡片，并定位到输入框可见的位置；再次单击该缩略卡片收起。输入框的空格不得触发项目区域展开；点击卡片右上角「⋯」中的 Open 进入完整项目画布，操作入口不得遮挡真实卡片标题。总览可回复 Agent、发送指令；输入不设置额外文本长度上限。展开项目画布后可查看完整终端与长对话、调整该项目内的卡片布局；返回总览保留该项目的卡片和运行状态。
6. **创建 Agent**：新 Agent 必须有明确项目区域，默认使用该区域已选定并保存的实际目录作为 cwd，直接创建，不弹 worktree 选择或确认；目录是 worktree 或普通非 Git 项目均适用，不自动新建／切换 worktree 或分支。没有目标项目时仅选择／添加项目区域。Dock、快捷键、项目菜单与自定义 Agent 入口采用同一规则。已有 Agent 的项目与 cwd 不随区域展开、工作空间切换、卡片布局或新默认规则变化；多个 Agent 使用同一目录直接允许。卡片可查看项目与实际执行目录，避免误认目标。
7. **快速切换**：同级项目通过底部编号或项目快捷键直接移动到目标 Agent 画布，使用 23 号原型的连续镜头和项目淡入淡出，不能先回总览，也不能清除全部动画；重复点击不重启，中途改目标保留位置与速度，减少动态效果即时到达。工作空间总览和展开项目使用原有 Canvas Dock，不增加第二条底部菜单或 Norma 派工栏。Dock 中的工作空间按钮或可配置快捷键 `⌘⇧K` 直接把当前画布切换为占满窗口的工作空间缩略图网格，不弹出居中对话框；可搜索、选择目标或返回当前画布。选择目标仍在当前窗口完成，不新开窗口。快捷键在项目总览、展开画布和卡片聚焦时可用，在 Settings → Keyboard Shortcuts 可录制和恢复。切换视图有选中、悬停、按下、键盘焦点和空状态反馈。选择工作空间时始终停留该空间的项目总览，保留总览滚动位置；不自动展开历史项目。用户明确点击项目或执行项目导航快捷键时才展开项目，其画布视口与卡片保持原状态。
8. **工作空间级 Norma**：左侧抽屉复用现有 `⌘E` 实时对话；明确指名项目时可向当前工作空间内其他项目的 Agent 派工，并显示逐目标回执。卡片内输入始终只作用于该卡片。工作空间总览没有聚焦项目时，派活前必须明确目标；只读查询可汇总当前工作空间。
9. **移除项目区域**：从当前工作空间移除一个项目区域会清空该区域的画布、卡片和会话关联。每次移除都先确认并说明影响；有运行中 Agent/PTY 时列出其数量。确认后只结束该区域的运行实例，取消则什么也不改变。重新加入同一项目得到空画布。仓库、worktree、项目级 Agent 定义以及其他工作空间中的同一项目不受影响。
10. **删除工作空间**：每次删除都先确认并说明该工作空间的项目区域和卡片将消失；如有运行中任务，确认后只结束该工作空间的运行实例。取消不产生副作用。删除不触碰项目目录、worktree 或其他工作空间；之后创建同名工作空间仍是新的空工作空间。

### 生命周期与失败状态

- 切换工作空间或收起项目区域只改变当前视图，不停止 Agent/PTY。未启用手机服务且没有后台项目时，关闭最后窗口沿用现有退出规则；手机服务开启后关窗只解除视图并保留运行实例。主动退出必须停止并回收所有运行实例。重新启动恢复工作空间、项目关联、画布和卡片的持久状态，不把已结束的进程显示为仍在运行，也不自动重放未完成任务。
- 项目目录被移动、删除或暂不可访问时，工作空间及其区域仍可见并明确显示不可用；不可启动该项目的新 Agent。原路径重新可访问时恢复；路径改变时不自动猜测新目录，用户可移除区域并重新添加。
- Agent 创建在后台校验所选区域目录及项目身份，捕获原始 workspace／area／目录；项目身份识别不依赖外部 Git 可执行文件，非 Git 目录可直接创建。异步结果不得因切换而投递到另一个项目，目标移除或失效时不得启动，失败显示可重试状态。不因取消选择弹层而绕过目录校验。
- 工作空间快照或项目画布保存失败时显示可见错误并保留当前内存状态；不能报告保存成功。总览缩略图可以暂用上次快照，但运行状态必须取当前实例，不能把旧快照冒充实时执行状态。
- 对多个项目派工时逐目标显示 `已提交／等待／失败` 等真实状态；请求澄清或单个目标失败不能使其他已成功目标重复执行。

## User Stories

1. 作为桌面用户，我想从位置固定的工作空间网格找到并打开目标空间，以便快速继续工作。
2. 作为桌面用户，我想创建空工作空间并添加多个本地项目，以便把一件工作的相关项目放在同一画布。
3. 作为桌面用户，我想在总览中直接查看和回复不同项目的 Agent，以便不用反复展开项目。
4. 作为桌面用户，我想展开一个项目区域使用完整画布，以便阅读终端、长对话和调整卡片布局。
5. 作为桌面用户，我想通过底部工具栏或快捷键切换工作空间，以便离开当前画布但让 Agent 继续运行。
6. 作为桌面用户，我想在两个工作空间中分别使用同一个项目，以便保留不同的卡片和会话。
7. 作为桌面用户，我想让不同 Agent 同时使用一个 worktree，以便自行决定协作方式。
8. 作为桌面用户，我想让 Norma 在当前工作空间内分别向多个项目派工，并看到每个目标的真实结果。
9. 作为桌面用户，我想移除项目区域或删除工作空间，而不误删仓库或另一个工作空间的会话。
10. 作为桌面用户，我想在重新启动后找回新工作空间及其画布，并清楚知道哪些任务已经结束。

## Implementation Decisions

- 桌面工作空间使用独立 ID；不得把现有按项目定义的 `workspace_id` 改成桌面工作空间 ID，也不得把桌面工作空间身份写入现有 iOS 协议。
- 项目区域和画布实例由「桌面工作空间 ID + 稳定项目身份」唯一标识。属于同一个 Git 仓库的 worktree 通过 Git common dir 归并为一个项目；Git worktree 是每张 Agent 卡片的执行目标，不参与区域去重。非 Git 项目以规范化目录身份识别。
- 默认 cwd 复用项目区域已有的 `root`，不新建目录选择模型。用户所说“项目作为工作空间”指 Agent 的执行目录，不把桌面工作空间与项目绑定，也不改写既有卡片的执行目录。
- 新桌面工作空间目录、关联关系、视角和每个画布实例的持久化数据独立于旧单项目画布存档。旧版画布与卡片不迁移、不自动导入，也不主动删除旧文件；本地项目可以重新加入。
- 桌面视图选择与运行实例生命周期分离；打开另一个工作空间不得走结束旧 Runtime 的旧项目替换流程。隐藏工作空间的运行实例继续接收输出并更新状态，但不连续重绘不可见画布。
- 首页缩略图来自各项目保存的真实画布节点；已加载项目直接读运行实例的节点与内容，运行状态独立实时更新。当前工作空间总览复用相同的卡片 chrome 与内容绘制器作为只读缩小投影，点击后展开的卡片仍指向同一运行实例，不另建 Agent 或 PTY。
- 工作空间级 Norma 使用当前工作空间内的项目／卡片身份进行目标解析；每个目标执行独立派发与回执，模糊目标需要澄清。
- 新快捷键进入现有可配置快捷键注册表及 Settings，不从底层 PTY 接收该按键。

## Testing Decisions

- 自动化以用户可观察的完整流程为主：真实工作空间身份、卡片归属、运行状态、切换、删除和重启恢复；纯单测只覆盖不依赖 UI 的身份、去重、路由与存储规则。
- 旧 `crates/e2e` 已停用，不新增、维护或运行。由所属 crate 单元/集成测试和 Computer Use 操作隔离真实 App 覆盖创建并添加 A/B、另一空间添加 A、同目录双 Agent、总览输入、展开、切换、移除与删除及失败路径；用真实 PTY/Agent 回执验证持续运行与精确回收。
- Agent 创建覆盖普通目录、Git 主目录、多个 worktree 下的已选目录、同目录并行与创建中导航／删除；至少用 Codex、Claude 验证各入口没有 worktree 弹窗、实际启动 cwd 正确，不只比较 UI 文案。
- 新页面、工具栏、缩略图与交互状态必须通过 Computer Use 操作真实 macOS App 验收；headless GPUI 和静态截图仅作补充。验证 1600 × 1000、默认窗口尺寸、键盘导航和减少动态效果。
- 共享项目加载、关闭和会话路由改动需跑现有手机后台项目回归；验收要求 iOS 页面、手机协议和既有项目级访问不发生回归。
- 代码改动后按涉及 crate 运行项目规定检查，真实 PTY 与隔离真实 App 按改动范围验收；不使用旧套件或其 L1/L2/L3 入口作为证据。

### 验收场景

| 编号 | 操作 | 必须观察到 |
| --- | --- | --- |
| DWS-01 | 从普通新建和项目目标选择器输入名称创建，验证空白／80与81字符边界／取消／失败／重复提交；搜索、改名并重启 | 合法名称一致展示并恢复；取消或非法输入无新增，失败保留输入，同名仍有独立 ID；项目上下文保留，无自动默认名称或旧单项目画布导入 |
| DWS-02 | 在工作空间甲添加项目 A、B，再次添加 A | 总览只有两个项目区域；第二次添加 A 定位已有区域，不创建新会话 |
| DWS-03 | 在甲总览点击 A、B 的真实 Agent 缩略卡片并分别输入，再展开 A 项目画布并返回 | 缩略卡片保留真实节点位置与内容；点击后在当前画布放大且可输入；两边只收到各自输入，展开前后的 A 卡片是同一会话，B 保持运行 |
| DWS-04 | 用底部按钮和 `⌘⇧K` 切到工作空间乙，再切回甲 | 当前窗口数量不变；甲的 Agent 在不可见期间继续输出；回到甲的项目总览并保留总览滚动位置，不自动展开历史项目 |
| DWS-05 | 甲、乙分别添加同一个项目目录／worktree，从各自区域直接创建 Agent | 两张画布与卡片独立，Agent 实际 cwd 为所属区域所选目录；无 worktree 选择、确认或锁，创建中切换／删除不投递到错误项目 |
| DWS-06（`⌘E` 对话） | 在甲向 A、B 派发明确的跨项目指令 | 路由层分别提交任务并产生独立回执；单个目标失败不重放另一目标 |
| DWS-07（`⌘E` 对话） | 在甲提交未指明项目的跨项目指令 | 路由层请求澄清；在回答前没有向任何项目派工 |
| DWS-08 | 甲/A 运行中尝试移除，先取消，再确认移除并重新添加 A | 取消时任务与卡片原样继续；确认后仅甲/A 停止、清空；重新添加为空，乙/A 仍运行 |
| DWS-09 | 删除含运行任务的甲 | 确认前甲和任务仍在；确认后甲消失、其运行实例被回收；乙和项目目录保持不变 |
| DWS-10 | 从首页通过菜单打开项目，或在乙中克隆项目 | 首页路径要求选择目标工作空间；乙中克隆结果直接加入乙；均不产生无归属项目窗口 |
| DWS-11 | 将项目目录临时移走并尝试启动该区域 Agent | 区域显示不可用且不启动任务；其他区域仍可操作，项目文件不被修改 |

## Out of Scope

- iOS Workspace 页面、同步、身份或手机协议改造；首版不要求手机感知、区分或控制新桌面工作空间的卡片。
- 旧单项目画布、卡片及会话迁移；不自动合并两个工作空间的卡片。
- 卡片跨项目或跨工作空间移动，工作空间之间共享同一画布实例。
- 同一 worktree 的互斥锁、二次确认或自动冲突解决。
- 触控板横滑切换工作空间；先使用底部工具栏和快捷键。

## Further Notes

- 桌面 UI 中可简称「工作空间」；规格和内部身份应明确称「桌面工作空间」，避免与 iOS 协作 Workspace 混淆。
- 早期效果图里的自由排列卡片不覆盖最终「项目区域固定排列、区域内保留项目画布」的决定。
- 新版默认快捷键选用当前注册表尚未占用的 `⌘⇧K`；用户仍可在 Settings 中修改。
- G0–G3 将现有 `⌘E` 对话接入工作空间内的跨项目路由与回执，不新增第二个统一输入服务，也不改变手机协议或现有 CLI 的项目寻址合同。
