# #57 / #59：线程可靠送达与单 Mac 派工

2026-09-29，实施规格。依据 A1 云服务架构、原生架构、现行 iOS 样式规范和 [本阶段 Goal](../exec-plans/2026-09-29-norma-ios-single-mac-goal.md)。GitHub CLI 已恢复读取并核对 #59：票据仍为 OPEN，明确包含真实派工、登录后后台接收与蜂窝网络验收；本轮仅本地运行，不能据本地联调关闭跨网络门槛。

## 1. 不变的产品行为

想法仍独立记录；讨论不自动执行。线程内 @Agent 必须回应、执行或明确说明失败。手机 Norma 负责云模型推理和派工选择，Mac 复用现有执行路径，不对同一手机消息再次默认推理。底栏和原型结构不变。

`collaboration_workspace_id`、`thread_id` 与旧协议的 `workspace_id`（Mac 项目）分开；手机长期保存 Mac / 项目 / Agent 定义身份，发送前读取最新 route 和卡片。成员与项目必须属于该 Workspace；跨线程引用带来源，不携带整库私聊、原始终端或私有推理。

## 2. 在线中继（首个实现切片）

在既有 `services/norma-cloud` 进程新增两条 WebSocket 路径：`/v1/relay/mac`、`/v1/relay/phone`。生产仅经 HTTPS/WSS，开发仅回环地址。旧语音和文字接口保持兼容；独立手机准入记录同时用于文字和中继，不另建云账户或把全局管理令牌下发客户端。

- **Mac 身份**：复用本机配对证书私钥。服务器发一次性 32 字节挑战，Mac 签名固定用途前缀、服务器 audience 和挑战；服务器核对 `NORMA_RELAY_TRUSTED_CERTIFICATES` 受控证书清单及证书 SHA-256 对应的 Mac ID。此清单是本地测试／服务端部署配置，手机不填写配置。失败、超时或重复身份不能顶掉在线 Mac。
- **手机身份**：Authorization Bearer 使用 #58 的独立受邀设备凭据。握手、打开通道和每次转发都检查当前撤销状态；不接受旧语音授权替代。云设备身份只允许占用中继，不能替代 Mac 上的配对与项目权限。
- **开通道**：手机发送 `{type:"open", request_id:<UUID>, machine_id:<Mac ID>}`；中继在线查找 Mac，为该连接生成随机 `stream_id`，两端收到 open。Mac 离线返回 offline，不建立队列。
- **转发**：双方发送 `{type:"data", stream_id, data:<base64>}`，只向该通道的另一端转发不透明字节。`close` 释放对应通道；断连通知对端。消息正文与操作身份只在端到端加密内容内出现。
- **边界**：握手 10 秒；单帧解码后最多 256 KiB；每连接最多 8 个通道、全局最多 8 个手机和 8 台受信 Mac；通道闲置 60 秒关闭；每连接每分钟最多 120 条控制或数据帧；输出累计超过 1 MiB 关闭慢端。所有定时器随连接释放。单实例内存目录，不存正文、队列或长期事件。
- **状态**：open/data 仅意味着路由可用／已转发，不返回 delivered/accepted/completed。中继失去连接后手机按原操作 ID 向 Mac 核对；中继从不替 Mac 签收。

Mac 注册签名输入为 UTF-8 `Norma relay registration v1\n` + `audience` + `\n` + 64 个小写十六进制字符的 challenge；ECDSA P-256 / SHA-256，签名 ASN.1 DER 转小写 hex，与既有 Mac 签名编码一致。注册内容 `{type:"register", machine_id, signature}`，服务器从受信清单找到对应证书验证。挑战不写磁盘。WebSocket 每 20 秒心跳，连续未响应在最多 40 秒内断开。

## 3. 端到端会话与授权（后续接入切片）

中继不取得配对 token 或任务明文。使用系统／现有密码库：手机与 Mac 生成 X25519 临时密钥；Mac 用既有配对证书签署包含协议版本、通道 ID、手机随机数及双方临时公钥的完整握手转录。手机先按已配对证书指纹验证，再以 HKDF-SHA256 分方向导出 AES-256-GCM 会话密钥。每方向单调序号作为 nonce 的后 64 位（前 32 位为零），转录摘要、方向和序号作为 AAD；拒绝重放、反向帧和乱序。新通道使用新密钥，不跨连接复用。以下精确字节格式由 Swift CryptoKit／Rust ring 与独立 Node crypto 互操作测试验证。

### 会话字节契约 v1

- 手机 hello：`{version:1, client_key, nonce}`，两个值均为 32 字节的小写 hex。
- Mac handshake：`{version:1, server_key, certificate, signature}`，均使用小写 hex；公钥 32 字节，证书 DER 最大 16 KiB，ECDSA P-256/SHA-256 签名 DER 最大 80 字节。
- 签名原文（UTF-8，末尾无换行）：`Norma collaboration session v1\n<stream_id>\n<nonce>\n<client_key>\n<server_key>\n<machine_id>`。stream_id 为中继返回的原始 UUID；machine_id 必须与手机已配对证书的 SHA-256 相同。先验签再发送配对凭据。
- `H = SHA256(签名原文)`；`K = HKDF-SHA256(X25519 共享秘密, salt=H, info="Norma collaboration keys v1", length=64)`；前 32 字节为手机上行，后 32 字节为 Mac 下行。
- 密文帧：8 字节大端序号 + AES-GCM ciphertext + 16 字节 tag；nonce 为 4 零字节 + 同一大端序号；AAD 为 H + 1 字节方向（上行 0／下行 1）+ 同一序号。每方向从 0 严格递增。帧最大 256 KiB，明文最大 262120 字节（262144 - 8 - 16）。序号耗尽必须重建会话。
- 对外中继 data 使用此完整二进制帧的规范 base64。握手也在不透明 data 通道内传输。会话密钥不落盘；协议或认证错误后连接适配器必须关闭该通道。手机握手只能消费一次，禁止复制会话计数器。

解密后复用原 device_id/token 认证和最新设备授权修订，协商 `collaboration_v1`。在端到端认证与能力协商完成前不得发指令；旧 Mac 保留既有配对／浏览，提示升级，不把旧项目消息冒充协作线程派工。

### 原生网络接入切片

Mac 手机服务持有唯一出站连接，后台连接固定服务地址；本地验收入口只允许回环地址。校验挑战 audience 与配置完全一致后签名，不跟随重定向。断线只重建连接，不重放应用请求。关闭手机服务立即取消连接与重连；权限改变会断开当前中继连接，所有通道重新认证（个人单 Mac 阶段的简单实现）。

每个通道先进行密码握手，再用端到端加密的旧请求信封执行 `authenticate`。首次接入只开放认证与 `snapshot`；每个请求重新核对 Mac 配对授权，禁止中继触发配对、语音或未实现的动作。认证响应只列出实际实现的能力；线程接收未完成前不得宣称 `collaboration_v1`。同一通道禁止更换设备身份，协议／认证失败直接关闭通道。

手机固定云服务地址、复用独立云设备凭据；开发只提供回环端口。每次握手及请求都有总超时，取消时关闭 socket；同一会话最多一个在途请求，避免并发响应串线或加密计数乱序。校验请求关联 ID、Mac ID、通道 ID；握手成功不等于 Mac 持久签收。网络测试要使用正式 Node 中继和真实 `MobileServer`，独立于尚未完成的 App 派工验收。

## 4. 操作、执行和事件

### 线程消息持久接收切片

消息同步与执行分别处理。`thread_message` 只保存频道可见消息副本，不启动 Agent；`thread_receipt` 按原操作查回执，`thread_events` 按当前 Workspace／线程游标补回接收事件。认证声明 `thread_delivery_v1` 时可使用这三项；完整派工仍由后续 `collaboration_v1` 声明，不能用接收能力冒充执行能力。

消息封套字段为 `operation_id`、`collaboration_workspace_id`、`thread_id`、`message_id`、`origin_device_id`、`project_ids`、`text`。前五项为 UUID，项目 ID 使用旧协议的稳定 ID；项目列表升序去重，1–32 项；正文非空、UTF-8 最多 64 KiB。超限保留手机原文，提示缩短后另发，不截断。首版目标为一个 Mac；没有关联项目或关联多台 Mac 时保留待发，不能擅自挑选电脑。准备发送后目标和封套固定，配置变更不能把同一操作改派到另一台 Mac。

幂等指纹为 SHA-256：固定 UTF-8 前缀 `Norma thread message v1\0`，接着依次写入目标 Mac ID、五项 UUID、项目数（u32 大端）、各项目 ID、正文；每个字符串先写 UTF-8 字节长度（u32 大端），再写原字节。重试不得改变大小写、项目顺序或正文。Mac 以已认证配对设备隔离操作空间；同 ID 改内容、同消息 ID 换操作、同线程换 Workspace／来源均拒绝。

Mac 同一 SQLite 事务保存线程归属、原消息和唯一接收事件，提交成功后返回 `state=received`、稳定事件 ID／游标、目标 Mac、操作／消息／Workspace／线程和指纹。每次接收、查询和补事件都重查当前配对授权以及封套的所有项目；讨论只需读权限，后续执行另查控制权限。Mac 的接收回执不表示 Agent 已接单、执行完成或用户验收。

手机追加消息时同一事务创建 outbox 操作和清理匹配版本草稿；未能确定目标的 outbox 可保留空封套。发送前把目标与完整封套原子冻结，重启不重建操作。收到回执后，校验上述全部归属和指纹，在同一事务保存回执并将消息标为 delivered；没有回执时保持 pending。旧消息按需补建一次 outbox，已交付消息不得退回 pending；错误回执不得推进状态或游标。

### App 投递接入切片

iOS 前台自动检查全部工作线程的持久待发记录，不要求停留在原线程；没有派工待发时每轮最多向每台 Mac 投递两条；有待发/待核对任务时改为一条消息加一个任务，轮次间隔至少 5 秒，以遵守中继帧预算。进入后台取消在途网络等待，重新进入前台先查原回执后续发。配置或权限错误按消息显示，不能清除原文或把另一线程标成送达。回执更新只刷新状态，不打断用户阅读历史的滚动位置。

Mac 开启手机服务时同时启动中继，复用既有停服／撤权生命周期。Release 使用固定生产地址；本地开发构建仅在 `NORMA_CLOUD_LOCAL_PORT` 为有效端口时连接 `127.0.0.1`，未设或非法时绝不回退访问生产。iOS 本地模式继续沿用端口及独立命名空间配置。本地联调仍需将该隔离 Mac 的公开安装证书加入本地中继受信清单，测试凭据不能写入正式配置。

手机原子保存消息及待发操作；操作包含稳定 ID、协作 Workspace、线程、来源消息、目标 Mac/项目/Agent 定义、必要上下文与版本。身份与任务正文不随重试改变；route / 授权修订是每次尝试检查的临时元数据。重复同 ID 同内容返回原回执；同 ID 改正文或归属拒绝。

Mac 持久保存线程归属和接收状态后才回「已送达」。进入既有命令去重／租约／Agent 执行路径，新增的是协作上下文绑定，不建第二套执行器。执行前再次校验当前授权与目标；已开始但执行结果不明时保持「结果未知」，不得自动重发副作用。

事件携带稳定 event_id、source_mac_id、Workspace/线程/操作归属和单调游标。手机校验后在事务中合并事件、更新消息／任务与游标；旧事件重复拉取不新增气泡，其他线程事件不能写入当前线程。回复、任务进展、成果引用分别呈现；Mac 接收、Agent 接收、执行完成、用户验收各有独立含义。手机离线时 Mac 继续已接收工作并保存事件，重连后补齐。

## 5. 验收对应

### 真实 iOS 页面派工验收（2026-09-29 接续）

- 复用真实 Codex L3 的隔离 Mac App、项目与正式本地中继；原生准备测试仅写入本轮临时配对/云准入，不能预填 Workspace、消息、任务或成果。
- `RealMacThreadFlowTests` 从正式 UI 新建 Workspace，选择真实目录中的项目和 Alice，创建线程并发送一次明确指令。通过标准：真实执行完成、具名回复、两个准确的冻结文件内容；执行完成不能自动变成验收通过。
- 重启 iOS App 后重新进入原空间/线程，仍只有一个原任务和一条 Alice 回复；真实项目的追加文件只能一行。此处不冒充 Mac/中继重启或跨网络验收。
- Computer Use 随后操作同一实际成果页并留图，再交独立只读 UI 复核。XCTest 截图和测试通过不能替代实际 Computer Use 操作。

### 单 Agent 派工接入契约

`thread_task` 接收手机已经决定的单 Agent 任务，不再次调用 Mac Norma 推理。任务固定 `operation_id`、协作 Workspace、线程、已送达来源操作/消息、Mac 项目、`agent_definition_id`、任务正文和上下文文本/版本；`route_id`、`grant_revision` 仅属本次尝试。上下文由手机从当前线程及共享事实生成，不能包含整个想法库或 Norma 私聊。首个接口只声明 `thread_tasks_v1`，尚不声明完整 `collaboration_v1`。

Mac 验证来源消息已持久接收、所有来源项目仍可读、目标项目在来源范围且可控制、当前授权修订一致。线程绑定与既有 `mobile_commands` 的预留同事务落盘；同操作改正文、Agent 或线程拒绝。换 route/授权修订重试只能返回原回执；已预留但结果未知不能重执行。旧 `command` 的身份/route 语义保持兼容。

前台按 Agent 定义 ID 找当前名称及启用状态，通过既有 `AssignAgentTask` 适配器和 FIFO 队列执行；沿用既有 lease、后台落盘确认和成果追踪，不新建执行器。`thread_task_receipt` 只返回同设备、同 Mac、同 Workspace/线程的持久命令回执及原绑定；其中命令 `succeeded` 仅表示派工被持久确认，不等于 Agent 完成任务。

派工成功结果同时包含 `task_ref`、`task_id` 与 `node_id`。`task_ref` 是既有任务库的 `<runtime_instance_id>:<task_id>` 持久身份；手机核对其数字后缀并保存完整引用。后续事件查询必须以持久引用定位，不能在 Mac 重启后仅凭可能复用的数字 task_id 查任务。

派工指纹使用 SHA-256：UTF-8 前缀 `Norma thread task v1\0`；依次写入 Mac ID、操作 ID、协作 Workspace、线程、来源操作、来源消息、项目，每个字符串先写 u32 大端 UTF-8 长度；再写 Agent 定义 ID（正数 u64 大端）、上下文版本（u64 大端）、任务正文和上下文字符串（同长度编码）。任务与上下文合计最多 32 KiB，规范 JSON 最多 64 KiB。两端不截断、不改大小写；重试不重新生成上下文。

本切片验收接口沿用 Goal 已确认的存储公开 API、真实中继到 `MobileServer` 网络接口及现有前台执行 seam：验证原子绑定、跨线程拒绝、同操作重试/重启不重派、撤权取消。使用截留前台请求的网络测试只证明路由与去重；真实 Agent 执行、结果事件和原生页面另需完整证据。

### 执行状态与成果回传契约

- 复用 `thread_task_receipt` 查询，新增可选 `execution` 事件；不会为结果另建执行器或自动重派任务。支持端声明 `thread_task_results_v1`。派工回执 `succeeded` 仍只表示 Agent 接收。
- Mac 先按设备、Mac、Workspace、线程、操作定位原绑定并校验当前来源项目读权限，再用持久 `task_ref` 读取原项目任务库；核验 Agent 定义、节点、数字任务 ID 和正文。项目根目录只来自 Mac 已登记身份；项目数据库沿用当前构建的数据模式，查不到时不创建空库、不按相同数字 ID 找替代任务。
- 执行快照复用已有任务状态和持久结果。未跟踪任务明确为 `untracked`；缺失记录返回空执行信息，不冒充运行或完成。回复预览最多 16 KiB UTF-8，超出时按字符边界截取并显式 `truncated=true`，原文仍留 Mac。
- 成果只关联原设备/操作持久绑定的完整 Provider 回合（节点、profile、run/session/turn），查询已有冻结成果元数据，不扫描当前目录、不取节点最新成果、不在回执中传文件字节。尚未捕获不显示可用成果；读取成果正文的后续入口仍须按此身份校验和分段传输。
- Mac 在同步读取时，将已持久任务快照的变化追加为稳定事件，序号单调递增；重复状态重用原事件，重启保留 ID。离线任务继续由已有任务/成果库保存，重连投影最新持久快照；不声称重建离线期间未保存的每次 UI 瞬态。终态不退回进行中、不换最终回复，只允许补上原回合成果。

### 冻结成果正文读取

`thread_task_review` 按原 Workspace/线程/操作、完整 task_ref 与已同步成果 fingerprint 读取，不接收文件路径或另一个 Provider 回合。每片重查当前设备及来源项目授权、原派工绑定与冻结成果；找不到原记录或指纹不符时拒绝，不能退回当前目录或同节点最新成果。读取已保存成果不要求旧项目窗口/route 仍活跃，也不重新捕获文件。

复用既有 ProjectReviewResponse 与文件/图片预览数据结构。序列化后最多 32 MiB，每片最多 160 KiB 原始字节，经 base64 后小于 214 KiB，给 256 KiB 中继载荷留出封套及加密空间；片可跨 UTF-8 边界，完整重组后才解码。请求显式带 offset，响应回显完整请求及总字节数；手机核验连续偏移/固定总长/身份/指纹/文件范围后才展示，取消或中途失败不显示部分文件。重试核对同一冻结指纹，不能变成另一次成果。

手机读取遵守现有中继帧限额，用户进入后台或离开页面取消在途读取。成果内容仅按用户打开时获取；线程自动同步继续只取元数据。验收通过和修改反馈仍复用既有命令通道，不能因成功读取而自动验收。

## 线程 Norma 编排契约（2026-09-30）

首个实现切片为正式 HTTP 候选动作边界，不表示手机入口和真实模型验收已完成。

- 手机收到后还须核对原回合及 Workspace/线程/来源消息，重验当前参与成员/项目，把 Norma 可见回复与稳定操作 ID 的任务在同一事务保存；失败不能留下部分任务。重复响应只读原记录，不能产生新操作。后续发送复用既有消息送达、派工和 Mac 最终授权检查；未完成手机接入前，`@Norma` 仍保持明确不可用，不能伪装上线。
- 自动化验收通过正式网关 HTTP 和 Swift 客户端验证：合法候选、纯讨论、错误来源、未知目标、截断、重复回合、撤销及与普通文字共享额度。供应商测试替身必须标记；真实模型回合另留证据。

接口预算沿用 Mac 派工协议：每项任务与其冻结快照的 UTF-8 字节数合计不得超过 32 KiB，即任务上限为 `min(8 KiB, 32 KiB - contextBytes)`。当前消息与 Norma 回复各至多 8 KiB，成员的每个描述字段至多 4 KiB，总请求仍受 64 KiB 限制。UUID 大小写不改变回合身份，普通文字与编排共享去重记录；无效或截断候选统一返回 `provider_invalid_plan`，不返回部分任务。

### 手机接入与恢复

- 发送 `@Norma` 时冻结当前线程快照和参与成员；仍复用原线程输入框，等待期间原草稿持续保存在手机。普通消息和直接 `@Agent` 路径保持各自含义。混合提及通过稳定成员选择消除同名歧义，将明确提及的成员 ID 放入当前快照供 Norma 判断。
- 不保存或展示模型半份候选。完整响应必须同时核对回合、Workspace、线程和来源消息；再用同一 SQLite 事务保存用户原文、Norma 回复、稳定任务操作及本轮记录。任务继续复用既有待发送队列，只有真实 Mac 回执改变送达/执行状态。
- 应用前重新检查当前空间、成员和关联项目。任何候选无效或目标已变化时整轮回滚，草稿保留。重复应用已落盘的同一结果读取原消息与任务，不重新解释当前配置；不同结果不能覆写原回合。
- 请求失败或 App 在完整结果落盘前退出，重启后保留原草稿，可再次发送；云端只推理，未落手机库的候选不可能已向 Mac 执行。落盘后退出则恢复原消息和待发队列。只清除发送时的草稿版本，等待期间新编辑的文字不能被清除。
- 不增加单独的 Norma 文字聊天页面。P05 的协调者回复沿用左侧具名气泡与 Norma 头像；发送按钮提供等待反馈，失败原因和重试通过原输入框呈现。原型保真、Computer Use 及独立 UI 复核仍为上线条件。

#### 追问正式中继与 Swift 契约（2026-09-30，基础切片）

- 连续追问的输入校验：复用同一原任务的已确认追问回合，以原回合或最近一次已确认追问回合作为当前终端锚点。其他任务/线程/设备、普通终端输入产生的回合不能冒充这条追问链。该锚点在后台从既有绑定、队列与 Provider 起点记录解析，在真正写入前于同一次前台更新核对 Agent、原 `task_ref`、route、run/session 及最新回合；不在 GPUI 前台查库。队列等待期间任务被替换须明确取消，不能刷新快照后跟随新任务。
- 手机追问保存在同一 Workspace SQLite 的独立记录中，来源消息与追问原子落盘；清除草稿只认捕获的 revision。追问不是新的执行任务；每份确认的新回合回复只追加一次，引用原任务及本次来源消息，保留原任务回复与成果。已确认签收后 Mac 账本丢失只报待核对，不重发。Mac 回执携带原派工的 `original_key`，允许尚未完成的原任务追问取得可信会话绑定；该值首次核对后固定，之后不得换绑。

- 通过 `thread_task_followup_v1` 协商；提交为 `thread_task_followup`，查询为 `thread_task_followup_receipt`。查询只返回原回执或 `null`，不建立新队列。新提交要求实际命令、快照和终端通道可用，不能接收一个没有工作线程的队列。
- 载荷包含独立追问操作、独立来源消息/送达操作、Workspace、线程、原派工操作、完整 `task_ref` 和用户正文；正文必须与已送达的来源一致，不能复用父任务的来源。正文最多 32 KiB，JSON 最多 64 KiB；Mac 身份与所有字段使用域分离的 SHA-256 长度前缀指纹。
- 回执保存原绑定、持久排队签收、实时队列状态，以及实际新回合的回复/成果。排队签收不表示 Provider 收到；只有队列确认的 `turn_id` 可用于读取本次回复。旧回合、错误节点/run/session、不同线程或成果身份均拒绝。响应上限为 256 KiB 减 16 KiB 外层预算，即 240 KiB。
- Swift 复用既有 `QueuedMessageStatus` / `MobileCommandReceipt` 的状态与身份校验，并额外核对原任务、来源、原回合及新成果。回执支持 Codable，保留回复正文；网络恢复只查询原操作，重复同操作保持原执行 route。
- 当前基础切片已覆盖连续两次追问及真正输入前的任务归属检查；手机以 `thread_followup_outbox` 原子保存来源和独立追问，回复引用原任务及本次来源。恢复复用现有单任务轮转，每个前台周期只处理一个任务或追问，保持最多 108 帧/分钟的既有预算。正式 Swift→Node 中继→Rust MobileServer→SQLite 的重启恢复、重复回执与丢账本不重发已验证；Provider 前台仍为明确 fixture。W06/P05 追问入口与回复对象草稿已实现，标准/AX5 原生追问流程通过；独立 Computer Use 正在复核。追问新成果读取、嵌套成果返回与真实 Coding Agent 验收尚未收口。

### 终端输入权仲裁（实施中，2026-09-30）

- 接管首先绑定原任务已确认的 Provider 回合，再占用同一个 run/session 的输入权；它暂停 Norma/自动派工向该终端写入，不宣称冻结 Coding Agent 已经执行中的推理、工具或进程。已有输出继续可读，任务完成态仍以真实回执为准。
- Mac Runtime 是输入权的裁决方。持有期间桌面键盘、普通手机输入、自动派工、消息提交和审批/中断快捷键都不得绕过；持有者仍走原屏幕签名、输入序号、文字校验和 PTY 写入路径。取消任务的显式控制必须先按正式流程交还输入权，不能偷偷注入停止键。上层接入时，控制标识须由 Mac 生成并绑定已认证的设备/接管命令，不得直接把客户端自选 operation_id 当作跨设备输入权凭据。
- 只在没有未提交文字、待确认 Enter、消息提交、审批提交或中断提交时取得输入权。重复的同一次接管可续期，不同持有者拒绝；旧 run/session、无真实回合及非法标识拒绝。上层必须验证设备/项目授权及原 task_ref，Runtime 方法不替代授权。
- 输入权为 15 秒内存租期（预定每 5 秒确认一次，可覆盖两次遗漏），到期或会话替换后失效；续期必须在到期前发生。输入本身不隐式续期，过期旧输入不能重新取得控制。Mac 重启不恢复过期输入权。
- 交还/到期都不删除或自动提交用户留在原终端的文字。自动派工在已有草稿时继续等待；用户可回到桌面处理原草稿。人工输入引起后续 Provider 回合时，不把新回复冒充原任务结果；原任务终端读取仍保持精确回合校验，受控后续回合的界面与回执将在接管协议接入时补齐。
- 自动派工与会话追问复用既有队列，接管/人工草稿保护期间保持 Queued；交还且输入可用后恢复原阶段，不丢弃或重建任务。原自动提交失败后的清理/重试保持原行为；迟到的同一回合 Hook 不能确认新人工 Enter。
- 本切片先实现并验证 Runtime 仲裁与自动派工入口；中继接管操作、授权撤销/离线释放、W06a 输入界面和真实 App 验收仍属于必做后续，不能据域测试将 W06a 标为完成。

#### 断线与撤权的输入租约（实施中）

- 网络侧持有 Mac 创建、绑定原 `MobileTurnKey` 的不可反序列化租约；Runtime 只接受该对象，不能用手机传来的字符串取得输入权。
- 租约可由后台线程撤销。每个输入入口、续期和自动队列检查都读取同一撤销状态；撤销后立即失效，不必等待前台收到额外消息或15秒到期。正在进行的单次PTY写入不能回滚，回执仍须按实际结果记录。
- 交还、到期、换会话、删除节点和释放Runtime都会永久撤销旧租约。后续即使另一个人接管又交还，迟到的旧续期也不能复活原租约；只保存当前对象，不添加无界历史集合。
- 断线/撤权不清空也不提交人工草稿。没有草稿时，已有自动任务/追问队列正常继续；有草稿时继续等待用户处理。
- 该对象是Mac内部能力，不是完整网络协议。后续正式中继须将租约绑定已认证连接、设备及持久接管操作；连接关闭、设备撤权和服务停止必须调用撤销，再接入持久输入回执及W06a页面。

### 正式中继终端接管协议（实施中）

- 公开验收边界沿用正式中继 RPC、App 前台命令和 Runtime 原 PTY，不建立新执行器。`thread_task_terminal_control` 只接受原任务来源和 Claim/Input/Release/Read 操作；普通 command 不能反序列化内部接管命令。
- Claim、Input、Release 使用既有持久命令回执和操作 ID 去重。相同操作改正文或任务必须冲突；丢回执只核对原结果，不重放。重连读到旧 Claim 成功不代表新连接持有输入权，须新操作显式接管。
- 接管能力绑定认证设备、连接和原任务。Read 只续期已经取得的同一输入权，不能隐式接管；历史页不可输入。续期不写持久命令表，复用原终端读取通道。
- 正常关闭、处理中连接取消、设备撤权及停服永久撤销租约；延迟到达的前台 Claim/Input 不能越过撤销。已写入 PTY 的字节不能回滚，结果不明不自动重发。
- 手机不能指定 node/run/session；Mac 从原持久派工推导。首次接管检查完整原回合与协调任务，受控人工后续回合仍保留原任务来源并展示真实当前回合。
- 本地网络测试须覆盖重复输入、冲突、错误线程、重连后的旧 Claim、断线和撤权。前台 fixture、录制 PTY 与真实 App 验收分别报告；协议测试通过不等于 W06a 页面交付。

### 手机终端操作保存与恢复（2026-09-30）

- 验收边界复用正式中继 RPC 与手机 CollaborationWorkspaceStore：显式接管/输入/交还先保存稳定操作及原任务、设备、回合与输入参数，再允许发出；不建立新的自动执行队列。
- `lookup_only: true` 只查询同内容的已有控制回执；未到 Mac 的操作返回 `not_found`，绝不创建记录、派发或取得输入权。普通提交保持已有能力协商；查询不得回退为执行。Read 不能使用该标志。
