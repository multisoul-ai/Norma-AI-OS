# Norma Spatial：自由画布上的 AI 开发团队

原型位置：`spikes/norma-spatial-prototype/`。使用 `prototype` 技能的 UI 分支，先探索三个结构不同的方案，当前按反馈默认进入 VR 空间。Norma OS 当前是 Rust/GPUI macOS 应用，没有可承载 VR 探索的 Web 页面，因此原型独立放在 `spikes/`，没有改变生产运行时。

## 当前产品结构：执行状态与阅读内容分开

用户最新反馈：看不到任务执行进度和正在运行的 Agent；内容不必全部固定在同一张画布里。

当前 VR 默认展示一个正在执行的模拟任务。左侧为独立的「任务与 Agent」空间面板，持续显示总体进度、运行人数、各 Agent 百分比、状态和当前步骤。点击 Agent 行将其 CLI 或结果放到中央。中间默认专注 Codex CLI，按需切换到其他成果。自由画布作为一种可切换的组织方式保留。

进度面板与中央内容使用不同的 Three.js mesh 和变换，可以分别抓取摆放。切换内容不会隐藏任务进度，也不改变执行状态。常驻四项工具；距离、大小、团队详情、成果选择等按需出现。用户无需将所有内容同时铺开。

「对话」打开空间内 Norma 窗口，展示识别内容、回复、语音状态和错误反馈。浏览器支持时可持续 ASR / TTS；播报时暂停识别，结束后自动恢复，点击可打断。无麦克风时使用显式标记的演示指令触发相同任务状态机。意图解释为本地 mock 规则。

## 产品问题与边界

用户表达目标，Norma 协调多位 Agent；执行过程、当前上下文与成果始终可见、可接管。原型选用仓库 `crates/runtime/src/route.rs` 的输入路由任务作为具体演示。任务执行、分支、改动与验证均为 mock；不会启动真实 CLI 或写入仓库。

成果面板实际分别渲染 CLI、diff、审查文档、实时条形图、网页与图片，以及可旋转三维对象，不再用相同的占位面板代替。任意内容承载是产品扩展方向，当前没有通用文件导入或外部网站运行能力。

画布上的节点可摆放、添加与编辑；笔迹使用世界坐标。当前通过笔迹包围盒与节点区域相交关联内容，发送时携带标注数量和节点标题；尚未实现手写识别与视觉语义分析。

## 玻璃画布与待决策卡片

按新增反馈，主画布改为可透出环境的磨砂玻璃：环境采样、轻微边缘折射、细薄高光和独立清晰的内容层均在 Three.js 材质中渲染，WebXR 与浏览器预演使用同一场景。玻璃采样当前静态环境，不是系统透视相机或任意物体的通用实时折射。尊重减少透明度与增强对比度偏好；没有增加循环动画。

右侧「需要你决策」为独立可抓取的空间卡片。当前演示先由验证 Agent 请求测试范围，只有选定范围才从“等你决策”进入执行；普通“全部继续”不能绕过该事项。卡片包含所属 Agent、需要决定的问题、原因、Norma 建议、相关内容入口和两个明确选择。全队完成后产生验收事项，支持查看 diff、确认或退回 Codex 补充检查；无待办时卡片缩为简短状态。

采纳 `apple-design` 的材质层级、直接操作与减少透明度原则，以及 `emil-design-eng` 的克制视觉反馈；参考 [Apple 材质规范](https://developer.apple.com/design/human-interface-guidelines/materials)。玻璃只柔化环境，CLI 文字不随环境模糊；菜单清除覆盖区域的旧文字，避免两层文字透叠。

新增两项决策测试，覆盖阻塞范围、明确解锁、替代选择、重复点击、退回补充与最终确认。当前共 24 项单元测试及类型检查通过，构建通过。Computer Use 分段执行 `crates/e2e/browser/norma_vr_decisions.mjs` 的 12 项断言，覆盖范围决策、内容切换和验收；等待模拟执行时遇到工具单次轮询期限，读取可见完成状态后继续完成验收。证据位于原型 `outputs/vr-glass-decisions-evidence.json`。

## 多任务待决策队列

右侧默认呈现 5 个独立任务待办，每页 4 项。列表包括任务、问题摘要、负责 Agent 和总数；点选任意项后在中央打开独立详情，右侧仍可继续浏览或切换。查看上下文关闭详情但保留待办；明确选择只移除对应项并继续对应任务，不自动跳入下一个决定。页码在末页删空后钳回有效页。当前任务的最终验收可与其他待办并存。

为验证任务隔离，首页、预览、文档和兼容性任务拥有各自的 mock 状态与进度；主任务的验证范围不会被其他任务的决定解锁。全局暂停也覆盖这些独立任务。当前共 26 项测试、类型检查和构建通过。Computer Use 执行 `crates/e2e/browser/norma_vr_queue.mjs` 的 13 项断言，验证任意选择、详情切换、分页、独立处理和清空。证据位于 `outputs/vr-multi-decision-evidence.json`。

## VR 交互设计评估

当前是可交互的空间工作台原型，尚不能视为经过头显验证的成熟 VR 体验。它采用世界固定窗口、远距离选择、克制的常驻控件和玻璃层次；主要欠缺是三列信息密度、侧边文字的视角尺寸、详情覆盖上下文、持续操作的手眼舒适性，以及语音与捏合的真实设备验证。

参考 [Apple：Principles of spatial design](https://developer.apple.com/videos/play/wwdc2023/10072/) 的自然视线、舒适距离、世界固定、尽量少移动与微妙深度原则，以及 [WebKit 的自然输入说明](https://webkit.org/blog/15162/introducing-natural-input-for-webxr-in-apple-vision-pro/)。浏览器预演通过不能替代佩戴头显的阅读、误触与疲劳验证。后续应优先降低外围信息密度、按视角评估目标与文字尺寸，并让决策及其证据在同一主要阅读区更清楚地关联。

## 历史对照方案

| 方案 | URL | 设计问题 |
| --- | --- | --- |
| A 空间工作台 | `/?compare=1&variant=A` | 团队、自由画布与任务侧栏，是否足以支持持续指挥？ |
| B 双终端驾驶舱 | `/?compare=1&variant=B` | 让宽画布占据主体，能否通过 CLI 和标注完成大部分协作？ |
| C 任务指挥台 | `/?compare=1&variant=C` | 目标、执行阶段与工作画布并列，是否更容易掌控复杂任务？ |

底部浮动原型切换器、左右键和可分享查询参数。文本编辑时不拦截方向键。Vinext 的 router.replace 在本原型中会重新挂载会话，因此使用其已拦截的 History API 配合 useSearchParams 同步查询参数，保留内存状态。三个方案共享任务与画布状态，刷新清空，不持久化。工作台、专注与空间漫游是另外的使用模式，用 `mode=workspace|focus|orbit` 表达。

## 可体验的闭环

1. 给 Codex 输入目标，终端逐步显示模拟 Read / Search / Write / Test 输出。
2. Ctrl+C 或自然语言暂停指定会话；继续保留上下文。Claude 可接收 Codex 的目标进行独立审查。
3. 在任意内容附近画线、圈出问题，撤销/重做或擦除，再把标注交给 Norma。
4. 拖动标题摆放节点，拖右下角调整大小；滚轮平移，Cmd/Ctrl+滚轮锚点缩放，空格临时移动画布。
5. 添加图片、网页预览、diff、CLI 或可编辑便签。任意内容承载是可扩展方向，当前为六种 mock 节点，不宣称已支持任意文件格式。
6. 空间漫游由 Three.js 实际渲染，WebXR 会话使用同一场景与状态。面板上的画笔可绘制，选择可移动节点；窗口可拖动、固定、缩放、调整远近与居中；三维构型可旋转。
7. 通过空间内对话窗口使用连续语音或演示指令。回复结束自动继续聆听，点击可打断；原型的理解与回答为本地规则。

## Apple 原则的落地

使用 `apple-design`，动效参考 `emil-design-eng` 与 `review-animations`。仓库锁文件指向的本地技能目录缺失，本轮读取同来源上游版本。技能没有导致额外审批。

| 原则 | 本次实现 | 验证 |
| --- | --- | --- |
| 内容优先 | 中央专注内容，独立执行状态面板，自由画布按需进入 | 真实浏览器输入与内容切换 |
| 直接操作 | 标题拖动、大小手柄、世界坐标笔迹、锚点缩放 | 指针拖动、绘制、擦除与恢复 |
| 用户掌控 | 点名中断、会话上下文保留、标注后明确发送 | 24 项聚焦测试与浏览器流程 |
| 层级与材质 | 静态自然环境、半透明控制层、较实的内容层 | 精简版桌面与空间漫游视觉检查 |
| 即时反馈 | hover、pressed、focus、selected 与 disabled；笔迹跟手 | 真实鼠标和键盘操作 |
| 空间稳定 | 世界固定面板，无自动镜头运动；重新居中跟随当前方向 | 三维预览拖动与绘制 |
| 可替代输入 | 文本替代语音、键盘操作、减少动态效果 | 输入方向键保护与媒体偏好样式 |

WebXR 自然输入参考 [WebKit 官方说明](https://webkit.org/blog/15162/introducing-natural-input-for-webxr-in-apple-vision-pro/)：通过 session selectstart/selectend 处理 transient-pointer，不固定输入源索引；target ray 用于选择，grip 位移用于捏合移动。没有请求持续眼动数据或完整手骨骼。

## 验收记录与限制

- 前轮 VR 主路径（新增右侧决策前）：Computer Use 在独立的 1280×720 真实预览中执行 `crates/e2e/browser/norma_vr.mjs`，8 项断言通过，涵盖初始运行状态、点名暂停、通过进度面板打开 Claude、全队暂停以及报告/图表/网页/三维对象切换时的进度保留。
- 真实指针操作另确认三维模型旋转、进度面板单独抓取，以及在空间对话中恢复指定 Agent。

- `npm test`：24 项通过；新增独立活动进度、连续语音交接、打断与过期回调清理、无语音能力反馈、空间菜单与演示指挥测试，并涵盖协作状态、暂停恢复、确认、独立 CLI、审查上下文、笔迹恢复、关联节点、锚点缩放与 VR 坐标映射。
- `npm run typecheck`、`npm run build` 通过。Three.js 的 bundle 有体积提示，未作为生产体积优化项目扩展范围。
- 前轮 Computer Use 在旧比较页面完成 14 项共享流程断言：默认 CLI、独立输入、中断、保留内容、Claude 接手、diff、添加图片、变体结构和状态保留、输入框方向键保护。
- 另有 7 项共享指针流程断言通过：绘制、撤销、重做、擦除、关联 CLI 发送、节点移动和键盘缩放；空间绘制与返回后共享笔迹另外经 Computer Use 验证。
- Rust `cargo test -p e2e` 被本机缺失 Xcode Metal Toolchain 阻断，没有伪称通过。浏览器 runner 存在 `crates/e2e/browser/`，与 GPUI 测试分开。
- 未完成真实头显佩戴、持续自然捏合精度和真人语音识别验收。空间总览文字需要头显评估；可切到独立终端阅读。
- 本机入口为 `http://localhost:3000/`。远程头显需可信 HTTPS；当前没有在线部署，不能把局域网 HTTP 作为已可用的头显地址。

## 待验证的产品结论

已按反馈采用独立任务进度 + 当前内容的 VR 结构，保留渐进展开和可选自由画布。后续实机评估阅读角度、持续佩戴舒适性、捏合精度和语音服务可用性。

正式实现需独立设计内容适配协议、PTY 会话桥接、真实 Agent 调度、语音中断、恢复与持久化。原型只用于选择体验方向，胜出后重写并删除未选变体。
