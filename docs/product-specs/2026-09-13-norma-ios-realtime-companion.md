# Norma iOS 实时虚拟人指挥台

2026-09-14 · 首版功能已实现，v49当前代码的豆包云端与真实 Codex/原生模拟器闭环已验证，按用户最新要求以豆包对话验收收口。GPT 云端、物理设备与用户界面验收延后，不阻塞本轮开发。产品中成果仍需用户明确验收，不能自动通过。本文不代表功能已上线。

## 1. 背景与目标

用户在地铁或路上戴着耳机，与 Norma 实时讨论想法、安排任务、查询进度并接收成果反馈。把 companion 虚拟人模式纳入 Norma iOS 指挥台，执行仍复用 Mac 上的 Agent 卡片和队列。

本规格扩展[原 iOS 产品提案](2026-09-06-norma-ios-companion.md)。本次改动、阶段与证据统一记录在[实时指挥台 Goal](../exec-plans/2026-09-13-norma-ios-realtime-command-goal.md)；其他既有能力以[原 iOS 实施计划](../exec-plans/2026-09-07-norma-ios-goal.md)和源码为准，不沿用旧提案中的“尚未实现”等历史状态。

### 1.1 当前产品目标（2026-09-22）

**让一个人可以跨仓库指挥多个 Agent，同时把人的注意力维持在一个稳定入口。** Agent 的并行度可以增长，但用户不应被迫在项目、终端和会话之间反复巡检。

- `Work` 默认汇总所有项目的 Agent Card，项目只作为过滤条件，不成为信息孤岛。
- `Inbox` 是唯一主动争夺注意力的入口，只收决定、风险、失败和待验收成果；普通进度保持安静。
- Agent Card 是稳定身份和可接管的手机工作空间。点击后使用层级导航进入全屏详情，而不是桌面式弹窗；用户可查看任务目标、执行方案、当前步骤、关键动态和交付证据。
- 用户对某张卡片的追问、补充或退回必须回到同一 Agent Card，不复制任务，不把上下文散落到新的聊天线程。
- Norma 负责跨仓拆解、合并进展和控制打断频率；用户负责目标、边界与关键判断。

当前产品链路为 `Thought → Mission → Agent Card → Plan → Run → Artifact`。本节记录设计目标，不代表原生 iOS 已完成相应界面迁移；HTML 原型用于先验证交互。

## 2. 已实现首版范围（实施基线）

以下记录 2026-09-14 首版实现边界；其中“通话绑定一个项目、不新增跨项目规划”的限制不再约束 §1.1 的当前产品设计目标，后续原生迁移需单独立项和验收。

- 用户主动开聊后持续通话、允许插话；前台显示角色、表情与嘴型，锁屏暂停角色渲染并继续音频。
- 一次通话绑定一个项目；浏览其他页面或项目不改变派工目标，明确要求换项目才切换。
- 通常在一个项目安排任务，不新增跨项目规划体系。
- 支持讨论、派工、查询、完成汇报，以及 Web、手机端、桌面端界面成果的用户验收。
- 不在手机运行 Coding Agent，不新增通用远程桌面。
- 原生界面采用已选 v1「陪伴」方向，删除旧指挥台页面和专属布局，不保留旧版开关。底部仍为「项目 / 指挥台 / 任务」，其他模块交互保持现状；必要工程、生命周期、通知路由与 Mac 工具接线按 Goal 白名单实施。

## 3. 用户意图与执行边界

讨论期间可查询、分析、整理方案；“这个思路不错”不等于开始执行。“那就把这个改好”等明确执行意图出现后，Norma 自主选择 Agent、拆分并派工，不要求固定口令或逐项确认。

任务正文需保留讨论中的目标、约束和交付标准。需要补充决定时提出具体问题；已有权限和执行边界继续适用。长任务先返回真实接收回执，允许对话继续；只有真实完成结果才能用于完成汇报。

插话与挂断不取消已派任务。取消需要用户明确表达，并取得执行层回执。

## 4. 运行流程

~~~text
iPhone / 耳机                         实时语音模型
  |                                    |
  |<========== WebRTC 音频 ============>|
  |                                    |
  |  已配对控制通道：会话绑定信息         | sideband：工具调用 / 结果
  +------------------> Mac Norma <-----+
                         |
                   共享工具定义与校验
                         |
                   现有编排入口 / 队列
                         |
                    Agent 卡片执行
                         |
                  接收回执 / 任务事件
                         |
          +--------------+---------------+
          |                              |
     通话中简短汇报                 现有成果 / 通知入口
          |                              |
      继续讨论                    有界面变化：待你验收
                                         |
                                通过 / 退回原任务修改
~~~

开聊和明确切换项目时，从 Mac 已授权快照提供当前项目概况、Agent 名单和任务摘要，并标记采样时间。名单复用桌面项目定义，包含尚未打开卡片的 Agent、准确名称、语音别名和启用状态；不能把“未开卡”当作“不存在”或把禁用 Agent 当作可派工。初始概况沿用桌面最多 32 个 Agent 的预算，并包含最多 16 张卡片的任务摘要，总计不超过 24KB；任务标题和摘要各最多 240 字符，路由所需的名称与别名不截断，省略数明确标记。快照不可用时明确未知，不能当作空项目；详情和最新进度按需查询。普通聊天直接由实时模型完成，不串行经过桌面 NormaSession 的另一次 LLM 推理。

## 5. 复用与接入方式

| 能力 | 接入决定 | 实现与验收边界 |
|---|---|---|
| 虚拟人、采集和播放 | companion 必需源码、真实模型与资源已迁入 Norma；原工程只读，不依赖本机绝对路径 | Swift 6、资源校验与原生入口已验证；来源已记录，模型对外分发授权仍待确认 |
| 实时语音 | 豆包 WebSocket/PCM 与 GPT 原生 WebRTC 已迁入，共享 App 级通话生命周期 | 豆包真实云端及模拟器实际系统后台已验证；物理耳机、锁屏 30 分钟和声学测量未完成 |
| 工具执行 | 复用 Norma 工具目录、参数校验、权限、预算、执行入口、队列和持久回执 | Rig 与实时入口已共用约束，重连/重启去重和取消已有回归证据 |
| Mac 接入 | GPT call_id sideband；豆包媒体身份与一次性工具票据；均经已配对控制通道绑定项目 | 豆包本地新网关真实云端闭环已验证；GPT 官方同项目凭据验收仍待完成 |
| 后台项目 | 沿用现有手机服务与后台项目生命周期，无 Window Adapter 已接线 | 真实 Mac App 无窗口派工、挂断保留任务与主动退出已有 L3 证据 |
| 成果与通知 | 复用当前任务、成果、审批和通知定位入口；执行、验收、语音已播分别记录 | 豆包成果与真实 PCM 播放已验证；GPT 云端汇报待验收；APNs 按既有决定不部署 |

豆包在 Norma 本地新网关已支持语音、角色行为、Mac 任务工具与独立 TTS 汇报；默认线上旧网关尚未部署这些更新，旧网关仍按实际能力降级为聊天。不能将豆包会话伪装为 GPT 媒体身份。以下 sideband 约定适用于 GPT。

Realtime sideband 使用 call_id 协议；不混用 GPT-Live 的 session_id/attach 协议。实时模型通过 function 工具调用应用执行层，无需为本机再建立公网 MCP 服务。

手机使用短期凭证；长期项目凭证留在服务端或 Mac。Mac 的 sideband 认证必须有权访问相应实时会话；会话绑定不能绕过设备配对与项目授权。语音凭证与会话建立不能依赖 Mac 始终在线，否则无法满足离线仍可聊天。

## 6. 状态与身份

沿用现有设备、项目、Agent 卡片、任务与 operation_id 身份；新增会话绑定所需的最小关联信息，不创建第二套任务模型。

- 任务工具调用只有一个执行方：Mac。手机收到同一调用事件时不得重复派工，仅处理本地角色行为工具。
- 同一操作恢复先查原接收回执；Mac 在既有 SQLite 中执行前保存调用占位和共享回合预算，重连/重启不重置预算。未完成占位或 unknown 冻结回合，手机只读核对原电脑和项目，不能补发任务。
- 区分未提交草稿、接收回执、执行中、待决定、待验收、完成与失败；这些是显示语义，优先映射现有任务状态及验收元数据。
- 执行完成、用户验收通过、语音已经播放是不同事实，不共用一个“完成”标志。
- 重连先核对回执并补齐事件；未提交想法保留完整原话与说话时绑定目标，不自动当作新任务执行。项目菜单提供「讨论草稿」与「任务操作记录」；损坏文件保留并提示，接收、执行、验收与已播放分别记录。

## 7. 汇报与交互

任务接收时简短确认，普通进度随问随答。普通完成事件约 5 秒合并，播报控制在约 10 秒内；这些是体验默认，需真机调优。

GPT 与豆包均已接入上述汇报队列；豆包本地新网关以独立 TTS 播放真实成果摘要，不为汇报额外调用 Chat。旧网关未声明汇报能力时保留队列与可见状态，不声称已播。播放中进程退出后保留「播放待核对」，由用户明确恢复汇报后重试。

用户讲话时汇报排队；需要用户决定的事项优先在一句话结束后提醒。支持“先别汇报”“等会儿一起说”，不暂停任务。通话中用任务事件汇报；挂断后通过既有成果和通知入口继续反馈。

Apple 设计原则落实为：当前绑定项目持续可见；输入立即反馈；通话与任务状态明确分开；弹层可直接关闭；主要触控目标至少 44pt；支持 VoiceOver、动态字号与减少动态效果。通话由 App 生命周期持有，浏览其他页面、项目或电脑不改变绑定，也不建立第二通话。

[实时指挥台交互原型](../prototypes/norma-realtime.html?v=4)以「虚拟人主场 + 全局 Work + 全屏 Agent Card」为当前设计基线。对话、想法、执行空间与电脑注册使用手机 Sheet 或全屏层级；v28 工作台 HTML 已归档，不再作为当前入口。HTML 共用本地演示状态，角色为示意，不采集麦克风、不执行任务，也不提供真实构建或锁屏通话；[原型验证记录](../prototypes/assets/norma-realtime/validation.md)不代表原生功能通过。正式页面使用真实角色，锁屏与后台通话使用系统能力。

## 8. 成果验收

| 成果类型 | 交付给用户查看 | 完成判定 |
|---|---|---|
| Web 页面与交互 | 手机可打开的交互预览、截图、验证结果 | 用户查看并明确验收 |
| 手机端页面与交互 | 对应设备测试构建、录屏、验证结果 | 用户在对应设备实际操作后验收 |
| 桌面端页面与交互 | 录屏、截图、测试构建 | 用户在桌面设备实际操作后验收 |
| 非界面任务 | 约定产物与验证证据 | 按任务验收条件判断，区分通过、失败、未验证 |

实现和自检结束后，有界面变化的任务进入“待你验收”。用户可以稍后查看，不阻塞无依赖的其他任务；修改意见返回原任务，新版本重新验收。截图、录屏和 Agent 自检不能替代用户对实际交互的确认。

## 9. 异常与恢复

- Mac 离线：语音仍可聊天，明确无法派工或获取最新状态；指挥台与通话设置显示最后一次 Mac 项目概况采样时间，保留草稿。重试不刷新旧时间；明确换项目或开始新通话清除旧时间，旧版 Mac 未提供时间时不伪造当前日期。
- 手机切网、音频中断、耳机断开：呈现准确连接与音频状态；恢复后核对任务回执，不重复执行。
- 锁屏：保持用户主动开启的音频会话，暂停角色；审查凭据在锁屏恢复时的可用性。
- Mac 关窗：遵循[手机服务后台项目约定](../exec-plans/2026-09-12-mobile-background-projects.md)，复用同一 Runtime 和 PTY；主动退出按既有规则停止服务。
- Agent 失败或需要决定：反馈真实原因与下一步；没有完成证据时不得报成功。

## 10. 质量目标与交付依赖

以下均为待测验收目标，不是已有成绩：

- 真机、耳机、锁屏连续通话 30 分钟。
- 普通对话从说完到耳机首音：P50 ≤ 1.5 秒，P95 ≤ 2.5 秒；需记录设备、网络、模型、轮次与统计口径。
- 插话触发到停播 ≤ 150ms；用实际输出停止测量，不只看事件到达。
- Mac 工具执行不能阻塞音频对话；GPUI 前台不得承担网络、长任务或阻塞等待。

已知依赖：Norma 已将后台角色与音频分离，并完成模拟器回归；仍不能以此宣称物理耳机锁屏验收通过；APNs 服务尚未部署；角色模型与动作素材在正式分发前需落实授权。GPT 模型与账号可用性、sideband 权限、真机网络延迟需实际验证。
