# #54｜独立想法库实施规格

状态：实现中 · 2026-09-28。依据 [Goal](../exec-plans/2026-09-28-norma-ios-issues-01-05-native-goal.md)、[逐屏验收](2026-09-06-norma-ios-companion.md#appendix-prototype-fidelity)、[P01](norma-ios-ideas-workspaces-2026-09-28/P01-idea-library.png)、[P02](norma-ios-ideas-workspaces-2026-09-28/P02-voice-idea.png) 与 GitHub #54。

## 用户流程与边界

1. 从现有 App 的明确入口打开「想法库」；未连接 Mac 及断网时仍可新建文字想法。保存成功才显示「已记录」，返回列表即可看到，重启后仍在。空白正文不可保存；落盘失败时保留编辑内容并显示错误。
2. 搜索正文和原始转写，可打开想法继续编辑。编辑只更新该想法和修改时间，不创建 Workspace、项目、线程或任务，不访问 Mac 与云端。
3. 语音页在用户点按录音后请求麦克风与系统语音识别权限；麦克风被拒绝时不能启动录音，页面说明恢复路径。Apple Speech 优先设备端识别；设备端不可用且系统在线识别可用时使用 Apple 在线识别。音频录在 App 私有目录，实时显示转写且可编辑。
4. 停止录音或保存时，原始音频、时长和用户文字一起落盘。识别失败、断网或没有转写结果时，仍允许保存为「待转写」并显示重试入口；录音在重启后可播放和重新转写。语音想法既不自动派工，也不自动加入 Workspace。
5. UI 与 [P01/P02](2026-09-06-norma-ios-companion.md#appendix-prototype-fidelity) 的信息顺序、字号、间距、卡片、颜色、主按钮、波形及反馈对齐。原型机身、假状态栏不进入 App；系统 Sheet/导航使用可用 SDK 的原生材质，iOS 17–25 回退到系统材质。支持动态字号、VoiceOver、减少动态效果和键盘安全区。

## 存储契约

- iPhone App 私有目录持有 SQLite `ideas.sqlite` 和 `IdeaRecordings/<idea-id>.caf`。想法 ID 为独立 UUID 字符串，不借用旧协议代表 Mac 项目的 `workspace_id`。每条记录含类型、正文、原始识别结果、转写状态、可选录音文件名/时长、创建与修改时间；不含 Workspace ID。
- `text` 记录必须有非空正文且没有录音；`voice` 记录必须有原始录音，可以暂时无文字。转写状态为「待转写／已完成／失败」；进行中的 UI 状态不作为已完成落盘。
- SQLite 提交成功才报告保存成功。写入失败不能清空编辑页；损坏数据库不能当空库覆盖。录音移动到私有目录后如果数据库提交失败，原音频仍留在设备上供恢复或再次保存，不能静默丢弃。
- 正文按本机用户输入原样保存；搜索只返回匹配项，按修改时间倒序。重新转写仅在用户尚未编辑正文时写入正文，避免覆盖用户修改；原始识别结果独立保存。
- 首版不做云同步、跨设备恢复或自动导入旧实时通话记录。删除想法时须经明确操作，不因移除 Workspace 关联而删除。

# #55｜Mac 配对、全项目设备授权与连接状态

状态：to-spec 已固定，待失败测试与实现 · 2026-09-29。依据 [Goal](../exec-plans/2026-09-28-norma-ios-issues-01-05-native-goal.md)、[W02](norma-ios-prototypes-2026-09-26/W02-connected-computers.png)、[P03](norma-ios-ideas-workspaces-2026-09-28/P03-workspaces-drawer.png) 与 GitHub #55。

## 真实用户流程

1. 从「更多模块 → 已连接电脑」打开 Mac 列表。页面分在线与离线 Mac；每台展示真实名称、项目数、来源/连接方式和最后成功同步时间。新设备从「扫码添加电脑」进入现有相机扫码与双端验证码核对；只有 Mac 持久提交设备授权后才显示已连接。二维码超时、错误、拒绝或连接断开时不得显示成功。
2. Mac 首次确认配对时可明确选择「本机当前及今后注册的全部项目：控制」或逐项目授权。全项目选项须有清楚的授权文案，不能由二维码扫描或 iPhone 单方请求自动开启。旧配对与旧数据库记录仍保持原逐项目范围。
3. Mac 设备管理页可把已配对手机切到全项目控制、改回逐项目范围或撤销设备。每次变更推进授权修订号；iPhone 仅显示最近一次 Mac 返回的授权摘要。新项目注册后，全项目授权可立即读取/控制它，逐项目授权不能获得它。
4. 撤销或降权后，Mac 对新请求、等待 UI 的请求和已排队但未执行的命令均重新核验**当前**授权与修订号；旧快照、旧操作 ID、iPhone 离线缓存不能恢复权限。已实际完成的旧操作只保留历史回执，不回滚执行结果。

## 两端契约与兼容

- Mac 持久化的设备授权新增明确的全项目 `read/control` 模式；旧记录缺省为逐项目模式。`MobileDeviceGrant.projects` 在每次读取授权时由当下真实注册的项目目录解析为可访问项目列表，因此现有 `allows(project, control)` 只会命中已注册项目；新增的授权模式字段供 Mac/iPhone UI 说明来源。数据库保存模式，不通过把当下项目 ID 列表写死来冒充未来项目授权。
- 项目目录、快照、事件订阅和推送对象继续依据解析后的项目列表。注册新项目后下一次鉴权即可得到它；不能让任意字符串项目 ID 因全项目模式而通过。
- 授权修订号绑定每次命令。模式、等级或撤销变化均递增修订号；执行前再次核验。旧手机反序列化无新字段的 grant 时按逐项目解释；新手机读取旧 Mac 响应时也按逐项目解释。
- `workspace_id` 在当前手机协议仍指 Mac 项目；新产品 Workspace ID 在 #56 独立建立。手机的「项目数」以 Mac 核验后的可访问项目目录计数，离线时显示「上次同步」而非在线授权承诺。
- 复用现有 QR/验证码、Keychain、设备凭据、TLS 固定身份与撤销链路；不向云服务上传设备 token，不在 iPhone 缓存可用于绕过 Mac 的权限表。

# #56｜手机本机 Workspace 与正式导航

状态：实现中，尚未完成真实 Mac 与逐屏验收 · 2026-09-29。

## 数据与边界

- 每个 Workspace 使用独立 UUID、本机名称、创建/更新时间与归档状态。完整配置存于 iPhone 私有 SQLite；保存想法不会创建 Workspace。
- 项目关联由 `machineID + projectID` 标识，另存上次核验的名称作为离线显示快照。Agent 关联由 `machineID + projectID + definitionID` 标识，只允许选择关联项目中 Mac 已返回的真实 Agent 定义。Norma 是协调入口，不伪造为 Mac Agent 定义。
- 可创建、改名、搜索、归档及重开多个 Workspace。设置中添加/移除项目和 Agent；移除项目同时移除该项目的 Agent 关联，不删除 Mac 项目、定义或线程历史。
- 已保存关联离线仍可读。新增关联从实时核验的项目/定义选择，不用离线快照冒充可执行授权；连接失败保留配置并明确显示错误。配置是本机设置，后续同步/派工须取得真实 Mac 回执，不能仅因本地保存就显示已同步。
- 数据库损坏时保留原件并显示错误，不重建空库。新表与旧配对、想法、私聊存储独立；旧 `workspace_id` 仍指 Mac 项目。

## 页面及验收

P03 为列表主构图，P04 为设置，W03 为项目选择 Sheet。使用浅色语义色、SF 字体、44pt 触控、系统导航/Sheet 材质。列表显示真实本地配置，不放演示任务或执行状态。

# #57｜Workspace 工作线程、长期消息与工作简报

状态：实施中，不能作为验收完成证明。依据 01–05 Goal、原生架构、数据存储矩阵及 P05/W04/W05；2026-09-29。

## 用户闭环

1. Workspace 可有多个线程。用户从 Workspace 新建，或在已保存想法的菜单选择「在工作空间推进」，选择已有 Workspace、填写线程标题后创建。保存想法本身不创建线程。
2. 来源想法继续留在独立想法库。线程保存原想法 ID 和引用时的文字快照；以后编辑想法不静默改写线程历史。来源卡可回看引用原文，也可打开当前想法。
3. P05 承载群聊。每条消息有稳定 ID、线程 ID、来源设备、作者、正文、时间和同步状态，先落盘再显示已保存；两个线程不串消息，Norma 私聊不自动复制到线程。离线消息明确显示「待发送」，不会显示 Agent 已接收。
4. W05 工作简报显示当前线程目标、Workspace 项目、共同事实和决定。修订记录原文、版本、修改者、时间及来源消息；来源消息必须属于同一 Workspace。目标只改变当前线程，共同事实/决定可被同 Workspace 其他线程查看。没有硬约束模块。
5. 归档 Workspace 保留线程与历史；重开后原 ID 与消息不变。关联项目移除不删除线程或改写既有来源。当前阶段不提供永久删除。

## 数据与依赖

复用 `CollaborationWorkspaceStore` 的本机 SQLite，扩充线程、消息、事实版本表与本机来源 ID；不再引入另一套数据库封装。Workspace 外键、消息唯一 ID 与事实版本唯一键由 SQLite 守住。原有配对、想法与私聊文件保留。

| 对象 | 身份与保存内容 | 约束 |
|---|---|---|
| WorkThread | UUID、Workspace ID、标题、来源想法 ID/引用快照、本机来源 ID、创建时间 | 创建时 Workspace 必须存在且未归档；一个线程只有一个 Workspace；当前切片不提供线程改名 |

# #58｜Norma 单聊主屏的云端文字输入实施规格

状态：实现中，待真实云服务及 UI 验收 · 2026-09-29。依据 [01–05 Goal](../exec-plans/2026-09-28-norma-ios-issues-01-05-native-goal.md)、[云服务架构](../design-docs/2026-09-28-norma-cloud-service-architecture.md)、[存储矩阵](2026-09-06-norma-ios-companion.md#appendix-storage-matrix)与 GitHub #58。本规格交付 **W07 Norma 单聊主屏中的文字输入能力**，不新增独立的「Norma 文字对话」页面或菜单模块；派工中继、Workspace 共享历史和实时通话分别属于后续切片。

## 用户流程与边界

1. 受邀者在 iPhone 上打开一次性邀请链接，App 自动向默认云服务登记设备并把返回的设备凭据保存到 Keychain。邀请由云服务管理员在服务器上生成；用户不填模型、供应商 Key、服务地址或 Mac 配对信息。未受邀设备不能消费模型。退出/重装后若本机凭据丢失，重新邀请；首版不提供云账户或换机恢复。
2. 用户点底部「Norma」进入 W07 角色主屏；点同屏的「输入文字」切换键盘和私聊历史，返回角色后仍停留在同一主屏。邀请深链也进入此主屏。iPhone 先把用户消息和稳定 `turn_id` 落入本机私聊库，再请求云端。全部 Mac 关闭时流程相同。云端按有界上下文推理、逐段返回 Norma 文字，iPhone 只在收到终止事件后将回复标为完整；途中断线保留用户原文，标明「回复中断，可重试」。
3. 用户可滚动、搜索、重启后继续查看完整私聊历史。每次请求只送必要的最近消息，云端不做长期聊天存储；私聊不会自动加入任何 Workspace/线程，也不出现 Mac「已接收／执行完成」状态。
4. 准入失效、被撤销、当天额度用尽、请求过大、模型不可用、超时分别显示可理解的状态；不自动重复一个结果未知的回合。用户主动重试时产生新 `turn_id`，本机保留前一次错误记录与原文。

单聊与群聊的页面边界：Norma 私聊以 W07 为唯一主入口，角色、语音控制和文字输入同属一页；Workspace 群聊按 P05/W04，承载具名消息、工作简报、Agent 回执和任务卡。私聊记录不自动注入群聊。旧版独立文字页的视觉 PASS 不作为修正后的验收证据。

## 首版准入与部署契约

- 继续使用当前 HTTPS 基址 `https://soulvoiceai.com/norma/voice`，保留旧 `/v1/session`、`/v1/voice`、`/v1/tools` 与 Mac 签名令牌的原语义；新接口是同一基址下的 `/v1/devices/claim` 和 `/v1/text/turn`。Mac 不签云端通行证，供应商 Key 只在服务器环境中。
- 单实例管理员命令生成 32 字节随机、7 天有效、只能兑换一次的邀请。二维码/链接使用 `norma://invite?code=…`；App 只提取一次性邀请码并将其提交到固定 HTTPS 基址，不把第三方链接当作服务地址。服务器只保存邀请码哈希，不记录明文或 URL。
- `POST /v1/devices/claim` 接受邀请码和至多 80 字符的设备显示名，原子消耗邀请并返回 32 字节随机设备令牌。设备令牌只在本机 Keychain 保存；服务器只保存哈希、设备 ID、创建/撤销时间和额度计数。每个文字请求都重新查撤销状态，撤销立即阻止新回合。首版用受控邀请、TLS、Keychain 和可撤销令牌服务少量设备；不引入尚无用户账户的登录 UI。
- 设备/邀请码/配额状态在服务器私有持久文件中原子写入，权限 `0600`。现有 systemd `ProtectSystem=strict` 保持不变，新增专用 `StateDirectory` 作为唯一可写状态目录；启动时损坏状态文件必须拒绝准入和推理，不能当空名单覆盖。首版单实例；扩容前再迁移共享存储。
- 默认每台设备同时最多 1 个文字回合，每 UTC 日最多 300 回合（服务端可通过 `NORMA_TEXT_DAILY_LIMIT` 调整）；用户输入最多 4096 个 Unicode 字符，上下文最多 24 条、JSON 请求最多 32 KiB，模型输出最多 1024 token。超过上限拒绝且不调用供应商。每日额度在发起上游请求前持久扣除；不因客户端断线自动返还或重发。`429` 带可读的限额原因和 `Retry-After`。

## 文字协议和本机历史

| 阶段 | 契约 |

# #57 / #59：线程可靠送达与单 Mac 派工

2026-09-29，实施规格。依据 A1 云服务架构、原生架构、现行 iOS 样式规范和 [本阶段 Goal](../exec-plans/2026-09-29-norma-ios-single-mac-goal.md)。GitHub CLI 已恢复读取并核对 #59：票据仍为 OPEN，明确包含真实派工、登录后后台接收与蜂窝网络验收；本轮仅本地运行，不能据本地联调关闭跨网络门槛。

## 1. 不变的产品行为

想法仍独立记录；讨论不自动执行。线程内 @Agent 必须回应、执行或明确说明失败。手机 Norma 负责云模型推理和派工选择，Mac 复用现有执行路径，不对同一手机消息再次默认推理。底栏和原型结构不变。

`collaboration_workspace_id`、`thread_id` 与旧协议的 `workspace_id`（Mac 项目）分开；手机长期保存 Mac / 项目 / Agent 定义身份，发送前读取最新 route 和卡片。成员与项目必须属于该 Workspace；跨线程引用带来源，不携带整库私聊、原始终端或私有推理。

## 2. 在线中继（首个实现切片）

在既有 `services/norma-cloud` 进程新增两条 WebSocket 路径：`/v1/relay/mac`、`/v1/relay/phone`。生产仅经 HTTPS/WSS，开发仅回环地址。旧语音和文字接口保持兼容；独立手机准入记录同时用于文字和中继，不另建云账户或把全局管理令牌下发客户端。

- **Mac 身份**：复用本机配对证书私钥。服务器发一次性 32 字节挑战，Mac 签名固定用途前缀、服务器 audience 和挑战；服务器核对 `NORMA_RELAY_TRUSTED_CERTIFICATES` 受控证书清单及证书 SHA-256 对应的 Mac ID。此清单是本地测试／服务端部署配置，手机不填写配置。失败、超时或重复身份不能顶掉在线 Mac。
- **手机身份**：Authorization Bearer 使用 #58 的独立受邀设备凭据。握手、打开通道和每次转发都检查当前撤销状态；不接受旧语音授权替代。云设备身份只允许占用中继，不能替代 Mac 上的配对与项目权限。
- **开通道**：手机发送 `{type:"open", request_id:<UUID>, machine_id:<Mac ID>}`；中继在线查找 Mac，为该连接生成随机 `stream_id`，两端收到 open。Mac 离线返回 offline，不建立队列。
- **转发**：双方发送 `{type:"data", stream_id, data:<base64>}`，只向该通道的另一端转发不透明字节。`close` 释放对应通道；断连通知对端。消息正文与操作身份只在端到端加密内容内出现。
- **边界**：握手 10 秒；单帧解码后最多 256 KiB；每连接最多 8 个通道、全局最多 8 个手机和 8 台受信 Mac；通道闲置 60 秒关闭；每连接每分钟最多 120 条控制或数据帧；输出累计超过 1 MiB 关闭慢端。所有定时器随连接释放。单实例内存目录，不存正文、队列或长期事件。
- **状态**：open/data 仅意味着路由可用／已转发，不返回 delivered/accepted/completed。中继失去连接后手机按原操作 ID 向 Mac 核对；中继从不替 Mac 签收。

Mac 注册签名输入为 UTF-8 `Norma relay registration v1\n` + `audience` + `\n` + 64 个小写十六进制字符的 challenge；ECDSA P-256 / SHA-256，签名 ASN.1 DER 转小写 hex，与既有 Mac 签名编码一致。注册内容 `{type:"register", machine_id, signature}`，服务器从受信清单找到对应证书验证。挑战不写磁盘。WebSocket 每 20 秒心跳，连续未响应在最多 40 秒内断开。

## 3. 端到端会话与授权（后续接入切片）

中继不取得配对 token 或任务明文。使用系统／现有密码库：手机与 Mac 生成 X25519 临时密钥；Mac 用既有配对证书签署包含协议版本、通道 ID、手机随机数及双方临时公钥的完整握手转录。手机先按已配对证书指纹验证，再以 HKDF-SHA256 分方向导出 AES-256-GCM 会话密钥。每方向单调序号作为 nonce 的后 64 位（前 32 位为零），转录摘要、方向和序号作为 AAD；拒绝重放、反向帧和乱序。新通道使用新密钥，不跨连接复用。以下精确字节格式由 Swift CryptoKit／Rust ring 与独立 Node crypto 互操作测试验证。

### 会话字节契约 v1

- 手机 hello：`{version:1, client_key, nonce}`，两个值均为 32 字节的小写 hex。
- Mac handshake：`{version:1, server_key, certificate, signature}`，均使用小写 hex；公钥 32 字节，证书 DER 最大 16 KiB，ECDSA P-256/SHA-256 签名 DER 最大 80 字节。
- 签名原文（UTF-8，末尾无换行）：`Norma collaboration session v1\n<stream_id>\n<nonce>\n<client_key>\n<server_key>\n<machine_id>`。stream_id 为中继返回的原始 UUID；machine_id 必须与手机已配对证书的 SHA-256 相同。先验签再发送配对凭据。
- `H = SHA256(签名原文)`；`K = HKDF-SHA256(X25519 共享秘密, salt=H, info="Norma collaboration keys v1", length=64)`；前 32 字节为手机上行，后 32 字节为 Mac 下行。
- 密文帧：8 字节大端序号 + AES-GCM ciphertext + 16 字节 tag；nonce 为 4 零字节 + 同一大端序号；AAD 为 H + 1 字节方向（上行 0／下行 1）+ 同一序号。每方向从 0 严格递增。帧最大 256 KiB，明文最大 262120 字节（262144 - 8 - 16）。序号耗尽必须重建会话。
- 对外中继 data 使用此完整二进制帧的规范 base64。握手也在不透明 data 通道内传输。会话密钥不落盘；协议或认证错误后连接适配器必须关闭该通道。手机握手只能消费一次，禁止复制会话计数器。

解密后复用原 device_id/token 认证和最新设备授权修订，协商 `collaboration_v1`。在端到端认证与能力协商完成前不得发指令；旧 Mac 保留既有配对／浏览，提示升级，不把旧项目消息冒充协作线程派工。

### 原生网络接入切片

Mac 手机服务持有唯一出站连接，后台连接固定服务地址；本地验收入口只允许回环地址。校验挑战 audience 与配置完全一致后签名，不跟随重定向。断线只重建连接，不重放应用请求。关闭手机服务立即取消连接与重连；权限改变会断开当前中继连接，所有通道重新认证（个人单 Mac 阶段的简单实现）。

每个通道先进行密码握手，再用端到端加密的旧请求信封执行 `authenticate`。首次接入只开放认证与 `snapshot`；每个请求重新核对 Mac 配对授权，禁止中继触发配对、语音或未实现的动作。认证响应只列出实际实现的能力；线程接收未完成前不得宣称 `collaboration_v1`。同一通道禁止更换设备身份，协议／认证失败直接关闭通道。

手机固定云服务地址、复用独立云设备凭据；开发只提供回环端口。每次握手及请求都有总超时，取消时关闭 socket；同一会话最多一个在途请求，避免并发响应串线或加密计数乱序。校验请求关联 ID、Mac ID、通道 ID；握手成功不等于 Mac 持久签收。网络测试要使用正式 Node 中继和真实 `MobileServer`，独立于尚未完成的 App 派工验收。

## 4. 操作、执行和事件

### 线程消息持久接收切片

消息同步与执行分别处理。`thread_message` 只保存频道可见消息副本，不启动 Agent；`thread_receipt` 按原操作查回执，`thread_events` 按当前 Workspace／线程游标补回接收事件。认证声明 `thread_delivery_v1` 时可使用这三项；完整派工仍由后续 `collaboration_v1` 声明，不能用接收能力冒充执行能力。

消息封套字段为 `operation_id`、`collaboration_workspace_id`、`thread_id`、`message_id`、`origin_device_id`、`project_ids`、`text`。前五项为 UUID，项目 ID 使用旧协议的稳定 ID；项目列表升序去重，1–32 项；正文非空、UTF-8 最多 64 KiB。超限保留手机原文，提示缩短后另发，不截断。首版目标为一个 Mac；没有关联项目或关联多台 Mac 时保留待发，不能擅自挑选电脑。准备发送后目标和封套固定，配置变更不能把同一操作改派到另一台 Mac。

幂等指纹为 SHA-256：固定 UTF-8 前缀 `Norma thread message v1\0`，接着依次写入目标 Mac ID、五项 UUID、项目数（u32 大端）、各项目 ID、正文；每个字符串先写 UTF-8 字节长度（u32 大端），再写原字节。重试不得改变大小写、项目顺序或正文。Mac 以已认证配对设备隔离操作空间；同 ID 改内容、同消息 ID 换操作、同线程换 Workspace／来源均拒绝。

Mac 同一 SQLite 事务保存线程归属、原消息和唯一接收事件，提交成功后返回 `state=received`、稳定事件 ID／游标、目标 Mac、操作／消息／Workspace／线程和指纹。每次接收、查询和补事件都重查当前配对授权以及封套的所有项目；讨论只需读权限，后续执行另查控制权限。Mac 的接收回执不表示 Agent 已接单、执行完成或用户验收。

手机追加消息时同一事务创建 outbox 操作和清理匹配版本草稿；未能确定目标的 outbox 可保留空封套。发送前把目标与完整封套原子冻结，重启不重建操作。收到回执后，校验上述全部归属和指纹，在同一事务保存回执并将消息标为 delivered；没有回执时保持 pending。旧消息按需补建一次 outbox，已交付消息不得退回 pending；错误回执不得推进状态或游标。

### App 投递接入切片

iOS 前台自动检查全部工作线程的持久待发记录，不要求停留在原线程；没有派工待发时每轮最多向每台 Mac 投递两条；有待发/待核对任务时改为一条消息加一个任务，轮次间隔至少 5 秒，以遵守中继帧预算。进入后台取消在途网络等待，重新进入前台先查原回执后续发。配置或权限错误按消息显示，不能清除原文或把另一线程标成送达。回执更新只刷新状态，不打断用户阅读历史的滚动位置。

Mac 开启手机服务时同时启动中继，复用既有停服／撤权生命周期。Release 使用固定生产地址；本地开发构建仅在 `NORMA_CLOUD_LOCAL_PORT` 为有效端口时连接 `127.0.0.1`，未设或非法时绝不回退访问生产。iOS 本地模式继续沿用端口及独立命名空间配置。本地联调仍需将该隔离 Mac 的公开安装证书加入本地中继受信清单，测试凭据不能写入正式配置。

手机原子保存消息及待发操作；操作包含稳定 ID、协作 Workspace、线程、来源消息、目标 Mac/项目/Agent 定义、必要上下文与版本。身份与任务正文不随重试改变；route / 授权修订是每次尝试检查的临时元数据。重复同 ID 同内容返回原回执；同 ID 改正文或归属拒绝。

Mac 持久保存线程归属和接收状态后才回「已送达」。进入既有命令去重／租约／Agent 执行路径，新增的是协作上下文绑定，不建第二套执行器。执行前再次校验当前授权与目标；已开始但执行结果不明时保持「结果未知」，不得自动重发副作用。

事件携带稳定 event_id、source_mac_id、Workspace/线程/操作归属和单调游标。手机校验后在事务中合并事件、更新消息／任务与游标；旧事件重复拉取不新增气泡，其他线程事件不能写入当前线程。回复、任务进展、成果引用分别呈现；Mac 接收、Agent 接收、执行完成、用户验收各有独立含义。手机离线时 Mac 继续已接收工作并保存事件，重连后补齐。

### 单 Agent 派工接入契约

`thread_task` 接收手机已经决定的单 Agent 任务，不再次调用 Mac Norma 推理。任务固定 `operation_id`、协作 Workspace、线程、已送达来源操作/消息、Mac 项目、`agent_definition_id`、任务正文和上下文文本/版本；`route_id`、`grant_revision` 仅属本次尝试。上下文由手机从当前线程及共享事实生成，不能包含整个想法库或 Norma 私聊。首个接口只声明 `thread_tasks_v1`，尚不声明完整 `collaboration_v1`。

Mac 验证来源消息已持久接收、所有来源项目仍可读、目标项目在来源范围且可控制、当前授权修订一致。线程绑定与既有 `mobile_commands` 的预留同事务落盘；同操作改正文、Agent 或线程拒绝。换 route/授权修订重试只能返回原回执；已预留但结果未知不能重执行。旧 `command` 的身份/route 语义保持兼容。

前台按 Agent 定义 ID 找当前名称及启用状态，通过既有 `AssignAgentTask` 适配器和 FIFO 队列执行；沿用既有 lease、后台落盘确认和成果追踪，不新建执行器。`thread_task_receipt` 只返回同设备、同 Mac、同 Workspace/线程的持久命令回执及原绑定；其中命令 `succeeded` 仅表示派工被持久确认，不等于 Agent 完成任务。

派工成功结果同时包含 `task_ref`、`task_id` 与 `node_id`。`task_ref` 是既有任务库的 `<runtime_instance_id>:<task_id>` 持久身份；手机核对其数字后缀并保存完整引用。后续事件查询必须以持久引用定位，不能在 Mac 重启后仅凭可能复用的数字 task_id 查任务。

派工指纹使用 SHA-256：UTF-8 前缀 `Norma thread task v1\0`；依次写入 Mac ID、操作 ID、协作 Workspace、线程、来源操作、来源消息、项目，每个字符串先写 u32 大端 UTF-8 长度；再写 Agent 定义 ID（正数 u64 大端）、上下文版本（u64 大端）、任务正文和上下文字符串（同长度编码）。任务与上下文合计最多 32 KiB，规范 JSON 最多 64 KiB。两端不截断、不改大小写；重试不重新生成上下文。

### 执行状态与成果回传契约

- 复用 `thread_task_receipt` 查询，新增可选 `execution` 事件；不会为结果另建执行器或自动重派任务。支持端声明 `thread_task_results_v1`。派工回执 `succeeded` 仍只表示 Agent 接收。
- Mac 先按设备、Mac、Workspace、线程、操作定位原绑定并校验当前来源项目读权限，再用持久 `task_ref` 读取原项目任务库；核验 Agent 定义、节点、数字任务 ID 和正文。项目根目录只来自 Mac 已登记身份；项目数据库沿用当前构建的数据模式，查不到时不创建空库、不按相同数字 ID 找替代任务。
- 执行快照复用已有任务状态和持久结果。未跟踪任务明确为 `untracked`；缺失记录返回空执行信息，不冒充运行或完成。回复预览最多 16 KiB UTF-8，超出时按字符边界截取并显式 `truncated=true`，原文仍留 Mac。
- 成果只关联原设备/操作持久绑定的完整 Provider 回合（节点、profile、run/session/turn），查询已有冻结成果元数据，不扫描当前目录、不取节点最新成果、不在回执中传文件字节。尚未捕获不显示可用成果；读取成果正文的后续入口仍须按此身份校验和分段传输。
- Mac 在同步读取时，将已持久任务快照的变化追加为稳定事件，序号单调递增；重复状态重用原事件，重启保留 ID。离线任务继续由已有任务/成果库保存，重连投影最新持久快照；不声称重建离线期间未保存的每次 UI 瞬态。终态不退回进行中、不换最终回复，只允许补上原回合成果。
- 手机同步复用现有每 Mac 每 5 秒至多一条消息加一次任务查询的调度，结果查询与派工公平轮转。事件、任务状态、最终回复、成果引用和游标同事务去重写回原线程；终态回复按原操作仅一份。该接入与本机中继网络专项已完成；测试任务来自显式 fixture，真实 Coding Agent 执行仍待验收。

手机接入落点：执行事件沿用 `ThreadTaskReceipt` 的可选字段，完整事件与成果元数据保存在原任务记录内。最终非空文字回复写入既有 `work_messages`，角色为 Agent，记录来源操作；任务同时保存唯一回复 ID，两边的线程/Workspace/Mac/正文必须匹配。Agent 回复不创建用户消息 outbox，可作为共同决定的来源和后续本线程上下文。写失败整笔回滚，读到缺失回复报告损坏，不静默补写或伪装同步完成。

派工队列与执行同步队列分别可读、共用每轮一次任务请求的调度。已派工任务只查原回执；本机有接单/派工证据而 Mac 查询为空时保留原记录并报错，不能重新提交。终态无成果时继续轮转查询，直到原回合可用成果或明确不可用记录到达。终态且成果记录齐全后停止自动查询；未来验收结果同步另行接入，不把当前静态成果记录视为已验收。较旧事件忽略，同序号不同内容拒绝，新序号也不能退回终态或改最终文字。

本切片沿用已确认的存储公开 API 与真实中继到 MobileServer 验收接口；测试需覆盖重启及数字 ID 重用不串任务、当前撤权、错设备/线程隔离、重复查询稳定、终态不回退和成果晚到。

### 冻结成果正文读取

`thread_task_review` 按原 Workspace/线程/操作、完整 task_ref 与已同步成果 fingerprint 读取，不接收文件路径或另一个 Provider 回合。每片重查当前设备及来源项目授权、原派工绑定与冻结成果；找不到原记录或指纹不符时拒绝，不能退回当前目录或同节点最新成果。读取已保存成果不要求旧项目窗口/route 仍活跃，也不重新捕获文件。

复用既有 ProjectReviewResponse 与文件/图片预览数据结构。序列化后最多 32 MiB，每片最多 160 KiB 原始字节，经 base64 后小于 214 KiB，给 256 KiB 中继载荷留出封套及加密空间；片可跨 UTF-8 边界，完整重组后才解码。请求显式带 offset，响应回显完整请求及总字节数；手机核验连续偏移/固定总长/身份/指纹/文件范围后才展示，取消或中途失败不显示部分文件。重试核对同一冻结指纹，不能变成另一次成果。

手机读取遵守现有中继帧限额，用户进入后台或离开页面取消在途读取。成果内容仅按用户打开时获取；线程自动同步继续只取元数据。验收通过和修改反馈仍复用既有命令通道，不能因成功读取而自动验收。

原生入口：任务详情的「本轮成果」提供「查看文件与变更」。沿系统导航打开浅色成果页，显示原任务、保存时间、Agent 总结与可打开的文件证据；没有图片时不生成示意图冒充成果预览。复用原生 TextKit 全文选择/复制与系统图片缩放，任务起点/本次交付切换仅列实际适用版本。载入、离线/权限错误和重试清晰可见；离开或进入后台取消读取，重进重新认证，部分文件永不呈现为完整成果。返回保留原线程位置。本切片为成果阅读，验收/修改动作随后接入，不显示虚假的验收成功或已完成证据。

验收映射：既有 ThreadExecutionFlowTests 验证入口；ReviewViewTests 验证浅色 TextKit 与图片、完整正文；正式本地中继 fixture 加原生 ThreadReviewFlowTests 验证任务→成果→文件→版本→返回/后台恢复；Computer Use 操作同流程，独立只读审查按 W09 的浅色卡片层级与证据区域复核。fixture 明确标注，不计真实 Coding Agent 执行。

### 手机派工待发记录与恢复

- 直接呼叫 Agent 时，原消息、消息待发记录与任务待发记录在同一 SQLite 事务保存；写失败保留原草稿。Norma 后续决定派工可引用已有消息追加操作。

## 线程 Norma 编排契约（2026-09-30）

首个实现切片为正式 HTTP 候选动作边界，不表示手机入口和真实模型验收已完成。

- `POST /v1/threads/plan` 复用受邀手机 Bearer、撤销、每设备并发、日额度及 turn ID 去重；不增加 Mac 签发凭据。供应商 Key 仍仅在服务端。
- 请求严格包含 `turn_id`、`workspace_id`、`thread_id`、`message_id`（UUID）、`message`、`context` 和 `agents`。`context` 是手机冻结的当前线程快照，必须与 Workspace/线程身份一致；不包含其他线程原文、全想法库或 Norma 私聊。成员仅提供本回合可选目标的 `id/name/project/profile`，不传执行凭据。请求总长最多 64 KiB，快照最多 32 KiB，成员最多 64 个。
- 云端只推理，响应 `{turn_id,workspace_id,thread_id,message_id,reply,assignments:[{target_id,task}]}`。四项来源身份由服务端从已校验请求回填，不采信模型输出。讨论/澄清返回空 assignments；明确执行指令才提出候选。每轮最多 8 个不同目标，单任务最多 8 KiB、候选总长最多 32 KiB；这是协议预算，长工作交由 Agent 内部推进。
- 模型必须完整结束，候选结构、目标和长度全部合法后才一次性返回；不把半句、截断 JSON、未知成员、重复目标或额外执行字段交给手机。生成期间撤销手机准入则丢弃候选。响应不等于 Mac 接收或执行，云端不调用仓库/终端，不保存长期对话或执行队列。
- 手机收到后还须核对原回合及 Workspace/线程/来源消息，重验当前参与成员/项目，把 Norma 可见回复与稳定操作 ID 的任务在同一事务保存；失败不能留下部分任务。重复响应只读原记录，不能产生新操作。后续发送复用既有消息送达、派工和 Mac 最终授权检查；未完成手机接入前，`@Norma` 仍保持明确不可用，不能伪装上线。
- 自动化验收通过正式网关 HTTP 和 Swift 客户端验证：合法候选、纯讨论、错误来源、未知目标、截断、重复回合、撤销及与普通文字共享额度。供应商测试替身必须标记；真实模型回合另留证据。

接口预算沿用 Mac 派工协议：每项任务与其冻结快照的 UTF-8 字节数合计不得超过 32 KiB，即任务上限为 `min(8 KiB, 32 KiB - contextBytes)`。当前消息与 Norma 回复各至多 8 KiB，成员的每个描述字段至多 4 KiB，总请求仍受 64 KiB 限制。UUID 大小写不改变回合身份，普通文字与编排共享去重记录；无效或截断候选统一返回 `provider_invalid_plan`，不返回部分任务。

- Mac 必须从原派工的持久回执和 Provider 起点解析原节点/run/session，不能信任手机提交的节点或选择“最新任务”。会话替换、项目撤权或任务归属变化时拒绝输入；不得改派其他节点。
- 追问绑定、来源消息与现有 `mobile_message_queue` 入队回执在同一 SQLite 事务提交。来源未送达、任一写入失败均不能留下可执行的孤立队列；相同操作只能返回原回执。重连可改变请求路由，但不能替换已保存的执行路由和目标。
- 复用现有 Mac 队列与 `send_mobile_chat`，忙碌、人工草稿或终端接管时保持排队；明确交还且可输入后继续。`terminal_controlled` 是输入前的可等待结果，不能误报结果未知。输入后失联只查原回执，不自动重发。
- Mac 入队与 Provider 收到分别展示；回复/成果按该追问实际确认的 Provider 回合回到原线程，保留原任务及历史成果。不能把上一回合回复当作追问答案，也不能因已有终态而吞掉后续回复。
- 验收顺序：存储公开接口验证事务回滚、冲突与重启；正式网络验证认证及队列；手机验证草稿/来源/回复；最后使用真实 Coding Agent 与 Computer Use 验证原会话追问及无重复执行。底层测试通过不代表手机入口已交付。
- 工作情况页以任务指令为标题，其后显示原 Agent、状态、项目和所属 Mac。长指令标题最多三行，完整内容必须可展开阅读；进展不使用截断标题作为执行输入。最终回复作为具名的「最新进展」，成果仍沿原任务进入文件与变更。原型中的具体工作步骤只能来自可验证的 Agent 计划事件，不能从接收／完成回执推测生成。
- 已有 `runtime::ego` 的接管状态属于 Ego 工作面，不能直接当作终端输入锁。后续终端协议应复用 `mobile_terminal_page`／`send_mobile_terminal_input` 的运行与屏幕签名验证，并在真实输入入口仲裁；工作线程还需从原 `task_ref` 验证当前会话，防止复用节点打开别的任务。此段是待实施边界，不表示终端接入已交付。

#### 追问正式中继与 Swift 契约（2026-09-30，基础切片）

- 连续追问的输入校验：复用同一原任务的已确认追问回合，以原回合或最近一次已确认追问回合作为当前终端锚点。其他任务/线程/设备、普通终端输入产生的回合不能冒充这条追问链。该锚点在后台从既有绑定、队列与 Provider 起点记录解析，在真正写入前于同一次前台更新核对 Agent、原 `task_ref`、route、run/session 及最新回合；不在 GPUI 前台查库。队列等待期间任务被替换须明确取消，不能刷新快照后跟随新任务。
- 手机追问保存在同一 Workspace SQLite 的独立记录中，来源消息与追问原子落盘；清除草稿只认捕获的 revision。追问不是新的执行任务；每份确认的新回合回复只追加一次，引用原任务及本次来源消息，保留原任务回复与成果。已确认签收后 Mac 账本丢失只报待核对，不重发。Mac 回执携带原派工的 `original_key`，允许尚未完成的原任务追问取得可信会话绑定；该值首次核对后固定，之后不得换绑。

- 通过 `thread_task_followup_v1` 协商；提交为 `thread_task_followup`，查询为 `thread_task_followup_receipt`。查询只返回原回执或 `null`，不建立新队列。新提交要求实际命令、快照和终端通道可用，不能接收一个没有工作线程的队列。
- 载荷包含独立追问操作、独立来源消息/送达操作、Workspace、线程、原派工操作、完整 `task_ref` 和用户正文；正文必须与已送达的来源一致，不能复用父任务的来源。正文最多 32 KiB，JSON 最多 64 KiB；Mac 身份与所有字段使用域分离的 SHA-256 长度前缀指纹。
- 回执保存原绑定、持久排队签收、实时队列状态，以及实际新回合的回复/成果。排队签收不表示 Provider 收到；只有队列确认的 `turn_id` 可用于读取本次回复。旧回合、错误节点/run/session、不同线程或成果身份均拒绝。响应上限为 256 KiB 减 16 KiB 外层预算，即 240 KiB。
- Swift 复用既有 `QueuedMessageStatus` / `MobileCommandReceipt` 的状态与身份校验，并额外核对原任务、来源、原回合及新成果。回执支持 Codable，保留回复正文；网络恢复只查询原操作，重复同操作保持原执行 route。
- 当前基础切片已覆盖连续两次追问及真正输入前的任务归属检查；手机以 `thread_followup_outbox` 原子保存来源和独立追问，回复引用原任务及本次来源。恢复复用现有单任务轮转，每个前台周期只处理一个任务或追问，保持最多 108 帧/分钟的既有预算。正式 Swift→Node 中继→Rust MobileServer→SQLite 的重启恢复、重复回执与丢账本不重发已验证；Provider 前台仍为明确 fixture。W06/P05 追问入口与回复对象草稿已实现，标准/AX5 原生追问流程通过；独立 Computer Use 正在复核。追问新成果读取、嵌套成果返回与真实 Coding Agent 验收尚未收口。

### 终端读取切片

- `thread_task_terminal` 只接受原 Workspace、线程、派工操作、完整 task_ref 及历史分页位置。Mac 从持久命令和已确认 Provider 起点绑定推导项目、route、node、run、session、turn；手机不能指定另一个终端。没有真实回合绑定时明确不可用。
- 复用 `MobileTaskBaselineStore`，后台只读取回合身份元数据，不反序列化文件快照；每次重新验证配对与原消息所有项目的读取权限。读取前后校验授权修订，撤权或权限变化则丢弃结果。
- 复用现有终端前台通道与原 PTY。前台在同一次更新中检查原 route、完整回合及当前协调任务；排队中的新任务接替、会话重启、节点复用或后续 turn 都使旧终端读取失败。已完成任务只有原回合仍是当前最后回合时可读，不伪造历史终端快照。
- 首个切片提供受任务约束的单页读取和显式能力 `thread_task_terminal_v1`；中继保持禁止普通 terminal/command 绕过入口。序列化结果超过 240 KiB 时明确失败，不截断文字；接管/交还、实时更新、原生 W06a 和输入仲裁继续按完整目标实施。
- 验收：存储重开与错设备/项目/操作/route；同节点换 turn/新任务/route 后拒绝；正式本机中继验证来源、task_ref、分页、撤权和普通终端绕过。前台录制 PTY/网络 fixture 只证明接口，不作为真实 Coding Agent 或 UI 验收。

### 终端输入权仲裁（实施中，2026-09-30）

- 接管首先绑定原任务已确认的 Provider 回合，再占用同一个 run/session 的输入权；它暂停 Norma/自动派工向该终端写入，不宣称冻结 Coding Agent 已经执行中的推理、工具或进程。已有输出继续可读，任务完成态仍以真实回执为准。
- Mac Runtime 是输入权的裁决方。持有期间桌面键盘、普通手机输入、自动派工、消息提交和审批/中断快捷键都不得绕过；持有者仍走原屏幕签名、输入序号、文字校验和 PTY 写入路径。取消任务的显式控制必须先按正式流程交还输入权，不能偷偷注入停止键。上层接入时，控制标识须由 Mac 生成并绑定已认证的设备/接管命令，不得直接把客户端自选 operation_id 当作跨设备输入权凭据。
- 只在没有未提交文字、待确认 Enter、消息提交、审批提交或中断提交时取得输入权。重复的同一次接管可续期，不同持有者拒绝；旧 run/session、无真实回合及非法标识拒绝。上层必须验证设备/项目授权及原 task_ref，Runtime 方法不替代授权。
- 输入权为 15 秒内存租期（预定每 5 秒确认一次，可覆盖两次遗漏），到期或会话替换后失效；续期必须在到期前发生。输入本身不隐式续期，过期旧输入不能重新取得控制。Mac 重启不恢复过期输入权。
- 交还/到期都不删除或自动提交用户留在原终端的文字。自动派工在已有草稿时继续等待；用户可回到桌面处理原草稿。人工输入引起后续 Provider 回合时，不把新回复冒充原任务结果；原任务终端读取仍保持精确回合校验，受控后续回合的界面与回执将在接管协议接入时补齐。
- 自动派工与会话追问复用既有队列，接管/人工草稿保护期间保持 Queued；交还且输入可用后恢复原阶段，不丢弃或重建任务。原自动提交失败后的清理/重试保持原行为；迟到的同一回合 Hook 不能确认新人工 Enter。
- 本切片先实现并验证 Runtime 仲裁与自动派工入口；中继接管操作、授权撤销/离线释放、W06a 输入界面和真实 App 验收仍属于必做后续，不能据域测试将 W06a 标为完成。

#### 断线与撤权的输入租约（实施中）

- 网络侧持有 Mac 创建、绑定原 `MobileTurnKey` 的不可反序列化租约；Runtime 只接受该对象，不能用手机传来的字符串取得输入权。
- 租约可由后台线程撤销。每个输入入口、续期和自动队列检查都读取同一撤销状态；撤销后立即失效，不必等待前台收到额外消息或15秒到期。正在进行的单次PTY写入不能回滚，回执仍须按实际结果记录。
- 交还、到期、换会话、删除节点和释放Runtime都会永久撤销旧租约。后续即使另一个人接管又交还，迟到的旧续期也不能复活原租约；只保存当前对象，不添加无界历史集合。
- 断线/撤权不清空也不提交人工草稿。没有草稿时，已有自动任务/追问队列正常继续；有草稿时继续等待用户处理。
- 该对象是Mac内部能力，不是完整网络协议。后续正式中继须将租约绑定已认证连接、设备及持久接管操作；连接关闭、设备撤权和服务停止必须调用撤销，再接入持久输入回执及W06a页面。

### 正式中继终端接管协议（实施中）

- 公开验收边界沿用正式中继 RPC、App 前台命令和 Runtime 原 PTY，不建立新执行器。`thread_task_terminal_control` 只接受原任务来源和 Claim/Input/Release/Read 操作；普通 command 不能反序列化内部接管命令。
- Claim、Input、Release 使用既有持久命令回执和操作 ID 去重。相同操作改正文或任务必须冲突；丢回执只核对原结果，不重放。重连读到旧 Claim 成功不代表新连接持有输入权，须新操作显式接管。
- 接管能力绑定认证设备、连接和原任务。Read 只续期已经取得的同一输入权，不能隐式接管；历史页不可输入。续期不写持久命令表，复用原终端读取通道。
- 正常关闭、处理中连接取消、设备撤权及停服永久撤销租约；延迟到达的前台 Claim/Input 不能越过撤销。已写入 PTY 的字节不能回滚，结果不明不自动重发。
- 手机不能指定 node/run/session；Mac 从原持久派工推导。首次接管检查完整原回合与协调任务，受控人工后续回合仍保留原任务来源并展示真实当前回合。
- 本地网络测试须覆盖重复输入、冲突、错误线程、重连后的旧 Claim、断线和撤权。前台 fixture、录制 PTY 与真实 App 验收分别报告；协议测试通过不等于 W06a 页面交付。

### 手机终端操作保存与恢复（2026-09-30）

- 验收边界复用正式中继 RPC 与手机 CollaborationWorkspaceStore：显式接管/输入/交还先保存稳定操作及原任务、设备、回合与输入参数，再允许发出；不建立新的自动执行队列。
- `lookup_only: true` 只查询同内容的已有控制回执；未到 Mac 的操作返回 `not_found`，绝不创建记录、派发或取得输入权。普通提交保持已有能力协商；查询不得回退为执行。Read 不能使用该标志。
- 同任务只保留当前待核对人工操作；未解决的操作不得被下一次输入覆盖。手机重启仅核对结果，未找到或结果未知时保留草稿供用户明确处理，不能重放。已终结回执不得被迟到 accepted 覆盖。
- 终端文字草稿复用本地任务 SQLite 保存；只有匹配该输入操作的成功回执才清理同一草稿 revision，拒绝、未知和之后新编辑的草稿保留。已完成人工操作不进入后台派工队列。
- 受控读取可显示同 run/session 的真实后续 turn，但原任务 key 和来源不变；普通读取仍拒绝后续 turn 或可输入状态。成功接管回执本身不足以恢复连接输入权，界面须等当前连接受控读取确认。

### W06a 原生终端页面（2026-09-30 实施中）

- W06 的「工作情况／终端」进入同一原任务，浅色外壳、深色实际终端、持续可见电脑/项目及输入权；不恢复旧原型的硬约束。系统键盘上方提供 Esc、Tab、Ctrl-C、方向与退格键。
- 显示真实 PTY 的绝对光标行列；保持 Mac 网格与横向滚动，历史页不显示当前光标、不接受输入。只在输入时随实时输出滚动，允许用户独立回看。
- 中文/系统输入法先编辑持久本地草稿。Return 或功能键显式提交当前文字，收到真实写入回执后才发送该键；文字结果不明时不补发 Enter。输入回执只表示写入 PTY，不表示命令执行成功。
- 接管只暂停 Agent 自动输入，进程继续运行。查看、重连与重新进入均不自动接管；关闭页面、切后台及时关闭正式连接以撤销输入权，草稿保留。待核对操作只查询；用户明确在 Mac 核对后，可保留真实回执和草稿，解除阻塞，不记为成功、不重发。
- 当前 Mac 的后台投递在终端活跃时让出请求预算，其他目标继续。等待已开始的同 Mac 批次结束；会话使用独立标识，旧页面退出不能释放新页面。每2秒读取，未决回执同周期查询，沿用正式108帧/分钟客户端预算与15秒接管租期。
- 公共验收边界：真实 SQLite/原生 App Model、正式中继网络、系统键盘 UI 流程及 Computer Use；静态截图与前台 fixture 不算真实 Coding Agent 新验收。
- 小屏与最大辅助字号：键盘展开可把任务标题/工作情况入口移入系统导航，接管与成功反馈合并一行；Agent/Mac及项目长名称用原生横向滚动完整读取，项目具有独立视觉边界。保留系统字号、至少44pt交还入口及至少90pt输出视口，不用字号上限或放宽断言掩盖遮挡。
- 光标位于长行右侧时，输入和实时跟随定位到Mac提供的真实光标，验收要求整个光标矩形位于输出视口内。历史回看保留独立滚动，返回实时再跟随。
- 连接结束统一清除旧接管/成功提示并释放输入权；本地草稿保留。错误或未决操作收起键盘，保留完整说明与核对入口，人工核对反馈可在重新读取持久记录后恢复。

9. **计数** N 数全部未处理事项，不按日期过滤；写「· 2」不补零；底栏角标与 N 一致。
10. 失败卡的**「放弃」只把卡片从收件箱移除，Mac 上的任务状态不变**；Mac 端新增「忽略」操作，带回执，卡片照旧等回执后才消失。「放弃（忽略）」只对任务失败卡开放；审批卡只有「批准 / 拒绝」，成果卡只有「验收通过 / 退回修改」。失败重试后再次失败会换 `run/turn`，算一张新卡，不受旧的忽略记录影响。

第三轮（2026-10-07，关闭剩余开放问题）：

## 1. 背景与目标

### 1.2 目标

用户打开「收件箱」第一眼就看到**所有已连接 Mac** 上真正需要自己处理的事，一件事一张卡；点一下直接进入决定页或验收页处理；Mac 确认后卡片消失。用户不需要先挑电脑、再挑工作空间。

### 1.3 范围内

- 收件箱首屏（W08）重做：标题区、计数、卡片列表、各状态、右上角**搜索**与**任务提醒设置**两个入口、底栏角标。

- 两类卡片：「需要决定」（工具审批、任务失败）和「成果待验收」。

- 不做验收后的归档（M09「可进一步归档」）；不做 W06/W06a 任务详情与终端接管。
- 不改 Mac 授权模型（#55）、中继与端到端会话（#59）。

## 2. 第一屏结构

自上而下（对照 W08）：

1. **标题行**：左侧大标题「收件箱」；右侧两个并排的圆形图标按钮，左为**搜索**（放大镜，与 W08 一致，无障碍标签「搜索收件箱」），右为**任务提醒设置**（铃铛，无障碍标签「任务提醒设置」，点开现有「任务提醒设置」Sheet `NotificationSettingsView`）。两个按钮尺寸、底色按 W08 搜索按钮的样式，触控区各 ≥44pt。
2. **计数行**：「今天需要你处理 · N」（N 的口径见第 6 节，不补零）。
3. **离线提示行**（仅在有 Mac 离线时出现，见 2.4/2.5）：一行文字，紧贴计数行下方、卡片列表上方。
4. **卡片列表**：一件事一张卡，按第 7 节排序（创建时间倒序），纵向滚动，支持下拉刷新。
5. **底栏**：「工作空间 / Norma / 收件箱」，收件箱选中；收件箱图标右上角红色角标显示 N（N=0 时不显示角标）。

以下状态互斥地决定第 3、4 区显示什么；标题行、底栏始终存在，计数行除「未配对电脑」外始终存在。

### 2.1 有事（至少 1 张卡）

- 显示：卡片列表；计数行「今天需要你处理 · N」。
- 操作：点卡片（整卡及「下一步」按钮均可点）进入去向页；下拉刷新；右上角搜索、任务提醒设置。

### 2.2 空（全部已连接 Mac 在线且读取成功，且没有任何事项）

- 显示：计数行「今天需要你处理 · 0」；列表区居中空状态，只显示主文案「目前没有需要你处理的事」，**不加**副文案（不显示「Norma 会继续跟进。」）。底栏无角标。
- 操作：下拉刷新；右上角搜索（结果必然为空，见 2.7）、任务提醒设置。
- 约束：只有**所有**已配对 Mac 都在本次读取成功时才能显示空状态；任一 Mac 离线或读取失败时不得显示「目前没有需要你处理的事」（见 2.4/2.5）。

### 2.3 加载

- **首次加载、本机没有任何缓存**：计数行显示「今天需要你处理 · …」（不显示数字），列表区显示系统进度指示 +「正在读取你的电脑上的待处理事项」。底栏不显示角标。不显示空状态。
- **已有缓存再刷新**：先显示上次的卡片和计数，刷新在后台进行，不清空列表、不闪烁；刷新完成后按新结果增删卡片（短淡入/淡出，减少动态效果下只淡入淡出）。
- 多台 Mac 各自独立读取：先返回的 Mac 先出卡片，慢的 Mac 不阻塞其他 Mac 的卡片；某台 Mac 仍在读取时不算离线，也不出离线提示。
- 何时触发读取见第 2.8 节。

### 2.4 部分 Mac 离线（≥1 台在线读取成功，≥1 台离线或读取失败）

- 离线提示行：
  - 1 台：「「{Mac 名称}」离线，它的事项可能已过期」
  - ≥2 台：「{K} 台电脑离线，它们的事项可能已过期」
  - 在线但本次读取失败（非离线）：同样计入，文案用「「{Mac 名称}」暂时读取失败，它的事项可能已过期」；与离线并存时合并为「{K} 台电脑暂时无法读取，它们的事项可能已过期」。
- 卡片：在线 Mac 的卡片正常显示；离线 Mac 的**上次已同步**卡片照样显示、照样参与排序，卡上加「可能已过期」标记（第 3.3 节）。
- 操作：点提示行进入现有「已连接电脑」页（W02），可在那里看连接状态；点「可能已过期」的卡片仍可进入去向页，但页内处理按钮不可用（第 4.3 节）。
- 被撤销授权或已解除配对的 Mac：它的事项立即从列表移除，不作为「可能已过期」保留（与 #55「离线缓存不是通行证」一致）。

### 2.5 全部 Mac 离线（已配对 ≥1 台，本次全部离线或读取失败）

- 离线提示行：「所有电脑都离线，以下事项可能已过期」（只有 1 台已配对 Mac 时用「「{Mac 名称}」离线，以下事项可能已过期」）。
- 有缓存卡片：全部显示并带「可能已过期」。
- 无缓存卡片：列表区显示「暂时连不上你的电脑」+ 说明「连上后才能看到需要你处理的事」+ 按钮「查看已连接电脑」。**不显示**「目前没有需要你处理的事」。
- 计数与角标按第 6 节口径（包含「可能已过期」卡）。

### 2.6 未配对电脑（本机没有任何已配对 Mac）

- 计数行隐藏（不显示「今天需要你处理 · 0」）；列表区显示「先连接你的电脑」+ 说明「连接后，需要你决定和验收的事会出现在这里」+ 主按钮「扫码添加电脑」，点后进入现有扫码添加电脑流程（W02 主操作）。底栏无角标。
- 右上角任务提醒设置入口仍在；搜索按钮隐藏（没有可搜的内容）。

### 2.7 搜索（最小可行定义）

- **入口**：点右上角搜索按钮，标题行下方出现系统搜索栏并自动聚焦键盘，占位文字「搜索标题、工作空间、Agent 或电脑」，右侧「取消」。
- **搜索范围**：只在收件箱**当前列表里的卡片**中本地过滤，不向 Mac 发请求，不搜已处理事项、详情原文、审批参数或成果文件。包括「可能已过期」与「等待 Mac 确认 / 结果未确认」的卡片。
- **匹配字段**：卡片标题、Mac 桌面工作空间名、Agent 名、来源电脑名（Mac 名称），任一字段包含关键词即命中。忽略大小写与首尾空格；中文按子串匹配；多个空格分隔的词需全部命中（每个词可命中不同字段）。
- **输入即过滤**：每次输入变化立即更新结果，不需要回车。结果保持第 7 节的排序。关键词为空时显示全部卡片。
- **无结果**：列表区显示「没有找到「{关键词}」相关的事项」+ 说明「可以换个关键词，或取消搜索查看全部」。
- **计数与角标**：搜索期间计数行与底栏角标**仍显示全部未处理数 N**，不随搜索结果变化。
- **搜索中的变化**：刷新导致卡片新增/消失时，结果实时更新；在搜索结果里点卡片进入去向页，返回后保留关键词与结果；处理成功的卡片从结果中消失。
- **退出**：点「取消」清空关键词、收起键盘、恢复完整列表；切换底栏标签再回来时不保留搜索状态。
- 离线提示行在搜索时照常显示。

### 2.8 刷新时机（前台）

收件箱向每台已配对 Mac 拉取待处理列表的时机只有以下几种：

| 触发 | 行为 |
|---|---|
| 打开收件箱 | 每次进入收件箱页面（点底栏「收件箱」、从其他标签切回、App 回到前台时正停在收件箱、点通知 / 实时活动落到收件箱）立即拉一次 |
| 收到推送 | App 在前台收到收件箱相关推送（审批、失败、待验收）时立即拉一次，不论当前停在哪个标签，以便更新计数和角标 |
| 停留补拉 | 停留在收件箱页面（含首屏、搜索中）期间，每 30 秒补拉一次 |
| 下拉刷新 | 用户下拉时立即拉一次 |
| 退到后台 | 停止所有拉取和 30 秒补拉；回到前台按「打开收件箱」规则处理 |

- 离开收件箱页面（切到其他标签、进入决定页 / 验收页）后停止 30 秒补拉；回到收件箱首屏重新按「打开收件箱」拉一次，并重新开始 30 秒计时。
- 某台 Mac 的上一次拉取尚未结束时，不对它再发新的拉取（合并为一次），避免请求堆积。
- 拉取失败按第 2.4/2.5 节处理，不额外加快重试。
- 不在其他标签页定时拉取；底栏角标在其他标签上显示最近一次拉取（含收到推送时的那次）的 N。

## 3. 卡片

两类卡片共用同一版式（W08）：左上类型图标 + 类型徽标胶囊；标题（粗体大字）；来源行（文件夹图标 + Mac 桌面工作空间名）；Agent 与来源电脑行；Norma 一句说明（最多 2 行，超出省略）；分隔线；底部「下一步」按钮文案 + 右箭头；时间。卡片右上的装饰色块按 W08 还原，不承载信息。

### 3.1 字段与文案

### 3.2 各类卡片在去向页的按钮（互不混用）

| 卡片 | 主按钮（右，蓝色） | 次按钮（左，白底） | 不出现的按钮 |
|---|---|---|---|
| 需要决定 · 工具审批 | 「批准」 | 「拒绝」（红字） | 「重试」「放弃」「验收通过」「退回修改」 |
| 需要决定 · 任务失败 | 「重试」 | 「放弃」 | 「批准」「拒绝」「验收通过」「退回修改」 |
| 成果待验收 | 「验收通过」 | 「退回修改」 | 「批准」「拒绝」「重试」「放弃」 |

- **审批**：只显示 Mac 返回的、该审批实际允许的选项（`ApprovalSnapshot.decisions`，`crates/norma/src/mobile/approval.rs:95-102`）；只允许其一时只显示那一个。项目只读授权（`Decide` 需要 control 权限，`crates/app/src/mobile/activity.rs:136-139`）时两个按钮都不可用，并显示「你在这台电脑上只有查看权限，请在 Mac 上处理」。
- **失败**：
  - 「重试」= 让同一 Agent 在原任务上再执行一次（Mac 端「重试」操作，T2 计划提供），带回执。
  - 「放弃」= **只把这张卡从收件箱移除，Mac 上的任务状态不变**（仍为失败，线程与任务里照常可见）。实现为 Mac 端新增的「忽略」操作（T2 计划提供），带回执、可幂等；卡片等回执成功后才消失。页面在按钮上方固定提示「放弃只把这件事移出收件箱，Mac 上的任务状态不变」（见 W08b）。
  - 被忽略的事项 Mac 不再返回（T1）。忽略记录存在 Mac 本机，以「项目 + 事项键」为准（事项键按 `project_id` 计算，不带 `area_id`，与第 7.2 节去重键一致）；工作空间 ID 只作附带信息。因此在任一工作空间下放弃后，这台 Mac 的**所有**工作空间都不再出这张卡。
  - 忽略只作用于这一次失败（同一 `run/turn`）：重试后再次失败会换新的 `run/turn`，作为一张新卡出现，**不受旧忽略记录影响**。
- **成果**：「退回修改」打开意见 Sheet，发送后走 Mac 端「退回修改」操作（T2 计划提供），带回执；「验收通过」沿用现有 `accept`。

### 3.3 「可能已过期」

- 出现条件：仅当卡片来源 Mac 当前离线或最近一次读取失败。Mac 重新连上并读取成功后，标记消失；若该事项在 Mac 上已不存在，卡片直接消失。
- 视觉：灰色小字，不改变卡片类型颜色；卡片整体不置灰（保持可读）。
- 无障碍：VoiceOver 读出「可能已过期」。

## 4. 点击去向与返回

### 4.1 去向

- 点「需要决定」卡 → **决定页**；点「成果待验收」卡 → **验收页**（W09）。直接压入收件箱的导航栈，**不经过**「工作空间详情」，也不以 Sheet 打开。
- **决定页**（设计图：[W08a 工具审批](norma-ios-prototypes-2026-09-26/W08a-decision-approval.png)、[W08b 任务失败](norma-ios-prototypes-2026-09-26/W08b-decision-failure.png)、[W08c 等待 Mac 回执](norma-ios-prototypes-2026-09-26/W08c-decision-waiting.png)；沿用 W06/W09 的浅色版式、卡片圆角与底部双按钮）。自上而下：
  1. 顶栏：左上返回「‹」；居中标题「需要决定」，下方小字「› {Mac 桌面工作空间名}」；右上红色状态胶囊「待决定」。
  2. 头卡：红色警示图标 + 徽标「需要决定」+ 子类型胶囊「工具审批」或「任务失败」；标题；四项元信息：文件夹图标 + Mac 桌面工作空间名、电脑图标 + 来源电脑、Agent 图标 + Agent 名、时钟图标 + 创建时间（「今天 09:36」格式）。
  3. Norma 卡：Norma 头像 +「Norma」+ 一句说明（与收件箱卡同源）。
  4. 详情卡：
     - 审批：「工具与参数」——工具名 + Mac 返回的审批参数摘要（等宽、可选中、可展开查看全文）。
     - 失败：「失败原因」——Mac 返回的失败摘要（等宽）+「失败于 {步骤}」（Mac 有则显示）。
     - 两者底部都有次要入口「查看原任务 ›」，打开该事项所在任务/线程（使用已有入口，不新做页面）。
  5. 说明行（ⓘ）：审批「这次决定只对本次工具调用生效」；失败「放弃只把这件事移出收件箱，Mac 上的任务状态不变」。
  6. 底部双按钮：审批左「拒绝」右「批准」；失败左「放弃」右「重试」。
- **决定页按钮态**：
  - 可用：如 W08a/W08b。
  - **等待 Mac 回执**（W08c）：被点的按钮变浅蓝并显示转圈 +「正在等 Mac 确认…」，另一个按钮置灰不可点；说明行改为「已发给 {Mac 名称}，收到回执后这件事会从收件箱移除」。点「拒绝」「放弃」时同理，进度态出现在被点的按钮上。
  - 结果未确认 / Mac 离线 / Mac 拒绝执行：见第 5 节。
  - 只读或来源 Mac 离线：两个按钮均不可用（第 3.2、4.3 节）。
- **验收页**（W09）：顶部返回 + 标题「成果验收」+ 来源 + 状态胶囊「待验收」；成果预览、验收结果摘要、「验证与证据」三条、底部「退回修改」「验收通过」。「退回修改」→ 意见 Sheet（M09 第 184 行），输入框为空时「发送」不可用；发送后走第 5 节回执流程。等待回执态与决定页一致。

### 4.2 返回

- 左上返回（及系统右滑返回）回到收件箱首屏，**保持原滚动位置**（搜索中则保留关键词与结果）；未处理时卡片原样在原位置。
- 处理成功（收到 Mac 成功回执）后：页面按钮区短暂显示结果（「已批准」「已拒绝」「已重新开始」「已移出收件箱」「已验收」「已退回修改」），随后自动返回收件箱，该卡片淡出消失、计数和角标同步减 1。
- 处于「等待 Mac 确认」时返回：允许返回，卡片保留并显示等待状态（第 5 节）。

### 4.3 来源 Mac 离线时进入去向页

- 能打开，显示上次缓存的卡片信息（标题、来源、说明）；详情区显示「「{Mac 名称}」离线，连上后才能查看详情和处理」；所有处理按钮不可用。

## 5. 处理后消失的规则

总规则：**发出操作 → 等 Mac 回执 → 回执成功才消失**。适用于全部六个操作：批准、拒绝、重试、放弃（忽略）、验收通过、退回修改。没有「已处理」分区，本机不保留已处理卡片。线程/任务里的过程与决定照常留痕（#60 验收条件「验收后消项但线程留痕」）；「放弃」不改变 Mac 上的任务状态。

| 阶段 | 页面表现 | 收件箱卡片表现 | 计数/角标 |
|---|---|---|---|
| 发出前 | 按钮可用 | 正常 | 计入 |
| 已发出，等待回执 | 被点的按钮显示进度「正在等 Mac 确认…」，其余处理按钮不可用（W08c） | 下一步位置显示「等待 Mac 确认…」；可点进页面看状态，不能重复发操作 | 计入（未确认不减） |
| 回执成功 | 显示结果后自动返回 | 消失 | 减 1 |
| 回执失败：Mac 拒绝执行，事项仍在 | 显示「Mac 没有执行：{Mac 返回原因}」，按钮恢复可用 | 恢复正常 | 计入 |
| 回执失败：事项已不在（已在 Mac 或别处处理） | 显示「这件事已经处理完了」+「回到收件箱」 | 消失 | 减 1 |
| 超时/响应丢失（结果未知） | 显示「还没收到 Mac 的确认」+ 按钮「查询结果」（按原操作 ID 向 Mac 查询，沿用现有 `receipt` 查询）；**不自动重发**，处理按钮保持不可用直到查询有结论 | 下一步位置显示「结果未确认」，点进页面可查询 | 计入 |
| 等待中 Mac 离线 | 显示「「{Mac 名称}」离线，连上后会自动核对结果」 | 显示「结果未确认」+「可能已过期」 | 计入 |
| Mac 重新连上 | App 自动按原操作 ID 查询一次：成功→消失；Mac 拒绝→恢复；仍未知→保持「结果未确认」 | 随结论变化 | 随结论变化 |

补充规则：

- 同一事项同时只能有一个未决操作；本机已保存的未决操作在 App 重启后仍在（现有 `activity-decisions.json`，`ios/App/WorkspaceActivityDetailView.swift:21`），重启后卡片仍显示「结果未确认」，可查询。
- 离线时不排队任何审批、重试、放弃、验收、退回（与 2026-09-06 规格第 164 行「审批…不能排队后静默执行」一致）。
- 用户在 Mac 上或另一入口先处理了同一事项：下一次刷新后卡片直接消失，不提示。
- 重试、忽略、退回修改按 T2 计划均可幂等：同一操作 ID 重复发送只执行一次，查询返回同一回执。
- 「放弃」成功后，同一项目在这台 Mac 其他工作空间下的同一事项也不再出现（忽略按「项目 + 事项键」生效，见第 3.2 节）。

## 6. 计数与角标口径

- **N = 收件箱列表当前的全部未处理卡片数**，包括：两类全部卡片、「可能已过期」卡、「等待 Mac 确认 / 结果未确认」卡。不包括：已收到成功回执的事项、已忽略（放弃）的事项、已撤销授权/已解除配对 Mac 的事项、Agent 提问、#59 手机线程成果。
- **计数行 N 与底栏角标 N 必须始终是同一个数**，由同一份卡片列表计算，不允许各自取数；搜索不改变 N。现有 Mac 摘要里的 `failure_count` 与失败卡数量可能不一致（`workspace_activity.rs:285-299`：失败计数先加 1，只有 `run_id`、`turn_id` 非空才生成卡片），因此 N 不得用 Mac 的 `*_count` 字段相加，必须数卡片。
- 「今天」：文案保留「今天需要你处理」，**计数不按日期过滤**，统计全部未处理事项（昨天及更早的未处理事项也在列表和 N 中）。
- 数字格式：「今天需要你处理 · 2」，**不补零**（W08 原型上的「· 02」不照搬）。
- 角标：N=0 不显示；1–99 显示数字；>99 显示「99+」。计数行不截断。
- 首次加载未完成时不显示数字和角标（2.3）；有缓存时先显示缓存的 N。

## 7. 多 Mac 汇总：去重与排序

### 7.1 数据范围

- 汇总本机**所有**已配对、且授权仍有效的 Mac，每台独立读取，互不阻塞。每张卡必须带来源 Mac 标识与名称。
- 数据来源为每台 Mac 返回的统一待处理列表（T1 计划提供）；#59 手机线程的成果首版不纳入。

### 7.2 去重

- 唯一键：**Mac 标识 + 项目 + 事项 ID**（与 T1 一致）。
  - Mac 标识：`machine_id`。
  - 项目：Mac 项目 ID（`project_id`）。同一项目被放进同一台 Mac 的多个桌面工作空间时，同一事项只出一张卡，卡上显示 Mac 随该条返回的工作空间名。
  - 事项 ID：类型 + 事项目标。审批 = `node_id + profile + run_id + session_id + turn_id + request_id`；失败 = 同上但无 `request_id`；成果 = `fingerprint`。这与推送的事件身份同源（`push/activity.rs:106-119` 用 `machine + project_id + kind + node/profile/run/session/turn/request/fingerprint` 派生 `event_id`），保证「一条通知 ↔ 一张卡」。
- 不同 Mac 之间不合并：两台 Mac 上同名项目、同名任务各自成卡，靠来源电脑区分。
- 事项键只按项目计算，**不带 `area_id`、不带工作空间**；工作空间 ID / 名称只用于显示来源。Mac 的忽略记录用同一把键（项目 + 事项键），因此去重与忽略口径一致：一张卡对应一个事项，一处忽略处处不再出现。
- 刷新时同一唯一键的卡片原地更新内容，不重新插入、不改变位置。
- 同一失败重试后再次失败，以新的 `run/turn` 出现为新卡，旧卡因旧事项不存在而消失（不会同时出现两张）；之前对旧失败的忽略记录不影响新卡。

### 7.3 排序

- **按事项创建时间倒序，最新的在最上面**，两类卡混排，不按类型分组。
- 理由：用户最常见的进入方式是刚收到通知，最新事项在顶部最容易对上；旧事项靠「今天需要你处理 · N」和角标提醒总量。
- 同一时间的并列项：依次按 Mac 名称、工作空间名、事项 ID 排序，保证每次刷新顺序稳定。
- 「可能已过期」卡按其原创建时间参与排序，不沉底也不置顶。
- 创建时间由 Mac 返回（T1 计划提供；现有代码没有该字段，见第 9 节）。

## 8. 通知与实时活动点击去向

- **普通通知**（审批、失败、成果待验收）→ 切到「收件箱」标签 → 直接打开该事项对应的决定页 / 验收页；返回时回到收件箱首屏。不再打开「工作空间详情」（现状 `NotificationPresenter.swift:43-44`）。
- 打开前先向来源 Mac 核对该事项（与 2026-09-06 规格第 135 行「打开后…向 Mac 核验最新状态；延迟到达的通知不作为直接执行审批的依据」一致）。
- 事项已被处理 / 已忽略 / 已消失：落在收件箱首屏，顶部一行提示「这项提醒已经处理完了，以下是当前事项」（沿用现有 `CommandDecisionInbox.swift:87` 的同义文案），2–3 秒后自动淡出。

- 通知指向的 Mac 已解除配对 / 授权已撤销：落在收件箱首屏，不提示具体内容。
- **锁屏实时活动 / 灵动岛**（汇总视图）点击：打开**收件箱首屏**，不打开工作空间详情，也不直达某张卡。
- 成果通知精确定位依赖推送带 `fingerprint`（T1 计划提供；现有 `push/activity.rs:131-138` 不带）。
