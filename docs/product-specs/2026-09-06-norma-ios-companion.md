# Norma for iPhone：功能清单与首版原型

2026-09-07 · 产品提案 v0.16（多电脑切换） · 范围：功能梳理与交互 HTML，尚未实现 iOS App 或远程服务。

**定位：随身的 Norma 工作台。** 用户离开 Mac 后，能够看懂 Agent 做到哪里、处理阻塞、补充方向，并查看项目中的所有 AI 卡片。代码、Shell、Agent 和执行上下文仍留在用户的 Mac 上。

> **此工作台 HTML 原型已于 2026-09-20 归档。** 当前可交互原型是[实时虚拟人指挥台](../prototypes/norma-realtime.html)。归档副本：[v28 工作台](../prototypes/archive/2026-09-06-norma-ios/norma-ios.html)。

桌面浏览器显示手机与演示路线；手机直接显示应用界面。全部数据为模拟，点击不会运行本地命令或发布软件。状态仅保留在本次页面会话。

实现推进见 [Goal 实时实施计划](../exec-plans/2026-09-07-norma-ios-goal.md)，其中单独记录已完成的规划与尚未启动的真实开发阶段。

## 1. 从 Orca 借鉴什么

已核对 [Orca IDE 的 App Store 页面](https://apps.apple.com/cn/app/orca-ide/id6766130217)，用户已确认参考对象为该产品。页面说明及截图是本次参考依据；未安装或实际测试 Orca iOS。

| Orca 官方页面描述 | Norma 采用方式 |
|---|---|
| 手机作为桌面客户端，代码、Shell、Agent 在桌面执行 | 复用这一职责划分；手机负责查看、指令、确认和提醒 |
| 实时终端镜像，输入、滚动、Tab、Ctrl-C | 任务详情提供终端入口与辅助按键；首先让用户读懂任务摘要 |
| 多 worktree、多终端切换 | 按项目、任务组织，保留工作区、分支、Agent 与节点关联 |
| 二维码配对，配对密钥加密通信 | 首次连接在 Mac 发起，手机扫码，Mac 确认设备与授权范围 |
| 后台长任务与 TUI 空闲通知 | 根据明确的任务完成、失败、待确认事件通知，不把终端空闲直接当成功 |
| 当前描述要求同一 Wi‑Fi / 本地网络 | 局域网用于第一阶段验证；Norma 首发完整验收还要覆盖蜂窝网络到家中 Mac |

任务摘要、结构化审批、项目卡片是本提案的 Norma 设计，不是已验证的 Orca 功能。Orca 页面文字和截图并非完全同步的产品规格，不由截图推导尚未证实的能力。

## 2. 核心场景与范围取舍

1. **先知道下一步，再做决定**：首页由 Norma 梳理当前方向、下一份交付和按优先级排列的 Agent 待办；用户只确认请求、选择优先事项或调整目标与取舍。具体执行、验证和完成状态由 Agent 回传。待决策页保留左右滑动确认。
2. **Agent 被阻塞**：通知进入对应任务，查看请求内容、命令与范围，允许一次或拒绝；收到桌面回执后更新状态。
3. **补充方向或新任务**：指定 Mac、已授权项目与 Agent，发送需求，区分未发送、已送达、已接收、执行中。
4. **需要接管**：查看终端输出、发送输入、中断，保留上下文继续；在手机断线时准确展示最后快照。

第一版围绕现有任务和可确认的动作。无限画布编辑、完整代码编辑器、手机本地运行 Coding Agent、通用远程桌面、多用户协作与自定义 CI 平台暂不进入首发。

按最新反馈，当前版本移除发布页面及相关入口、通知和演示流程，仅保留指挥台、项目、任务、设备。复制任务进展摘要仍作为轻量附属能力。

## 4. 信息架构

```text
连接 Mac（未配对首页 / 设备页扫码入口）
  ├─ 准备 Mac → 扫码取景 → 核对机器与授权 → Mac 确认 → 连接成功
  ├─ 输入配对码 → 校验 → 核对机器与授权
  └─ 连接帮助 / 返回 / 重新扫描

项目
  ├─ 选择项目 → 全部 Norma AI 卡片（双列）
  ├─ 创建卡片 → 选择 Agent / 可选名称 → 空闲卡片
  ├─ 有任务的卡片 → 详情 → 返回原项目
  ├─ 空闲卡片 → 安排任务 → 显式发送目标 → 绑定原卡片
  └─ 卡片选项 → 删除卡片 → 确认移除（保留任务和对话）

指挥台（原总览入口）
  ├─ 今日简报 / 待验收 → 成果对比与确认
  ├─ 行动计划：当前方向 → 下一份交付 → 需要你的决定
  │    ├─ Agent 的 To-do：具体下一步、执行者、状态、优先级
  │    ├─ 待办详情 → 预期交付 / 对应任务 / 去做决策
  │    └─ 调整方向 → 优先项与目标取舍 → Agent 收到方向
  └─ 待你决策：Agent、项目、请求、命令、影响范围
       ├─ 右滑允许 / 左滑拒绝 → 回执 → 下一项
       ├─ 暂时跳过 → 下一项（请求保留）
       └─ 处理记录 / 全部处理完成 → 返回 Agent 待办

任务
  ├─ 项目、状态、关键词筛选
  ├─ 新建任务 / 未发送草稿
  └─ 详情：对话 | 终端 | 变更 | 成果
       ├─ 补充指令、中断、继续
       ├─ 授权请求、产物预览
       └─ 成果：修改前后对比 → 验收通过 / 调整意见回到原对话


设备
  ├─ 我的电脑列表 → 切换当前电脑
  ├─ 添加电脑 → 扫码 / 配对码 → 命名 → Mac 确认 → 独立空工作区
  ├─ 连接、授权项目、查看与控制权限
  ├─ 关键事件通知、外观
  └─ 撤销配对

全局：顶部电脑切换 → 当前 Mac 的项目 / 指挥台 / 任务；通知中心 → 当前电脑的精确任务；设置；断线或只读提示
```

## 5. 最小的系统接入方案

```text
iPhone 客户端
    │ 设备身份、有限范围指令、状态订阅
    │ 局域网 / Tailscale
    ▼
Mac 手机接入层（新增，显式启用）
    │ 校验设备、项目权限、请求唯一 ID、任务/版本状态
    ▼
现有 Norma 应用命令与任务协调器
    ├─ Agent / PTY 执行
    └─ 任务、节点与工作区状态
```

代码、凭据、PTY 与执行上下文留在 Mac。局域网与 Tailscale 共用经过设备认证的加密控制协议，首版不自建控制中继。通知只携带定位信息与最小事件摘要，手机锁屏默认不暴露终端内容、代码或错误日志。不要直接把当前本地 socket 暴露到公网。

Mac 休眠或 Norma 未运行时不承诺远程唤醒。手机展示最后快照并说明恢复方式；需要保持工作时，防休眠必须由用户显式启用。

2026-09-07 方案讨论已确认：关闭 Norma 窗口后，其中的 Agent 不继续运行；首版沿用现有窗口与任务生命周期，不新增脱离窗口运行的常驻执行服务。手机断线或切换电脑不结束 Mac 上的任务；窗口关闭后，手机将最近状态标为历史快照，不把旧任务显示为仍在实时运行。

2026-09-07 方案讨论已确认：首版支持手机锁屏后的待确认、完成和失败通知，引入轻量 APNs 通知服务。Mac 将事件交给通知服务，由 APNs 通知已绑定的 iPhone；服务不承载任务控制或执行。打开通知后，手机定位到对应电脑、项目与任务，并向 Mac 核验最新状态；延迟到达的通知不作为直接执行审批的依据。

2026-09-07 方案讨论已确认：指挥台统一汇总所有已配对电脑中、手机获授权查看的待决策事项；项目与任务页继续按当前电脑浏览。每张决策卡片标明来源电脑与项目，操作绑定来源电脑、项目、任务和决策请求，不随当前电脑选择变化。离线电脑的缓存事项标记为待核验，恢复连接并核验最新状态后才允许处理。此项是待实现方案；v28 HTML 原型的指挥台仍跟随当前电脑。

2026-09-07 方案讨论已确认：首版移动端完整支持的执行 Agent 限定为 Codex 与 Claude；Cursor / OpenCode 的移动端接入后续安排，不移除桌面已有能力。Norma 继续负责总结、规划与协调，不作为第三种执行 Agent。

2026-09-15 范围更新：Cursor 已进入移动端执行 Agent 范围。iOS 可从项目定义或手动类型创建 Cursor 卡片、查看状态/终端/原始对话、发送与排队消息、删除卡片，并使用 Cursor Hook 的 `conversation_id` / `generation_id` 生成准确会话与回合回执；OpenCode 仍后置。Cursor 当前没有经验证的结构化审批和可靠停止协议，界面必须按 Mac 返回的能力隐藏这些动作，不得用终端按键猜测成功。

### 状态与操作规则

- **任务执行与手机连接互相独立**：手机离线不表示任务失败，连接恢复也不等于任务已完成。
- **进度可信**：有明确步骤时显示“3/5 步”，其余显示当前阶段；不把步骤比当作耗时比。终端空闲与任务成功是不同事实。
- **写操作必须有回执**：请求唯一 ID 与目标版本；区分未发送、已送达、已接收、已执行、结果未知。结果未知时查询原请求，不能盲目重试。
- **离线不自动重放**：普通文字保留草稿；审批、终端控制与取消不能排队后静默执行。重连后重新读取对象状态，由用户确认。
- **输出与产物受限**：终端分块与背压，快照脱敏，产物受授权文件范围限制，预览不接受任意本地路径。

这些是实现要求；原型只覆盖主要可见状态和部分逻辑检查，不提供真实加密、鉴权、幂等存储或 Provider 适配。

## 6. Apple 设计原则如何落地

按最新反馈，全页面默认采用纯黑底色（#000）、炭灰卡片（#111）和白色主按钮。移除墨绿渐变、背景网格与指挥台装饰球，设备图片通过 CSS 灰度显示；少量颜色只用于品牌与警告。项目 `apple-design` 的内容优先、清晰层级、熟悉导航、直接反馈和用户控制原则贯穿项目、指挥台、决策、任务详情、设备、配对和弹层；任务名称先于 Agent 元信息，细线与大圆角负责分组。统一样式集中在 `norma-ios.css`，不引入框架或依赖。状态同时保留文字，设置中可切换浅色，刷新后默认深色。

主要动作进入拇指易达区域；按下立即反馈，按钮提供 hover、pressed、focus、selected 与 disabled。弹层使用原生 HTML `dialog` 支持焦点约束和 Escape，避免手写复杂手势。提供 `prefers-reduced-motion`、减少透明度与高对比偏好。真实 SwiftUI 版本仍需系统 Dynamic Type、VoiceOver 和 iPhone 设备验收，浏览器原型不能替代。

### 项目卡片与运行边框

“项目”底部入口展示项目卡片。项目内用双列卡片网格展示全部卡片，不受任务页搜索或状态筛选影响。示例中 Norma OS 有 4 张卡片（2 运行、1 完成、1 空闲），Studio Site 有 3 张待确认卡片。卡片注册表与任务分开，空闲卡片也能显示；本原型每张卡片最多关联一条任务，正式版本按桌面节点身份同步。

项目页的加号用于「创建卡片」，只选择执行 Agent（Codex / Claude / Cursor）及可选名称，创建后为 idle，taskId 为空，不生成任务或待办。用户稍后从空闲卡片点击「安排任务」，填写目标并显式发送，才创建任务并绑定原卡片，不额外复制卡片。任务页的独立新建任务流程仍可用。

每张卡片右上角提供 44px 的独立选项按钮，可查看任务或删除卡片。删除前说明影响范围：只移除项目中的卡片，不删除关联任务与对话，也不中断正在执行的 Agent；任务仍可从任务页访问。取消删除不改变状态。卡片关联的未发送草稿在删除后保留内容并解除关联。离线或只读禁止创建、删除与安排。

按 `apple-design` 与 `emil-design-eng` 原则，用克制的白色短拖尾表示“正在工作”：SVG 圆角描边配合原生 CSS 动画，每 3.8 秒沿真实边界走一圈，不代表任务完成比例。只有已配对、在线且任务为 running 时启用。完成、待确认、中断、空闲、仅送达不播放；手机离线保留任务最后状态，但停止动画，标注快照。页面隐藏时暂停，`prefers-reduced-motion` 下使用静态浅灰边框，状态文字始终保留。卡片标题均衡换行，触控与键盘焦点沿用现有反馈。

按最新反馈，卡片内容只保留品牌图标、卡片名称（未命名时使用任务名称）和状态；移除 Norma 编号、重复的品牌名、阶段说明与步骤数，详情仍可点击查看。Codex 使用云形终端标记，Claude 使用星芒图标，替换字符占位；运行时 Codex 以 2.8 秒周期小幅浮动、Claude 以 8 秒周期旋转。中断、离线或完成时图标静止，减少动态效果时不播放。品牌名称作为图标辅助标签和卡片状态说明保留。任务列表与详情复用相同图标。图标路径来自 [LobeHub Icons](https://github.com/lobehub/lobe-icons) 的 `codex.svg` / `claude-color.svg`，MIT 声明随 HTML 内嵌，不依赖外部 CDN。

### 决策卡片：把首页从查看进展改为做决定

用户反馈总览与任务重复，因此删除首页任务计数、任务列表与项目入口聚合，底部入口统一命名为“指挥台”，其中“待你决策”子页兼容原有滑动交互。保留 `#overview` 链接。决策队列只呈现状态为 WaitingApproval 的请求；三个示例是连接测试、锁文件更新和视觉快照更新，审批与任务详情共用相同状态和请求内容。

沿用 Apple / Emil 的直接操作原则：卡片水平跟手移动，拖动过程中显示方向和“松手允许/拒绝”，释放后才提交。距离阈值为卡宽的 28%，限定在 88–118px；纵向滚动、短滑、pointercancel、失去焦点都不提交。按钮提供同样的决定能力，支持键盘和辅助技术；减少动态效果时取消卡片位移但保留决定提示。离线或只读时禁止滑动提交与按钮操作。

“暂时跳过”只切换当前卡片，不减少请求数量。成功处理后自动进入下一项；确认回执写入处理记录，重复请求不会再处理。全部完成时显示空状态。正式接入仍需 Mac 校验请求身份、版本和范围，并返回接收/执行回执；本页只模拟明确的授权动作，不提供生产发布或通用高风险动作的一滑批准。

### 指挥台：用户决定，Agent 执行

“行动计划”是默认首页。Norma 用一条方向和下一份交付说明要往哪里走，再突出当前需要用户决定的事项。下方 To-do 展示后续动作而非重复任务标题，例如“完善语音输入体验”的下一步为“验证弱网下的语音连续性”，预期交付为测试结果与修复说明。每项标明 Codex / Claude、项目与状态，点击可查看交付内容和关联任务。

用户没有执行工作或手动勾选完成的职责。待办由任务状态投影，完成/取消后退出；审批通过变为进行中，拒绝后保留为已中断。计划与决策、项目卡片共用任务数据。当前 demo 是已定义任务的确定性梳理，未调用模型生成计划。

“调整方向”选择一项优先推进的工作，输入 1–300 字目标和取舍；成功发送后更新方向和待办排序，并在该执行 Agent 的任务上下文留下指令回执。不自动批准请求，不把排序改变冒充任务已暂停或完成。离线、只读、未配对、无效事项与空输入均不能修改状态。真实接入由 Norma 返回结构化计划、任务关联和执行回执，再同步手机；计划建议与已执行事实需分开。

沿用 `apple-design` 的内容优先与渐进呈现：先方向，再用户决策，再 Agent 待办；执行细节进入底部弹层，使用原生表单和分段控件。保持默认深色、44px 触控区域和现有焦点/按下反馈；沿用决策页的原生手势，不添加依赖。

### 任务详情：把屏幕还给内容

按用户对内容受挤压的反馈，详情采用 Apple 式推入页面：收起全局品牌栏与底部三项导航，顶部仅保留返回、任务标题、Agent 状态和任务信息入口。“对话 / 终端 / 变更 / 成果”紧接导航，分支、项目、耗时与进展摘要移入任务信息弹层；长标题可在弹层完整查看。

终端输出独立滚动，快捷键与输入区固定底部；去掉重复元信息、快照说明和大圆角容器。“模拟快照”持续可见，任务信息保留不执行真实命令的说明。对话与变更共用紧凑头部，各自内容滚动；返回原项目/任务/指挥台时恢复全局导航。中断后输入区变为继续任务入口，恢复后重新开放输入。

### 默认聊天与紧凑字号

任务默认打开“对话”。原动态时间线改为正常聊天阅读顺序：用户目标、Agent 当前进展、后续补充消息与接收回复。聊天内容独立滚动，底部固定多行输入框与发送按钮；发送成功后清空并保留输入焦点、滚动到最新消息。输入随内容增长，最大 120px，超出后在输入框内滚动；按钮点击区域保持 44px。

Enter 发送，Shift+Enter 换行，中文输入法组词期间不提交；空白消息禁止发送。草稿按任务保存，切换终端/变更后回来仍保留；离线和只读允许编辑草稿，但不允许发送，重连不自动重放。已完成或中断的任务需显式继续。中断入口收进“任务信息”。聊天复用既有消息状态，回复明确标注为模拟，不调用真实模型。

整体字号下调：页面标题 24–26px、计划与弹层标题 18px、任务标题 14px、卡片和消息正文 13px；辅助信息不继续压小。iPhone 输入框保留 16px，避免聚焦时浏览器自动放大；仅缩小视觉文字，不缩小触控区域。继续使用系统字体、深色外观与现有 Apple 式层级。

### 成果验收与今日简报

成果页提供“修改前 / 修改后”对比，当前仅 `workspace` 任务包含项目卡片的示例视觉预览，其他任务显示成果准备状态。已完成任务才允许验收；确认后保留任务完成状态并记录已验收回执，重复验收被拒绝。运行中、离线和只读不可提交验收。

“继续调整”或预览上的批注点打开反馈输入，发送后在原任务留下验收反馈，并标为已送达、等待 Agent 接收；重新继续已验收任务时清除旧验收标记。页面不把反馈送达当作执行完成。指挥台的待验收入口和今日简报随当前演示状态更新，简报汇总方向、待决策、待验收与下一份交付。

### 居中导航与扫码连接

底部导航已通过 390px 与 320px 真实浏览器验收，中央入口偏移不超过 0.01px，顶部无重叠，触控区域至少 44px。[项目页与新版导航](../prototypes/archive/2026-09-06-norma-ios/assets/norma-ios-project-navigation.png)。

底部导航固定为「项目 · 指挥台 · 任务」，三个等宽入口让指挥台始终处于手机正中。中央使用 Norma 标志，保留文字名称，选中时显示白色圆形按钮；设备管理移到右上角，仍可一键进入扫码连接和授权管理。默认保持深色，44px 触控与键盘焦点不缩小。

页面主标题与正文左对齐，便于顺序扫读；底部“指挥台”始终居中。连接流程使用居中的紧凑导航标题，隐藏全局品牌栏与底部导航，遵循 `apple-design` 的明确层级、内容优先和可逆导航原则。

参考 Orca IDE App Store 明确描述的「桌面显示二维码、手机扫码配对」，新增 `#connect` 独立页面。引导用户在 Mac 打开 Norma 的「设置 → 手机连接 → 连接手机」；首次连接建议同一 Wi-Fi。此桌面入口、相机权限及真实网络配对均是产品方案，尚未实现。

扫码演示与手动六位码共用设备核对页，默认预览只读授权。识别机器不会立即注册；只有点击「模拟 Mac 确认并连接」后，演示设备状态才变为已配对，并出现成功页。正式版本须由 Mac 校验和确认权限。用户可以返回、重新扫描或查看连接帮助，取消不会撤销已有配对；新增电脑只有在 Mac 确认后加入设备列表，不覆盖当前电脑。

### 多电脑切换：电脑先于项目

顶部 Norma 标志下方持续显示当前电脑，并提供“切换电脑”入口；项目页的电脑名称也可以点击切换。设备页列出全部电脑与当前选中项，显示在线 / 离线 / 未配对、控制权限、项目数量及运行任务。沿用 `apple-design` 的明确归属、直接操作与渐进呈现原则，保持纯黑风格、中央指挥台和 44px 触控。

每台电脑保存独立的项目、卡片、任务、消息、草稿、方向、审批记录、连接和授权状态。当前示例为 MacBook Pro 的 Norma OS / Studio Site，以及 Mac mini 的 Website。切换不会中断任何 Agent；筛选与详情切回当前电脑有效的项目，未发送聊天按电脑及任务保留。任务详情、发送提示和进展摘要都注明执行电脑。

URL 同时携带电脑身份与项目 / 任务位置，浏览器后退和前进会恢复对应电脑；未知电脑进入设备选择提示，不能把同 ID 任务误当成另一台的任务。单机离线、只读或撤销不影响其他电脑；未配对引导仍提供切换入口，避免用户困在已撤销的机器上。

“添加电脑”复用扫码引导，允许给新电脑命名，默认只读，只有模拟 Mac 确认后才加入列表。新机拥有独立空工作区，原有电脑的数据和权限保持不变。所有注册与状态仍是本页模拟，刷新重置；真实版本需要稳定设备 ID、持久化配对与独立网络连接。

## 8. 推荐开发顺序

1. **先验证 Agent 接入**：在实际使用的 Codex / Claude 版本上，分别验证原有会话中的消息读取、发送、状态关联和按请求批准 / 拒绝；检查手机操作与桌面处理发生竞争时的结果。若现有会话无法通过受支持接口完成审批，先明确运行方式的改造代价，再定接入方案，不以统一输入 `y` 代替结构化审批。
2. **完成最小真机闭环**：SwiftUI 客户端、Mac 受控网络入口、扫码配对、Keychain、项目授权与撤销；两台 Mac 上通过局域网 / Tailscale 查看真实任务、发送指令并获得回执。断线恢复和请求去重在这一阶段完成。
3. **接齐项目、卡片与聊天**：按电脑 / 项目 / 会话隔离消息与草稿，完整聊天采用分页历史与增量更新；复用创建、关闭卡片和任务队列，保留创建卡片不立即派任务的语义。验证只读、窗口关闭、重启后旧请求失效与忙碌任务取消。
4. **完成指挥台与锁屏通知**：各 Mac 保有真实决策状态，手机汇总全部获授权电脑的事项；APNs 发送最小通知，打开后回源校验。接入 Norma 总结、方向、关联 Agent 的 Todo 与成果验收，确保建议、已安排和执行完成有明确区别。
5. **完成发布前验收**：真实 iPhone 蜂窝网络连接家庭 Mac；覆盖网络切换、锁屏通知、重复与过期审批、桌面和手机同时操作、两台电脑的同名项目、单机离线与单机撤销。完成系统键盘 / 语音输入、Dynamic Type、VoiceOver 与弱网测试，再进入发布流程。

首批验证指标：待确认事件到用户处理的耗时；移动端发出指令的成功回执率；连接恢复后状态一致性；任务阻塞定位与恢复是否不依赖返回电脑。基线尚未采集，不给出未经验证的业务数字。

状态：**历史原型规格，已由 [2026-09-28 架构讨论稿](../design-docs/2026-09-28-norma-ios-native-architecture-proposal.md)与 [Goal](../exec-plans/2026-09-28-norma-ios-ideas-workspaces-native-goal.md) 取代**。本文件中的「保存想法即建 Workspace」及 Workspace 硬约束属于旧方案，不作为当前开发或新原型依据；已有 W01–W09 图片只作历史视觉参考。

**给设计 AI 的阅读顺序**：先看「一」理解产品对象与角色，再看「四」逐项落实功能描述和交互，最后按「五」逐页生成图片。每张图片只表现一个页面或一个 Sheet 状态；同名 Workspace、电脑、项目、Agent、任务和成果在全套图片中保持一致。

## 一、产品骨架

**一句话定义**：用户用一个 Workspace 推进一件事；Norma 在其中协调多个 Agent，电脑提供可执行的项目，用户只在需要定方向、处理例外和验收成果时被打扰。

**Workspace 就是频道**：保存一个想法即创建一个 Workspace；一个 Workspace 可以关联多个现有项目，没有 Mission 或第二层频道。创建本身不触发 Agent 执行。

| 功能模块 | 用户在这里完成什么 | 对应原型画面 |
| --- | --- | --- |
| M01 工作空间与想法 | 找事、存想法、回到待办 | P01–P02 |
| M02 电脑与扫码 | 注册 Mac、查看执行设备和项目来源 | P03–P05 |
| M03 Workspace 对话 | 与 Norma 和 Agent 持续讨论、`@` 指令、查看工作事件 | P06 |
| M04 设置与项目 | 为当前 Workspace 添加已有项目、管理参与者 | P07–P08 |
| M05 工作简报 | 查看和纠正共享目标、决定与硬约束 | P09 |
| M06 派工与任务 | 看具名接单、进展、受阻与证据 | P10 |
| M07 Norma 实时对话 | 语音讨论、打断、回写当前 Workspace | P11 |
| M08 收件箱 | 处理真正需要人的事项 | P12 |
| M09 成果与归档 | 退回或验收成果、归档、重开 | P13–P14 |

| 对象 | 在产品里是什么 | 用户在哪里看见它 |
| --- | --- | --- |
| Workspace（工作空间） | 一个想法或一件事对应的频道，也是持续对话和执行的容器。没有额外的 Mission 层级。 | 工作空间列表、对话顶部、设置、收件箱来源 |
| 电脑 | 安装并运行 Norma 的 Mac，向手机提供在线状态和已有项目。 | 已连接电脑、扫码注册 |
| 项目 | 某台已注册电脑上的真实项目或仓库；一个 Workspace 可关联多个项目，同一项目可被多个 Workspace 使用。 | Workspace 设置、项目选择器、任务卡 |
| 工作简报 | 当前目标、硬约束、已确认决定和项目范围组成的共享事实。 | 对话置顶卡、工作简报详情 |
| Agent 任务 | Agent 领取的一项具体工作，持续记录状态、进展和证据。 | 对话里的任务卡、任务详情 |
| 成果 | 可预览、可核对证据、可退回或验收的交付物。 | 对话、收件箱、成果验收页 |

**角色分工**：

- **用户**：保存想法、表达执行意图、设置或修订不可越过的硬约束；需要时直接 @Agent；处理真正需要人决定的例外，验收成果，决定归档或重开。
- **Norma**：作为 Chief 理解目标、维护工作简报、在硬约束内自主关联已有项目和加入 Agent、派工与追踪、消化普通失败、汇总关键事项。普通目标或决定可自主调整，但必须留下可追溯的变更记录。
- **其他 Agent**：在 Workspace 的共享事实和所关联项目中执行具体任务；每次被 @ 都要有具名回应、接收回执或完成回报。需要其他 Agent 时向 Norma 提议，不自行无限转派。

**统一状态**：保存想法后为「构思中」；用户说“开始做”或发出可执行的 @指令后进入「执行中」；有待确认成果时为「待验收」；验收后为「已验收」；用户可「归档」，以后可「重开」并继续原记录。保存想法本身不触发 Agent 执行。

## 二、全套原型统一使用的示例

- 当前 Workspace：「改进 iOS 首屏交接」。目标：「让用户从 Mac 切到 iPhone 时，一眼看懂当前任务并继续操作」。
- 已连接电脑：「Alan Studio」，在线，提供「iOS App」「Norma API」；「Build Mac」，离线，提供「Release Ops」。
- 当前 Workspace 已关联「iOS App」「Norma API」，硬约束为「禁止发布生产环境」。
- 参与者：用户、Norma、Codex、Design。Codex 负责 iOS 与 API 状态，Design 负责首屏信息层级。
- 当前决定：「首屏只呈现任务状态与最近成果」「交接只保留一个主操作」。
- 示例成果：「iOS 入口与 API 状态已对齐」，附界面预览、改动摘要和验证记录。

所有页面保持上述名称、项目归属、任务与状态一致。不要把离线电脑的项目画成正在执行，也不要在「构思中」画出已派发任务。

## 三、导航和 iPhone 交互基线

底部三个入口为「工作空间」「Norma」「收件箱」。「Norma」是回到最近使用的 Workspace 与 Norma 对话或通话的快捷入口，跨 Workspace 时先显示工作空间选择，不创建脱离 Workspace 的全局任务对话。全局「已连接电脑」从工作空间列表进入；「工作空间设置」只能从当前 Workspace 进入。

使用 iOS 熟悉的层级：列表进入详情使用推进式导航；创建、项目选择、提及成员和操作菜单使用可下拉关闭的底部 Sheet；影响当前工作的操作在原页面给即时反馈。返回按钮和下滑关闭都保留原位置与草稿。触控目标至少 44pt，适配安全区和键盘。导航、底部输入栏与 Sheet 使用克制的浅色 Liquid Glass；长文本、证据和任务卡使用近白色实底以保证可读性。所有可点控件有按下、选中、禁用或加载反馈；页面转场轻快且可被手势打断。减少动态效果时用短淡入和文字状态代替大幅位移或持续波形。

下面每一项都写明「用途、入口、操作、反馈」，可直接指导画面和点击热区设计。

## 四、功能模块

### M01｜工作空间列表与想法捕获

**页面任务**：用户打开 App 就知道哪件事正在推进、哪件事需要自己处理，并能把新想法立刻存成 Workspace。

| 功能 | 功能描述 | 入口与交互方式 | 画面反馈与状态 |
| --- | --- | --- | --- |
| 浏览工作空间 | 列表按最近活动排列；每行显示名称、状态、最近一句进展、关联项目及待处理标记。 | 点整行进入该 Workspace 对话；返回时保留滚动位置。 | 当前示例排在前列，显示「执行中 · iOS App + Norma API」；构思中的想法不出现任务数。 |
| 保存想法 | 一句话即可创建 Workspace，标题可从输入自动生成，用户可修改。 | 右上角「＋」→ 创建 Sheet → 输入想法 →「保存为工作空间」。 | 保存后进入新 Workspace，状态「构思中」；对话中有原始想法，暂时没有 Agent 任务。 |
| 搜索与筛选 | 找到进行中、已验收或归档的旧工作。 | 下拉或点搜索框输入关键词；点状态筛选切换「全部／进行中／构思中／已归档」。 | 列表即时变化；无结果时给出「清除筛选」；归档项可直接打开并重开。 |
| 快速回到待办 | 让用户从列表看见真正需要自己处理的 Workspace。 | 点卡片上的「待验收」标记进入该 Workspace 的成果。 | 收件箱数量与列表标记一致，普通进展不显示红点。 |

**原型画面**：工作空间列表；创建想法 Sheet；搜索／归档状态各至少一个可见示例。

### M02｜已连接电脑与扫码注册

**页面任务**：让手机看到真实执行设备和项目来源，建立「这项工作将在哪里运行」的信任。

| 功能 | 功能描述 | 入口与交互方式 | 画面反馈与状态 |
| --- | --- | --- | --- |
| 设备列表 | 每台电脑显示名称、在线状态、最后同步时间和项目数。 | 从工作空间列表顶部「已连接电脑」进入；点设备行查看其项目。 | Alan Studio 显示在线、2 个项目；Build Mac 显示离线、1 个项目。 |
| 扫码注册 | Mac 端 Norma 展示配对二维码；手机扫码后核对设备身份。 | 底部主按钮「扫码添加电脑」→ 相机扫描 → 设备确认 Sheet → 点「连接电脑」。 | 成功后设备立即进入列表；请求相机权限发生在点扫码时。 |
| 扫码异常 | 应对二维码过期、识别失败、网络中断和相机无权限。 | 扫码页提供「重新扫描」与「手动输入配对码」；权限缺失引导到系统设置。 | 错误留在扫码页，不假装设备已连接；配对码过期明确写「请在 Mac 重新生成」。 |
| 项目同步 | 刚连接的电脑可能没有项目，离线项目也可能不是实时状态。 | 点设备展开项目列表；点同步状态查看最后同步时间。 | 空状态写「请先在这台电脑的 Norma 中添加项目」；离线项目可查看但不能新派工。 |

**原型画面**：已连接电脑列表；扫码取景页；识别后的设备确认 Sheet。二维码和相机画面可用模拟内容，但不能把模拟说明放在正式产品 UI 中。

### M03｜Workspace 对话

**页面任务**：这是产品主界面。像频道聊天一样持续呈现用户、Norma 和多个 Agent 的讨论及关键执行事件，同时保持消息输入简单。

| 功能 | 功能描述 | 入口与交互方式 | 画面反馈与状态 |
| --- | --- | --- | --- |
| 连续消息流 | 用户和 Agent 消息按时间排列；派工、接收、阻塞、成果以紧凑事件卡插入对话。 | 从列表点 Workspace；纵向滚动；点事件卡进入对应任务或成果。 | 长终端输出折叠在任务详情，不淹没对话；返回后停在原消息位置。 |
| 顶部定位 | 始终知道当前在哪个 Workspace、运行状态和项目范围。 | 顶栏显示名称、状态、项目短标签；右上角「•••」打开操作菜单。 | 菜单包含「工作空间设置」「工作简报」「归档」（仅适用状态显示）。 |
| 发送文本与附件 | 对话框常驻底部；可附照片、截图、文件或项目链接。 | 点输入框弹键盘；左侧「＋」打开附件 Sheet；发送按钮在有内容时启用。 | 本人消息立即入流，发送中与失败可见；失败消息可点重试，草稿不丢。 |
| @Norma 与 @Agent | 用户可明确指定谁回答或执行。 | 输入 @ 或点提及按钮打开成员 Sheet；选 Norma、Codex 或 Design 后继续写指令。 | 发出后先显示送达，再出现具名回应；忙碌 Agent 也须回复「已收到，排队中」或解释无法执行。 |
| 开始执行 | 讨论想法与执行有清楚界限；完整的 @Agent 指令也属于执行意图。 | 构思中的 Workspace 显示「让 Norma 开始」；用户也可直接发送“开始做”或 @Agent 指令。 | Norma 说明将使用哪些项目和 Agent，随后逐个出现真实接收回执；没有接收回执不能显示「执行中」。 |
| 追问与讨论串 | 对活跃 Agent 的追问续接原任务；细节可在消息的讨论串中展开，主时间线只保留关键事件。 | 在频道 @Codex 问当前进展，或从任务详情点「在频道 @Codex」；点消息的回复数打开讨论串。 | 回复关联原任务；讨论串可回到原消息；明确提出独立工作时才产生新任务。 |
| 定位旧信息 | 人可浏览完整频道记录；Agent 默认使用工作简报、相关摘要和最近消息，旧内容按需取。 | 顶部搜索查消息、决定或成果；结果点开回到原位置。 | 简报中的每条决定能回看来源；界面不出现 token 或内部压缩机制。 |

**原型画面**：执行中的对话主屏；构思中空任务状态；@成员选择 Sheet；附件 Sheet；消息讨论串。主屏应看见工作简报置顶卡、用户指令、Norma 回应、Agent 接收和一张任务卡，底部为悬浮输入栏。长终端日志不直接铺满频道。

### M04｜Workspace 设置与项目关联

**页面任务**：用户必须能在明确的位置为当前 Workspace 添加已经存在的项目，并确认 Agent 的执行范围。

| 功能 | 功能描述 | 入口与交互方式 | 画面反馈与状态 |
| --- | --- | --- | --- |
| 打开设置 | 设置只管理当前 Workspace。 | 对话右上角「•••」→「工作空间设置」。 | 顶部显示当前 Workspace 名称，首个分组为「关联项目」，并提供醒目的「添加已有项目」。 |

### M05｜工作简报与共享上下文

**页面任务**：让用户用一屏看懂 Agent 正按什么目标、决定和限制行动；必要时能立即纠正。

| 功能 | 功能描述 | 入口与交互方式 | 画面反馈与状态 |
| --- | --- | --- | --- |
| 查看共同事实 | 把目标、关联项目、参与者、硬约束、已确认决定放在同一页。 | 点对话顶部「工作简报」，或从设置进入。 | 顶部大字呈现目标；下方分组展示项目、硬约束和决定，不像技术日志。 |
| 硬约束 | 用户标记「绝不能自行越过」的限制；Norma 和 Agent 不得自行改写。 | 点「硬约束」查看具体内容和设置者；用户可在编辑页修改。 | 示例「禁止发布生产环境」固定醒目；任务与其冲突时停止相应动作并进入收件箱。 |
| 决定与来源 | 展示目前采用的决定，以及是谁何时改变的。 | 点每条决定查看原始消息、修改时间；点「查看变更记录」看前后版本。 | Norma 调整普通决定后在频道留下简洁回执，不悄悄覆盖过去。 |
| 纠正目标与限制 | 用户可以直接改目标、普通决定和硬约束。 | 底部「纠正目标与限制」→ 编辑 Sheet → 保存。 | 立即显示新内容，频道出现变更摘要；Norma 将新简报同步给活跃 Agent。 |
| 多项目上下文 | 同一 Workspace 的成员共享目标、消息、决定、任务状态和成果；原始仓库文件按任务需要读取。 | 点项目标签查看项目来源；点来源消息回到对话。 | 页面不暴露模型内部摘要或完整终端；人能核查当前事实与证据。 |

**原型画面**：工作简报全屏；编辑目标与硬约束 Sheet；一条已确认决定的来源详情。

### M06｜Norma 协调与 Agent 任务

**页面任务**：用户可以让多 Agent 并行，又能确认每个人确实接了什么、做到哪一步、为什么受阻。

| 功能 | 功能描述 | 入口与交互方式 | 画面反馈与状态 |
| --- | --- | --- | --- |
| 自主派工 | Norma 根据执行意图、简报和项目范围拆任务、选 Agent、跟进。 | 用户点「让 Norma 开始」或发送指令；Norma 在对话中说清分工。 | 每位 Agent 接收后出现具名回执与任务卡；未接收、排队和执行中不能混写。 |
| 任务详情 | 一张卡代表一项稳定任务，含负责人、项目、阶段、最近进展和证据。 | 点对话中的任务卡进入详情；可从收件箱直达。 | 状态按「待接收／执行中／受阻／待验收／完成」变化；顶部标明 Workspace。 |
| 查看与接管终端 | 任务详情可在「工作情况／终端」间切换；终端连接该 Agent 正在使用的电脑、项目和会话。 | 点「终端」查看实时输出；点「接管终端」后可用 iPhone 键盘直接输入命令，点「交还 Codex」恢复 Agent 输入。 | 接管时明确显示 Codex 暂停输入、连接状态和当前项目；用户与 Agent 不同时向同一终端输入，断线时停止输入并保留已显示内容。 |
| Agent 协作 | Agent 需要他人时向 Norma 提议，由 Norma 决定是否增派。 | 任务流显示「Codex 请求 Design 协助」及 Norma 的处理结果。 | 不把 Agent 间建议直接伪装成用户批准或已执行。 |
| 失败与恢复 | Norma 自行处理可恢复的问题；只有需要人判断或触及硬约束的情况进收件箱。 | 点任务「查看原因与恢复动作」查看失败、重试和当前阻塞。 | 自动恢复在频道留简短记录；需人处理时任务停在清楚的阻塞状态。 |
| 证据与回执 | 每个关键结果指向真实改动、验证或产物。 | 点证据行看预览、文件/链接、验证结果；返回仍在任务详情。 | 没有证据时标「待验证」，不能用完成态代替。 |

**原型画面**：任务详情全屏，顶部有「工作情况／终端」切换；另画终端已接管、键盘可输入的状态。任务详情突出「谁、在哪些项目、当前状态、最近证据」，不要画成密集运维仪表盘。

### M07｜Norma 虚拟人实时对话

**页面任务**：用户离开 Mac 后，仍可在当前 Workspace 中自然说话、打断和发出指令；口头内容回写频道。

| 功能 | 功能描述 | 入口与交互方式 | 画面反馈与状态 |
| --- | --- | --- | --- |
| 开始通话 | 通话绑定一个明确的 Workspace，并继承它的简报与项目范围。 | 在 Workspace 对话点「与 Norma 通话」；底部「Norma」入口先定位最近 Workspace 或让用户选择。 | 通话顶部始终显示 Workspace 名称；切换 Workspace 要显式选择。 |
| 实时字幕与状态 | 用户说话、Norma 理解和回应都有可读反馈。 | 说话时显示转写；Norma 回应时同步显示文字。 | 用「正在聆听／正在思考／Norma 正在说话」标识状态，不只靠波形或头像动画。 |
| 打断与静音 | 用户随时插话、暂停麦克风，避免长回答占据注意力。 | 点「打断」立即停止播报并继续听；点「静音」切换麦克风。 | 控件状态与字幕即时变更；触感反馈只用于关键切换。 |
| 安静模式 | 降低普通进展的口头播报，只主动说需要用户处理的事项。 | 点「稍后汇报」开启/取消。 | 顶部出现「只播报关键事项」状态，频道继续记录普通进展。 |
| 语音指令回写 | 用户说“让 Codex 继续检查 API”后，消息送入本 Workspace。 | 转写确认后显示发送回执；挂断回到原对话。 | 对话里有语音转写和具名回应，原任务继续，不额外创建一个语音任务。 |

**原型画面**：浅色 3D 二次元虚拟人通话主屏；静音或被打断的状态。人物是情感锚点，Workspace 名称、实时字幕和四个操作按钮始终清晰。

### M08｜收件箱与注意力管理

**页面任务**：用户无需巡查所有频道。真正需要人的事情集中出现，普通进展留在原处。

| 功能 | 功能描述 | 入口与交互方式 | 画面反馈与状态 |
| --- | --- | --- | --- |
| 关键事项聚合 | 只收需要决定、无法自主恢复的失败、硬约束冲突和待验收成果。 | 底部点「收件箱」；角标为未处理事项数。 | 卡片说明「发生了什么／Norma 建议什么／用户下一步是什么」，标出来源 Workspace。 |
| 同一问题去重 | 失败与恢复建议属于同一张待办。 | 点卡片进入详情，同时看原因、Norma 已尝试的动作和可选处理。 | 同一问题不因多次重试刷出多条通知。 |
| 就地处理 | 从事项进入原任务或成果，操作结果回到 Workspace。 | 点「查看并决定」或「验收成果」；处理完可返回收件箱。 | 完成后角标减少，该事项消失；原频道保留过程与决定。 |
| 通知节奏 | 用户可选择只推送关键事项，普通进展在频道内看。 | 收件箱右上角「通知设置」选择关键事项与静默时段。 | 默认不把每条 Agent 回执变成系统通知。 |
| 空状态 | 没有事时，让用户放心离开。 | 所有事项处理后自然出现。 | 文案：「目前没有需要你处理的事。Norma 会继续跟进。」 |

**原型画面**：两条事项的收件箱；空状态。示例事项为「部署前检查 · 需要决定」和「改进 iOS 首屏交接 · 成果待验收」。

### M09｜成果验收、归档与重开

**页面任务**：让人基于可核对的成果做最后判断，然后主动结束或继续一件事。

| 功能 | 功能描述 | 入口与交互方式 | 画面反馈与状态 |
| --- | --- | --- | --- |
| 成果总览 | 汇集预览、改动摘要、验证结果及来源任务。 | 从对话成果卡或收件箱事项进入全屏成果页。 | 首屏先呈现可见结果，再列三条关键证据；来源项目与任务可点开。 |
| 退回修改 | 用户指出不满意之处，原 Agent 继续同一任务。 | 点「退回修改」→ 意见 Sheet → 发送。 | 成果回到执行中，收件箱待验收事项消失；频道出现反馈，原卡继续更新。 |

| 重开 Workspace | 需要新一轮工作时回到原上下文。 | 在归档列表打开条目 →「重开工作空间」。 | 状态为「待继续」；旧记录可读，后续指令继续在原频道。 |

**原型画面**：成果验收全屏；退回意见 Sheet；已归档 Workspace 的重开状态。主操作始终是「退回修改／验收通过」，归档在验收后出现。

### 画面之间必须成立的交互

1. **想法到执行**：P02 保存只产生 P06-A；用户明确发出执行指令后，才切换到执行中的 P06，出现 Norma 分工、Agent 具名回应和任务卡。
2. **项目配置**：P06 → P07 → P08 → P07 → P06 是完整路径；「关联项目」始终位于当前 Workspace 内，不能藏进全局设备页。
3. **共享上下文**：P06 的简报入口打开 P09；目标、硬约束、决定、项目与 Agent 是同一 Workspace 的事实，来源消息可回到 P06。
4. **任务与终端**：P06 的任务卡 → P10 工作情况 → P10-T 同一会话的终端；用户接管时 Codex 暂停输入，交还后继续，切回 P10 不丢任务状态。
5. **语音闭环**：P06 → P11 说话、打断或静音 → 挂断回 P06；转写与 Agent 回执出现在原频道，不另起任务。
6. **收口**：P12 → P13 可退回原任务或验收；验收后用户归档到 P14，重开回原 P06。

## 首版存储载体建议

- iPhone：长期增长的想法、Workspace、线程、消息与任务索引用本地可查询数据库；录音和附件用应用私有文件；配对密钥继续放 Keychain。现有少量配对元数据、草稿和待发指令可沿用已有本地存储，在替换阶段逐步迁移。
- Mac：继续持有项目仓库、Agent 会话、终端和真实执行回执；同步过的 Workspace 设置保留本机副本，桌面 Norma 可在其中新建线程，线程创建、消息与派工先在 Mac 持久保存，新增按事件游标同步的接口。iPhone 上的可见时间线由本机记录和已核验的 Mac 事件合并，线程与消息必须有稳定 ID、来源、时间与同步状态；旧项目聊天不自动猜归属。
- 首版只支持用户当前 iPhone 的产品数据，不提供跨手机自动同步或换机自动恢复。iPhone 负责把必要的线程上下文和新派工转给相关 Mac；手机失联时，Mac 已接收任务继续本机执行并暂存结果，新跨 Mac 协作等手机重连。不能仅靠「iPhone 有一份完整显示」推断所有 Mac 已同步；手机丢失或卸载 App 后，不承诺从 Mac 的执行副本重建完整想法库与对话。

## 目前实现与目标的关键差距

当前 iOS 已把配对电脑、草稿、待发指令和部分实时讨论记录落在本机；Agent 对话页主要从 Mac 拉取会话。现有实时讨论记录有数量上限，也不是完整的长期 Norma 对话库。目标产品需要新增想法、Workspace、工作线程和长期 Norma 对话的存储及同步；现有手机协议 `workspace_id` 仍是项目身份，不能直接当新 Workspace ID。

09-29 实现补充：新工作线程的未发送正文在 Workspace SQLite `work_thread_drafts` 中按线程保存 `{text, revision}`；与正式消息分离，发送只原子清理对应版本，其他线程/后来编辑的同文草稿保留。逐线程保存失败独立提示与重试。

## 冲突与优先级

1. 09-28 图和已确认的数据模型决定产品结构：**想法独立于 Workspace；一个 Workspace 关联项目和 Agent，并包含多个工作线程**。W01 中「想法保存即产生 Workspace」的状态不得照搬。W01 的搜索、筛选与卡片视觉仍需实现。
2. P03/P05 是 Workspace 首页和工作线程的主视觉基准。W01/W04 补足搜索筛选和持续对话的交互状态；W03 的 Sheet 从 P04 打开，不以旧聊天页为固定背景。
3. 已取消 Workspace「硬约束」功能。W03、W05、W06、W08 的旧禁令或冲突文案需换成普通工作要求或真实待决事项；保留图的层级、位置、材质与颜色关系，不暗示系统保证了不存在的门禁。Mac 原有设备授权与高风险操作审批继续有效。
4. Norma 首页的长期私聊独立于 Workspace。W07 所示 Workspace 信息仅在用户明确选定关联上下文后出现；语音不会默认把私聊注入线程。

## 开发 Agent 自行验收的交付物

每个页面任务结束时，开发 Agent **自己完成测试、操作和差异修正**，并在任务验收记录中留下：参考图路径、同尺寸真实 App 截图、逐屏差异记录及修复结果、关键交互的自动化用例与运行结果、Computer Use 操作真实 App 的记录。可观察流程覆盖原生 UI/e2e；Mac 派工、终端、成果使用真实回执，不用假卡片证明完成。T9 汇总检查全部 15 张图，无遗漏、无过期产品规则、无被遮挡或不可点击的入口。扫码、麦克风、实时通话和设备上的玻璃材质/性能另在真机核对；若当时无法取得真机或真实服务，只能记录为未验收，不能写成通过。
