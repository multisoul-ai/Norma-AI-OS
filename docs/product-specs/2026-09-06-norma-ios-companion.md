# Norma for iPhone：功能清单与首版原型

2026-09-07 · 产品提案 v0.16（多电脑切换） · 范围：功能梳理与交互 HTML，尚未实现 iOS App 或远程服务。

**定位：随身的 Norma 工作台。** 用户离开 Mac 后，能够看懂 Agent 做到哪里、处理阻塞、补充方向，并查看项目中的所有 AI 卡片。代码、Shell、Agent 和执行上下文仍留在用户的 Mac 上。

**[打开可交互原型](../prototypes/norma-ios.html)**。桌面浏览器显示手机与演示路线；手机直接显示应用界面。全部数据为模拟，点击不会运行本地命令或发布软件。状态仅保留在本次页面会话。

实现推进见 [Goal 实时实施计划](../exec-plans/2026-09-07-norma-ios-goal.md)，其中单独记录已完成的规划与尚未启动的真实开发阶段。

## 1. 从 Orca 借鉴什么

已核对 [Orca IDE 的 App Store 页面](https://apps.apple.com/cn/app/orca-ide/id6766130217)，用户已确认参考对象为该产品。页面说明及截图是本次参考依据；未安装或实际测试 Orca iOS。

| Orca 官方页面描述 | Norma 采用方式 |
|---|---|
| 手机作为桌面客户端，代码、Shell、Agent 在桌面执行 | 复用这一职责划分；手机负责查看、指令、确认和提醒 |
| 实时终端镜像，输入、滚动、Tab、Ctrl-C | 任务详情提供终端入口与辅助按键；首先让用户读懂任务摘要 |
| 多 worktree、多终端切换 | 按项目、任务组织，保留工作区、分支、Agent 与节点关联 |
| 二维码配对，配对密钥加密通信 | 首次连接在 Mac 发起，手机扫码，Mac 确认设备与授权范围 |
| 后台长任务与 TUI 空闲通知 | 根据明确的任务完成、失败、待确认事件通知，不把终端空闲直接当成功 |
| 当前描述要求同一 Wi‑Fi / 本地网络 | 局域网用于第一阶段验证；Norma 首发完整验收还要覆盖蜂窝网络到家中 Mac |

任务摘要、结构化审批、项目卡片是本提案的 Norma 设计，不是已验证的 Orca 功能。Orca 页面文字和截图并非完全同步的产品规格，不由截图推导尚未证实的能力。

## 2. 核心场景与范围取舍

1. **先知道下一步，再做决定**：首页由 Norma 梳理当前方向、下一份交付和按优先级排列的 Agent 待办；用户只确认请求、选择优先事项或调整目标与取舍。具体执行、验证和完成状态由 Agent 回传。待决策页保留左右滑动确认。
2. **Agent 被阻塞**：通知进入对应任务，查看请求内容、命令与范围，允许一次或拒绝；收到桌面回执后更新状态。
3. **补充方向或新任务**：指定 Mac、已授权项目与 Agent，发送需求，区分未发送、已送达、已接收、执行中。
4. **需要接管**：查看终端输出、发送输入、中断，保留上下文继续；在手机断线时准确展示最后快照。

第一版围绕现有任务和可确认的动作。无限画布编辑、完整代码编辑器、手机本地运行 Coding Agent、通用远程桌面、多用户协作与自定义 CI 平台暂不进入首发。

按最新反馈，当前版本移除发布页面及相关入口、通知和演示流程，仅保留指挥台、项目、任务、设备。复制任务进展摘要仍作为轻量附属能力。

## 4. 信息架构

```text
连接 Mac（未配对首页 / 设备页扫码入口）
  ├─ 准备 Mac → 扫码取景 → 核对机器与授权 → Mac 确认 → 连接成功
  ├─ 输入配对码 → 校验 → 核对机器与授权
  └─ 连接帮助 / 返回 / 重新扫描

项目
  ├─ 选择项目 → 全部 Norma AI 卡片（双列）
  ├─ 创建卡片 → 选择 Agent / 可选名称 → 空闲卡片
  ├─ 有任务的卡片 → 详情 → 返回原项目
  ├─ 空闲卡片 → 安排任务 → 显式发送目标 → 绑定原卡片
  └─ 卡片选项 → 删除卡片 → 确认移除（保留任务和对话）

指挥台（原总览入口）
  ├─ 今日简报 / 待验收 → 成果对比与确认
  ├─ 行动计划：当前方向 → 下一份交付 → 需要你的决定
  │    ├─ Agent 的 To-do：具体下一步、执行者、状态、优先级
  │    ├─ 待办详情 → 预期交付 / 对应任务 / 去做决策
  │    └─ 调整方向 → 优先项与目标取舍 → Agent 收到方向
  └─ 待你决策：Agent、项目、请求、命令、影响范围
       ├─ 右滑允许 / 左滑拒绝 → 回执 → 下一项
       ├─ 暂时跳过 → 下一项（请求保留）
       └─ 处理记录 / 全部处理完成 → 返回 Agent 待办

任务
  ├─ 项目、状态、关键词筛选
  ├─ 新建任务 / 未发送草稿
  └─ 详情：对话 | 终端 | 变更 | 成果
       ├─ 补充指令、中断、继续
       ├─ 授权请求、产物预览
       └─ 成果：修改前后对比 → 验收通过 / 调整意见回到原对话


设备
  ├─ 我的电脑列表 → 切换当前电脑
  ├─ 添加电脑 → 扫码 / 配对码 → 命名 → Mac 确认 → 独立空工作区
  ├─ 连接、授权项目、查看与控制权限
  ├─ 关键事件通知、外观
  └─ 撤销配对

全局：顶部电脑切换 → 当前 Mac 的项目 / 指挥台 / 任务；通知中心 → 当前电脑的精确任务；设置；断线或只读提示
```

## 5. 最小的系统接入方案

```text
iPhone 客户端
    │ 设备身份、有限范围指令、状态订阅
    │ 局域网 / Tailscale
    ▼
Mac 手机接入层（新增，显式启用）
    │ 校验设备、项目权限、请求唯一 ID、任务/版本状态
    ▼
现有 Norma 应用命令与任务协调器
    ├─ Agent / PTY 执行
    └─ 任务、节点与工作区状态
```

代码、凭据、PTY 与执行上下文留在 Mac。局域网与 Tailscale 共用经过设备认证的加密控制协议，首版不自建控制中继。通知只携带定位信息与最小事件摘要，手机锁屏默认不暴露终端内容、代码或错误日志。不要直接把当前本地 socket 暴露到公网。

Mac 休眠或 Norma 未运行时不承诺远程唤醒。手机展示最后快照并说明恢复方式；需要保持工作时，防休眠必须由用户显式启用。

2026-09-07 方案讨论已确认：关闭 Norma 窗口后，其中的 Agent 不继续运行；首版沿用现有窗口与任务生命周期，不新增脱离窗口运行的常驻执行服务。手机断线或切换电脑不结束 Mac 上的任务；窗口关闭后，手机将最近状态标为历史快照，不把旧任务显示为仍在实时运行。

2026-09-07 方案讨论已确认：首版支持手机锁屏后的待确认、完成和失败通知，引入轻量 APNs 通知服务。Mac 将事件交给通知服务，由 APNs 通知已绑定的 iPhone；服务不承载任务控制或执行。打开通知后，手机定位到对应电脑、项目与任务，并向 Mac 核验最新状态；延迟到达的通知不作为直接执行审批的依据。

2026-09-07 方案讨论已确认：指挥台统一汇总所有已配对电脑中、手机获授权查看的待决策事项；项目与任务页继续按当前电脑浏览。每张决策卡片标明来源电脑与项目，操作绑定来源电脑、项目、任务和决策请求，不随当前电脑选择变化。离线电脑的缓存事项标记为待核验，恢复连接并核验最新状态后才允许处理。此项是待实现方案；v28 HTML 原型的指挥台仍跟随当前电脑。

2026-09-07 方案讨论已确认：首版移动端完整支持的执行 Agent 限定为 Codex 与 Claude；Cursor / OpenCode 的移动端接入后续安排，不移除桌面已有能力。Norma 继续负责总结、规划与协调，不作为第三种执行 Agent。

### 状态与操作规则

- **任务执行与手机连接互相独立**：手机离线不表示任务失败，连接恢复也不等于任务已完成。
- **进度可信**：有明确步骤时显示“3/5 步”，其余显示当前阶段；不把步骤比当作耗时比。终端空闲与任务成功是不同事实。
- **写操作必须有回执**：请求唯一 ID 与目标版本；区分未发送、已送达、已接收、已执行、结果未知。结果未知时查询原请求，不能盲目重试。
- **离线不自动重放**：普通文字保留草稿；审批、终端控制与取消不能排队后静默执行。重连后重新读取对象状态，由用户确认。
- **输出与产物受限**：终端分块与背压，快照脱敏，产物受授权文件范围限制，预览不接受任意本地路径。

这些是实现要求；原型只覆盖主要可见状态和部分逻辑检查，不提供真实加密、鉴权、幂等存储或 Provider 适配。

## 6. Apple 设计原则如何落地

按最新反馈，全页面默认采用纯黑底色（#000）、炭灰卡片（#111）和白色主按钮。移除墨绿渐变、背景网格与指挥台装饰球，设备图片通过 CSS 灰度显示；少量颜色只用于品牌与警告。项目 `apple-design` 的内容优先、清晰层级、熟悉导航、直接反馈和用户控制原则贯穿项目、指挥台、决策、任务详情、设备、配对和弹层；任务名称先于 Agent 元信息，细线与大圆角负责分组。统一样式集中在 `norma-ios.css`，不引入框架或依赖。状态同时保留文字，设置中可切换浅色，刷新后默认深色。

主要动作进入拇指易达区域；按下立即反馈，按钮提供 hover、pressed、focus、selected 与 disabled。弹层使用原生 HTML `dialog` 支持焦点约束和 Escape，避免手写复杂手势。提供 `prefers-reduced-motion`、减少透明度与高对比偏好。真实 SwiftUI 版本仍需系统 Dynamic Type、VoiceOver 和 iPhone 设备验收，浏览器原型不能替代。

### 项目卡片与运行边框

“项目”底部入口展示项目卡片。项目内用双列卡片网格展示全部卡片，不受任务页搜索或状态筛选影响。示例中 Norma OS 有 4 张卡片（2 运行、1 完成、1 空闲），Studio Site 有 3 张待确认卡片。卡片注册表与任务分开，空闲卡片也能显示；本原型每张卡片最多关联一条任务，正式版本按桌面节点身份同步。

项目页的加号用于「创建卡片」，只选择 Agent（Codex / Claude / Norma）及可选名称，创建后为 idle，taskId 为空，不生成任务或待办。用户稍后从空闲卡片点击「安排任务」，填写目标并显式发送，才创建任务并绑定原卡片，不额外复制卡片。任务页的独立新建任务流程仍可用。

每张卡片右上角提供 44px 的独立选项按钮，可查看任务或删除卡片。删除前说明影响范围：只移除项目中的卡片，不删除关联任务与对话，也不中断正在执行的 Agent；任务仍可从任务页访问。取消删除不改变状态。卡片关联的未发送草稿在删除后保留内容并解除关联。离线或只读禁止创建、删除与安排。

按 `apple-design` 与 `emil-design-eng` 原则，用克制的白色短拖尾表示“正在工作”：SVG 圆角描边配合原生 CSS 动画，每 3.8 秒沿真实边界走一圈，不代表任务完成比例。只有已配对、在线且任务为 running 时启用。完成、待确认、中断、空闲、仅送达不播放；手机离线保留任务最后状态，但停止动画，标注快照。页面隐藏时暂停，`prefers-reduced-motion` 下使用静态浅灰边框，状态文字始终保留。卡片标题均衡换行，触控与键盘焦点沿用现有反馈。

按最新反馈，卡片内容只保留品牌图标、卡片名称（未命名时使用任务名称）和状态；移除 Norma 编号、重复的品牌名、阶段说明与步骤数，详情仍可点击查看。Codex 使用云形终端标记，Claude 使用星芒图标，替换字符占位；运行时 Codex 以 2.8 秒周期小幅浮动、Claude 以 8 秒周期旋转。中断、离线或完成时图标静止，减少动态效果时不播放。品牌名称作为图标辅助标签和卡片状态说明保留。任务列表与详情复用相同图标。图标路径来自 [LobeHub Icons](https://github.com/lobehub/lobe-icons) 的 `codex.svg` / `claude-color.svg`，MIT 声明随 HTML 内嵌，不依赖外部 CDN。

### 决策卡片：把首页从查看进展改为做决定

用户反馈总览与任务重复，因此删除首页任务计数、任务列表与项目入口聚合，底部入口统一命名为“指挥台”，其中“待你决策”子页兼容原有滑动交互。保留 `#overview` 链接。决策队列只呈现状态为 WaitingApproval 的请求；三个示例是连接测试、锁文件更新和视觉快照更新，审批与任务详情共用相同状态和请求内容。

沿用 Apple / Emil 的直接操作原则：卡片水平跟手移动，拖动过程中显示方向和“松手允许/拒绝”，释放后才提交。距离阈值为卡宽的 28%，限定在 88–118px；纵向滚动、短滑、pointercancel、失去焦点都不提交。按钮提供同样的决定能力，支持键盘和辅助技术；减少动态效果时取消卡片位移但保留决定提示。离线或只读时禁止滑动提交与按钮操作。

“暂时跳过”只切换当前卡片，不减少请求数量。成功处理后自动进入下一项；确认回执写入处理记录，重复请求不会再处理。全部完成时显示空状态。正式接入仍需 Mac 校验请求身份、版本和范围，并返回接收/执行回执；本页只模拟明确的授权动作，不提供生产发布或通用高风险动作的一滑批准。

### 指挥台：用户决定，Agent 执行

“行动计划”是默认首页。Norma 用一条方向和下一份交付说明要往哪里走，再突出当前需要用户决定的事项。下方 To-do 展示后续动作而非重复任务标题，例如“完善语音输入体验”的下一步为“验证弱网下的语音连续性”，预期交付为测试结果与修复说明。每项标明 Codex / Claude、项目与状态，点击可查看交付内容和关联任务。

用户没有执行工作或手动勾选完成的职责。待办由任务状态投影，完成/取消后退出；审批通过变为进行中，拒绝后保留为已中断。计划与决策、项目卡片共用任务数据。当前 demo 是已定义任务的确定性梳理，未调用模型生成计划。

“调整方向”选择一项优先推进的工作，输入 1–300 字目标和取舍；成功发送后更新方向和待办排序，并在该执行 Agent 的任务上下文留下指令回执。不自动批准请求，不把排序改变冒充任务已暂停或完成。离线、只读、未配对、无效事项与空输入均不能修改状态。真实接入由 Norma 返回结构化计划、任务关联和执行回执，再同步手机；计划建议与已执行事实需分开。

沿用 `apple-design` 的内容优先与渐进呈现：先方向，再用户决策，再 Agent 待办；执行细节进入底部弹层，使用原生表单和分段控件。保持默认深色、44px 触控区域和现有焦点/按下反馈；沿用决策页的原生手势，不添加依赖。

### 任务详情：把屏幕还给内容

按用户对内容受挤压的反馈，详情采用 Apple 式推入页面：收起全局品牌栏与底部三项导航，顶部仅保留返回、任务标题、Agent 状态和任务信息入口。“对话 / 终端 / 变更 / 成果”紧接导航，分支、项目、耗时与进展摘要移入任务信息弹层；长标题可在弹层完整查看。

终端输出独立滚动，快捷键与输入区固定底部；去掉重复元信息、快照说明和大圆角容器。“模拟快照”持续可见，任务信息保留不执行真实命令的说明。对话与变更共用紧凑头部，各自内容滚动；返回原项目/任务/指挥台时恢复全局导航。中断后输入区变为继续任务入口，恢复后重新开放输入。

### 默认聊天与紧凑字号

任务默认打开“对话”。原动态时间线改为正常聊天阅读顺序：用户目标、Agent 当前进展、后续补充消息与接收回复。聊天内容独立滚动，底部固定多行输入框与发送按钮；发送成功后清空并保留输入焦点、滚动到最新消息。输入随内容增长，最大 120px，超出后在输入框内滚动；按钮点击区域保持 44px。

Enter 发送，Shift+Enter 换行，中文输入法组词期间不提交；空白消息禁止发送。草稿按任务保存，切换终端/变更后回来仍保留；离线和只读允许编辑草稿，但不允许发送，重连不自动重放。已完成或中断的任务需显式继续。中断入口收进“任务信息”。聊天复用既有消息状态，回复明确标注为模拟，不调用真实模型。

整体字号下调：页面标题 24–26px、计划与弹层标题 18px、任务标题 14px、卡片和消息正文 13px；辅助信息不继续压小。iPhone 输入框保留 16px，避免聚焦时浏览器自动放大；仅缩小视觉文字，不缩小触控区域。继续使用系统字体、深色外观与现有 Apple 式层级。

### 成果验收与今日简报

成果页提供“修改前 / 修改后”对比，当前仅 `workspace` 任务包含项目卡片的示例视觉预览，其他任务显示成果准备状态。已完成任务才允许验收；确认后保留任务完成状态并记录已验收回执，重复验收被拒绝。运行中、离线和只读不可提交验收。

“继续调整”或预览上的批注点打开反馈输入，发送后在原任务留下验收反馈，并标为已送达、等待 Agent 接收；重新继续已验收任务时清除旧验收标记。页面不把反馈送达当作执行完成。指挥台的待验收入口和今日简报随当前演示状态更新，简报汇总方向、待决策、待验收与下一份交付。

### 居中导航与扫码连接

底部导航已通过 390px 与 320px 真实浏览器验收，中央入口偏移不超过 0.01px，顶部无重叠，触控区域至少 44px。[项目页与新版导航](../prototypes/assets/norma-ios-project-navigation.png)。

底部导航固定为「项目 · 指挥台 · 任务」，三个等宽入口让指挥台始终处于手机正中。中央使用 Norma 标志，保留文字名称，选中时显示白色圆形按钮；设备管理移到右上角，仍可一键进入扫码连接和授权管理。默认保持深色，44px 触控与键盘焦点不缩小。

页面主标题与正文左对齐，便于顺序扫读；底部“指挥台”始终居中。连接流程使用居中的紧凑导航标题，隐藏全局品牌栏与底部导航，遵循 `apple-design` 的明确层级、内容优先和可逆导航原则。

参考 Orca IDE App Store 明确描述的「桌面显示二维码、手机扫码配对」，新增 `#connect` 独立页面。引导用户在 Mac 打开 Norma 的「设置 → 手机连接 → 连接手机」；首次连接建议同一 Wi-Fi。此桌面入口、相机权限及真实网络配对均是产品方案，尚未实现。

扫码演示与手动六位码共用设备核对页，默认预览只读授权。识别机器不会立即注册；只有点击「模拟 Mac 确认并连接」后，演示设备状态才变为已配对，并出现成功页。正式版本须由 Mac 校验和确认权限。用户可以返回、重新扫描或查看连接帮助，取消不会撤销已有配对；新增电脑只有在 Mac 确认后加入设备列表，不覆盖当前电脑。

### 多电脑切换：电脑先于项目

顶部 Norma 标志下方持续显示当前电脑，并提供“切换电脑”入口；项目页的电脑名称也可以点击切换。设备页列出全部电脑与当前选中项，显示在线 / 离线 / 未配对、控制权限、项目数量及运行任务。沿用 `apple-design` 的明确归属、直接操作与渐进呈现原则，保持纯黑风格、中央指挥台和 44px 触控。

每台电脑保存独立的项目、卡片、任务、消息、草稿、方向、审批记录、连接和授权状态。当前示例为 MacBook Pro 的 Norma OS / Studio Site，以及 Mac mini 的 Website。切换不会中断任何 Agent；筛选与详情切回当前电脑有效的项目，未发送聊天按电脑及任务保留。任务详情、发送提示和进展摘要都注明执行电脑。

URL 同时携带电脑身份与项目 / 任务位置，浏览器后退和前进会恢复对应电脑；未知电脑进入设备选择提示，不能把同 ID 任务误当成另一台的任务。单机离线、只读或撤销不影响其他电脑；未配对引导仍提供切换入口，避免用户困在已撤销的机器上。

“添加电脑”复用扫码引导，允许给新电脑命名，默认只读，只有模拟 Mac 确认后才加入列表。新机拥有独立空工作区，原有电脑的数据和权限保持不变。所有注册与状态仍是本页模拟，刷新重置；真实版本需要稳定设备 ID、持久化配对与独立网络连接。

## 8. 推荐开发顺序

1. **先验证 Agent 接入**：在实际使用的 Codex / Claude 版本上，分别验证原有会话中的消息读取、发送、状态关联和按请求批准 / 拒绝；检查手机操作与桌面处理发生竞争时的结果。若现有会话无法通过受支持接口完成审批，先明确运行方式的改造代价，再定接入方案，不以统一输入 `y` 代替结构化审批。
2. **完成最小真机闭环**：SwiftUI 客户端、Mac 受控网络入口、扫码配对、Keychain、项目授权与撤销；两台 Mac 上通过局域网 / Tailscale 查看真实任务、发送指令并获得回执。断线恢复和请求去重在这一阶段完成。
3. **接齐项目、卡片与聊天**：按电脑 / 项目 / 会话隔离消息与草稿，完整聊天采用分页历史与增量更新；复用创建、关闭卡片和任务队列，保留创建卡片不立即派任务的语义。验证只读、窗口关闭、重启后旧请求失效与忙碌任务取消。
4. **完成指挥台与锁屏通知**：各 Mac 保有真实决策状态，手机汇总全部获授权电脑的事项；APNs 发送最小通知，打开后回源校验。接入 Norma 总结、方向、关联 Agent 的 Todo 与成果验收，确保建议、已安排和执行完成有明确区别。
5. **完成发布前验收**：真实 iPhone 蜂窝网络连接家庭 Mac；覆盖网络切换、锁屏通知、重复与过期审批、桌面和手机同时操作、两台电脑的同名项目、单机离线与单机撤销。完成系统键盘 / 语音输入、Dynamic Type、VoiceOver 与弱网测试，再进入发布流程。

首批验证指标：待确认事件到用户处理的耗时；移动端发出指令的成功回执率；连接恢复后状态一致性；任务阻塞定位与恢复是否不依赖返回电脑。基线尚未采集，不给出未经验证的业务数字。
