# 可语音呼叫的持久 Agent 与高层委派工具 SPEC

- 日期：2026-07-14
- 状态：Ready for Agent
- 范围：Agent 定义、呼叫名、活跃 Agent 卡片、任务委派、CardTask 提示词、单次语音指令、持续聆听、任务跟踪与迁移

## Problem Statement

用户已经可以在 Settings 中维护项目级 Agent 定义，也可以在画布上创建 Codex、Claude 或 OpenCode Agent 卡片，并通过语音 CardTask 操作卡片。但这三种能力尚未形成同一个产品模型：快速创建和语音创建仍可能产生没有持久定义、没有稳定名称的匿名 Agent 卡片；Settings 中的 Agent 名称只被复制成卡片 alias，卡片没有保存定义身份；语音只能让模型先列出卡片、猜测目标 node id，再发送文本。

因此，用户无法可靠地说“Alan，帮我开发一个贪吃蛇”并确信任务会进入名为 Alan 的持久 Agent。模型可能不知道 Alan 是否为当前项目 Agent，可能创建另一张匿名 Codex 卡片，可能模糊匹配错误名称，也可能把“已写入卡片”误报为“任务已完成”。同一个 Agent 忙碌时，后续指令还可能直接注入正在运行的 CLI，破坏当前任务。

现有提示词只描述通用 CardTask 和底层卡片工具，不认识 Agent 定义、双语呼叫名、唯一名称、单卡约束、任务队列和 Hook 降级规则。即使增加新的工具，如果不同时增强 Dialogue、CardTask、动态 Agent 名册、确定性路由兜底和结构化工具回执，真实模型仍可能不调用工具或选择错误工具。

用户需要把 Agent 理解为项目内可命名、可再次呼叫的持久身份，而不是一次性卡片。无论从 Settings、工具栏、菜单、快捷键还是语音创建，所有 Agent 卡片都应绑定一个 Agent 定义；无论使用单次语音指令还是持续聆听，相同呼叫都应经过同一套高层委派能力并产生真实、可审计的回执。

## Solution

建立一个项目级 Agent 协调模块，作为 Agent 定义、名称分配、活跃卡片、任务队列、任务跟踪和真实回执的唯一业务入口。Settings、工具栏、菜单、快捷键、单次语音指令、持续聆听和 CardTask subagent 都调用这个模块，不再各自拼装“查卡片、创建卡片、发送文本”的流程。

Agent 定义是持久身份，包含项目内唯一的呼叫名、Codex/Claude/OpenCode 运行时类型、可用状态和可选的 Workflow Description。同一个定义可以暂时没有活跃卡片，但同一时间最多拥有一张活跃 Agent 卡片；每张 Agent 卡片必须绑定一个定义。删除或关闭卡片不删除定义，再次呼叫时自动激活新卡片。活跃期间允许重命名，名称立即同步且会话不中断；运行时类型、禁用和删除必须等卡片关闭后执行。

呼叫名支持纯中文或纯英文。中文名为 2–8 个汉字，英文名为 2–16 个英文字母；首版不支持中英文混用、数字、空白和标点。英文忽略大小写，中文按原文匹配。正式名称与预设语音别名共享唯一命名空间，禁止任何会让一次语音同时匹配两个 Agent 的配置。

内置名称池提供 30 个简短英文人名及一对一中文语音别名。用户未指定名称时，系统按固定顺序分配当前项目第一个未占用且无语音别名冲突的名称；重命名或删除定义后释放旧名称。名称池耗尽时不生成编号后缀，要求用户指定自定义名称。

CardTask subagent 新增高层 Agent 工具：列出 Agent、创建 Agent、激活 Agent、原子委派一个或多个任务。Agent 操作不得再通过通用 `create_card(kind=agent)` 和 `send_text` 组合实现。模型负责理解自然语言、识别明确呼叫或分工并选择高层工具；协调模块负责强制名称、唯一性、单卡、状态、队列、原子性和真实回执。

单次语音指令和持续聆听共享同一高层 Agent 工具。每轮 Dialogue 和 CardTask 请求注入一份紧凑的当前 Agent 名册，仅包含名称、预设语音别名、运行时类型、启用状态和活跃状态，不注入 Workflow Description 或其他自由文本。Dialogue 提示词负责把明确的 Agent 呼叫派发给 CardTask；确定性路由策略为“名称开头呼叫”“让/请/交给/打开某个 Agent”等明确结构提供漏调用兜底。普通提及名称不得触发执行。

同一 Agent 一次只执行一个任务，后续任务按 FIFO 排队；不同 Agent 可以并行。Hook 可用时，Hook 终态驱动队列自动推进和完成通知。Hook 不可用时仍允许提交首个任务，但任务标记为未跟踪，不产生自动完成通知；后续提交必须来自用户明确的强制发送表达，否则拒绝本次执行并要求重新表达。

信息不足时首版不维护可恢复澄清会话。缺少运行时类型、多个 Agent 分工含糊、未知名称、禁用名称、名称冲突或未跟踪 Agent 的非强制二次提交，都结束本次 CardTask、保证零副作用，并用简短理由要求用户重新下达完整指令。

### Observable acceptance behavior

- “创建一个 Codex Agent”分配第一个可用名称，保存定义并立即打开绑定卡片。
- “创建一个叫小安的 Claude Agent”保存中文定义并打开唯一卡片。
- “Alan，开发一个贪吃蛇”精确解析 Alan；有卡片则复用，没有卡片则激活后提交去除寻址语句的任务正文。
- “艾伦，开发一个贪吃蛇”在 Alan 使用内置中文语音别名时产生同样结果。
- “总结 Alan 昨天的工作”只进行普通对话，不委派任务。
- 未知、禁用或模糊名称不执行、不隐式创建，并提示可用候选。
- “Alan 修后端，Bella 写测试”在所有目标通过预检后整体入队并允许跨 Agent 并行。
- “Alan 和 Bella 一起开发”因分工不明确而零副作用拒绝。
- Hooks 存在时，Alan 忙碌期间的第二项任务保持排队，收到 Done/Failed 后再自动提交。
- Hooks 不存在时，首项任务仍可提交；第二项只有在用户明确说“仍然发送给 Alan”时才发送。
- 已提交、已排队、已完成、失败、中断和部分成功使用不同回执，不得把接收误报为完成。
- 持续聆听期间可以 TTS 播报真实终态；单次语音结束后只显示非打扰式 UI 通知。

## User Stories

1. 作为项目用户，我想为每个 Agent 设置稳定呼叫名，以便以后通过名字再次找到它。
2. 作为项目用户，我想让 Agent 定义在卡片关闭后继续存在，以便关闭窗口不会丢失身份。
3. 作为项目用户，我想让一个 Agent 定义最多拥有一张活跃卡片，以便名称始终指向唯一会话。
4. 作为项目用户，我想让每张 Agent 卡片都绑定定义，以便 Settings、画布和语音看到的是同一个 Agent。
5. 作为项目用户，我想创建 Codex、Claude 或 OpenCode Agent，以便选择适合任务的执行环境。
6. 作为语音用户，我想说“创建一个 Codex Agent”，以便系统自动命名、持久化并打开卡片。
7. 作为语音用户，我想在创建时指定中文或英文名，以便使用自己容易呼叫的名称。
8. 作为语音用户，我想在未指定运行时类型时得到明确提示，以免系统静默选择错误执行环境。
9. 作为语音用户，我想在显式名称重复时看到冲突，以免系统复用或修改错误 Agent。
10. 作为 Settings 用户，我想在未保存草稿中先修改自动名称和运行时类型，以便确认后才占用名称。
11. 作为 Settings 用户，我想保存定义而不立即打开卡片，以便先配置项目 Agent 名册。
12. 作为快速创建用户，我想通过工具栏、菜单或快捷键立即创建并打开已命名 Agent，以便保持现有低摩擦体验。
13. 作为中文用户，我想用 2–8 个汉字命名 Agent，以便自然呼叫“小安”等名称。
14. 作为英文用户，我想用 2–16 个英文字母命名 Agent，以便自然呼叫 Alan 或 Reviewer。
15. 作为语音用户，我想让英文大小写和相邻标点不影响匹配，以便转写格式变化不会导致失败。
16. 作为语音用户，我想让内置英文名支持确定的中文语音别名，以便 ASR 输出“艾伦”时仍能呼叫 Alan。
17. 作为语音用户，我想禁止模糊名称自动路由，以免 Allen 被错误发送给 Alan。
18. 作为项目用户，我想让正式名称与语音别名共同保持唯一，以便一个呼叫永远只有一个目标。
19. 作为新建 Agent 的用户，我想从 30 个自然英文人名中自动获得未使用名称，以便无需每次思考名称。
20. 作为项目用户，我想让自动名称分配固定且可预测，以便测试和使用体验一致。
21. 作为项目用户，我想在重命名或删除定义后释放旧名称，以便以后可以重新使用。

24. 作为语音用户，我想呼叫暂时没有卡片的 Alan，以便系统自动激活后提交任务。

## Implementation Decisions

### Deep Agent coordination module

- 建立一个项目级 Agent 协调模块，外部 interface 只接受高层命令并返回结构化结果；名称分配、定义约束、活跃卡片、队列、跟踪、批量预检、迁移和回执均隐藏在实现内部。
- 协调模块保持零 GPUI，并通过注入的定义仓库、任务仓库和活跃卡片 host adapters 执行持久化与 Runtime 副作用。
- 生产 adapters 连接项目 SQLite 与 Runtime；测试 adapters 使用内存实现。调用方和测试都从同一高层 seam 观察结果。
- Settings、快速创建、语音和 CardTask 不允许绕过协调模块直接创建 Agent 定义或 Agent 卡片。

### Agent definition and card identity

- Agent 定义继续归当前项目所有，包含稳定 id、呼叫名、运行时类型、可用状态、排序和可选 Workflow Description。
- Workflow Description 改为可选，自动创建保存为空；已有内容原样保留，首版不进入提示词或任务文本。
- 活跃 Agent 卡片持久化定义 id，并可保留同步后的显示名缓存供零 Storage 的画布模型渲染；定义 id 是身份来源，显示名缓存不是独立身份。
- 同一个定义最多映射一张活跃卡片。激活已有活跃定义返回现有卡片，不创建第二张。
- 重命名立即更新活跃卡片显示名和语音路由，不重启 CLI。活跃期间禁止改运行时、禁用和删除。
- 关闭空闲卡片直接执行；关闭忙碌卡片需要用户确认，确认后中断运行任务、取消等待任务并保留定义。

### Naming catalog and validation

- 内置名称池按固定顺序包含：Alan、Bella、Bruno、Chloe、Daisy、Ethan、Felix、Grace、Henry、Iris、Jasper、Kevin、Leo、Mason、Nora、Oscar、Piper、Quinn、Ruby、Simon、Sophie、Tessa、Tommy、Uma、Victor、Wendy、Xena、Yara、Zane、Rowan。
- 对应中文语音别名为：艾伦、贝拉、布鲁诺、克洛伊、黛西、伊森、菲利克斯、格蕾丝、亨利、艾瑞斯、贾斯珀、凯文、利奥、梅森、诺拉、奥斯卡、派珀、奎因、鲁比、西蒙、苏菲、泰莎、汤米、乌玛、维克多、温迪、西娜、雅拉、赞恩、罗文。
- 自定义名称只能是 2–8 个汉字或 2–16 个 ASCII 英文字母。英文规范化为大小写不敏感键，中文保留原文；首尾空白和呼叫相邻标点不进入键。
- 正式名称及其所有预设语音别名共同参加项目级唯一性校验。分配、创建和重命名必须在持久化提交前完成同一套校验。
- 自动命名选择固定目录中第一个所有键均未占用的名称；禁用定义仍占用名称。重命名和删除释放旧键。
- 显式重复创建返回名称冲突及现有 Agent 类型，不激活、不改类型、不复用。

### High-level CardTask tools

- CardTask 工具集新增列出 Agent、创建 Agent、激活 Agent、批量委派 Agent 任务四种高层工具。
- 通用卡片创建工具不再接受 Agent kind；Agent 文本提交不得通过通用 send-text 工具绕过协调模块。
- 创建工具要求运行时类型，名称可选；名称缺失时自动分配。Settings 创建可选择只保存定义，语音和快速创建选择保存并激活。
- 批量委派工具接受一项或多项明确 assignment。协调模块先验证全部名称、启用状态、任务正文、跟踪状态和单卡约束，全部通过后才整体入队。
- 工具结果至少区分 created、activated、submitted、queued、untracked、name conflict、unknown name、disabled、missing profile、requires explicit force、partial activation failure 和 no-effect rejection。
- 创建定义成功但卡片启动失败保留定义并返回部分成功；任务不得标记为已提交。

### Agent task queue and tracking

- 每个 Agent 定义拥有独立 FIFO 队列，同一 Agent 最多一个运行任务；不同 Agent 队列可以并行推进。
- 入队记录保存原始指令、提取后的任务正文、目标定义、状态、跟踪模式、关联卡片和时间信息。
- Hook 可用时状态为 managed；Thinking、RunningTool 和 WaitingApproval 均视为忙碌，Done 或 Failed 结束当前任务并驱动下一项。
- Hook 不可用时首项任务允许提交并标记 untracked；不自动推断完成，不自动推进队列，不产生完成 TTS。
- untracked Agent 的后续提交默认零副作用拒绝；只有用户新的完整指令明确表达强制发送时才允许直接发送。
- 项目关闭、应用退出或恢复遗留任务时，所有未完成记录进入 Interrupted，不自动续跑。
- CardTask 的“已提交”只表示任务文本成功进入 Agent 卡片，不表示 CLI 内部工作完成。

### Voice modes, prompts and routing

- 单次语音指令继续直接进入 CardTask；持续聆听继续先经过 Dialogue。两条路径共用同一高层 Agent 工具和协调模块。
- 每轮 Dialogue 与 CardTask 请求注入动态 Agent 名册，字段限于正式名称、预设语音别名、运行时类型、启用状态和活跃状态。
- Dialogue prompt 明确呼叫、创建、激活、多 Agent 委派、普通提及和真实回执规则；CardTask prompt 明确每类意图对应的高层工具及禁止底层绕过规则。
- Tool schema 描述业务语义、必填信息、批量原子性和 force 含义；结构化回执成为模型生成用户反馈的唯一执行事实。
- Dialogue 路由策略使用动态名称键识别明确呼叫结构。当真实 Dialogue Provider 漏掉 card-task start 时，策略注入一次且仅一次 fallback；普通提及和否定创建不触发 fallback。
- 缺少运行时类型、分工含糊或其他信息不足不创建持久澄清任务。当前请求以零副作用结束并返回简短重新表达提示，下一条语音是新请求。
- 现有 Norma 简短回复风格继续生效；复杂细节进入 UI 状态和日志，不由 TTS 长篇播报。

### UI behavior

- Settings 的 Add Agent 创建未保存草稿，预填下一个可用名称并可见地默认选择 Codex；用户可在保存前改名和改类型，取消不占用名称。
- Settings 保存只创建定义，不自动打开卡片；Open Card 通过协调模块激活定义。
- 工具栏、菜单和快捷键保留类型专用快速入口，自动分配名称、创建定义并立即打开唯一卡片。
- Settings 展示活跃保护错误、名称冲突、名称池耗尽、禁用状态和部分激活失败。
- 持续聆听期间真实 Done/Failed 可以排入 TTS 通知；其他模式只更新卡片状态和非打扰式 UI 通知。

### Persistence and migration

- 项目数据库增加规范化名称占用信息，以同时约束正式名称和预设语音别名；不能只依赖显示名称的大小写索引。
- Agent 委派任务使用独立于 CardTask 工具循环审计的持久记录，避免把“subagent 完成卡片操作”和“CLI Agent 完成开发任务”混成一个状态。
- 旧画布快照中缺少定义 id 的 Agent 卡片在项目恢复流程中迁移。合法且未冲突的 alias 优先保留，否则分配名称池名称并创建定义。
- 迁移保留原运行时类型、卡片和会话快照。名称池耗尽或无法安全命名时，卡片保持不可激活并提示用户处理，不生成非法名称。
- 迁移完成后持久化定义关联，后续打开不得重复创建定义。
- 所有 SQLite I/O 和旧卡片扫描发生在项目加载、用户操作或后台持久化路径，不进入 PTY output、Runtime route、send-node-input、mouse-move 或无脏关闭热路径。

## Testing Decisions

- 最高主 seam 是 Agent 协调模块的公开命令/结果 interface。名称、创建、激活、单卡、重命名保护、批量原子性、队列、managed/untracked、部分成功和恢复都从该 interface 验证，不断言私有集合或内部调用顺序。
- 协调模块测试使用真实内存 adapters，不 mock 自有内部模块。预期值来自本 SPEC 的固定名称、状态和任务文本，不通过复用生产算法计算。
- AgentSystem 是提示词与工具路由 seam。Scripted Provider 测试从完整用户文本开始，观察公开 AgentEvent、工具请求与结构化回执；不得直接调用私有解析函数代替核心路径。
- Prompt contract 测试验证 Dialogue 与 CardTask 请求实际包含 Agent 高层工具、动态名册、普通提及保护、底层绕过禁令和真实回执规则。测试必须通过最终 ProviderRequest 观察，而不是读取源文件搜索字符串作为唯一证据。
- 真实 Provider compliance 测试覆盖中文名、英文名、中文语音别名、明确呼叫、普通提及、创建缺少类型、多 Agent 明确分工、多 Agent 含糊分工和强制发送表达，并分别报告漏派发与误派发。
- Storage 测试通过仓库 interface 创建、列出、重命名、删除和恢复定义及任务，验证正式名称/语音别名冲突、Workflow Description 空值、队列状态和 Interrupted 恢复；不绕过 interface 直接把数据库查询当作主要断言。
- Canvas/Runtime 测试验证定义 id 随 snapshot 往返、旧 snapshot 兼容、一个定义只对应一个 live node、名称同步、Hook 终态推进以及关闭中断。Runtime 保持零 GPUI。
- App 单元测试验证 Settings 草稿不提前占名、快速创建调用统一协调 seam、活跃保护、简短回执、TTS 模式差异和 untracked 强制发送 UI。
- Headless GPUI e2e 至少覆盖：Settings 手动保存定义但不打开；工具栏快速创建定义与卡片；单次语音呼叫已有 Agent；持续聆听呼叫非活跃 Agent；未知/禁用名称零副作用；managed FIFO；untracked 二次提交拒绝与强制发送；旧卡片迁移。
- L1/L2 e2e 不声称启动真实 `.app` 或真实 CLI。新增 ignored L3 runner，使用真实 PTY 与已安装的 Agent Hook 验证任务文本进入 Codex/Claude/OpenCode 卡片、Hook Done/Failed 推进队列以及完成通知；报告必须明确环境前置条件和跳过原因。
- 所有用户可观察验收都必须映射到自动化证据。无法在无真实 CLI 环境稳定验证的部分使用 ignored L3，而不是只写手测说明。
- 所有新增 Rust 测试遵守仓库强制结构：完整场景、数据构造与数值推导、逐步执行过程、预期结果；每个断言带失败说明，关键状态逐一包含具体正断言和负断言，不用循环代替关键验收。
- 实现期间使用垂直 TDD：一个失败测试、最小实现、聚焦验证，再进入下一切片；禁止先批量写完所有测试或所有实现。
- 最终验证包含所有受影响 crate 测试、应用检查、完整 e2e、workspace 测试、存储/性能护栏、文件行数、禁止 allow、Agent 指南行数和 release build。真实 L3 按环境可用性运行并明确结果。

## Out of Scope

- 执行或解释 Workflow Description；它只保留为可选数据，后续规格再定义固定工作指令语义。
- 新增全局文字聊天输入框；现有卡片内键盘输入保持不变。
- 名称模糊匹配、编辑距离、发音相似度或由模型猜测最接近目标。
- 自定义 Spoken Name、多个自定义语音别名或自动生成中文音译。
- 中英文混合名称、数字名称、带空格、连字符、下划线或其他标点的名称。
- 同一 Agent 定义同时打开多张卡片或并行执行多个任务。
- 语音创建缺少运行时类型时静默默认 Codex。
- 可恢复的 AwaitingClarification 状态、跨回合澄清任务或自动保留未完成槽位。
- 自动安装、修改或强制要求 Codex、Claude、OpenCode hooks。
- 无 hooks 时猜测 CLI 是否空闲、扫描终端提示符或用定时器自动推进队列。
- 应用重启后自动恢复或重新执行未完成任务。
- 将提示词作为唯一业务约束；确定性规则必须保留在协调模块。
- 动态 Agent 市场、远程名称目录、跨项目名称唯一或跨设备同步 Agent 定义。
- 删除 Agent 定义时自动保留其卡片；活跃卡片必须先关闭。

## Further Notes

- 本规格深化现有实时 Dialogue/CardTask 架构：原有 CardTask 继续负责短生命周期工具循环，本规格新增的是持久 Agent 身份与 CLI 任务委派，不把两类任务状态混为一谈。
- 本规格遵循共享语音回合运行时 ADR：单次语音指令与持续聆听保留不同会话语义，但共享 Agent/工具执行能力。
- 主要架构取舍是用高层原子 Agent 工具取代模型自由组合通用卡片工具。提示词负责理解和选工具，确定性路由负责漏调用兜底，协调模块负责不变量，结构化回执负责真实性。
- 测试 seam 已在需求讨论中确认：协调模块公开 interface 是最高主 seam；AgentSystem 是提示词与工具路由 seam；headless e2e 与 ignored L3 只覆盖无法从主 seam 证明的用户集成行为。
- 本规格仅保存为仓库 Markdown，不发布到 Issue Tracker。
