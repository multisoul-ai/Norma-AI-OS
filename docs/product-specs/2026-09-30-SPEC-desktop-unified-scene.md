## Problem Statement

用户希望像 Windows 多任务视图一样同时看到多个工作空间，并像 Apple 桌面总览一样连续进入工作空间、展开项目和返回。目前缩略图、总览和展开项目经过不同显示路径；镜头运动时又不断改变控件布局，造成跳变、重影、文字尺寸变化、壁纸覆盖和输入位置不一致。仅调整弹簧或增加过渡层无法稳定消除这些问题。

用户还需要在多个项目和 Git worktree 中同时运行真实 Agent。动画必须保持任务、输入目标和画布位置连续，并在更多工作空间、活跃终端和视频壁纸同时存在时保持响应。

## Solution

桌面工作台采用统一场景、独立布局和 GPU 合成。所有工作空间、固定项目区域和真实卡片拥有稳定身份和共同坐标关系。总览、工作空间、展开项目以及卡片聚焦，是同一场景的不同视角与局部布局。

点击后立即从实际可见位置开始运动；再次点击会从当前画面和速度转向新目标。聚焦区域填满窗口安全边距与原有 Canvas Dock 之间的空间，消除外围边框和重复标题。壁纸和固定控件保持稳定，Agent 输入始终发生在卡片内。

优先复用真实内容的绘制结果，复杂内容按测量结果采用有限的 GPU 纹理缓存。隐藏工作空间停止无意义绘制，运行实例继续接收输出。缩略图不能使用另写的简化卡片冒充真实画布。

2026-10-01 缩略一致性修订：项目总览和目录内的项目预览与展开态复用同一真实 Canvas/session。字体、标题、徽章、按钮、圆角、阴影、玻璃及运行状态统一等比缩小，不单独 fit 每张节点或限制缩略字号。缩放只改变呈现，不改节点布局／viewport／PTY 尺寸。总览就地操作原卡片，目录只导航工作空间；不增加独立 Agent 输入栏。加载／未打开状态明确占位，禁止仿制实时卡片。展开和返回的起止内容矩形一致，无末帧换皮；原生 Browser 合成需独立验收。

### 对象关系

| 对象 | 本次采用的含义 |
| --- | --- |
| 桌面工作空间 | 本机持久化容器，可含多个固定排列的项目区域 |
| 项目区域／项目画布 | 同一「桌面工作空间 × 稳定项目身份」实例的总览与展开视角 |
| 卡片 | 项目画布中的真实 Live Node；导航不复制节点、Agent 会话或 PTY |
| Git worktree | Agent 执行目录；允许多个独立卡片同时使用，不决定画布身份 |
| 场景 | 上述对象的显示结构与坐标关系；不成为第二份业务数据或会话注册表 |
| 镜头 | 视口对场景的平移和缩放；与卡片内容、项目布局分别失效 |

## User Stories

1. 作为桌面用户，我想看到真实工作空间画布的缩略图，以便根据内容找到要继续的工作。
2. 作为桌面用户，我想在当前窗口进入工作空间的项目总览，以便自己选择项目；不自动恢复上次展开的项目或追加一次项目放大动画。
3. 作为桌面用户，我想在创建时为工作空间命名，再从空工作空间开始添加项目，以便辨认并组织工作。
4. 作为桌面用户，我想让多个项目自动排列为固定区域，以便稳定找到它们。
5. 作为桌面用户，我想再次添加同一项目时定位已有区域，以便避免重复画布。
6. 作为桌面用户，我想从项目区域的当前位置展开项目，以便理解总览与详细内容的关系。
7. 作为桌面用户，我想让展开项目占满可用画布且去掉外围边框和重复标题，以便集中阅读内容。
8. 作为桌面用户，我想返回时看到同一项目和卡片缩回原区域，以便继续操作其他项目。
9. 作为桌面用户，我想直接切换工作空间或项目，以便不用等待上一段动画完成。
10. 作为桌面用户，我想在动画中途反向操作，以便立即改变目标且不发生跳帧。
11. 作为桌面用户，我想在所有卡片视图中仍看清项目归属，以便不会混淆输入目标。
12. 作为桌面用户，我想从总览中的真实 Agent 卡片聚焦并输入，以便操作不同项目的 Agent。
13. 作为桌面用户，我想让发送、粘贴和快捷键只作用于目标卡片，以便避免向其他任务发送内容。
14. 作为中文用户，我想在缩放和聚焦后正确使用输入法候选框，以便输入位置与文字位置一致。
15. 作为桌面用户，我想在卡片里选择文字、滚动和操作链接，以便保留现有 Terminal／Agent 功能。
16. 作为桌面用户，我想在项目内移动和调整卡片，而不能把卡片移到其他项目或工作空间，以便保持归属明确。
17. 作为桌面用户，我想在两个工作空间分别使用同一项目和 worktree，以便同时开展不同任务且卡片互相独立。
18. 作为桌面用户，我想切走后 Agent 继续运行，切回时看到期间输出，以便放心同时处理多个任务。
19. 作为桌面用户，我想在目录、工作空间和展开项目间保留壁纸、半透明材质与卡片样式，以便界面保持一致。
20. 作为桌面用户，我想进入工作空间后使用原有 Canvas Dock，以便保留熟悉的创建和切换入口。
21. 作为桌面用户，我想通过 Dock 和可配置快捷键打开全窗口工作空间总览，以便快速切换且不出现额外弹窗。
22. 作为桌面用户，我想搜索后的工作空间位置与进入动画一致，以便不会出现隐藏结果重新出现或目标跳位。
23. 作为桌面用户，我想调整窗口和切换显示器后仍正确缩放、裁剪和点击，以便适应不同桌面环境。
24. 作为桌面用户，我想 Browser 和其他卡片在展开、收起时保持会话与正确层级，以便不出现浮在画布外的原生视图。
25. 作为开启减少动态效果的用户，我想保留明确状态与焦点反馈而减少大范围移动，以便舒适操作。
26. 作为键盘用户，我想在各个视角中继续导航和操作卡片，以便不依赖鼠标完成切换。
27. 作为桌面用户，我想在大量卡片和持续输出时仍流畅切换，以便任务越多时界面仍可用。
28. 作为桌面用户，我想重启后恢复工作空间及视角，同时正确区分历史内容和运行状态，以便不会把结束的任务误认为还在运行。
29. 作为桌面用户，我想移除或删除时只停止明确选中的运行实例，以便不影响共享项目目录的其他工作空间。
30. 作为已有用户，我想保留桌面已有卡片内容与 iOS 访问行为，以便渲染重构不会改变业务数据和手机协议。
31. 作为桌面用户，我想在已选项目中直接创建 Agent，默认使用该项目目录，以便不再重复选择或确认 Git worktree。

## Implementation Decisions

### 架构与范围

- 保留 Rust、现有 GPUI 与组件库版本；允许扩展仓库维护的 GPUI 补丁以支持场景变换、缓存重放和一致的输入命中。先验证扩展的可行性，不把普通容器缩放视为现成 API。
- 几何、布局和变换运算归零 GPUI 的画布域；输入意图沿用 runtime 路由；绘制、平台输入、原生视图和 GPU 资源归 app／GPUI。优先扩展现有职责，不另建通用渲染框架。
- 渲染以既有工作空间、项目区域、节点和运行实例为事实源；稳定显示身份包含所属工作空间和项目实例，不能仅按目录或局部节点 ID 复用。
- 删除预览／展开的独立卡片实现和为交接而存在的导航排队。异步项目加载仍可等待，但旧加载结果不得覆盖更新的导航目标。
- 不新增业务数据库结构，不迁移旧单项目画布；保留本工作树已实现的新桌面工作空间数据。GPU 资源与缓存可随时丢弃重建，不参与业务持久化。

### 布局与动画

- 工作空间列表按创建时间从早到晚固定排列，同时间戳按 ID 排序；新建追加末尾。打开、返回、搜索清空和重启均不按最近访问时间重排，列表与前后切换快捷键采用相同顺序。
- 统一计算场景逻辑布局；镜头变化不得触发响应式断点、终端网格缩放或全量内容重排。新增／删除／真实窗口尺寸变化／项目展开重排才使相关布局失效。
- 展开项目可产生新的内部目标布局；采用起止布局与视觉变换分离的方式呈现连续重排。不能以“布局稳定”为由省掉原型中的项目展开和卡片重排。
- 原型镜头采用临界阻尼弹簧，角频率为 15，阻尼系数为 2 × 15；平移和缩放共用显示时钟，改变目标时保留当前位置与速度。采纳原型的可中断性，不强制先收回旧项目再打开新项目。
- 原型局部卡片重排基准为 330ms、cubic-bezier(0.2, 0.8, 0.2, 1)；项目区域几何基准为 350ms ease-out，非目标区域透明度为 180–200ms ease-out。用合成变换重现可见轨迹，并验证文字、圆角与裁剪的连续性。
- 按真实显示帧时间推进；不得硬编码每帧至少 16ms。长停顿、窗口隐藏与恢复按当前目标稳定收敛；不得补播长时间积压动画。
- 命令一到即更新目标与选中反馈。系统减少动态效果开启时直接定位并保留焦点、选中等反馈；不以关闭普通模式动画作为性能优化。
- 23 号原型的布局关系、连续运动和展开后的简洁程度是基准；24 号参考决定最新窗口外观。两级总览采用自动网格、轻薄深色半透明底板、细边框、较小圆角与克制的选中描边；标题和状态保持简洁，真实 Agent／Terminal／Browser 内容随画布整体缩小，空窗口保留同样外壳。
- 工作空间缩略卡片的名称、次要状态与菜单锚点置于卡片内部的紧凑顶部标题栏，和预览共用半透明外壳；名称单行省略并可查看全文，窄窗口先省略次要状态。预览在标题栏下方等比显示，移除外置名称及预留间距；空／加载中／非空一致。名称与主体点击进入同一空间，菜单不误触发导航；标题随外壳淡出／恢复，展开后无残留。
- 展开时外壳淡出，返回时边框、底板与内容连续恢复；不得浮出无框卡片、末帧补框、背景覆盖内容或缩略控件比例失真。保留用户壁纸；不照搬参考中的视频人物、外部桌面、演示输入栏、固定窗口数量或假 Agent 内容。

### 绘制与资源

- 先复用真实卡片的绘制指令、文字与终端缓存，再依据性能测量决定哪些复杂子树需要离屏纹理；同一内容在不同视角沿用同一内容渲染入口。
- 总览中的可见输出持续更新；只缓存未变化内容。聚焦输入、光标和选区立即失效对应卡片；隐藏区域不做与可见画面无关的逐帧绘制。
- 缓存正确性必须覆盖内容版本、布局尺寸、显示缩放、主题／字体、裁剪和资源生命周期。纹理尺寸按当前显示需求分配，设置明确总预算、淘汰和失效规则；禁止每张卡片永久保留全分辨率纹理。
- GPU 缓存从真实绘制产生，不走每帧 CPU 截图、读回再上传。若首阶段无需纹理即可满足门槛，保留绘制复用方案，不提前构建纹理缓存系统。
- 壁纸维持固定屏幕坐标和正确背景层级；视频维持后台解码及低拷贝上屏。原有 Dock 固定，不随世界镜头缩放；按用户修订删除顶部导航横栏，释放占位。导航快捷键可录制与恢复，定义见 `docs/references/keyboard-shortcuts.md`。
- 半透明面板必须与壁纸正确混合；缓存不得把旧壁纸烘焙到卡片里。裁剪、圆角、阴影、文字栅格化与显示器像素比均属于渲染验证范围。
- Browser 等原生视图单独验证变换与裁剪支持；如需过渡缓存，必须来自同一真实内容且保留会话，落定后无跳变接回交互。不得用普通矩形代替或省略该类型。

### 工作空间创建时命名（2026-10-01，待实施）

- 所有新建入口先收集名称，再持久化并进入空总览；打开／克隆项目的目标选择器中新建时，命名成功后继续添加原项目。取消命名返回来源，保留待添加项目，不创建默认名称空间。
- 复用 `DesktopWorkspace.name` 及现有存储校验：trim 后 1–80 个 Unicode 字符，中文和同名可用、ID 独立；空白／超长提示并阻止提交。命名框自动聚焦，Enter 提交但输入法组词时不提交，Escape 取消；提交中防重复，失败保留输入供重试。
- 目录缩略图、切换入口、搜索及重启恢复沿用同一名称；长名省略并可查看完整内容，保留改名能力。具体交互与边界以桌面工作空间 SPEC 的创建流程及实施计划 §4 为准。

### 输入与生命周期

- 绘制变换和命中逆变换同源；命中、滚动、拖拽、文字选区、输入法候选框、可访问性边界和菜单定位一致。只变换视觉而保留旧点击位置不算完成。
- 总览缩略图先选择或聚焦目标，再接收文字输入；工作空间总览中保留原有卡片就地聚焦能力。已有显式键盘焦点可以继续向同一会话输入，隐藏或切换后的焦点不得泄漏。
- PTY 行列数由卡片实际内容布局决定；镜头缩放不得发送逐帧 resize。局部重排的内容布局与终端 resize 必须形成一致提交点，避免动画末帧重新换行和闪跳。
- 视图切换不启动、关闭或复制 Agent；会话继续运行。移除／删除／退出沿用已有确认与精确回收规则。
- 创建 Agent 默认取所属项目区域保存的实际目录 `area.root` 作为 `cwd`，包括普通目录和已选 Git worktree；不再列出、选择或确认 worktree，不自动创建／切换 worktree 或分支，也不退回仓库主目录。未确定项目时仅选择／添加项目区域。这里的 Agent 工作目录不改变桌面工作空间身份；既有卡片的 `cwd` 不被覆盖。
- Dock、快捷键、项目菜单和自定义 Agent 定义共用以上创建规则；后台校验目录与项目身份且不依赖外部 Git 可执行文件，捕获原始 workspace／area／目录，导航后不投递到新选中项目。目标被移除或失效时不启动并给出可重试状态；允许同目录多 Agent 及跨空间独立会话。
- 性能诊断复用现有可选诊断入口，默认只记 ID、计数和耗时；遵循诊断日志 ADR，不记录终端或用户正文，不在渲染热路径同步写日志或数据库。

## Testing Decisions

用户于 2026-09-30 明确要求停用旧 `crates/e2e`。不再新增、维护、运行该套件，也不把其历史结果作为验收证据；不要换目录继续运行旧 harness。

2026-10-01 验收分工修订：原型布局、材质和动效还原由用户亲自验收，不再安排独立 UI 验收 subagent。23／24 号参考及本规格的实现标准保留；Agent 继续负责单元／集成测试、Computer Use 真实 App 功能／交互回归和性能验收。矩阵中的功能证据与用户的原型验收结论分别记录，未收到用户结论时不代判还原通过。

- 纯几何、导航状态机、路由、存储与进程生命周期由所属 crate 的单元/集成测试覆盖；GPUI 补丁使用底层图元、变换和缓存测试。
- 真实 PTY 集成测试覆盖输入、输出、会话身份与回收；不以模型响应时间衡量 UI 延迟。
- 用户流程由 Computer Use 操作隔离真实 App，保存连续画面、回执、构建身份和性能原始数据。单元测试或单张截图不能代替真实动画验收。
- 全部 USC-01 至 USC-14 保持原行为标准；矩阵中的“单元/集成”表示新的所属 crate 证据，“真实 App”表示独立应用验收，不是旧套件的层级入口。
- 历史恢复失败改由真实产品路径复核：产品缺陷需要修复，旧 harness 的时序或共享环境问题只留历史记录。

## Out of Scope

- iOS 页面、同步语义、手机协议或 workspace 身份重构。
- 替换业务存储、迁移旧单项目存档、重写 Agent／PTY／ANSI 协议。
- 卡片跨项目或工作空间移动、同 worktree 互斥限制。
- 重建工作空间级 Norma 输入框或扩大跨项目派工功能。
- 引入 Electron／WebView 全工作台替换方案，或升级整套 GPUI／组件库。
- 泛化的跨平台合成引擎、未经瓶颈证实的全终端 dirty-row 重构。
- 新增触控板横滑交互、自动发布或强制推送。

## Further Notes

- 采用 `apple-design` 的空间连续性、内容优先与可访问性，采用 `emil-design-eng` 的及时响应和可中断性；依据 `improve-animations` 将实现问题按优先级写入计划，原型还原最终由用户验收。
- 原型优先于通用动画技能里的时长建议；本任务明确需要快速切换的连续动画，不能按通用高频操作规则删掉它。
- 当前已确认的是源码结构和缓存失效条件，尚没有统一场景方案的真实性能结果；实施必须先经过纵向验证关卡。
- 旧计划归档表示被新方案替代，不表示此前 Goal 已完成。未提交代码必须保留并逐项评估复用。
- 本规格与实施计划的初版已一起发布到 #73；2026-10-01 本地修订尚未同步 Issue。旧 #65–#71 的产品范围与状态不自动关闭。

### 2026-10-01 项目快捷切换补充

底部编号、项目菜单和项目快捷键直接从当前 Agent 画布移动到目标 Agent 画布。使用 23 号原型的同一镜头弹簧（225/30）、180ms 项目淡入淡出和350ms局部尺寸过渡；不先回总览，也不清除动画瞬间替换。连续改目标保留可见位置与速度，重复当前目标不重播，减少动态效果即时到达。壁纸／Dock 固定，真实会话不中断；未加载目标就绪前保留当前画布。验收包含双向、三项目中途转向、加载／取消、返回总览和实际输入，使用底层测试与 Computer Use 连续画面。
