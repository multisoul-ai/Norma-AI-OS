- 范围：Dialogue、当前画布上下文、当前项目、Agent 呼叫、多 Agent 委派、CardTask、Agent 工作上下文与任务接力

## Problem Statement

用户已经能在项目中定义具名 Agent，并通过 CardTask 把任务派发到 Agent 卡片。但当前交互仍像在操作一套命令系统：用户往往需要完整说出“指派一个任务给 Bella”，而不能像在同一个工作间里那样直接说“Bella，你去搜索一下当前的项目”。

现有 Dialogue 只注入当前 Agent 名册，不知道当前项目和画布上其他卡片的轻量摘要。确定性路由可以为部分单 Agent 句首点名表达兜底，但现有产品规则仍过度强调“让、请、交给、打开”等委派词，且对多 Agent 的自然集合呼叫、同一任务并行派发和任务正文中的 Agent 名称缺少完整语义。这会导致真实模型漏调工具、多余确认、错把普通提及当成目标，或无法把一个共同任务派发给多个 Agent。

更进一步，“Bella，检查 Alan 写的代码”不只是名称解析问题。Bella 是接收者，Alan 是工作来源；如果 Alan 仍在工作，还存在立即检查阶段性成果或等待完成后接力的时序区别。当前系统没有简约的 Agent 工作上下文、跨 Agent 依赖或只读查询工具，因此无法可靠表达这类工作接力。

用户需要 Norma 理解“谁在画布上、当前项目是什么、谁是任务接收者、谁只是任务内容中的工作来源”，同时保持提示词简约、不复制完整卡片内容，并且不把任务已接收误报为已完成。

## Solution

建立一套“结构化上下文 + 明确语义规则 + 确定性兜底 + 高层 Agent 工具”的自然委派链路。Prompt 负责向模型解释产品语义，结构化当前画布上下文提供当前事实，确定性路由为明确可执行表达的漏调工具兜底，CardTask 与 Agent 协调器继续作为唯一副作用执行边界。

一期交付自然委派与画布感知：

- 将“句首精确点名 + 可识别动作”定义为直接寻址指令，与“让、请、交给、指派”等显式委派等价。
- 在每轮 Dialogue 中提供简约的当前项目与当前画布上下文。所有卡片暴露身份与基本状态，Agent 卡片额外暴露名称、语音别名、运行时类型、启用、活跃、跟踪与忙碌状态。
- “当前项目”“这个项目”“我们的项目”默认指向当前打开的 workspace；存在 workspace 时不再追问路径，不存在时不猜测本地目录。
- 支持一条指令内多 Agent 独立分工，也支持用“都”“一起”把同一任务分别派发给多个 Agent。此处的“一起”只表示各自独立接收同一任务，不声称 Agent 之间存在实时协作。
- 只把句首点名集合或明确分工结构中的 Agent 视为委派目标；任务正文里提及的 Agent 不自动成为目标。
- 已定义、已启用但没有活跃卡片的 Agent 在派发时自动激活；未知或已禁用目标不隐式创建、不隐式启用。
- 多 Agent 委派在任何副作用前完成全量目标与任务预检；任一目标无效时整组不执行。
- 详细卡片内容不进入默认上下文；副作用执行前仍由工具查证实时状态。

二期交付 Agent 工作上下文、任务接力与按需查询：

- 为 Agent 工作建立简约上下文，包含当前任务、运行状态、工作位置、最近结果、错误摘要和可定位变更，但不默认复制完整对话、终端输出、文件内容或 diff。
- 派发时只携带最小交接摘要和定位信息；目标 Agent 通过项目内只读查询工具按需获取协作元数据，通过自身文件与 Git 能力读取代码与 diff。
- 用户引用仍在运行的来源 Agent 工作时，默认等待来源任务结束再启动接力；“现在”“当前部分”等明确即时表达会直接使用阶段性成果。
- 来源任务成功时正常接力；失败时携带失败与错误摘要继续接力；用户主动中断或取消时取消等待中的接力；状态无法验证时暂停并说明原因。

## User Stories

1. 作为画布用户，我想说“Bella，搜索一下当前项目”，以便不必先说“指派一个任务”。
2. 作为语音用户，我想让句首 Agent 名称后的自然停顿、逗号或冒号都能被理解，以便 ASR 标点差异不会改变意图。
3. 作为文字用户，我想用“让 Bella”“请 Bella”“交给 Bella”或“指派给 Bella”，以便显式委派表达继续可用。
4. 作为项目用户，我想让“当前项目”“这个项目”“我们的项目”自动指向当前 workspace，以便不必重复路径。
5. 作为没有打开项目的用户，我想让系统不猜测本地目录，以便避免任务进入错误位置。
6. 作为画布用户，我想让 Norma 知道当前画布上有哪些卡片，以便我可以基于当前工作台语境表达意图。
7. 作为画布用户，我想让所有卡片只暴露身份和基本状态摘要，以便不会把大量卡片内容塞进每轮提示词。
8. 作为 Agent 用户，我想让 Norma 了解 Agent 的名称、语音别名、运行时类型和可用状态，以便委派目标稳定。
9. 作为 Agent 用户，我想让 Norma 了解 Agent 是否已活跃、是否忙碌以及是否可跟踪，以便能准确表达已提交或已排队。
10. 作为隐私敏感用户，我想让终端正文、网页内容和完整会话默认不进入 Dialogue 上下文，以便减少敏感内容泄露与 token 浪费。
11. 作为多 Agent 用户，我想说“Bella 和 Alan，你们都分析当前项目”，以便同一任务可以并行派发给两个 Agent。
12. 作为多 Agent 用户，我想说“Bella 搜索项目，Alan 运行测试”，以便在一条指令里完成独立分工。
13. 作为多 Agent 用户，我想让“一起”只表示每个 Agent 独立接收同一任务，以便系统不会虚构 Agent 间实时协作。
14. 作为多 Agent 用户，我想让整批委派在任一目标无效时零副作用失败，以便不会只执行成功一部分。
15. 作为用户，我想让“Bella，检查 Alan 写的代码”只把 Bella 当成接收者，以便任务正文中的 Alan 不被误派发。
16. 作为用户，我想让“让 Bella 检查 Alan 写的代码”只有一个目标，以便宾语位置的名称不改变委派集合。
17. 作为用户，我想让“我觉得 Bella 这个名字不错”保持普通对话，以便名称提及不会意外触发工具。
18. 作为用户，我想让对 Agent 过去工作或当前状态的询问不新建执行任务，以便查询与委派保持区分。
19. 作为已经定义 Bella 的用户，我想在 Bella 卡片已关闭时仍直接呼叫她，以便系统自动激活卡片后派发。
20. 作为调用禁用 Agent 的用户，我想获得明确禁用反馈且没有副作用，以便我可以先恢复 Agent。
21. 作为调用未知名称的用户，我想让系统不隐式创建新 Agent，以便名称错误不会制造新卡片。
22. 作为用户，我想让任务正文只移除寻址词和口语冗余，以便目标、范围、顺序、约束、交付物和明确命令不会丢失。
23. 作为用户，我想让信息充分的自然委派立即进入 CardTask，以便模型不再追问可选的实现细节或验收标准。
24. 作为用户，我想让目标、动作或多候选指代真正不可识别时只出现一个最小必要问题，以便不必重述整个任务。
25. 作为用户，我想让已提交、已排队、未跟踪和已完成保持不同语义，以便 Norma 不会误报任务状态。
26. 作为真实模型用户，我想在模型漏调 `card_task` 时仍能派发明确指令，以便关键副作用不只依赖 Prompt 服从度。
27. 作为真实模型用户，我想让普通提及与说明性问题不被确定性兜底扩大成执行，以便兜底不会带来新的副作用风险。
28. 作为维护者，我想让 Prompt、上下文渲染、路由策略和工具 schema 使用同一套领域词汇，以便不会再次出现语义冲突。
29. 作为维护者，我想在公开 AgentSystem 管线上验证自然语料到高层派发命令，以便测试保护用户行为而不是私有函数。
30. 作为维护者，我想让默认画布上下文大小有界，以便卡片数增长时不会无限吞噬模型上下文。
31. 作为二期用户，我想让 Bella 收到 Alan 的简约工作上下文，以便她知道要检查哪项工作。
32. 作为二期用户，我想让交接摘要只包含任务、状态、工作位置、最近结果、错误摘要和变更定位信息，以便提示词保持简约。
33. 作为二期用户，我想让 Bella 用只读工具查询 Alan 的详细协作元数据，以便她可以按需深入而不是一次接收所有内容。
34. 作为二期用户，我想让 Bella 使用自身文件与 Git 能力读取代码，以便 Norma 不必在派发提示词中复制完整 diff。
35. 作为二期用户，我想在 Alan 仍在工作时说“Bella，检查 Alan 写的代码”，以便系统默认等 Alan 当前任务结束后再派发。
36. 作为二期用户，我想说“Bella，现在检查 Alan 已经写的部分”，以便可以明确绕过默认等待。
37. 作为二期用户，我想在 Alan 成功时自动启动 Bella 的接力任务，以便无需手动看守。
38. 作为二期用户，我想在 Alan 失败时仍让 Bella 接力，并获得错误摘要，以便失败成果也能被检查或修复。
39. 作为二期用户，我想在主动中断 Alan 后取消等待中的 Bella 任务，以便已放弃的方向不会继续。
40. 作为二期用户，我想在 Alan 状态不可验证时看到接力已暂停的真实反馈，以便系统不会根据猜测执行。
41. 作为二期用户，我想让只读查询严格限制在当前项目，以便不会跨 workspace 泄露信息。
42. 作为二期维护者，我想让任务接力复用现有 Agent 终态事件与任务队列，以便不会建立第二套并行真相源。

## Implementation Decisions

### 分期与交付边界

- 一期是可独立交付和验收的端到端切片，包含自然 Agent 呼叫、多 Agent 语义、当前项目、当前画布上下文、自动激活、原子委派、真实回执和漏调工具兜底。
- 二期在一期语义之上增加 Agent 工作上下文、只读查询工具和任务接力。一期不得预先声称二期已有的依赖或查询能力。
- 二期必须建立在可信 Agent 任务终态之上；无法跟踪或无法验证来源状态时，不得自动推进依赖任务。

### 当前画布上下文契约

- 为 Dialogue 提供一份结构化、项目内、有界的当前画布上下文，不使 Dialogue 反向依赖 App、Runtime、Storage 或 GPUI。
- 当前项目至少包含可供模型理解的项目身份与 workspace root；未打开项目时显式表达缺失，不注入猜测路径。
- 非 Agent 卡片摘要只包含稳定节点身份、类型、可用标题与基本交互状态；Agent 卡片额外包含定义身份、呼叫名、语音别名、运行时类型、启用、活跃、跟踪与忙碌状态。
- 默认上下文不包含终端正文、网页 DOM 或页面内容、文件内容、完整对话、完整任务历史和 diff。
- 上下文渲染必须有确定顺序和显式大小上限。超过上限时保留当前项目、可寻址 Agent 与当前聚焦卡片，其余卡片使用稳定截断与计数标记，不得静默伪装成完整画布。
- 当前画布上下文是意图理解快照，不是执行真相源。聚焦、发送、删除、激活与委派在产生副作用前必须通过工具和协调器重新验证。

### Agent 呼叫与目标解析

- 继续使用当前项目 Agent 呼叫名与预设语音别名作为寻址的唯一事实源，保留精确匹配、英文大小写容忍和未知名称不隐式创建等现有约束。
- 将句首单个或多个精确呼叫名，后接非空可识别动作的结构视为直接寻址。允许逗号、冒号、自然空白和 ASR 可能产生的相邻标点，但不对名称做模糊匹配。
- 多 Agent 目标集合只来自句首集合呼叫或显式分工结构。任务正文中的其他 Agent 呼叫名保持任务内容，不加入目标集合。
- 明确集合表达将同一轻量润色后的任务正文复制为每个目标的独立 assignment；明确分工表达为每个目标产生对应任务正文。
- “一起”“都”是共同任务集合标记，不代表共享上下文、直接消息、主从关系、互相等待或实时协作。
- 名称仅作为话题、属性、历史工作或状态查询对象时，不产生新任务。如果查询需要副作用或状态工具，必须使用对应查询动作，不得伪装为新委派。

### Prompt、确定性路由与 CardTask

- Dialogue Prompt 明确使用“Agent 呼叫”“多 Agent 委派”“当前画布上下文”与“当前项目”领域词汇，不再暗示用户必须说出“指派任务”。
- CardTask Prompt 使用同一目标解析与共同任务语义，不得在 Dialogue 已识别目标后重新提高派发门槛。
- 确定性路由扩展到明确的单 Agent 直接寻址、多 Agent 集合寻址和独立分工，并保留对普通提及、说明性问题、否定指令和状态查询的误触发保护。
- 当确定性路由判定为明确委派，但 Dialogue 模型没有产生有效 `card_task start` 时，丢弃模型的多余追问或建议文本，并用原始用户意图创建唯一兜底任务。
- 委派意图只做 Agent 任务润色，不摘要化删减、不新增用户未提出的需求，不代替目标 Agent 分析实现。
- 当前画布上下文与用户原始指令作为 Dialogue 意图理解输入；CardTask 对任何副作用仍通过高层工具获得实时状态与结构化回执。

### 委派执行与原子性

- 现有高层 Agent 列表、激活与批量委派工具继续作为执行边界，不回退到通用卡片创建与文本发送组合。
- 已定义且已启用的非活跃 Agent 在委派执行中自动激活，并在 CLI 可提交前保持等待提交状态。
- 批量委派在激活或写入任务之前预检所有目标、启用状态、任务正文、跟踪状态和强制发送条件。预检失败时整批零副作用。
- 多目标中已激活与未激活 Agent 可共存，但不得因激活中途失败而把未完整执行误报为全部成功；结果必须如实反映已发生的事实。
- 同一 Agent 的多任务继续使用 FIFO 队列，不同 Agent 可并行；“一起”不改变单 Agent 并发上限。
- 对用户的立即反馈只能表达 submitted、queued、untracked 或真实失败；只有可信终态可表达 completed 或 failed。

### 二期 Agent 工作上下文与只读查询

- Agent 工作上下文是结构化、项目内、有界的交接摘要，其事实来自现有 Agent 定义、任务队列、运行时终态和已持久化任务记录，不从模型自由文本中推测。
- 最小交接摘要只包含来源 Agent 身份、当前或最近任务、可信状态、工作位置、最近结果或错误摘要，以及可用的变更定位索引。
- 只读查询工具允许目标 Agent 查询当前项目内的 Agent 任务与状态元数据、变更文件列表、可定位 diff 或有界日志。工具默认不返回完整对话与无界终端输出。
- 代码内容和 Git diff 优先由目标 Agent 使用自身现有文件与 Git 工具读取。Norma 查询工具负责提供工作来源、状态与定位索引，不复制通用代码浏览器。
- 所有查询严格限定当前项目，是只读、可审计、有返回大小上限的操作。

### 二期 Agent 任务接力

- 任务接力使用现有 Agent 任务终态作为唯一推进信号，不从卡片文本、模型回答或超时猜测完成。
- 当来源 Agent 正在运行且用户没有立即标记时，接收任务进入等待来源状态；明确的“现在”“当前部分”直接以当前阶段性工作上下文派发。
- 来源进入成功终态时，生成最小交接摘要并派发接收任务。来源进入失败终态时，摘要包含失败和错误摘要，仍派发接收任务。
- 来源因用户主动中断或取消结束时，取消所有直接依赖该次工作的等待任务并给出真实反馈。
- 来源丢失、终态不可验证或跟踪不可信时，接力进入暂停，不自动执行，不将暂停误报为取消或完成。
- 任务接力不赋予 Agent 间实时通信、共享记忆或相互工具调用；它是由 Norma 协调的有向、可审计、基于终态的工作移交。

### 诊断与真实性

- 当启用完整 Prompt/response trace 时，诊断信息可记录当前画布上下文的结构与截断元数据，但必须遵守现有敏感信息开关，默认日志不复制完整内容。
- 路由决策、目标集合、原子预检失败、激活结果、派发回执和二期接力状态必须可诊断，但不将日志当作产品事实源。

## Testing Decisions

### 主验收 seam

- 一期使用公开 AgentSystem 管线作为最高的主测试 seam：输入原始用户语料与当前项目/画布上下文，使用可编程 Provider 模拟模型漏调、正常调用与错误调用，最终观察公开事件、高层 CardTask 命令、原子派发回执和审计记录。
- 二期继续复用同一主 seam，只扩展可观察输入为来源 Agent 终态与只读查询回执，输出为接力等待、派发、取消或暂停状态。
- 主 seam 测试只验证外部行为，不断言私有路由函数的中间分支，不绑定 Prompt 的完整字符串，不以模型生成的自然语言总结代替结构化回执。

### 一期必要语料与行为矩阵

- 单 Agent 直接寻址：“Bella，你去搜索一下当前的项目”必须产生 Bella 的唯一 assignment，模型漏调时仍必须进入 CardTask。
- 无标点直接寻址：“Bella 你去搜索当前项目”必须被识别，但“Bella 是一个好名字”不得触发。
- 共同任务：“Bella 和 Alan，你们都搜索当前项目”必须产生两项正文语义相同的 assignment。
- 独立分工：“Bella 搜索项目，Alan 运行测试”必须产生两项不同 assignment，且顺序可预期。
- 工作来源非目标：“Bella，检查 Alan 写的代码”必须只派发 Bella，任务正文保留 Alan。
- 普通提及：“我觉得 Bella 这个名字不错”必须保留 Dialogue 回答且不产生任务。
- 说明性请求：“怎么让 Bella 搜索项目”必须保持说明性 Dialogue，不得执行。
- 项目指代：存在 workspace 时，“当前/这个/我们的项目”均不追问路径；缺失 workspace 时零副作用说明。
- 非活跃 Agent：已定义且启用的 Bella 必须先激活再提交，且不创建第二个定义。
- 原子失败：两个目标中任一未知、禁用或任务为空时，两个目标都不得被激活或写入。
- 上下文隐私：渲染后的当前画布上下文必须包含项目身份、Agent 和非 Agent 卡片摘要，同时明确不包含构造的终端秘密、网页正文和完整对话标记。
- 上下文截断：超过上限时保留当前项目、全部可寻址 Agent 与当前聚焦卡片，并输出被截断卡片数，不得泄漏详细内容。

### 二期任务接力矩阵

- 来源已完成或空闲：“Bella，检查 Alan 写的代码”立即派发，最小交接摘要包含 Alan 的最近任务与定位信息。
- 来源正在运行：无即时标记时 Bella 进入等待且不得提前写入；带“现在”或“当前部分”时立即派发。
- 来源成功：成功终态只触发一次接力，交接摘要不包含完整输出或 diff。
- 来源失败：失败终态仍触发一次接力，并携带有界错误摘要，不得宣称 Alan 成功。
- 用户主动中断：等待中的 Bella 任务被取消且永不提交。
- 状态不可验证：Bella 任务进入暂停，不得误报完成、失败或取消。
- 只读边界：查询只返回当前项目、授权字段和有界结果；跨项目、写操作、完整对话与无界日志请求均被拒绝。

### 测试层级与先例

- Agent 领域测试覆盖上下文渲染契约、Prompt 行为标记、确定性路由正反语料、多目标解析、CardTask 工具 schema 和任务润色。优先复用现有 Dialogue policy、Agent roster context、Prompt template 与 Agent tool contract 测试风格。
- App 边界测试覆盖从当前 workspace、Canvas document、Agent definitions 和 Runtime 状态组装轻量上下文，以及非活跃 Agent 自动激活、批量预检和真实回执。
- Headless GPUI e2e 覆盖打开项目、存在多张 Agent/非 Agent 卡片时，从对话入口提交自然指令到画布上的卡片激活、任务状态和原子失败。该层不声称启动真实 `.app`。
- 真实 Provider 合规语料可作为受环境控制的补充验证，但不作为唯一回归保障；模型漂移必须由确定性契约测试兜底。
- 新增的所有单元测试必须使用项目约定的场景、数据构造、执行过程、预期结果注释；每个断言带失败说明，关键目标同时有具体正断言和负断言。

## Out of Scope

- 一期不实现 Agent 工作上下文查询工具、跨 Agent 任务依赖或等待接力。
- 不在默认当前画布上下文中注入完整终端输出、网页内容、文件内容、对话历史、无界日志或完整 diff。
- 不实现 Agent 间实时通信、共享记忆、直接相互调用、主从 Agent 编排或同一任务的合并交付物。
- 不使用 Agent 工作流描述进行模糊自动路由，不将 Workflow Description 自动注入 Agent CLI 任务。
- 不对未知名称自动新建 Agent，不对已禁用 Agent 自动启用。
- 不引入跨项目或全局 Agent 上下文，不允许一个 Agent 查询另一 workspace 的卡片或任务。
- 不在本 SPEC 中重新设计 Agent 呼叫名、语音别名、单卡约束、FIFO 队列、Hook 终态或现有 TTS 任务通知。
- 不以提示词变更为理由放宽副作用真实性、原子性、未跟踪任务二次提交或其他现有安全约束。

## Further Notes

- 本 SPEC 使用根词汇表中的“Agent 呼叫”“多 Agent 委派”“当前画布上下文”“当前项目”“Agent 工作上下文”与“Agent 任务接力”作为 canonical 领域语言。
- 本 SPEC 对“多 Agent 委派”的新决策取代旧规格中“Alan 和 Bella 一起开发必须因分工不明而拒绝”的早期限制。新语义是：当“都”“一起”等共同任务标记明确时，同一任务可以作为独立 assignment 分别派发给每个目标。
- 一期是对现有可语音呼叫 Agent 与高层委派能力的纵向深化，不是建立新的旁路对话运行时。
