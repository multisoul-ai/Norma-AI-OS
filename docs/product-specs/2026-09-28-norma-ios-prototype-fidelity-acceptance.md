# Norma iOS 两套原型的逐屏还原与验收

状态：开发与 to-spec 的强制视觉验收依据；原生页面尚未实现。参考图为 [09-28 五屏](norma-ios-ideas-workspaces-2026-09-28/生成提示词.md)与 [09-26 十屏](norma-ios-prototypes-2026-09-26/生成提示词.md)。

## 还原标准

- **一比一还原页面，而非复刻图片外壳。** 原生 SwiftUI 页面须对照参考图还原信息顺序、主要元素位置与比例、间距、字体层级、色彩、圆角、图标、头像、卡片、状态标记、底部操作区和可见文案；保留真实滚动、键盘、安全区和可点击控件。不要把整张原型图贴成页面，也不要在 App 内绘制 iPhone 边框或假状态栏。
- **浅色 iOS 与 Liquid Glass。** 以参考图的白、暖灰、深蓝、蓝色主操作、薄荷与少量粉黄为视觉基线。导航、浮动输入区、底栏、Sheet 等功能层在支持 Liquid Glass 的系统上使用原生玻璃材质与组合效果；正文卡片、长文本和证据保持清晰实底。当前项目最低 iOS 17：旧系统使用系统材质与相同层级的兼容表现，不用自制模糊层冒充系统 Liquid Glass。具体 API 以构建时可用的 iOS SDK 核实。
- **素材必须补齐。** 优先复用项目已有 Norma 形象与图标；缺少可用的虚拟人、头像、插画或成果预览时可生成素材并加入 iOS 资源，检查授权、分辨率、裁切及深浅背景可读性。不能用任意 emoji 或空白框代替参考图的关键形象。
- **静态图也要落实交互。** 导航进出沿同一路径，Sheet 从触发处出现、跟随拖动且可中途反向；保存、派工、接收、失败、验收等状态即时反馈；虚拟人说话和字幕同步。动效服务于状态与空间关系，不遮挡正文。系统开启减少动态效果时使用短淡入和明确文字状态；支持动态字号、VoiceOver、足够对比度与至少 44pt 的主要触控目标。设计检查采用 `.agents/skills/apple-design` 的层级、可中断性与可访问性原则。

## 冲突与优先级

1. 09-28 图和已确认的数据模型决定产品结构：**想法独立于 Workspace；一个 Workspace 关联项目和 Agent，并包含多个工作线程**。W01 中「想法保存即产生 Workspace」的状态不得照搬。W01 的搜索、筛选与卡片视觉仍需实现。
2. P03/P05 是 Workspace 首页和工作线程的主视觉基准。W01/W04 补足搜索筛选和持续对话的交互状态；W03 的 Sheet 从 P04 打开，不以旧聊天页为固定背景。
3. 已取消 Workspace「硬约束」功能。W03、W05、W06、W08 的旧禁令或冲突文案需换成普通工作要求或真实待决事项；保留图的层级、位置、材质与颜色关系，不暗示系统保证了不存在的门禁。Mac 原有设备授权与高风险操作审批继续有效。
4. Norma 首页的长期私聊独立于 Workspace。W07 所示 Workspace 信息仅在用户明确选定关联上下文后出现；语音不会默认把私聊注入线程。

## 开发 Agent 自行验收的交付物

每个页面任务结束时，开发 Agent **自己完成测试、操作和差异修正**，并在任务验收记录中留下：参考图路径、同尺寸真实 App 截图、逐屏差异记录及修复结果、关键交互的自动化用例与运行结果、Computer Use 操作真实 App 的记录。可观察流程覆盖原生 UI/e2e；Mac 派工、终端、成果使用真实回执，不用假卡片证明完成。T9 汇总检查全部 15 张图，无遗漏、无过期产品规则、无被遮挡或不可点击的入口。扫码、麦克风、实时通话和设备上的玻璃材质/性能另在真机核对；若当时无法取得真机或真实服务，只能记录为未验收，不能写成通过。
