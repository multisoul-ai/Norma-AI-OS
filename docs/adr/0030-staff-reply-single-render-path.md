# 幕僚回复单路径渲染：每轮一条消息、过程摘要落盘、升级清库

## 决策

1. 每个幕僚轮次在 `Task.messages` 里对应一条幕僚回复（`TaskMessage::Staff`），文字、
   过程摘要和卡片引用都是它的 parts。App 只渲染 `Task.messages`，不再维护内存里的
   活动时间线。
2. 流式期间 brain 通过 `TaskStore::update_live` 只改内存并广播本轮增量，不写盘、不加
   revision；步骤结束、卡片入库和回合结束时落盘。
3. 过程摘要（步骤标题、状态、耗时、计划）落盘；工具入参与输出不落盘。
4. 幕僚不再使用 `task reply`，流式文字是回复正文的唯一来源。
5. 快照升到 v2，不迁移 v1：读到 v1 时备份为 `tasks.v1.bak.json` 后从空库开始。

## 为什么

原来持久化消息与 `TaskActivity` 两套渲染靠消息下标对齐，brain 中途插入回复会挪动
下标；工具步骤只在内存，历史和实时看到的不一致；`task reply` 与流式文字两个来源
导致看到的话事后消失。合成一条消息、一条渲染路径后这些问题从结构上消失。

清库而非迁移：产品仍在开发期，旧消息无法还原过程摘要，迁移代码只会长期带着两套变体。

## 代价

- 升级时旧任务不可见（有备份文件）；由旧任务派发、仍在运行的 Worker 完成后无主。
- 流式期间内存与磁盘短暂不一致；进程崩溃丢失最近一次落盘后的流式文字，加载时
  `Running` 回复记为失败。
