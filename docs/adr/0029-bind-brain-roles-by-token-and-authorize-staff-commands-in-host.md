# 按 token 绑定大脑角色，由宿主授权幕僚命令

## 决策

大脑启动时为主大脑（含审批助手）和幕僚各生成一个独立的 `NORMA_BRAIN_TOKEN`。幕僚会话
进程的环境只带幕僚 token。宿主在命令入口按 token 认出角色，再检查：

1. 命令在该角色的白名单内（对 `BrainOp` 穷举匹配，新增命令必须先决定幕僚能不能用）。
2. 幕僚的 `task` 命令只能操作当前正在进行的那一轮所属的任务。
3. 幕僚的 `history` 只能读本任务派出过的 Agent；主动 `report` 每任务 10 分钟最多 2 条。

幕僚可以用 `task assign` 自行派发后续活，但必须同时满足：「后续任务」设置为「直接派发」、
目标是刚完成任务的同一个 Agent、本任务自动派发未满 3 次、内容不命中高风险类别。任一不
满足，宿主把它记成等用户采用的提议。

命令用法放进内置的 `norma-brain` skill（只装给当前大脑后端），系统提示词只保留角色、
底线和身份。

## 为什么

权限闸门移除后（`794eaa39`），命令边界只剩提示词，宿主分不清命令来自谁。提示词里的
“不能直接 assign”拦不住被注入的 Worker 输出。角色 token 让白名单由代码保证。

## 取舍

- 任务绑定靠“当前进行中的轮次”而不是每任务一个 token：ACP 会话进程跨任务复用，环境变量
  在进程启动时固定。代价是依赖 App 收到轮次开始事件的时机，没有进行中的轮次时一律拒绝。
- 关键词识别高风险是启发式，只降低概率；真正的边界是同一 Agent、次数上限和设置开关。
- 不暴露 `task message`：它会让模型以用户身份写消息并唤醒自己（`b73fd418`）。
- skill 装在 CLI 的全局目录，同一 CLI 下的 Worker 也能读到它；Worker 没有幕僚 token，
  误调用 `brain` 命令会被宿主拒绝。
