# 多 Agent 委派先原子接收再独立投递

多 Agent 委派不应一边向各 Agent 终端写入一边建立接收回执，否则中途失败会产生无法回滚的部分派发。我们决定：先预检全部目标并将整组任务一次性全部写入 Norma 管理的 Agent 队列，或全部不写入；每个逐 Agent 任务使用稳定 `assignment_id`，并以 `TraceId + assignment_id` 作为幂等键，重复派发调用只返回已有状态，不得重复入队。原子写入后的初始状态统一为 `Accepted（已接收）`，它只表示当前应用会话中的 Norma 已接管任务，不是目标 Agent 的派发回执，只更新界面的处理中状态，也不得触发“正在派发”或“任务已派发”播报。普通助手回复继续使用现有流式 TTS；任务结果复用现有回复与通知路径，但只有真实派发回执或可信终态才能播报。原子接收后再分别激活目标卡片、投递 CLI 并跟踪终态。多 Agent 回执先后到达时，界面逐个更新，语音必须等全部目标都有派发结果后汇总播报一次。单个 Agent 后续投递失败是该 Agent 任务的独立结果，不回溯否定整组已原子接收的事实；当同批目标只有部分派发成功时，批次状态为 `PartiallyDispatched（部分已派发）`，反馈必须逐 Agent 指明成功与失败，不得将整批笼统表述为成功或失败。取消操作按目标隔离：点名某个 Agent 只取消该目标任务，不影响同批其他目标；只有用户明确要求取消全部时才取消整批。应用退出、崩溃或重启时清空所有尚未提交给目标 Agent 的 `Accepted` 与等待任务，之后不自动恢复派发；任务历史保留并标记为 `Interrupted（已中断）`，继续使用原 `TraceId` 关联诊断日志。
